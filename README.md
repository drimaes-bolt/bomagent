# 다봄(DaBOM) — 전사 BOM 변환·추적 시스템 기획

> **시작도 뿌리도 BOM이다.** 다봄은 여러 부서의 업무로 넓어지지만, 모든 기능은 하나의 일에서 나온다. 회로설계 엔지니어가 쓴 E-BOM에 재고 리스트 같은 SCM 정보를 합쳐 양산용 M-BOM으로 자동 변환하고, 양산이 끝날 때까지 관리하는 일이다. 이름의 '봄'이 BOM이고, 약칭은 다봄(DaBOM) 또는 BOM Agent다.

다봄은 연구소의 E-BOM을 받아 사내 보유재고·사내 거래처·후보 부품을 반영한 M-BOM을 만들고, 양산이 끝날 때까지 모든 변경을 이유·영향과 함께 추적하는 드림에이스 사내 시스템이다. 연구소·생산관리·구매/자재·회계가 같은 BOM을 본다.

## 0. 시작도 뿌리도 BOM이다

| 층 | 무엇 | 문서 |
|---|---|---|
| **뿌리** | **BOM**: E-BOM(설계) + SCM 정보(재고 리스트·거래처·구매 이력) → M-BOM(양산), 그리고 개정과 변경 이력. 모든 부서가 같은 BOM을 본다 | [docs/01 1.6](docs/01_프로젝트_정의.md) |
| 줄기 | 처음 만든 기능. 가져오기 → 맞추기 → 만들기 → 품번 → 확정 → 추적 | [docs/02](docs/02_업무흐름.md) |
| 가지 | 부서별 확장. 원가·알림·생산 준비·품질 확인과 앞으로 늘 기능. 모두 BOM에서 읽고 BOM에 돌려준다 | [docs/03 0.1](docs/03_부서별_활용.md), [docs/04 1.1](docs/04_기능_범위.md) |

- 기능은 매우 다양하게 넓어질 수 있다. 다만 새 기능·화면·모듈은 "BOM의 무엇을 읽고 무엇을 BOM에 돌려주는가"를 한 줄로 적어야 한다. 적을 수 없으면 범위 밖 후보로 미결에 올려 사람이 범위를 정한다(DEC-18, [CLAUDE.md](CLAUDE.md) 4·5장).
- 시연 목업의 첫 화면이 이 구성이다: 뿌리 → 줄기 → 가지 지도 안에서 부서를 고른다([briefing/index.html](briefing/index.html)).

## 1. 이름

| 대상 | 이름 | 설명 |
|---|---|---|
| 시스템 | **다봄** (DaBOM) · 전사 BOM 변환·추적 시스템 | 현장에서 'BOM'을 '봄'으로 읽는 데서 따왔다. 다(모두) + 봄(BOM). 모든 부서가 같은 BOM을 다 본다. 기존 문서의 'BOM Agent'와 같은 대상이고 'BOM Agent'는 약칭으로도 쓴다(DEC-01 보충). 두 이름이 공유하는 낱말이 BOM이다 |
| 파생 프로젝트 | **다봄 구축 프로젝트** (Project DaBOM, 코드 `DABOM`) | 이 폴더가 다루는 드림에이스 사내 프로젝트 |
| 협력사 모델 | NC AI BOM 도메인 모델 | NC AI가 만들고 다봄이 API로 호출한다 |
| 사용자 메뉴(모듈) | 가져오기 · 맞추기 · 만들기 · 품번 · 확정 · 추적 · 알림 · 원가 · 기준정보 | 기능 목록은 [docs/04](docs/04_기능_범위.md) |

'BOM Agent'를 바꾼 이유와 검토한 다른 이름은 [docs/01 1장](docs/01_프로젝트_정의.md)에, 결정 기록은 [docs/11](docs/11_결정_미결_목록.md)의 DEC-01에 있다.

## 2. 큰 흐름

```text
 연구소 E-BOM 업로드
      │
      ▼
 ① 가져오기   파일 구조 해독 · 원문 보존 · 표기 분류와 사양 해석(모델)
      │
      ▼
 ② 맞추기     지정 부품 → 사내 기존 품목(동일·동등, 재고 보유 → 재고 0 사용 이력) → 후보 부품 풀 → 거래처 카탈로그 → 외부 후보
      │       품목마다 사내 거래처와 구매 조건을 붙인다
      ▼
 ③ 만들기     제품 → 반제품 → 부품 구조 · 수량과 LOSS · 베어 PCB·펌웨어·Set 조립 행 · ERP 양식
      │
      ▼
 ④ 품번       기존 ERP 코드 재사용 / 규칙대로 발번 / 사양 미확정이면 보류
      │
      ▼
 ⑤ 확정       확인 요청 처리 → 부서 승인 → 기준선 → ERP 등록
      │
      ▼
 ⑥ 추적·알림  설계 변경·고객 요청·단종·가격·공급 중단 → 변경 패키지 → 영향·효력·재고 처분·원가
      └──────▶ ②~⑤를 변경 패키지 단위로 다시 수행 (양산 종료까지)
```

## 3. 누가 무엇을 하나

| 주체 | 하는 일 | 하지 않는 일 |
|---|---|---|
| NC AI 모델 | 표기 분류, 사양 해석, 후보 판정과 근거 제시 | 부품 확정, 수량·원가 계산, 단가·재고 판단 |
| 다봄 | 파일 해독 준비, 사내 데이터 조회, 규칙 검증, ERP 코드 재사용·발번, M-BOM 구성, 승인 흐름, 변경 추적, 기록 | 사람 대신 확정하기, 제품·반제품 품번 만들기 |
| 사람(각 부서) | 확인 요청 응답, 제조사 선택, 구조·품번·변경 승인, 효력·재고 처분 결정 | 기록 없이 결과만 고치기(고친 내용은 교정 로그로 남긴다) |
