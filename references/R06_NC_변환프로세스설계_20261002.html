1. 개요

  • 금번 설계 범위는 BOM Agent 사용자 시나리오의 1순위 태스크인 E-BOM 표기 → MPN 매핑으로 한정하였습니다.
  • NCAI 모델 튜닝 전이므로, 데모에서는 Claude Opus 5를 연결하였습니다.

2. E-BOM → M-BOM 처리 흐름도

  • Agent 구조는 모델 작동 방식에 대한 이해를 돕기 위해 임시로 구성한 것입니다.
  • 전달 주신 문서(E-BOM 작성 가이드, 룰북, E-BOM/M-BOM 쌍) 중 모델 판단에 필요한 내용은 회사 관례·정책 문서 형태로 정리하였고, 모델이 필요할 때 이를 reference로 참조한다는 전제로 데모를 구성하였습니다. 문서의 어느 부분을 언제 넣을지는 Agent가 정합니다.
  • Agent는 컨텍스트*를 구성해 모델에게 전달하고, 모델은 분류·해석·판정만 수행하며, 모호한 사항은 담당자가 결정합니다.
    • 컨텍스트* = 참조 자료(부품 그래프 조회 결과, 회사 관례·결정 문서, 유통사 API 검색 결과 등) → Agent가 조회해 모델 입력에 넣습니다.
  • 3절의 Task 구성 및 모델 입출력은 공유해주신 ‘BOM Agent 사용자 시나리오 및 예외 룰북’을 출발점으로 삼되, 모델과 에이전트의 역할을 나누면서 일부 조정하였습니다. 추후 실제로 모델 학습을 수행하며 Task 및 입출력 구성이 변경될 수 있습니다.

3.1. [Task 1] 부품 카테고리 분류

  • Task 목표
    • 각 행에서 나타내는 부품이 어떤 부품 카테고리에 속하는지 하나로 분류합니다.
    • 올바른 부품 카테고리로 분류되면, [Task 2]에서 해당 카테고리가 가지는 필수/선택 속성 및 단위(UoM)을 조회하여 사양 문자열에 대한 정규화를 수행할 수 있습니다.
    • BOM에서 RES 1608, Chip, 1/10W, 5%과 같은 Part Description이 없고 MPN이 바로 주어진 경우, Digikey API 검색을 통해 얻은 해당 부품의 메타 정보를 input으로 사용합니다.

3.2. [Task 2] 사양 해석 및 정규화

  • Task 목표
    • [Task 1]의 분류 결과를 바탕으로, 그래프로부터 분류된 부품 카테고리의 속성/단위 정보를 참고하여 정규화를 수행합니다.
      • 정규화의 범위
        • 1) 최소 의미 단위의 사양 문자열(예: 470nF)이 어떤 속성을 가리키는지 매핑 (470nF → 정전용량; capacitance)
        • 2) 해당 속성의 기준 단위 확인 (F)
    • 모델 판정 결과에서 blocking: true 사안이 있을 경우, 사용자 확인이 끝나지 않는 이상 다음 단계로 넘어가지 않습니다.
  • [참고] 칩저항; Chip Resistor (SMD) 카테고리와 관련된 그래프 내 정보 탐색 결과
    • 그래프 내에는 각 부품 카테고리가 가지는 필수/선택 속성 및 각 속성의 표준 단위가 수록되어 있습니다.
    • 왜 RDB가 아닌 그래프를 활용하나?
      • 특정 속성이 가지는 허용값 목록, 속성값 간의 일치 관계(예: EIA 0402 == IEC 1005), 기업 내에서 사용하는 속성과 외부 체계(예: IEC, Digikey) 간의 연결고리를 생성하고 활용하는 데 있어 그래프가 가진 ‘연결성’이 유리하기 때문입니다.
