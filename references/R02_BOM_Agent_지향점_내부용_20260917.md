# 단일 진실 공급원(SSOT) 기반 지능형 BOM Agent 지향점

> **문서 성격** · 이 문서는 완성된 PRD가 아니다. 앞으로 기획할 **BOM Agent가 어떤 방향과 핵심 강점을 가져야 하는지**를 서술한 방향성 문서다. 화면 명세·API 스펙·일정은 포함하지 않으며, 기획 단계에서 확정할 판단 기준과 도메인 지식을 정의한다.
>
> **AX 방향성** · 본 문서는 계층형 BOM을 **없애는 것을 목표로 하지 않는다.** 계층을 사람이 만들고 갱신하는 **유지 비용을 없애는 것**이 목표다. 반제품 품번처럼 물리적·회계적 실체가 있는 항목은 정보량을 늘려도 자동화로 사라지지 않으므로, 대체 가능한 영역과 불가능한 영역을 [1.3.4](#134-ax의-역할-경계--무엇을-없애고-무엇을-없앨-수-없는가)에서 경계로 못박았다.
>
> **적용 전제** · ① 주력 제품군은 **산업용**(소량 다품종·장수명·광온도 등급)이다. ② 고객사의 물질 선언(각 부품의 화학성분 공개) 요구가 없다고 가정하고 초기에는 컴플라이언스 수집 프로세스는 범위 외로 둔다. ③ EMS·턴키 위탁은 현 단계에서 고려하지 않는다(사내 생산 전제). ④ 1.4의 계층형 BOM 샘플과 4장의 부품 예시는 **설명용 가상 예시**이며, 실물 표기 패턴은 향후 모델 학습 단계에서 대폭 보강한다. 범위에서 제외한 항목과 재검토 조건은 [부록 A](#부록-a-현-범위-제외-항목과-재검토-조건)에 남긴다.

## 1. E-BOM과 M-BOM 통합 단일 마스터 테이블(SSOT) 아키텍처

하드웨어 제조 현장에서 데이터 불일치가 발생하는 근본 원인은 설계 시점의 **E-BOM**(기능·스펙 중심)과 생산·구매 시점의 **M-BOM**(공정·조달 중심)이 서로 다른 시스템에서 복제·분리 관리되기 때문이다.

BOM Agent는 복수의 엑셀 파일을 유지하는 대신, 모든 라이프사이클 속성을 포괄하는 **통합 단일 마스터 테이블**을 관리하고, 각 부서의 접근 권한과 업무 목적에 맞춘 **가상 뷰(Role-Based Contextual View)** 를 실시간 렌더링한다.

### 1.1 통합 단일 마스터 테이블 데이터 스키마

단일 마스터 테이블의 각 행(Row)은 제품을 구성하는 물리적 실체 또는 가상 아이템을 정의하며, 다음과 같은 카테고리별 컬럼군을 **단일 레코드 내에서** 유지한다.

| 분류 | 컬럼명 | 설명 | 주 소유/수정 부서 |
|---|---|---|---|
| **기본 식별자** | `Item_ID` / `Line_No` | BOM 내 고유 순번 및 시스템 내부 UUID | 시스템 공통 |
| | `Ref_Designator` | 회로도 참조 부호 (예: C12, R45, U3) | R&D (연구소) |
| | `Raw_Input_Text` | 엔지니어가 원시 파일에 기재한 원본 텍스트 | R&D (연구소) |
| **엔지니어링 (E-BOM)** | `Normalized_Value` | 파싱 및 표준화된 전기적 수치 (예: 2.2kΩ, 100nF) | BOM Agent (자동) |
| | `Footprint_Package` | 실장 풋프린트 규격 (예: 1608 Metric / 0603 Imperial, SOIC-8) | R&D / Agent 검증 |
| | `Tolerance` / `Rating` | 공차(±1%) 및 정격 전압·전류 (예: 50V, 1A) | R&D (연구소) |
| | `Target_MPN` | 엔지니어 지정 또는 추론된 제조사 고유 부품 번호 | R&D / Agent 확정 |
| | `Schematic_Function` | 회로 기능 그룹 (예: Power Supply, I2C Pull-up, RF Filter) | R&D (연구소) |
| **조달·공급망 (P-BOM)** | `Internal_PN` (IPN) | 사내 ERP 정식 자재 마스터 코드 | 구매팀 / Agent 매핑 |
| | `Approved_MPN_List` | 호환 승인된 제조사 부품군 (AVL: FFF 호환 목록) | 구매팀 / Agent 추천 |
| | `Primary_Supplier` | 주 발주 거래처 (지사, 대리점, 상가 유통상, 직구 등) | 구매팀 |
| | `Unit_Price` / `Currency` | 체결 단가 및 통화 단위 (KRW, USD, CNY 등) | 구매팀 / 재무팀 |
| | `MOQ` / `SPQ` / `Lead_Time` | 최소발주수량, 포장단위(릴 수량), 예상 납기(Week) | 공급망 데이터 연동 |
| **제조·실장 (M-BOM)** | `SMT_Feeder_Type` | 표면실장 라인 피더 규격 (8mm Paper Tape, Tray, Tube 등) | 생산기술팀 |
| | `Drop_Loss_Factor` | 자재 탈락 로스율 (통상 Chip 계열 1~3% 가산) | 생산기술팀 |
| | `Assembly_Routing` | 투입 공정 단계 (SMT Top, SMT Bottom, 수삽(DIP), 조립) | 생산기술팀 |
| | `Consumable_Flag` | 부자재 여부 (솔더크림, 방열패드, 본드 등 E-BOM 누락 품목) | 생산기술팀 |
| **회계·자금 (Finance)** | `Payment_Terms` | 대금 결제 조건 (선결제, 마감 후 익월 말일 등) | 재무팀 |
| | `3Way_Match_Status` | 발주서(PO)–입고증–세금계산서 대사 상태 (`Pending` / `Matched` / `Exception`) | 재무팀 (자동) |
| | `Cost_Center` | 원가 배부 부서 및 프로젝트 회계 코드 | 재무팀 |

#### 1.1.1 라이프사이클·신뢰도 컬럼군 *(교차검증 보완 · 신규)*

시나리오 C(ECO 동기화)와 6장 KPI(환각률·Zero-Touch Rate)가 성립하기 위해 원본 스키마에 없던 **리비전·출처·신뢰도** 축을 추가한다. 이 축이 없으면 "무엇을 근거로 자동 확정했는가"를 사후 추적할 수 없다.

| 분류 | 컬럼명 | 설명 | 주 소유/수정 부서 |
|---|---|---|---|
| **리비전·라이프사이클** | `Revision_ID` / `ECO_Ref` | 마스터 테이블 리비전 및 이를 유발한 ECO 번호 | Agent (자동) / 품질팀 |
| | `Lifecycle_Status` | 부품 수명 상태 (`Active` / `NRND` / `EOL` / `Obsolete`) | 공급망 데이터 연동 |
| **추론 근거** | `Confidence_Score` | Agent의 MPN·IPN 확정 신뢰도 (0~100) | Agent (자동) |
| | `Source_Provenance` | 확정 근거 (사내 발주 이력 / AVL / 유통사 API / 모델 추론) | Agent (자동) |
| | `Verified_By` / `Verified_At` | 사람이 확인한 주체와 시각 (HITL 승인 감사 추적) | 각 부서 |

### 1.2 부서별 필터링 가상 뷰 (Contextual Views)

단일 테이블을 바라보되, 각 부서는 업무상 필요한 필드만 접근하며 **상호 합의되지 않은 필드의 수정은 차단된다.**

- **R&D 엔지니어링 뷰**
  회로 설계 및 전기적 특성 중심. 단가나 결제 조건 등 불필요한 상업적 데이터는 마스킹되며, 부품의 공급 상태(단종 여부, 활성 생산 여부, 장납기 위험 알림)와 풋프린트 일치 여부만 시각적으로 강조된다.

- **구매/조달 뷰**
  사내 품목 코드(IPN), 승인된 대체 MPN, 벤더별 실시간 재고 상태, MOQ, 단가 마진, 공급처별 납기 위주로 노출된다. 엔지니어링 스펙(정격전압, 허용오차 등)은 대체재 검토 시 팝업 형태로만 참조된다.

- **생산기술/자재관리 뷰**
  SMT 릴 단위 포장 상태, 라인별 피더 번호, 로스율 반영 소요량, 입고 예정일, 현장 랙(Rack) 위치 정보가 표시된다. 완제품 1단위 생산에 필요한 실제 물리적 자재 수량과 부자재(Consumables)가 포함된 최종 구조를 확인한다.

- **재무/회계 뷰**
  공급처별 매입채무 발생일, 약정 결제일, 세금계산서 수취 여부, 3-Way Matching 일치율, 외환 환산 손익 등 자금 집행 관점의 지표만 집계되어 표시된다.

- **품질/수입검사 뷰**
  수입검사 대상 목록, MSL 등급과 개봉 후 잔여 실장 가능 시간, 데이트코드·로트 번호, 베이킹 필요 판정, 대체재 승인 이력이 표시된다. 단가·결제 조건은 마스킹한다.

### 1.3 왜 설계는 단층 BOM, 양산은 계층 BOM인가

설계자가 넘기는 BOM은 거의 항상 **단층(Flat) 구조**이고, 세트 양산에서 쓰는 BOM은 **계층 구조**다. 어느 한쪽이 잘못 만든 것이 아니라 두 단계의 목적과 도구가 다르기 때문이다. Agent는 이 두 형태 사이의 변환을 담당하므로, 변환 규칙보다 먼저 **왜 형태가 다른지**를 명시해 둔다. 배경을 모른 채 변환하면 "설계자가 계층을 안 만들어 줬다"는 잘못된 진단으로 흐른다.

> **표기 기준 두 가지**
>
> - **레벨 번호** — 본 문서는 최상위를 **Lv 0**으로 표기한다. 현장과 MRP 교재에서는 최상위를 Level 1로 두는 표기도 널리 쓰이므로([Cambridge IfM MRP 설명](https://www.ifm.eng.cam.ac.uk/research/dstools/mrp/)), 사내 ERP 화면 표기와 다르면 **사내 기준으로 통일**한다. 어느 쪽이든 계층 깊이(완제품·반제품·부품 3단)는 같다.
> - **반제품 명칭** — 본 문서는 **PCBA**(Printed Circuit Board Assembly)를 표준으로 쓴다. 국내 현장에서 널리 쓰는 **PBA**(Printed Board Assembly)와 같은 대상이며, PCA·CCA도 동일 개념이다([용어 구분](https://www.viasion.com/blog/differences-similarities-between-pcb-and-pcba/)).

#### 1.3.1 설계 단계가 단층인 이유 — 도구의 산출 단위가 보드다

**① EDA의 BOM 출력 단위는 PCB 한 장이다**

Altium·OrCAD 같은 회로 설계 도구는 [계층형 멀티시트 회로도](https://www.altium.com/vi/documentation/altium-designer/schematic/multi-sheet-hierarchical-designs)를 정식 지원하고, Altium은 [멀티보드 설계 환경](https://www.altium.com/documentation/altium-designer/multi-board-design)까지 제공한다. **즉 EDA가 계층을 다루지 못하는 것이 아니다.**

문제는 그 계층의 성격이다. 회로도의 계층은 **도면 구성의 계층**(가독성, 회로 블록 재사용, 멀티채널 복제)이며 제조 조립 계층이 아니다. 컴파일 후 BOM은 참조 부호 단위로 평탄화되어 **보드 1장 기준 목록**으로 출력된다. 멀티보드 프로젝트에서도 보드 간 BOM 취합은 도구 밖의 별도 프로세스로 다뤄야 한다는 점을 [Altium 자체 자료](https://resources.altium.com/p/how-pros-manage-manufacturing-multi-board-projects)가 밝히고 있다.

따라서 정확한 진단은 이것이다. **설계자가 단층을 고른 것이 아니라, 도구의 산출 단위가 보드다.**

> 참고 · Altium의 BOM은 [베어 보드(PCB) 자체를 하나의 구성품으로 포함](https://www.altium.com/documentation/altium-designer/preparing-bom-report-manager)한다. [1.4.1](#141-3계층-bom-샘플-가상-예시--산업용-제어-유닛) 샘플에서 PCB를 부품 레벨(Lv 2) 자재로 배치한 근거가 여기에 있다.

**② SMT 프로그램은 참조 부호 1:1 대응을 요구한다**

SMT 장비가 입력으로 받는 것은 BOM이 아니라 **좌표 데이터**(Pick & Place / Centroid: 참조 부호 · X · Y · 회전각 · 실장면)이고, BOM은 그 좌표에 붙일 품번을 대응시키는 짝이다. 대응이 **참조 부호 단위 1:1**이어야 장비 프로그램이 성립하므로, 중간에 조립 계층이 끼어들 자리가 없다.

**③ 다만 생산 단위는 보드가 아니라 패널이다**

SMT는 보드 한 장씩 흘리지 않고 **다면취 패널** 단위로 생산한다. 1패널이 4면이면 패널 1장 투입 = 보드 4장 생산이다. 단층 BOM은 보드 1장 기준이므로, 실제 투입량과의 사이에 **패널 배수라는 또 하나의 수량 변환 지점**이 생긴다. 로스율과 별개의 배수이며, 계층 전개 시 놓치기 쉽다(`Panel_Qty`).

#### 1.3.2 양산 단계에서 계층이 필요해지는 조건

**계층화는 양산의 전제 조건이 아니다.** 아래 다섯 가지 사정 중 하나라도 성립할 때 계층이 필요해지는 것이며, 전부 성립하지 않으면 계층은 관리 편의에 그친다. 조건과 당위를 구분해 읽어야 [1.3.3](#133-계층-깊이-결정-기준--실물-품번인가-팬텀인가)의 판정 기준이 성립한다.

**① 공정 순서와 작업지시 제어**

세트 양산은 순차 공정을 거친다.

```text
[Lv 2 부품 투입]
   SMT 실장 → 수삽(THT/DIP) → 검사(AOI·ICT·기능)
        │
        ▼
[Lv 1 반제품 완성 = PCBA]
   기구·세트 조립 (하우징 결합, 하네스 배선, 라벨)
        │
        ▼
[Lv 0 완제품]
   최종 검사 → 포장
```

계층이 있으면 **반제품 단위로 작업지시(Work Order)를 분리 발행**할 수 있다. 산업용 제품은 커넥터·전해 커패시터·퓨즈 등 수삽 부품 비중이 커서 SMT와 수삽이 별도 공정으로 갈리며, 이 구분이 `Assembly_Routing` 값의 근거가 된다.

반제품을 별도 오더로 생산한다면 일정 축도 따라온다. MRP는 레벨별 생산 리드타임을 역산해 착수일을 잡으므로(lead-time offset), "최종 조립 납기를 맞추려면 PCBA를 언제 착수해야 하는가"가 레벨 구조에서 계산된다.

> **주의 · 투입 순서 제어만으로는 계층이 정당화되지 않는다**
>
> 부품의 투입 시점 제어는 계층 없이도 가능하다. 단일 레벨 BOM에서 **각 부품을 라우팅 공정(SMT → 수삽 → 조립 → 포장)에 배정**하면 계획 엔진이 배정된 공정을 기준으로 자재 소요일을 산출한다. 주요 ERP가 표준 기능으로 제공하는 방식이다([Oracle · Item and Operation Sequence](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/25c/fapim/item-and-operation-sequence.html), [SAP · Component Assignment](https://learning.sap.com/courses/s-4hana-peo-foundational-setup-and-basic-processes/assigning-components-prts-and-documents-to-operation-activities)).
>
> 따라서 이 항목은 **계층이 있을 때 얻는 이점**이지, 계층을 만들어야 하는 이유가 아니다. 계층을 강제하는 것은 아래 ②~⑤, 특히 반제품이 재고·거래·추적의 대상이 되는 경우다.

**② ERP/MRP 물류·재고·원가 집계**

반제품(PCBA)에 **자재번호가 부여되어야** 레벨별 재고와 재공(WIP), 그리고 반제품 단위 원가 집계가 가능해진다. 계층이 없으면 자재 소요량이 완제품 단위로만 전개되어 하위 반제품의 재고 파악과 원가 집계가 불가능하다.

산업용 제품에서 이 구조가 특히 중요한 이유는 **A/S**다. 서비스 자재는 완제품이 아니라 **PCBA 단위로 교체·공급**되므로, 반제품 품번이 없으면 수리용 재고를 잡을 수도, 서비스 단가를 산정할 수도 없다.

> 반제품 단위 외주 임가공도 같은 구조를 요구하지만, 위탁 생산은 현 범위 밖이다([부록 A](#부록-a-현-범위-제외-항목과-재검토-조건)).

**③ 모듈 재사용과 변경 관리 — 양면성이 있다**

하나의 PCBA를 여러 파생 모델(Model A / Model B)에 공용으로 쓰는 경우가 많다. 계층 구조에서는 회로 부품(Lv 2)이 바뀌어도 **해당 PCBA(Lv 1) 정보만 수정**하면 되고, 완제품(Lv 0) 구조를 모델마다 일일이 고칠 필요가 없다.

**그런데 같은 구조가 반대 방향으로도 작동한다.** 공용 모듈을 하나 바꾸면 그 모듈을 쓰는 **모든 파생 모델이 동시에 영향을 받는다.** 재사용의 이점과 변경 파급의 위험은 같은 구조에서 나온다. 따라서 계층 구조에는 **where-used 역추적**이 반드시 함께 있어야 하며, 이것이 시나리오 C의 영향도(Blast Radius) 계산이 존재하는 이유다.

**④ 기구·세트 자재의 편입**

회로 BOM에 존재하지 않는 자재가 세트 단계에서 추가되어 완제품 계층을 완성한다. 하우징(사출 또는 판금), 나사·스페이서, 케이블·와이어 하네스, 라벨, 사용설명서, 포장 박스가 그 대상이다. 이들은 참조 부호가 없고 단위가 섞이며 식별자가 도면번호일 수 있어, 회로 부품과 같은 로직으로 처리하면 깨진다([1.4.2](#142-회로-bom과-기구-bom의-구조-차이)).

**⑤ 소유권 경계**

계층화의 가장 근본적인 이유다. **Lv 0/Lv 1 경계가 곧 E-BOM(설계 소유)과 M-BOM(생산·구매 소유)의 책임 경계**다. 설계자는 PCBA 안쪽을 책임지고, 그 위 계층은 생산기술과 구매가 정의한다.

1장의 단일 마스터 테이블 전제가 여기서 의미를 갖는다. 경계를 파일 분리로 표현하면 두 개의 진실이 생기지만, **레벨 필드와 소유 부서 필드로 표현하면 하나의 테이블 안에서 소유권을 유지한 채 구조를 이어붙일 수 있다.**

#### 1.3.3 계층 깊이 결정 기준 — 실물 품번인가, 팬텀인가

계층을 없애는 것도, 계층을 깊게 만드는 것도 목표가 아니다. **목표는 계층 깊이를 조건으로 최소화하는 것**이다. 반제품 품번은 하나 늘어날 때마다 자재 마스터·재고 로케이션·검사 기준·작업지시가 함께 늘어나므로, 필요 없는 레벨은 만들지 않는 것이 옳다.

**판정 체크리스트** — 아래 다섯 질문 중 하나라도 '예'이면 실물 품번(재고를 잡는 반제품), 전부 '아니오'이면 팬텀으로 둔다.

| # | 판정 질문 | '예'일 때의 근거 |
|---|---|---|
| 1 | 이 반제품을 상위와 **분리해 재고로 보관**하는가? (선행 생산, 여유 생산, 다른 로트 크기) | 실물 재고에 붙일 식별자가 필요 |
| 2 | **A/S 또는 외부 거래로 단독 출하**하는가? | 출하·판매 문서의 대상 품번이 필요 |
| 3 | 반제품 단위 **시리얼·로트 추적이나 별도 검사 성적**이 필요한가? | 추적 단위가 곧 품번 단위 |
| 4 | 상위와 **다른 일정·로트 크기**로 생산하는가? | 리드타임 오프셋이 실재 |
| 5 | **둘 이상의 상위 모델이 공용**하는가? | 재사용 단위 정의와 where-used 색인이 필요 |

업계에서도 같은 기준을 쓴다. Cetec ERP는 "재사용되거나, 재고로 보유하거나, 시리얼 관리하거나, 별도 검사하거나, 자체 일정으로 생산되는 경우"에 연결된 서브어셈블리로 두라고 정리한다([판단 기준](https://cetecerp.com/blog/how-multi-level-boms-and-revisions-prevent-costing-and-build-errors-in-custom-fabrication/), [분리 시점](https://cetecerp.com/blog/scheduling/when-to-break-a-manufactured-part-into-subassemblies-in-cetec-erp/)).

**팬텀(Phantom)이라는 정식 선택지** — 체크리스트를 통과하지 못한 노드는 삭제하는 것이 아니라 **팬텀**으로 둔다. 구조는 BOM에 남지만 재고를 잡지 않고 작업지시도 생성되지 않으며, 상위 오더로 그대로 관통(blow-through)해 소비된다. Oracle·SAP·QAD·Epicor·Acumatica·Dynamics가 모두 표준 기능으로 제공한다([Oracle 정의](https://docs.oracle.com/cd/A60725_05/html/comnls/us/mrp/itmattrs.htm), [QAD](https://www.qad.com/documentation/EE/2017/UG/Manufacturing_UG_v2017EE/Phantoms.html), [Arena](https://www.arenasolutions.com/resources/glossary/phantom-bom/)). APICS 정의는 "물리적으로 존재하지 않을 수 있으나 회계 단위로 취급되는 항목"이며, 회계 관점에서는 재공(WIP)을 표현한다고 본다([해설](https://www.sikich.com/insight/phantom-boms-in-microsoft-dynamics-ax-their-role-in-mrp-and-costing/)).

팬텀은 **하이브리드 운영도 허용한다.** Oracle 문서는 팬텀의 용도 중 하나로 "필요할 때 제조해 재고로 둘 수 있게 하는 것 — 예를 들어 필드 서비스용 예비품을 간헐적으로 생산·보관"을 명시한다. 평시에는 관통 처리하고 A/S 수요가 발생할 때만 실물로 취급하는 운영이 가능하다.

**계층 없이 운영하는 대안들** — 참고로 정리해 둔다. 세 가지 모두 실제로 쓰이는 방식이며, 그중 하나는 본 프로젝트에 맞지 않는다.

| 대안 | 방식 | 본 프로젝트 적용 |
|---|---|---|
| **팬텀 BOM** | 구조 유지, 재고·오더 없음, 상위로 관통 | ✅ 채택 — 체크리스트 미통과 노드의 기본값 |
| **공정 배정형 단일 레벨** | 반제품 품번 없이 부품을 라우팅 공정에 배정, 소요일은 공정 기준 산출 | ⚠️ 부분 채택 — 투입 시점 제어에는 유효하나 A/S 품번 요구는 해결 못 함 |
| **반복 생산(REM) + 백플러시** | 계획오더를 작업지시로 전환하지 않고 완성 보고 시 일괄 역산 차감 | ❌ 부적합 — SAP가 적용 조건을 "제품 안정성·반복률 높고 **복잡도 낮은** 시나리오"로 규정([REM 개요](https://learning.sap.com/courses/configuring-sap-s-4hana-cloud-public-edition-manufacturing-execution/outlining-repetitive-manufacturing_e75801d3-0376-4c83-bb52-3802bf211132)). 산업용 소량 다품종은 정반대 조건 |
| **평탄화 뷰(Flattened BOM)** | 관리는 계층, 조달·원가 분석은 눌러서 조회 | ✅ 채택 — 관리 구조와 사용 형태의 분리([정의](https://www.arenasolutions.com/resources/glossary/flattened-bom/)) |

**1.4 샘플에 적용하면** — 제어 PCBA와 전원 PCBA는 A/S 대상이므로 실물 품번(질문 2), 함체 조립체와 하네스는 선행 가공·별도 재고 여부에 따라 갈리며(질문 1·4), 문서 세트는 이미 팬텀으로 표기되어 있다. 결과적으로 **3계층 구조는 유지되지만 재고를 잡는 노드는 그보다 적다.**

#### 1.3.4 AX의 역할 경계 — 무엇을 없애고, 무엇을 없앨 수 없는가

> **이 문서에서 가장 오해하기 쉬운 지점이므로 명시한다.**
>
> **AX는 계층을 없애지 않는다. 계층을 유지하는 비용을 없앤다.**
>
> 계층이 사람이 만들고 갱신하는 **작업물**에서, 관계 데이터로부터 필요할 때 생성되는 **계산 결과**로 바뀐다. 그러나 반제품이 물리적·회계적 실체로 존재하는 순간, 그 실체의 식별자는 AI가 추론으로 만들어 낼 수 없다.

**관점을 바꾸는 기술적 사실** — 주요 ERP도 다단 BOM을 그대로 저장하지 않는다. **부모–직속 자식 관계(단일 레벨 링크)만 저장하고, 다단 구조는 조회 시점에 전개(explosion)해서 만든다.** 즉 우리가 '계층 BOM'이라 부르는 것은 저장 형태가 아니라 **뷰**다.

본 문서의 스키마가 이미 같은 패턴이다. `Parent_Item_ID`와 `BOM_Level`은 관계를 기록하는 필드이고, 3계층 표([1.4.1](#141-3계층-bom-샘플-가상-예시--산업용-제어-유닛))는 그 관계에서 전개한 결과물이다. **파일을 여러 개 만들어 계층을 표현하지 않는다는 것이 1장 전제의 실질적 의미다.**

**경계 정리**

| AX가 없애는 것 (관리 비용) | AX가 없앨 수 없는 것 (실체) |
|---|---|
| 계층 구조를 사람이 수작업으로 만들고 리비전마다 갱신하는 작업 | 창고 선반에 놓인 반제품의 물리적 식별 — 라벨·바코드·재고 로케이션 |
| SMT용 평탄 뷰와 MRP용 계층 뷰를 각각 별도 파일로 유지하는 작업 | A/S 출하·판매 문서의 대상 품번 |
| 원가 롤업·where-used를 엑셀로 재계산하는 작업 | 재공(WIP) 회계 인식 단위 |
| 부품 투입 시점을 반제품 품번으로 우회 표현하던 작업 (→ 라우팅 공정 배정으로 대체) | 외부 거래(외주 임가공) 이관 단위 |
| 조달·원가 분석용 평탄화 시트를 따로 만드는 작업 | 규제·고객 요구에 따른 반제품 단위 추적 의무 |
| 기구·부자재를 별도 엑셀로 관리하고 조립 직전에 대조하는 작업 | 생산기술의 구조 확정 및 품번 발번 **권한** |

왼쪽은 **정보 처리 문제**이므로 자동화의 대상이다. 오른쪽은 **실체 존재와 권한 문제**이므로 정보량을 늘려도 사라지지 않는다. 이 구분을 흐리면 "AI가 알아서 해 줄 것"이라는 기대로 반제품 품번 체계를 정의하지 않게 되고, A/S 자재 공급 시점에 막힌다.

**기획 관점의 함의 세 가지**

1. **계층 설계를 AX 도입 이후로 미루지 않는다.** 반제품 품번 체계와 판정 기준([1.3.3](#133-계층-깊이-결정-기준--실물-품번인가-팬텀인가))은 사람이 먼저 정해야 하는 정책이다. Agent는 그 정책을 적용·검증하는 역할이다.
2. **Agent의 성과 지표는 '계층을 자동 생성했는가'가 아니다.** 계층 유지에 들던 공수가 줄었는지, 그리고 계층 오류(레벨 누락·배수 누락·팬텀 재고 계상)가 사전에 잡혔는지로 측정한다([검증 규칙 V3](#검증-규칙-v3--레벨배수-누락에-의한-수량-오류)).
3. **경계에서 멈추는 것이 정상 동작이다.** Agent가 구조를 제안하고 실물 품번 후보와 팬텀 후보를 분류해 근거와 함께 올리는 것까지가 범위이며, 확정은 사람이 한다. 이 멈춤을 '미완성'으로 읽지 않도록 규칙으로 못박는다(룰북 `RB-ST`).

#### 1.3.5 Agent가 수행해야 하는 변환

위 배경을 종합하면, 단층 입력을 계층 산출로 바꾸는 과정에서 Agent가 처리할 변환은 다섯 가지다.

| 입력 (설계 · 단층) | 필요한 변환 | 산출 (양산 · 계층) |
|---|---|---|
| 보드 1장 기준 부품 목록 | 상위 조립 구조 부여, 반제품 품번 발번 | Lv 0 완제품 / Lv 1 PCBA·기구 조립체 / Lv 2 부품 |
| 참조 부호 1:1 수량 | 패널 배수(`Panel_Qty`) × 로스율 적용 | 공정별 실제 투입량 |
| 회로 부품만 존재 | 기구·부자재·포장재 편입 | 완제품 전체 BOM |
| MPN 단일 식별 체계 | 도면번호 + 리비전 식별자 병행 | 혼합 식별 체계 |
| 단일 리비전 | 레벨별 리비전 + where-used 색인 | 변경 파급 추적 가능한 구조 |

**변환 시점과 권한** · Agent는 계층 구조를 자동 생성해 확정하지 않는다. 구조 제안까지가 Agent의 역할이고, **Lv 1 반제품 품번 발번과 구조 확정은 생산기술의 승인 사항**이다(시나리오 F). 설계가 소유한 Lv 2 영역과 생산이 소유한 Lv 0~1 영역의 경계를 Agent가 임의로 넘지 않게 하는 장치다.

### 1.4 계층형(멀티레벨) BOM 샘플과 회로·기구 BOM의 구조 차이

1.3의 배경을 실제 구조로 옮긴 것이 이 절이다. 완제품 조립 단계에서 필요한 형태를 미리 정의해 둔다. 현 단계에 조립 자동화가 없더라도 **스키마가 3계층을 표현하지 못하면 나중에 기구 BOM을 얹을 수 없다.**

가장 흔한 실패는 회로 BOM만 SSOT에 올리고 기구 BOM은 담당자 엑셀에 남겨두는 것이다. 이렇게 되면 완제품 원가에서 함체·나사·하네스가 빠지고, 조립 단계에서 기구 부품이 결품되며, 설계 변경이 기구에 미치는 영향을 추적할 수 없다.

#### 1.4.2 회로 BOM과 기구 BOM의 구조 차이

두 BOM은 형식만 비슷하고 관리 축이 다르다. 같은 로직으로 처리하면 기구 쪽에서 반드시 깨진다.

| 축 | 회로 BOM (PCBA 레벨) | 기구 BOM (조립 레벨) |
|---|---|---|
| **위치 식별** | 참조 부호(RefDes)로 실장 위치가 특정된다 | RefDes가 없다. 조립 위치는 도면·작업표준서에 있다 |
| **주 식별자** | 제조사 MPN 중심 | 사내 도면번호 + 리비전, 시중 규격품(나사·스페이서)이 혼재 |
| **수량 단위** | 대부분 EA, RefDes 개수와 일치해야 한다 | EA·m·g·매(sheet)가 혼재, 재단·절단 로스가 발생 |
| **대체 판정 기준** | FFF — 전기적 등가(정격·특성·핀 배열) | 치수·공차·재질·표면처리·체결 방식 |
| **변경 파급** | 스텐실·실장 프로그램·검사 프로그램 수정 | **금형·치공구 수정**이 필요할 수 있어 리드타임이 회로 대비 훨씬 길다 |
| **소요량 가산** | 드롭 로스(통상 Chip 계열 1~3%) | 가공 불량률·스크랩률, 절단 로스 |
| **검사 방식** | 전기 검사(ICT·기능 검사) | 치수·외관·도장 검사 |
| **조달 단위** | 릴·트레이·튜브(SPQ 고정) | 박스·kg·매, 최소 가공 수량(MOQ가 아니라 최소 로트) |
| **계층 깊이** | 통상 1~2계층 | 서브어셈블리가 다층으로 쌓이고 좌우 대칭품·공용품이 많다 |
| **리비전 주체** | 회로도·아트워크 리비전 | 도면 리비전 + 금형 리비전(별도 관리) |

> **설계 요구사항** · Agent는 위 표의 두 체계를 **같은 마스터 테이블에서 유형 필드로 구분**해 관리하고, 레벨별 소요량 전개표·회로/기구 분리 뷰·부자재 편입 목록을 산출할 수 있어야 한다. 기구 품목에 MPN 추론을 적용하거나, 회로 품목에 도면 리비전 로직을 적용하면 안 된다.

## 2. 사용자별 활용 케이스 — 누가, 언제, 무엇을 묻는가

3장의 시나리오가 **시스템이 도는 방식**이라면, 이 장은 **사람이 쓰는 방식**이다. 같은 프로세스라도 부서마다 겪는 통증과 원하는 출력이 다르므로, 질의 케이스를 주체별로 정리한다.

질의 케이스 ID는 부서 머리글자를 쓴다 — **D**(설계·R&D), **P**(구매·조달), **M**(생산기술·자재), **Q**(품질). 4장의 케이스 1~19(MPN 변환)와는 별개 체계다.

### 2.0 주체별 요약

| 주체 | 주된 통증 (As-Is) | Agent에 기대하는 것 | 얻는 것 (To-Be) |
|---|---|---|---|
| **설계 (R&D)** | 부품 선정 시 사내 표준·재고·단종 정보를 모른다. 조달 리스크를 구매팀 회신 후에야 알게 된다 | 설계 시점에 조달 가능성을 즉시 알려주는 검색·판정 | 설계 확정 전에 리스크를 걸러내 재설계 손실 제거 |
| **구매 (조달)** | 견적 취합·비교가 전부 수작업. 대체재 판단이 개인 경험에 의존 | 다채널 가용성·단가·납기 집계와 대체 후보 제시 | 단순 취합 시간 소멸, 판단 근거의 문서화 |
| **생산기술·자재** | 구버전 시트로 자재를 불출. 착수 가능 여부를 전화로 확인 | 최신 리비전 기준 소요량·부족 현황·착수 판정 | 라인 정지와 중복 배분 방지 |
| **품질** | 검사 강도와 보관 조건 관리가 담당자 재량. MSL·데이트코드는 수기 관리 | 입고 건별 검사 경로 판정과 보관수명 자동 추적 | 판정 기준의 일관성, 초과·누락의 사전 차단 |

> 재무·원가 관점은 별도 주체로 분리하지 않았다. 결제 조건과 정산은 시나리오 D·G, 측정은 6장 KPI에서 다룬다.

### 2.1 설계 (R&D) — 설계 확정 전에 조달 현실을 알고 싶다

#### 질의 케이스 D-1 · 부품 선정 중 사내 표준 확인

- **상황** — 회로 설계 중 2.2kΩ 1% 저항이 필요하다. 사내에 이미 쓰는 품목이 있는지 모른다.
- **현재(As-Is)** — 사내 표준 부품 목록 엑셀이 어디 있는지, 지금 보는 파일이 최신본인지 확인할 방법이 없다. 결국 데이터시트를 새로 찾아 신규 부품으로 지정하고, 구매팀은 또 하나의 신규 품목 등록을 처리한다. **부품 종류가 늘어나는 원인의 대부분이 이 지점에 있다.**
- **묻는 것**
  > "2.2k 1% 0603, 산업용 온도 범위. 우리가 이미 쓰는 품목 있어?"
- **기대 출력** — 충족 품목 후보 표. 열은 IPN · MPN · 표준 등급(`Preferred`/`Approved`/`Restricted`) · 현재 재고 · 최근 발주 단가 · 라이프사이클 상태 · 온도 등급 충족 여부. 없으면 "신규 등록 필요"를 명시하고 그 절차로 연결.
- **메리트(To-Be)** — 설계자가 표준 품목을 고르는 것이 **더 빠른 선택지**가 된다. 신규 등록은 정말 필요할 때만 발생한다.
- 연계: 시나리오 E · 케이스 1

#### 질의 케이스 D-2 · BOM 출도 직후 조달 리스크 사전 확인

- **상황** — 설계를 마치고 BOM을 뽑았다. 이 상태로 넘기면 문제가 없을지 알고 싶다.
- **현재(As-Is)** — 구매팀에 파일을 넘기고 며칠 뒤 "이 부품 20주 걸립니다", "이건 단종됐습니다"라는 회신을 받는다. **이미 아트워크가 끝난 뒤라 부품을 바꾸면 패턴을 수정해야 한다.** 이 재작업이 일정 지연의 주요 원인이다.
- **묻는 것**
  > "이 BOM에서 조달 리스크 있는 항목만 뽑아줘."
- **기대 출력** — 위험 항목만 추린 표. 위험 유형(장납기 / EOL·NRND / 단일 공급처 / 시장 재고 부족 / 신규 등록 필요)별로 분류하고, 각 항목에 대체 가능 후보와 그 후보 채택 시 회로 영향 여부를 함께 표시. 위험 없음 항목은 건수만 요약.
- **메리트(To-Be)** — 리스크 인지 시점이 **아트워크 이후에서 설계 중으로** 이동한다. 바꾸는 비용이 가장 싼 시점에 알게 된다.
- 연계: 시나리오 A·B·H

#### 질의 케이스 D-3 · 대체재 승인 요청 검토

- **상황** — 구매팀이 "이 부품 대신 저 부품 써도 되나요?"라고 물어왔다.
- **현재(As-Is)** — 데이터시트 두 개를 열어 항목을 눈으로 대조한다. 검토 결과는 이메일 회신으로 끝나고 **어떤 근거로 승인했는지는 어디에도 남지 않는다.** 같은 부품이 또 품절되면 같은 검토를 처음부터 반복한다.
- **묻는 것**
  > "이 대체품, 우리 회로에서 FFF 만족해?"
- **기대 출력** — 사양 비교표(원 부품 / 대체 후보 / 회로 요구값 3열)와 **차이가 있는 항목만 강조**. 판정은 3단계로 — 등가(자동 승인 가능) / 조건부(어떤 조건에서 사용 가능한지 명시) / 부적합(사유 명시). 승인 시 AVL과 승인 이력에 자동 기록.
- **메리트(To-Be)** — 검토 시간이 수시간에서 수분으로 줄고, **승인 이력이 자산으로 남아** 두 번째부터는 검토 자체가 사라진다.
- 연계: 시나리오 H·C · 케이스 9·10·13

#### 질의 케이스 D-4 · 설계 변경 전 파급 영향 확인

- **상황** — 양산 중인 제품의 부품을 바꾸려 한다.
- **현재(As-Is)** — 영향 범위를 알려면 구매·창고·생산에 각각 물어봐야 한다. 회의를 잡는 데 며칠, 회의에서 "이미 발주됐다", "재고가 3,000개 있다"는 사실이 드러난다.
- **묻는 것**
  > "R12를 다른 품번으로 바꾸면 뭐가 영향받아?"
- **기대 출력** — 영향도 리포트. 발주 상태(취소 가능 여부) · 잔여 재고와 불용 전환 금액 · 신규 부품 리드타임에 따른 생산 개시일 변동 · 영향받는 다른 제품·리비전 목록. **기구 영향**(치수 변경 시 함체 간섭)도 함께 판정.
- **메리트(To-Be)** — 변경 여부를 회의 없이 정량 근거로 판단한다.
- 연계: 시나리오 C

### 2.2 구매 (조달) — 취합을 없애고 판단만 남기고 싶다

#### 질의 케이스 P-1 · BOM 접수 직후 전체 조달 가능성 파악

- **상황** — 연구소에서 BOM을 받았다. 지금 다 살 수 있는지, 총액이 얼마인지 알아야 한다.
- **현재(As-Is)** — 4~5개 채널에 각각 견적 양식을 만들어 보내고, 서로 다른 서식으로 돌아온 회신을 하나의 시트로 수동 전사한다. **주당 20시간 이상이 단순 입력에 쓰인다.** 회신을 기다리는 동안 시장 재고가 소진되기도 한다.
- **묻는 것**
  > "이 BOM 전량 조달 가능해? 총 자재비랑 최장 납기 얼마야?"
- **기대 출력** — 라인별 가용성·단가·납기 집계표 + 요약 3종(총 자재비, 최장 리드타임 품목, 즉시 조치 필요 항목). 단가에는 **수량 구간과 기준 환율을 함께 표시.**
- **메리트(To-Be)** — 전사 작업이 사라지고, 남는 일은 "이 조합으로 발주할지" 판단하는 것뿐이다.
- 연계: 시나리오 B·G

#### 질의 케이스 P-2 · 결품 발생 시 대체안 탐색

- **상황** — 발주 직전에 핵심 부품이 품절로 확인됐다.
- **현재(As-Is)** — 시니어 담당자의 기억과 개인 인맥에 의존한다. 담당자가 부재하거나 퇴사하면 **탐색이 원점에서 다시 시작된다.**
- **묻는 것**
  > "이 부품 대체 가능한 거 뭐 있어? 사내 재고에 쓸 만한 건 없어?"
- **기대 출력** — 후보 목록을 우선순위대로. ① 사내 재고 보유 + AVL 등재(즉시 사용 가능) → ② AVL 등재 + 시장 재고 있음 → ③ 신규 후보(엔지니어 승인 필요). 각 후보에 신뢰도 점수와 승인 필요 여부를 명시하고, ③은 D-3 검토 요청을 바로 발행.
- **메리트(To-Be)** — 개인 암묵지가 조직 자산이 된다. 이미 사내에 있는 재고를 못 찾아 새로 발주하는 손실도 사라진다.
- 연계: 시나리오 B·H · 케이스 8

#### 질의 케이스 P-3 · 분할 발주와 자금 스케줄

- **상황** — 견적이 모였다. 어디에 얼마씩 나눠 발주할지 정해야 한다.
- **현재(As-Is)** — 엑셀에서 채널별 단가·납기를 수동 비교한다. MOQ·SPQ 때문에 실제 발주량이 소요량을 넘는 부분은 계산이 누락되기 쉽고, 결제 조건이 제각각이라 자금팀과 별도로 조율해야 한다.
- **묻는 것**
  > "납기 맞추면서 제일 싸게 나누는 조합 뽑아줘. 선결제 얼마 필요해?"
- **기대 출력** — 분할 발주 추천안(공급처 · 품목 · 수량 · 단가 · 납기)과 함께 ① **MOQ·SPQ 초과분 수량과 금액**, ② 결제 조건별 자금 소요 일정(선결제 vs 여신), ③ 추천안과 '최저가 조합'·'최단납기 조합'의 차이.
- **메리트(To-Be)** — 초과분과 자금 타이밍이 처음부터 보이므로, 발주 후에 드러나는 비용이 없다.
- 연계: 시나리오 B·G · 룰북 RB-LT

#### 질의 케이스 P-4 · 단종 통보 수신 시 영향 파악

- **상황** — 유통사로부터 특정 부품의 단종 통보를 받았다.
- **현재(As-Is)** — 이 부품이 어느 제품에 쓰이는지 알려면 제품별 BOM 엑셀을 하나씩 열어 검색해야 한다. 놓친 제품이 있으면 **몇 달 뒤 그 제품 생산 시점에 결품으로 드러난다.**
- **묻는 것**
  > "이 부품 쓰는 제품 전부 찾아줘. 최종 발주 몇 개 해야 해?"
- **기대 출력** — 영향 범위(제품 · 리비전 · 진행 중 작업지시 · 잔여 재고)와 LTB 수량 산정안. 산정에 사용한 가정(잔여 제품 수명, 예상 판매량, 서비스 예비분, 보관 가능 기간)을 **명시적으로 함께 제시**하고, 'LTB 확보' vs '대체재 전환 ECO' 두 경로의 비용·리드타임 비교를 붙인다.
- **메리트(To-Be)** — 검색 누락으로 인한 생산 중단이 사라지고, LTB 수량을 근거 있게 정한다.
- 연계: 시나리오 H · 룰북 RB-LT·RB-DP

### 2.3 생산기술·자재 — 최신 정보로 정확한 수량을 받고 싶다

#### 질의 케이스 M-1 · 작업지시 착수 가능 여부 판정

- **상황** — 다음 주 생산할 작업지시가 나왔다. 자재가 다 있는지 확인해야 한다.
- **현재(As-Is)** — 전산 재고를 보고 창고에 전화해 실물을 확인한다. 다른 작업지시가 같은 부품을 쓸 예정인지는 알 수 없어 **같은 자재를 두 오더가 각자 계산한다.**
- **묻는 것**
  > "이 작업지시 지금 착수 가능해? 안 되면 뭐가 부족해?"
- **기대 출력** — Clear-to-Build 판정(가능 / 불가) + 부족 품목별 부족 수량 · 입고 예정일 · 긴급 조달 가능 채널. 불가일 때는 **부분 착수 가능 여부**(부족 부품이 후공정에만 쓰이는지)를 근거와 함께 제시.
- **메리트(To-Be)** — 착수했다가 중간에 멈추는 일이 없어지고, 자재 중복 배분이 구조적으로 차단된다.
- 연계: 시나리오 I

#### 질의 케이스 M-2 · 완제품 조립용 3계층 소요량 표 요청

- **상황** — 완제품 조립을 준비한다. 회로 부품만이 아니라 함체·나사·하네스까지 포함한 목록이 필요하다.
- **현재(As-Is)** — 연구소에서 받은 것은 회로 BOM뿐이다. 기구 부품과 부자재는 담당자가 별도 엑셀로 관리하며, **누락되면 조립 당일에 발견된다.** 나사 한 종류가 없어 라인이 서는 일이 실제로 발생한다.
- **묻는 것**
  > "이 모델 100대분, 3계층 전개해서 실제 소요량 표로 줘. 기구랑 부자재 포함."
- **기대 출력** — [1.4.1](#141-3계층-bom-샘플-가상-예시--산업용-제어-유닛) 형식의 레벨별 전개표. 레벨·품목유형(회로/기구/부자재)·상위 1단위당 소요량·총 소요량(로스 포함)·단위·투입 공정·피더 규격. 회로/기구 분리 뷰와 부자재만 추린 목록을 함께 제공.
- **메리트(To-Be)** — 조립 단계 결품이 사라지고, 완제품 원가에 기구·부자재가 빠지지 않는다.
- 연계: 시나리오 F·I · 1.3–1.4

#### 질의 케이스 M-3 · ECO 수신 시 현장 조치 확인

- **상황** — 설계 변경이 승인됐다는 통보를 받았다.
- **현재(As-Is)** — 변경 내용을 문서로 받아 사람이 읽고, 피더맵·스텐실·검사 프로그램에서 무엇을 바꿔야 하는지 스스로 판단한다. 미실장 항목이 실장으로 바뀐 변경은 놓치기 쉽다.
- **묻는 것**
  > "이번 ECO로 라인에서 바꿔야 할 게 뭐야?"
- **기대 출력** — 현장 조치 목록. 피더 변경(슬롯·릴 교체) · 스텐실 수정 필요 여부 · **미실장 ↔ 실장 전환 항목** · 검사 프로그램 영향 · 기존 재고 처리 방침(소진 후 적용 / 즉시 전환).
- **메리트(To-Be)** — 구버전 시트로 자재를 불출하는 사고가 사라진다.
- 연계: 시나리오 C · 케이스 19

### 2.4 품질 — 판정 기준을 사람이 아니라 규칙에 두고 싶다

#### 질의 케이스 Q-1 · 입고 건별 검사 강도 판정

- **상황** — 자재가 입고됐다. 전수 검사할지 샘플만 볼지 정해야 한다.
- **현재(As-Is)** — 판정이 담당자 재량이다. 신규 공급처인지, 과거 불량 이력이 있는지를 그때그때 기억으로 판단한다. **사람이 바뀌면 기준이 바뀐다.**
- **묻는 것**
  > "이번 입고 건 검사 강도 어떻게 가야 해?"
- **기대 출력** — 검사 경로 판정(전수 / 샘플 / 무검사)과 **판정 근거**(신규 등록 부품 · 신규 공급처 · 과거 불량 이력 · 독립 유통 경유 여부). 품목 유형별 체크리스트(외관·마킹·데이트코드·습도 표시 카드)를 함께 제시.
- **메리트(To-Be)** — 담당자와 무관하게 같은 조건에서 같은 판정이 나온다.
- 연계: 시나리오 J

#### 질의 케이스 Q-2 · 보관 상태 부품의 실장 가능 여부

- **상황** — 창고에 있던 릴을 라인에 투입하려 한다. 개봉한 지 얼마나 됐는지 확실치 않다.
- **현재(As-Is)** — 방습 포장 개봉일을 라벨에 수기로 적어 관리한다. 적는 것을 잊거나 라벨이 떨어지면 추적이 끊긴다. **플로어 라이프를 초과한 부품을 그대로 리플로우하면 패키지 내부에 균열이 생기는데, 이 불량은 육안·기능 검사를 통과한다.**
- **묻는 것**
  > "이 릴 지금 실장해도 돼?"
- **기대 출력** — 실장 가능 여부 판정 + MSL 등급 · 개봉 시각 · 잔여 실장 가능 시간 · 초과 시 필요한 베이킹 조건. 보관 수명 관리 대상(전해 커패시터, 솔더 페이스트 등)이면 별도 경고.
- **메리트(To-Be)** — 나중에 필드에서 터지는 잠재 불량을 입고·투입 시점에 차단한다.
- 연계: 시나리오 J · 룰북 RB-EX

#### 질의 케이스 Q-3 · 필드 이슈 발생 시 영향 범위 역추적

- **상황** — 출하한 제품에서 특정 부품 관련 불량이 보고됐다.
- **현재(As-Is)** — 해당 로트가 어느 생산분에 들어갔고 어디로 출하됐는지 수불부와 출하 기록을 수동으로 대조한다. 며칠이 걸리고 범위 판정이 부정확하다.
- **묻는 것**
  > "이 로트 들어간 제품 어디까지 나갔어?"
- **기대 출력** — 로트–작업지시–제품 시리얼–출하 이력 연결 결과. 영향 제품 수량, 사내 잔여 재고, 미출하 재공 현황. 동일 부품의 다른 로트 사용 제품도 함께 표시(범위 과소 판정 방지).
- **메리트(To-Be)** — 대응 범위를 넓게 잡아 과잉 회수하거나, 좁게 잡아 놓치는 일이 줄어든다.
- 연계: 시나리오 J·D

## 3. BOM Agent의 엔드투엔드(End-to-End) 운영 시나리오

BOM Agent는 엔지니어가 EDA 도구에서 출력한 비정형 엑셀을 시스템 폴더나 웹 인터페이스에 업로드(Drop)하는 순간 트리거되어 전 프로세스를 자율 조율한다.

### 3.0 시나리오 맵

2장이 주체별 질의 관점이라면 이 장은 프로세스 관점이다. 시나리오 기호(A~J)는 서술 순서이고, 실제 실행 순서는 아래 라이프사이클 단계에 따른다. H는 특정 시점이 아니라 **상시 감시(Always-on)** 로 동작하며 트리거 시 C로 합류한다.

| 순서 | 시나리오 | 트리거 | 주 수행 부서 | 종료 조건 |
|---|---|---|---|---|
| 1 | **A** · 인제스천 및 암묵지 해석 | 원시 BOM 업로드 | Agent / R&D | 전 라인 MPN·IPN 확정 또는 확인 요청 발행 |
| 2 | **E** · 신규 부품 등록 심사 | 사내 표준·AVL에 없는 부품 감지 | R&D / 구매 / 품질 | 표준 품목으로 대체 또는 신규 IPN 발급 |
| 3 | **F** · 멀티레벨 BOM 전개 | 완제품 구조 정의 요청 | 생산기술 / R&D | 레벨별 소요량 확정, 부자재 편입 완료 |
| 4 | **B** · 견적(RFQ) 자동화 | IPN 확정 완료 | 구매 | 분할 발주 추천안 승인 |
| 5 | **G** · 원가 롤업·목표원가 검증 | 견적 회신 수집 완료 | 구매 / 재무 | 목표원가 내 승인 또는 초과 항목 에스컬레이션 |
| — | **H** · PCN·EOL 감시와 LTB 산정 | 상시(통보 수신 시) | 구매 / R&D | LTB 발주 확정 또는 대체재 전환 ECO 발행 |
| 6 | **C** · 설계 변경(ECO) 동기화 | 리비전 변경 BOM 업로드 | R&D → 전 부서 | 병렬 승인 완료 후 ERP·피더맵 갱신 |
| 7 | **I** · 킷팅·숏티지·Clear-to-Build | 작업지시(WO) 생성 | 자재관리 / 생산 | CTB 판정 및 부족 자재 조치안 확정 |
| 8 | **J** · 수입검사·MSL·보관수명 관리 | 자재 입고 | 품질 / 창고 | IQC 판정 및 적치 완료 |
| 9 | **D** · 3-Way Matching·재고 차감 | 세금계산서 수신 / 생산 완료 보고 | 재무 / 생산 | 대금 지급 및 수불 확정 |

### 시나리오 A · 인제스천 및 암묵지 해석 (Ingestion & Normalization)

1. **파일 감지 및 구조 파악**
   엔지니어가 `.xlsx` 파일을 업로드하면 Agent가 트리거된다. 시트 내 헤더 위치(1행이 아닌 수기 메모 뒤 5행부터 시작하는 케이스 등)를 자동 식별하고 테이블 데이터를 인메모리로 정규화한다.

2. **맥락적 사양 복원**
   MPN 컬럼이 비어 있거나 약칭(예: `R1608 2.2K`)만 기재된 항목을 식별하고, 사내 재고 마스터 및 과거 거래처 발주 데이터베이스를 대조하여 정식 MPN 및 IPN을 자동으로 역산해 채워 넣는다.

3. **1차 이상 징후 보고**
   사양 모호성이 완전히 해소되지 않은 항목(예: 내압 스펙이 누락된 고전압 라인 커패시터)만 요약하여 엔지니어에게 슬랙·메신저·알림창 형태로 즉각 확인을 요청한다.

> **검증 노트** · 원본의 "100% 일치하는 정식 MPN을 자동으로 역산"은 자동 확정 범위를 과대 설정한 표현이다. 역산 결과는 `Confidence_Score`와 `Source_Provenance`를 동반해야 하며, **사내 발주 이력과 완전 일치하는 건만 자동 확정**하고 그 외는 추천값으로 제시한다(6장 Zero-Touch Rate 정의와 일치).

### 시나리오 B · 견적(RFQ) 자동화 및 공급망 리스크 선제 차단

1. **가용성 실시간 조회**
   복원된 MPN 목록을 기반으로 유통사 **공식 API**(Digi-Key, Mouser 등) 또는 애그리게이터 API(Nexar/Octopart 계열)를 호출하여 전 세계 재고 유무 및 단가를 집계한다.

2. **국내 딜러 RFQ 일괄 생성**
   API 연동이 지원되지 않는 국내 상가 딜러(구로·광명·부천) 취급 품목의 경우, 해당 유통업체별 맞춤형 엑셀 RFQ를 백그라운드에서 자동 렌더링하여 이메일 또는 B2B 메신저로 발송한다.

3. **회신 견적 수집 및 다큐먼트 파싱**
   회신된 견적서(PDF, 이메일 본문, 엑셀)를 파싱하여 단일 마스터 테이블의 `Unit_Price`, `Lead_Time`, `MOQ` 필드를 자동 업데이트한다.

4. **최적 구매 포트폴리오 산출**
   '단가 최우선', '납기 최우선', '거래처 분산 최소화' 등 사전 설정된 최적화 규칙에 따라 분할 발주 추천안을 수립하여 구매 담당자에게 승인 요청을 전달한다.

> **검증 노트** · 원본의 "즉시 스크랩/호출"에서 **스크래핑은 설계 대안에서 제외**했다. 주요 유통사는 봇 차단·이용약관 제약이 있고, 스크래핑 기반 파이프라인은 화면 변경에 따라 상시 파손된다. 또한 LCSC는 범용 공개 API 제공이 제한적이므로 **파트너 채널 또는 애그리게이터 경유**를 전제로 기획해야 한다. 연동 대상 확정 시 각 유통사 API 약관·호출 한도(rate limit)를 조달 조건으로 함께 검토한다.

### 시나리오 C · 회의 없는 무마찰 설계 변경(ECO) 동기화

1. **ECO 감지 및 영향도(Blast Radius) 자동 계산**
   양산 진행 중 R&D 엔지니어가 수정된 BOM을 업로드하면, Agent는 이전 리비전과의 Diff(추가, 삭제, 수량 변경, 부품 스펙 변경)를 원자 단위로 추출한다.

2. **부서별 파급 영향 자동 분석**

   | 영향 축 | 자동 판정 내용 |
   |---|---|
   | 구매 영향 | 이미 PO가 발행되어 납품 대기 중인 자재인지 확인 (발주 취소 가능 여부 판단) |
   | 창고 재고 영향 | 변경으로 인해 기존 재고가 불용 재고(Dead Stock)로 전락하는지 여부 및 잔여 수량 금액 산출 |
   | 생산 일정 영향 | 변경된 신규 부품의 리드타임으로 인해 SMT 생산 개시일이 지연되는지 검증 |

3. **비동기 병렬 승인(Parallel Sign-off) 라우팅**
   회의를 소집하지 않고, 계산된 정량적 영향도 리포트(비용 변동분, 일정 지연일수)를 구매팀·생산기술팀·품질팀에 동시 발송하여 비동기 '승인/반려' 처리를 진행한다.

4. **시스템 자동 전개**
   전원 승인 즉시 ERP의 작업 지시 수량과 단일 마스터 테이블의 리비전을 갱신하고 현장 SMT 라인 피더 맵을 자동 업데이트한다.

### 시나리오 D · 3-Way Matching 및 재고 차감 자율화

1. **입고 데이터와 실시간 연계**
   창고에서 공급사 라벨 또는 거래명세서를 스캔하면, Agent는 단일 마스터 테이블의 발주 데이터와 실시간 대조하여 분할 입고 여부를 추적한다.

2. **3-Way Matching 대사**
   공급업체 전자세금계산서 수신 시, 발주 금액·입고 수량·청구 금액을 비교 검증한다. 단수 차이(소수점 절사 오류 등)나 사전 승인된 환율 변동 범위 내의 오차는 자율 처리하고, 비정상 단가 인상 건만 재무 담당자에게 플래그를 띄운다.

3. **실제 로스율 역산 차감**
   SMT 생산 완료 보고가 들어오면 기본 BOM 단위 차감 외에 실제 발생한 드롭 로스(Drop Loss)를 수불부에 자동 기표하여 **'유령 재고'**(전산 상에는 있으나 실제 없는 재고) 발생을 원천 차단한다.

### 시나리오 E · 신규 부품 등록 심사 (New Part Request)

부품 종류가 늘어나는 것 자체가 비용이다. 품목 하나가 추가되면 자재 마스터·재고 로케이션·최소 발주 단위·검사 기준이 함께 늘어난다. Agent는 신규 부품을 **등록해 주는 창구가 아니라 등록을 걸러내는 관문**으로 동작한다.

1. **표준 이탈 감지**
   인제스천 결과 중 사내 표준 부품 목록(`Part_Standard_Class` = `Preferred`)에도, AVL에도 없는 항목을 신규 부품 후보로 분리한다.

2. **기존 표준 품목으로의 흡수 시도**
   신규 후보의 전기적·물리적 사양을 사내 표준 품목과 비교해, 사양을 만족하는 기존 품목이 있으면 **대체안을 먼저 제시한다.** 예를 들어 2.2kΩ 1% 0603을 신규 요청했는데 사내 표준에 동일 규격이 이미 있으면 신규 등록을 진행하지 않는다.
   산업용 제품군에서는 **온도 등급(-40~85℃ 이상)** 과 정격 마진을 흡수 판정의 하드 조건으로 둔다. 상용 등급(0~70℃) 품목으로의 흡수는 자동 제안 대상에서 제외한다.

3. **정당화 사유가 필요한 항목만 심사 상정**
   흡수 불가로 판정된 항목만 `NPR_Status` = `Under_Review`로 올리고, 심사 패키지를 자동 구성한다. 패키지에는 요청 사유(기존 품목으로 대체 불가한 근거), 예상 연간 소요량, 조달 가능 채널 수, 라이프사이클 상태, 최소 발주 단위 대비 소요량 비율이 포함된다.

4. **등록 승인 및 IPN 발급**
   승인 시 IPN을 발급하고 `Part_Standard_Class`를 `Approved`로 설정한다. 조달 채널이 단일하거나 `Lifecycle_Status`가 `NRND`인 부품은 승인하더라도 `Restricted`로 표시하여 신규 설계에서의 재사용을 억제한다.

> **판단 기준** · 이 시나리오의 성과는 '심사를 빨리 끝냈는가'가 아니라 **'신규 등록을 얼마나 줄였는가'** 로 측정한다(6장 부품 표준화율).

### 시나리오 F · 멀티레벨 BOM 전개 및 서브어셈블리 구조화

산업용 장비의 완제품은 단일 PCBA가 아니다. 함체·전원부·제어 PCBA·와이어 하네스·라벨이 계층을 이루며, 계층별로 발주 주체와 재고 관리 방식이 다르다. 단일 마스터 테이블은 **파일을 나누는 대신 레벨 필드로 계층을 표현한다.** 설계가 단층으로 산출하고 양산이 계층을 요구하는 배경은 [1.3](#13-왜-설계는-단층-bom-양산은-계층-bom인가), 구체적인 구조와 회로/기구 BOM의 차이는 [1.4](#14-계층형멀티레벨-bom-샘플과-회로기구-bom의-구조-차이)에 정의했다.

이 시나리오의 산출물은 **제안**이며, Lv 1 반제품 품번 발번과 구조 확정은 생산기술 승인 사항이다(룰북 `RB-ST-08`). Agent는 각 노드를 [실물 품번 후보와 팬텀 후보로 분류](#133-계층-깊이-결정-기준--실물-품번인가-팬텀인가)해 근거와 함께 올리는 데까지 관여하고, 여기서 멈추는 것이 정상 동작이다([1.3.4](#134-ax의-역할-경계--무엇을-없애고-무엇을-없앨-수-없는가)).

1. **레벨 구조 인식**
   업로드된 시트가 단일 레벨(플랫 BOM)인지, 상위 조립품 컬럼을 포함한 다층 구조인지 판별한다. 플랫 BOM이면 `Assembly_Routing`과 참조 부호 패턴을 근거로 PCBA 레벨과 완제품 조립 레벨을 분리 제안한다.

2. **레벨별 소요량 전개**
   `Qty_Per_Parent`를 상위 수량과 곱해 최종 소요량을 산출한다. 완제품 100대 → 제어 PCBA 1대/완제품 → 저항 4개/PCBA면 소요량은 400개이며, 여기에 `Drop_Loss_Factor`를 적용한다. **레벨을 무시하고 곱셈 없이 합산하는 것이 현장에서 가장 흔한 수량 오류다.**
   SMT 투입 계획은 보드 단위가 아니라 패널 단위이므로, 생산 지시 수량 산출에는 `Panel_Qty`(다면취 배수)를 별도로 반영한다([1.3.1](#131-설계-단계가-단층인-이유--도구의-산출-단위가-보드다)).

3. **실물 품번 / 팬텀 분류**
   각 중간 노드를 [1.3.3 판정 체크리스트](#133-계층-깊이-결정-기준--실물-품번인가-팬텀인가)로 검사해 실물 품번 후보와 팬텀 후보로 나눈다. 팬텀(`Phantom_Flag`)은 재고를 잡지 않고 전개만 하며, 도면·문서 관리 목적의 그룹 노드가 실재 재고로 잡히면 재고 금액이 이중 계상된다(`RB-ST-06`·`RB-ST-07`).

4. **부자재 자동 편입**
   레벨별로 E-BOM에 누락되기 쉬운 부자재를 규칙 기반으로 편입한다. PCBA 레벨에는 솔더 페이스트·스텐실·본드, 완제품 조립 레벨에는 나사·스페이서·케이블 타이·라벨이 대상이다(`Consumable_Flag`).

5. **커스텀 품목 식별**
   벤더 MPN이 존재하지 않는 사내 제작 품목(가공 판금, 커스텀 하네스, PCB 자체)은 MPN 추론 대상에서 제외하고 **사내 도면번호 + 도면 리비전**을 식별자로 사용한다. Agent가 이를 일반 부품으로 오인해 MPN을 추론하면 안 된다(룰북 `RB-DP-06`).

### 시나리오 G · 원가 롤업 및 목표원가 검증

1. **수량 구간을 반영한 단가 확정**
   견적은 수량 구간별로 회신된다. Agent는 `Price_Break_Table`에서 이번 오더의 실제 발주 수량에 해당하는 구간 단가를 선택한다. **MOQ·SPQ 반올림으로 실제 발주량이 소요량을 초과하는 경우, 초과분까지 포함한 실지출액과 소요량 기준 원가를 함께 표시한다.**

2. **레벨별 원가 롤업**
   시나리오 F의 계층 구조를 따라 하위 레벨 원가를 상위로 누적해 PCBA 원가와 완제품 원가를 각각 산출한다.

3. **환율·부대비용 반영**
   해외 조달 품목은 `FX_Rate_Basis`에 사용 환율과 기준 시점을 기록한다. 관세·운임·부가 수수료는 품목별 배부 규칙에 따라 반영하며, **어떤 환율·어떤 배부 규칙으로 계산된 숫자인지 표시하지 않은 원가는 승인 대상으로 올리지 않는다.**

4. **목표원가 초과 항목 식별**
   `Target_Cost` 대비 편차가 큰 상위 항목을 자동 지목하고, 원인을 단가 상승·수량 변경·환율·MOQ 초과분 중 무엇인지 분해해 제시한다. 산업용 제품은 생산 수량이 적어 **MOQ 초과분이 원가를 왜곡하는 비중이 상대적으로 크다.**

### 시나리오 H · PCN·EOL 감시와 최종 발주(LTB) 수량 산정

산업용 제품은 제품 수명이 부품 수명보다 길다. 제품이 아직 팔리는 동안 부품이 먼저 단종되는 상황이 정상 경로이므로, 단종 대응은 예외 처리가 아니라 **상시 프로세스**로 설계해야 한다.

1. **통보 상시 수집**
   제조사·유통사의 변경 통보(PCN)와 단종 통보(EOL)를 수집해 사내 IPN·MPN과 매칭한다. 반도체 업계는 [J-STD-046](https://www.jedec.org/standards-documents/docs/j-std-046)(구 JESD46)에 따라 변경 시행 전 통상 90일 이상의 사전 통지를 제공하며, 제조사별로 최종 발주·최종 출하 기한을 함께 공지한다([TI 예시](https://www.ti.com/quality-reliability/quality/product-change-notification.html): 최종 발주 12개월·최종 출하 추가 6개월).

2. **영향 범위 역추적**
   해당 부품이 사용된 모든 제품·리비전·진행 중 작업지시를 역추적한다. 단일 마스터 테이블이므로 제품별 엑셀을 찾아다닐 필요가 없다.

3. **변경 등급 판정**
   PCN을 **FFF 영향 없음**(데이트코드·포장 변경 등)과 **FFF 영향 있음**(다이 변경, 패키지 변경, 특성 변경)으로 분류한다. 전자는 기록만 남기고, 후자는 재검증 대상으로 승격해 시나리오 C(ECO)로 넘긴다.

4. **LTB 수량 산정**
   최종 발주 수량은 잔여 제품 수명 기간의 예상 판매량 × 소요량 + 로스율 + 서비스·수리용 예비 수량으로 산정하고, 여기에 보관 가능 기간(습기 민감 부품의 보관 조건, 전해 커패시터의 보관 수명)을 제약으로 반영한다. **과다 발주는 즉시 불용 재고, 과소 발주는 제품 단절이므로 산정 근거와 가정을 함께 제시하고 사람이 확정한다.**

5. **대체재 전환 검토 병행**
   LTB와 동시에 FFF 대체재 후보를 탐색해, '재고 확보'와 '설계 변경' 두 경로의 비용·리드타임을 비교한 판단 자료를 만든다.

### 시나리오 I · 킷팅·숏티지 및 Clear-to-Build 판정

1. **작업지시 기준 필요량 산출**
   작업지시(WO) 수량에 시나리오 F의 레벨별 소요량과 로스율을 적용해 품목별 필요량을 확정한다.

2. **가용 재고 배분과 예약**
   여러 작업지시가 동일 부품을 요구할 때 선착순이 아니라 납기·우선순위 기준으로 배분하고 `Kit_Allocation`으로 예약한다. **예약 없이 전산 재고만 보고 착수하면 다른 오더가 이미 쓸 자재를 중복 계산한다.**

3. **포장 단위 제약 반영**
   SPQ(릴 단위)와 실제 필요량의 차이를 계산한다. 릴 1개가 5,000개인데 필요량이 400개면, 부족 여부 판정은 통과하지만 잔여 4,600개의 보관·수명 관리 대상이 발생한다는 점을 함께 보고한다.

4. **Clear-to-Build 판정**
   전 품목이 충족되면 `CTB_Flag`를 착수 가능으로 설정한다. 부족 품목이 있으면 `Shortage_Qty`와 함께 조치안(긴급 조달 가능 채널, 대체재 적용 가능 여부, 부분 착수 가능 여부)을 제시한다.

5. **부분 착수 판단 보조**
   산업용 소량 생산에서는 일부 부품 미도착 상태로 선행 공정만 진행하는 판단이 잦다. Agent는 미도착 부품이 SMT 이후 공정에만 쓰이는지 판별해 **선행 공정 착수 가능 여부를 근거와 함께 제시**하되, 착수 결정 자체는 사람이 한다.

### 시나리오 J · 수입검사(IQC)·MSL 및 보관수명 관리

1. **입고 시 검사 대상 자동 판정**
   품목 등급과 이력에 따라 전수·샘플·무검사 경로를 판정한다. 신규 등록 부품(시나리오 E 통과 직후), 신규 공급처, 과거 불량 이력 품목은 검사 강도를 높인다.

2. **MSL 등급과 플로어 라이프 관리**
   습기 민감 부품은 [J-STD-020](https://www.ipc.org/TOC/IPC-JEDEC-J-STD-020E.pdf)으로 분류된 MSL 등급을 갖고, [J-STD-033](https://www.ipc.org/TOC/J-STD-033D-TOC.pdf)이 취급·보관·개봉 후 실장 가능 시간(플로어 라이프)과 베이킹 조건을 규정한다. Agent는 방습 포장 개봉 시각을 기점으로 `Floor_Life_Remaining`을 감산하고, 초과 임박 시 경고를, 초과 시 `IQC_Result` = `Bake_Required`로 전환한다. **플로어 라이프 초과 부품을 그대로 리플로우하면 패키지 내 수분이 팽창해 균열(팝콘 현상)이 발생하며, 이는 육안 검사로 걸러지지 않는다.**

3. **데이트코드 기반 선입선출과 보관수명**
   `Date_Code`·`Lot_No`를 기록해 오래된 로트를 먼저 불출한다. 보관 기간 자체가 품질에 영향을 주는 품목(전해 커패시터, 솔더 페이스트, 흡습성 부자재)은 보관 수명 초과 여부를 별도로 판정한다.

4. **분할 입고와 라벨 불일치 처리**
   발주 수량 대비 부족 입고, 포장 형태 불일치(릴 발주인데 컷테이프 납품 등)를 감지해 구매팀 클레임을 자동 기안한다. 이 결과는 `3Way_Match_Status`에 반영되어 시나리오 D의 대사 근거가 된다.

5. **로트 단위 추적성 확보**
   불출된 로트와 완성된 제품 시리얼을 연결해 두어, 특정 로트에서 문제가 발견되면 영향 제품 범위를 역산할 수 있게 한다.

## 4. 현장 암묵지 및 비정형 표현의 MPN 변환 로직 (도메인 지식 베이스)

엔지니어들이 EDA 도구에 정식 MPN 대신 입력하는 비정형 표현, 약칭, 관용적 표기를 Agent가 맥락적으로 판단하여 정확한 실물 부품(MPN/IPN)으로 변환하는 대표적인 도메인 케이스는 다음과 같다.

```text
[원시 입력 데이터]
     │
     ▼
[1단계: 규칙 기반 토큰화 및 전기적 특성 추출]
     │
     ▼
[2단계: 사내 전산 자재 마스터(IPN) 매핑]
     │ ── (과거 생산 이력 존재) ──▶ [기존 승인 품목(AVL) 우선 채택]
     │
     ▼ (신규 자재인 경우)
[3단계: 맥락적 다차원 가중치 추론]
     │ ── 패키지 풋프린트 (Metric vs Imperial 교차 검증)
     │ ── 회로 기능 (전원 라인 vs 신호 라인 / 내압 마진)
     │ ── 공급사별 최소 주문 수량(MOQ) 및 가용 재고
     │
     ▼
[최종 표준 MPN 및 사내 품목 코드(IPN) 확정]
```

### 4.1 수동 소자 ① 저항: 코드 표기와 물리적 정격

#### 케이스 1 · `R1608 2.2K` 또는 `0603 2.2K 1%`

- **현장 맥락** — 1608은 밀리미터 단위(Metric, 1.6mm × 0.8mm)이며 인치 단위로는 0603(Imperial)과 동일한 사이즈다. 엔지니어는 종종 두 체계를 혼용한다. 공차 표기가 없는 경우 사내에서는 통상 1%급 칩 저항을 의미하는 것으로 통용된다.
- **변환 로직** — Footprint 컬럼이 0603이고 텍스트가 `2.2K`인 경우, 사내에서 가장 많이 발주된 1608 1% 2.2kΩ 1/10W 저항(예: 삼성전기 `RC1608F222CS`, YAGEO `RC0603FR-072K2L`)의 사내 재고를 검색하고, 재고가 존재하는 표준 IPN으로 자동 매핑한다.
- **주의** — "공차 무표기 = 1%"는 **사내 규약이지 업계 표준이 아니다.** 이 가정은 사내 설계 가이드라인에 명문화한 뒤에만 자동 확정 근거로 사용하고, 명문화 전에는 `Confidence_Score`를 낮춰 엔지니어 확인 대상으로 분류한다.

#### 케이스 2 · `4R7`, `1002`, `0R0` / `000`

- **현장 맥락** — 저항값 표기는 세 체계가 혼용된다. 소수점을 문자로 대체하는 방식(`4R7` = 4.7Ω, `1R00` = 1.00Ω), 3자리 코드(`222` = 22 × 10² = 2.2kΩ), 정밀 저항용 4자리 코드(`1002` = 100 × 10² = 10kΩ)다. 같은 `1002`가 3자리 체계 해석에서는 전혀 다른 값이 되므로, **자리 수를 먼저 판정하지 않으면 값이 100배 틀어진다.**
- **변환 로직** — ① 문자 `R`이 포함되면 소수점 치환으로 해석한다. ② 숫자만 있을 때는 공차 표기와 계열을 함께 본다. 1% 이하 정밀 저항은 E96 계열이라 4자리 코드를, 5% 저항은 E24 계열이라 3자리 코드를 쓰는 것이 통상이다. ③ 해석 결과가 표준 저항 계열값(E24/E96)에 없으면 파싱 오류로 판정하고 확인 요청을 발행한다.
- **0Ω 점퍼의 예외** — `0R0`, `000`, `Jumper`는 저항값이 아니라 **정격 전류로 선정하는 부품**이다. 저항값 검색 로직을 그대로 태우면 값이 0이라 후보를 찾지 못한다. 전용 분기로 보내 사이즈와 허용 전류(예: 0603 1A급)로 매핑하고, 전원 경로에 놓인 점퍼는 통과 전류를 회로 맥락에서 확인한다.

#### 케이스 3 · `0603 2.2K 1/4W` — 사이즈와 정격의 물리적 모순

- **현장 맥락** — 엔지니어가 정격 전력을 여유 있게 적었을 뿐, 해당 사이즈에 그 정격 품목이 존재하지 않는 경우가 있다. 0603(1608 Metric) 후막 칩 저항의 일반 정격은 **1/10W**이고, 1/4W는 상위 사이즈(1206 등) 또는 특정 벤더의 고전력 전용 시리즈에서만 나온다.
- **변환 로직** — 이 케이스는 부품을 찾는 문제가 아니라 **모순을 검출하는 문제**다. Agent는 사이즈와 정격의 조합이 표준 조합표에 없으면 임의로 한쪽을 버리지 않는다. ① 실제 회로에서 소모되는 전력을 추정할 수 있으면 함께 제시하고, ② '사이즈를 1206으로 올린다', '고전력 전용 시리즈를 쓴다', '정격 표기가 과잉이므로 1/10W로 확정한다'는 세 선택지를 엔지니어에게 제시한다.
- **왜 자동 확정이 금지인가** — 사이즈를 올리면 PCB 패턴을 바꿔야 하므로 설계 변경이고, 정격을 내리면 발열·소손 위험을 감수하는 결정이다. **어느 쪽도 조달 담당자나 Agent가 단독으로 정할 수 있는 사안이 아니다.** 동일 원리를 커패시터 내압·인덕터 정격 전류·다이오드 순전류에도 적용한다.

### 4.2 수동 소자 ② 커패시터: 유전체·극성·물리 규격

#### 케이스 4 · `C0603 104`, `100nF`, `0.1uF 50V`

- **현장 맥락** — `104`는 10 × 10⁴ pF = 100nF = 0.1µF를 뜻하는 세 자리 숫자 표기법이다. 세라믹 커패시터(MLCC)는 유전체 재질(X7R, X5R, Y5V)과 내압(16V, 25V, 50V)이 핵심 사양이다.
- **변환 로직** — 회로 블록의 VCC 레벨이 5V/12V인 맥락을 참조하여, 내압 50V·X7R 규격의 무라타 `GRM188R71H104KA93D` 또는 삼성전기 `CL10B104KB8NNNC`를 후보군으로 추출하고 기존 구매 이력과 대조하여 기본 부품 번호로 확정한다.
- **추가 판정 축** — Y5V·X5R 등 저급 유전체는 온도·DC 바이어스에 따른 용량 감소가 크므로, `Schematic_Function`이 전원 디커플링이면 X7R 이상으로 상향 제한하는 규칙을 둔다.

#### 케이스 5 · `10uF 6.3V A Case` 또는 `10uF Tantal`

- **현장 맥락** — 'A Case'는 탄탈 커패시터(및 알루미늄 전해 칩)의 EIA **3216-18** 표준 규격이다. 탄탈은 MLCC와 달리 **극성이 있는 부품**이다.
- **변환 로직** — RefDes가 `TC` 또는 `C`이고 `A Case` 키워드가 감지되면 탄탈 커패시터 군으로 분류하고, KYOCERA AVX `TAJA106K006RNJ` 등의 규격으로 정확히 전환한다.
- **오대체 리스크(양방향)**
  - 탄탈 자리를 MLCC로 대체 → 용량·ESR 특성 및 DC 바이어스 거동이 달라져 전원 안정성·리플 스펙 이탈.
  - **무극성 자리 또는 극성 반대로 탄탈을 적용 → 역전압·과전압 인가 시 발열·발화 위험.** 따라서 극성 부품 치환은 자동 확정 금지 대상(하드 가드레일)으로 둔다.

#### 케이스 6 · `470uF 25V` — 알루미늄 전해 커패시터

- **현장 맥락** — 용량과 내압만으로는 발주가 불가능한 대표적 부품이다. 실장 방식(SMD V-chip / 리드 타입 radial), 캔 직경과 높이, 리드 타입일 경우 리드 간격(Pitch), 수명 등급(예: 105℃ 2,000h), 허용 리플 전류, ESR이 모두 선정 조건이다. **높이 제약을 무시하면 조립 시 상부 케이스에 간섭해 기구 불량이 된다.**
- **변환 로직** — ① Footprint에서 캔 직경·높이·리드 간격을 역산해 후보를 제한한다. ② `Schematic_Function`이 전원 입력단·DC 링크면 리플 전류와 수명 등급을 상향 조건으로 걸고, 신호단 결합이면 완화한다. ③ 산업용 제품은 동작 온도와 요구 수명이 높으므로 **85℃ 등급 품목의 자동 채택을 제한하고 105℃ 이상을 기본 후보로 둔다.**
- **부가 판정** — 전해 커패시터는 극성 부품이며 보관 자체가 특성에 영향을 준다. 장기 보관 재고나 LTB로 대량 확보한 재고는 시나리오 J의 보관수명 판정 대상에 포함한다.

### 4.3 수동 소자 ③ 인덕터와 페라이트 비드

#### 케이스 7 · `10uH` 인가, 페라이트 비드인가

- **현장 맥락** — 회로도에 `L1`으로 표기되고 값이 `10uH`라고만 적혀 있으면, 전력 변환용 파워 인덕터인지 노이즈 억제용 페라이트 비드인지 구분되지 않는다. 두 부품은 선정 파라미터의 축 자체가 다르다.

  | 구분 | 규정 방식 | 핵심 파라미터 |
  |---|---|---|
  | 파워 인덕터 | 인덕턴스 (µH) | 정격 전류(포화·온도 상승), DCR, 포화 특성 |
  | 페라이트 비드 | **특정 주파수에서의 임피던스** (예: 600Ω @100MHz) | 정격 전류, DC 저항, 임피던스-주파수 곡선 |

- **변환 로직** — ① 값이 `Ω @ 주파수` 형태거나 회로 기능이 EMI 필터·전원 디커플링이면 비드로 분류한다. ② 값이 µH 단위이고 스위칭 레귤레이터 블록에 속하면 파워 인덕터로 분류하고 **정격 전류를 필수 입력으로 요구한다.** ③ 비드로 분류되었는데 임피던스 규격이 없으면 값만으로 확정하지 않고 확인 요청을 발행한다.
- **주의** — 페라이트 비드는 [고주파에서 저항성으로 동작해 노이즈를 열로 소산](https://www.analog.com/en/resources/analog-dialogue/articles/ferrite-beads-demystified.html)하는 부품이므로, 인덕턴스 값으로 등가 변환해 파워 인덕터로 대체하면 의도한 감쇠가 나오지 않고 공진을 유발할 수 있다. 또한 **DC 바이어스가 걸리면 임피던스가 크게 떨어지므로**, 정격 전류 대비 실제 통과 전류를 확인하지 않은 대체는 자동 확정 대상이 아니다.

### 4.4 디스크리트 반도체 및 회로 보호 부품

#### 케이스 8 · `SS14`

- **현장 맥락** — 쇼트키 배리어 다이오드 1A / 40V 규격을 통칭하는 업계 관용 약어다. 패키지는 통상 SMA(DO-214AC) 형태이며, 제조사마다 접두·접미사가 다르다 (Vishay `SS14-E3/61T`, onsemi `SS14`, Diodes Inc `B140-13-F` 등).
- **변환 로직** — 현재 창고에 보유 중인 SMA 규격 1A/40V 쇼트키 다이오드 IPN을 우선 조회하여 불필요한 신규 발주를 방지하고, 재고가 없을 시 단가와 납기가 가장 짧은 벤더의 표준 MPN을 할당한다.

#### 케이스 9 · `4148`, `1N4148W`, `1N4148WS`

- **현장 맥락** — 고속 스위칭 다이오드의 대명사이나, 동일 다이 계열이 서로 다른 패키지로 공급되므로 접미사를 무시하면 실장이 불가능하다.

  | 품번 | 패키지 | 실장 방식 |
  |---|---|---|
  | `1N4148` | DO-35 | 리드 타입 (수삽) |
  | `1N4148W` | SOD-123 | SMD |
  | `1N4148WS` | SOD-323 | SMD (SOD-123보다 소형) |
  | `1N4148WT` | SOD-523 | SMD (초소형) |

- **변환 로직** — EDA의 PCB Footprint 속성을 강제 대조한다. Footprint가 SOD-123이면 `1N4148W`, SOD-323이면 `1N4148WS`, DO-35이면 축방향 리드 부품으로 분기하여 M-BOM에 수삽(DIP) 공정 속성을 부여한다. **텍스트의 접미사와 Footprint가 불일치하면 Footprint를 우선하고 엔지니어 확인 핑을 전송한다.**

#### 케이스 10 · `2N7002` vs `2N7002K` vs `2N7002E`

- **현장 맥락** — 모두 N-Channel 60V MOSFET(SOT-23) 계열이지만 접미사에 따라 보호 기능과 전기적 특성이 다르다.

  | 품번 | 대표 사양 (Diodes Inc 기준) | 특징 |
  |---|---|---|
  | `2N7002` | 60V | 기본형 |
  | `2N7002K` | 60V / ID 380mA / R<sub>DS(on)</sub> 2Ω @10V | **ESD 보호 다이오드 내장 (2kV HBM)** |
  | `2N7002E` | 60V / ID 300mA / R<sub>DS(on)</sub> 3Ω @10V | 온저항·스위칭 특성 파생형 |

- **변환 로직** — 회로의 연결 노드가 외부 커넥터와 직접 닿는 I/O 라인인지 파악하고, 사내 회로 설계 가이드라인에 맞춰 ESD 보호가 내장된 `2N7002K`(예: Diodes Inc `2N7002K-7`)를 추천값으로 제안한다.
- **주의** — **접미사 의미는 제조사별로 통일되어 있지 않다.** 동일 `2N7002E`도 벤더에 따라 정의가 다르므로, Agent는 접미사 규칙만으로 확정하지 않고 해당 벤더 데이터시트의 파라미터(V<sub>DS</sub>, I<sub>D</sub>, R<sub>DS(on)</sub>, ESD 항목)를 대조한 뒤 확정한다.

#### 케이스 11 · `1A 퓨즈`

- **현장 맥락** — 전류 정격만으로는 부품이 특정되지 않는다. 동작 특성(속단 Fast-acting / 지연 Time-lag), 정격 전압, 차단 용량(Breaking Capacity), 그리고 **일회성 퓨즈인지 리셋 가능한 PPTC(폴리스위치)인지**가 모두 다른 부품이다.
- **변환 로직** — ① `Schematic_Function`이 입력 전원 보호이고 인러시 전류가 예상되는 위치(대용량 커패시터 후단, 모터 구동단)면 지연형을 후보로 둔다. ② 반도체 보호 목적이면 속단형을 후보로 둔다. ③ 정격 전압은 회로의 최대 인가 전압 이상이어야 하며, **AC 라인용과 DC 전용의 정격은 상호 대체되지 않는다.**
- **왜 자동 확정이 금지인가** — 퓨즈는 고장 시 회로를 끊어 화재를 막는 안전 부품이다. 속단/지연을 잘못 선정하면 정상 동작 중 단선되거나, 반대로 이상 전류에서 끊어지지 않는다. 안전 인증(제품 인증 시 지정 부품)과 연동된 품목이면 **인증 범위 내 지정 MPN만 허용하고 대체 추천 자체를 차단한다.**
- **PPTC 구분** — 리셋 가능한 PPTC는 정상 동작 시에도 직렬 저항이 존재해 전압 강하를 만든다. 일회성 퓨즈 자리에 PPTC를 넣거나 그 반대로 바꾸는 것은 회로 특성 변경이므로 대체 후보로 자동 제시하지 않는다.

### 4.5 아날로그·전원 IC: 핀 배치와 품번 인코딩

#### 케이스 12 · `AMS1117-3.3` vs `1117 Adj`

- **현장 맥락** — 3.3V 고정 출력형과 외장 저항으로 전압을 조절하는 가변(Adjustable)형은 외관(SOT-223)과 기본 품번이 같으나 **1번 핀의 기능이 다르다.** 고정형은 1번 핀이 GND, 가변형은 1번 핀이 ADJ(피드백)다. 서로 바꿔 실장하면 출력 전압이 폭주해 보드가 소손된다.
- **변환 로직** — 엔지니어가 단순히 `1117`이라고만 썼을 때, 회로도상 1번 핀이 접지(GND)에 직접 연결되어 있으면 고정 출력(Fixed)으로 판별하고, 분압 저항 네트워크에 연결되어 있으면 가변형 MPN(`AMS1117-ADJ`)으로 추론한다.
- **부가 판정** — 고정형으로 판별된 경우 출력 전압 값(1.8 / 2.5 / 3.3 / 5.0V)은 회로도 네트 라벨(`+3V3` 등)과 다운스트림 부품의 정격에서 교차 확인한다.

#### 케이스 13 · `LM358` — 동일 기능, 다른 온도 등급과 패키지

- **현장 맥락** — 범용 IC는 같은 기능이 **온도 등급별 파생 품번**으로 나뉜다. 대표적인 듀얼 OP앰프 계열이 그 예로, [TI LMx58 데이터시트](https://www.ti.com/lit/gpn/lm158-n) 기준 `LM158`은 -55~125℃, `LM258`은 -25~85℃, `LM358`은 0~70℃ 등급이다. 여기에 패키지·포장 접미사가 다시 붙는다(예: TI에서 `D` = SOIC, `DGK` = VSSOP, `P` = PDIP, 말미의 `R` = Tape & Reel).
- **왜 산업용에서 치명적인가** — 엔지니어가 습관적으로 `LM358`이라고 적으면 **상용 등급(0~70℃)** 이 발주된다. 산업용 장비의 동작 온도 요구가 -20℃ 이하 또는 70℃ 이상이면 사양 미달이며, 이 불일치는 실장·기능 시험을 모두 통과하고 **현장에서 온도가 내려간 뒤에야 드러난다.**
- **변환 로직** — ① 제품의 요구 동작 온도 범위를 프로젝트 속성에서 가져와, 품번의 온도 등급이 이를 포함하지 못하면 상위 등급 파생 품번을 제시한다. ② 포장 접미사(Tape & Reel / Tube / Tray)는 `SMT_Feeder_Type`과 대조해 결정한다. 릴 발주가 필요한 라인에 Tube 품번이 확정되면 실장 자체가 불가능하다. ③ 온도 등급 상향은 단가·조달성에 영향을 주므로 **자동 확정하지 않고 근거와 함께 제안한다.**

#### 케이스 14 · `STM32F103` — 품번 문자열 자체가 사양인 부품

- **현장 맥락** — MCU·FPGA·메모리처럼 파생 품번이 수십~수백 개인 반도체는 **품번 문자열에 핀 수·메모리 용량·패키지·온도 등급이 인코딩**되어 있다. 예를 들어 `STM32F103C8T6`은 [LQFP48 패키지, 64KB 플래시, -40~85℃ 등급](https://www.digikey.com/en/products/detail/stmicroelectronics/STM32F103C8T6/1646338)의 특정 파생품이다. 엔지니어가 계열명(`STM32F103`)만 기재하면 **선택지가 수십 개로 남아 발주 자체가 불가능하다.**
- **변환 로직** — ① 계열명만 있는 경우 임의 파생품을 고르지 않는다. ② Footprint의 핀 수와 패키지 형상으로 후보를 1차 축소하고, ③ 펌웨어 빌드 산출물의 메모리 사용량이나 과거 동일 계열 발주 이력으로 용량 후보를 좁힌 뒤, ④ **최종 파생 품번은 엔지니어 확정을 요구한다.**
- **주의** — 접미사 규칙은 벤더별·계열별로 다르고 개정된다. Agent는 문자 규칙을 하드코딩하는 대신 **해당 벤더의 주문 정보(Ordering Information) 표를 근거로 파싱**하고, 파싱 결과가 실재하는 판매 품번인지 유통사 카탈로그로 역검증한다. 존재하지 않는 조합을 생성하는 것이 이 부품군에서 가장 흔한 환각 유형이다.

### 4.6 사양이 품번 밖에 있는 부품: 타이밍·광부품

이 절의 두 케이스는 공통점이 있다. **텍스트에 적힌 값이 맞아도 부품이 특정되지 않으며, 빠진 파라미터가 회로 밖(주변 부품, 선별 등급)에 존재한다.**

#### 케이스 15 · `16MHz` — 크리스탈인가 오실레이터인가

- **현장 맥락** — 주파수만 적힌 경우 수정진동자(Crystal)와 오실레이터(Oscillator)가 구분되지 않는다. 크리스탈은 2단자 수동 부품으로 MCU 내부 발진 회로와 함께 동작하고, 오실레이터는 전원이 필요한 능동 부품으로 통상 4단자다. **핀 수와 전원 연결이 다르므로 상호 대체가 불가능하다.**
- **크리스탈 고유의 필수 파라미터** — 부하 용량(C<sub>L</sub>, 예: 8pF / 12.5pF), 주파수 허용 편차(ppm), 등가 직렬 저항(ESR), 구동 레벨이다. 부하 용량이 맞지 않으면 부품이 실장되고 발진도 하지만 **주파수가 규격을 벗어나** 통신 오류로 나타난다. 이 불량은 BOM 검토나 육안 검사로 잡히지 않는다.
- **변환 로직** — ① Footprint의 패드 수로 크리스탈/오실레이터를 1차 분기한다. ② 크리스탈로 판정되면 부하 용량을 필수 항목으로 요구하고, 주변 로드 커패시터(통상 크리스탈 양단의 두 개)의 용량값과 정합성을 교차 확인한다. ③ 통신 규격이 요구하는 주파수 정밀도(예: USB, CAN)가 있으면 ppm 등급을 하한 조건으로 걸어 대체재를 제한한다.

#### 케이스 16 · `빨강 LED 0603` — 선별 등급(Bin)이 빠진 부품

- **현장 맥락** — LED는 동일 품번 안에서도 **선별 등급(Binning)** 으로 나뉜다. 순전압(V<sub>F</sub>), 광도(mcd), 색좌표가 각각 등급 코드로 관리되며, 발주 품번에 등급 코드까지 포함되어야 한다. 등급을 지정하지 않으면 로트마다 밝기와 색감이 달라져, **같은 제품에서 표시등 색이 다르게 보이는 외관 불량**이 발생한다.
- **변환 로직** — ① 색상·사이즈만 기재된 항목은 사내 표준 등록 LED로 우선 매핑하고, ② 신규인 경우 V<sub>F</sub>·광도·색좌표 등급을 필수 확인 항목으로 올린다. ③ 직렬 저항값이 회로에 이미 정해져 있으면 V<sub>F</sub> 등급 변경이 밝기를 바꾸므로, **V<sub>F</sub> 등급이 다른 대체재는 저항값 재검토 필요 항목으로 표시한다.**
- **주의** — 등급 코드는 벤더 고유 체계다. IPN에 등급 코드까지 포함해 고정하지 않으면, 동일 IPN으로 발주해도 로트마다 다른 등급이 입고될 수 있다.

### 4.7 커넥터 및 기구 결합 부품: 짝을 이루는 품목의 누락

#### 케이스 17 · `2.54mm 1x4 Pin Header`

- **현장 맥락** — 핀 피치와 핀 수만 명시되고 DIP 스트레이트(Straight), 라이트앵글(Right Angle), SMD 타입 여부 및 도금 사양(금도금, 주석도금)이 누락되는 경우가 비일비재하다.
- **변환 로직** — 과거 프로젝트의 연관 완제품 조립 구조를 참조하고, 사내 표준 등록 핀헤더 목록 중 PCB 결합 방향과 일치하는 커넥터 규격으로 변환한 후 엔지니어 확인 핑을 전송한다.
- **주의** — 커넥터는 벤더별 품번 체계가 자주 개정되므로, 특정 벤더 품번을 하드코딩하지 않고 **사내 표준 등록 품목(IPN) 우선 매핑**을 원칙으로 한다.

#### 케이스 18 · `XH-4P` vs `B4B-XH-A`

- **현장 맥락** — 엔지니어는 관용적으로 'JST XH 4핀'이라는 의미로 `XH-4P`라고 기재하지만, 실제 발주용 정식 MPN은 JST의 `B4B-XH-A(LF)(SN)`이다. XH 시리즈의 피치는 **2.50mm**로, 2.54mm 핀헤더와 혼동하기 쉽다.
- **변환 로직** — 제조사 정규 카탈로그 명명 규칙(Rule-base Naming Grammar)에 따라 `B[핀수]B-XH-A` 패턴을 생성하여 글로벌 파트넘버로 정규화한다.
- **기판측 방향 구분** — 탑 엔트리는 `B4B-XH-A`, 사이드 엔트리는 `S4B-XH-A`로 갈리므로 Footprint·기구 간섭 정보를 대조해 분기한다.
- **BOM 누락 방지(중요)** — 커넥터는 **기판측 헤더 · 전선측 하우징(`XHP-4`) · 크림프 컨택트(`SXH-001T-P0.6` 등)** 가 별도 품번이다. 기판측만 발주되어 조립 단계에서 결품되는 사고가 잦으므로, Agent는 커넥터 인식 시 **짝을 이루는 하우징·컨택트 품목의 존재 여부를 검사하고 누락 시 부자재로 자동 제안**한다.

### 4.8 실장 제외 항목과 표기 정합성 검증

앞의 케이스들이 '무엇을 살 것인가'를 다뤘다면, 이 절은 **'사면 안 되는 것과 계산이 틀린 것'** 을 다룬다. MPN 추론이 완벽해도 이 검증을 건너뛰면 오발주가 발생한다.

#### 케이스 19 · `DNP`, `NC`, `Not Used`, `TBD`

- **현장 맥락** — 회로도에는 존재하지만 실제로는 실장하지 않는 항목이 항상 있다. 옵션 회로, 디버그용 점퍼, 파생 모델용 예비 자리다. 표기는 `DNP`(Do Not Populate), `NC`, `Not Used`, `-`, 빈 셀, 수량 0, 심지어 셀 취소선처럼 통일되지 않는다. **`TBD`는 성격이 완전히 다르다. 미실장 확정이 아니라 아직 결정되지 않았다는 뜻이므로, 발주 제외 처리하면 결품이 된다.**
- **변환 로직** — ① 미실장 후보를 감지하면 조달 대상에서 제외하되 **행 자체는 삭제하지 않고 참조 부호와 함께 유지**한다. 삭제하면 리비전 비교 시 '삭제된 부품'으로 오인되어 불필요한 ECO가 발생한다. ② `TBD`·빈 셀은 미실장이 아니라 **미결정**으로 분류해 별도 확인 요청 목록에 올린다. ③ 미실장 항목의 상태 변화(실장 ↔ 미실장)는 값 변경과 동일한 무게의 설계 변경이므로 시나리오 C의 Diff 대상에 포함한다.
- **부가 판정** — 스텐실·검사 프로그램은 실장 여부에 따라 달라지므로, 미실장 항목 목록을 생산기술 뷰에 명시적으로 노출한다.

#### 검증 규칙 V1 · 참조 부호 개수와 수량의 불일치

- **현장 맥락** — 참조 부호 컬럼에 `R1, R2, R3`이 적혀 있는데 수량 컬럼은 `2`인 경우다. 엑셀에서 행을 병합·복사하거나 미실장 항목을 수량에서만 뺐을 때 발생한다. **어느 쪽이 맞는지는 Agent가 알 수 없다.**
- **검증 로직** — 참조 부호를 파싱해 개수를 세고 수량과 대조한다. 불일치 시 자동 보정하지 않고 확인 요청을 발행한다. 참조 부호 중복(같은 부호가 두 행에 등장), 누락(부호 없이 수량만 존재)도 같은 규칙으로 검출한다.
- **왜 자동 보정이 금지인가** — 수량을 참조 부호 개수로 맞추면 미실장 항목까지 발주되고, 반대로 참조 부호를 지우면 실장 위치 정보가 사라진다. 둘 다 되돌리기 어려운 손실이다.

#### 검증 규칙 V2 · 단위(UoM) 불일치와 반올림

- **현장 맥락** — 모든 자재가 개수로 세어지지 않는다. 와이어·열수축 튜브·실드 테이프는 길이(m), 솔더 페이스트·본드는 무게나 용기 단위(g, cc, 통), 나사·와셔는 개수(EA)이지만 발주는 봉지·박스 단위로 이뤄진다. 도면에는 `와이어 AWG22 150mm`처럼 **소요량 단위**로 적히지만 발주는 **구매 단위**로 나간다.
- **검증 로직** — ① 소요량 단위와 구매 단위를 분리 보관하고(`UoM`), 환산 계수를 품목 속성으로 관리한다. ② 환산 후 구매 단위 기준으로 올림 처리하며, **올림으로 발생한 초과분은 원가(시나리오 G)와 잔여 재고(시나리오 I)에 함께 반영한다.** ③ 환산 계수가 등록되지 않은 품목은 자동 발주 대상에서 제외한다.
- **주의** — 이 규칙은 부자재에서 특히 자주 깨진다. 부자재는 금액 비중이 작아 검증이 느슨해지지만, **결품되면 라인이 멈추는 것은 IC와 동일하다.**

#### 검증 규칙 V3 · 레벨·배수 누락에 의한 수량 오류

- **현장 맥락** — 단층 BOM을 계층으로 올리는 과정에서 수량이 틀어지는 경로가 세 가지 있다. ① 레벨 간 곱셈을 하지 않고 단순 합산, ② SMT 패널 다면취 배수(`Panel_Qty`) 미반영, ③ 팬텀 아이템을 실재 재고로 계상. 세 오류 모두 **개별 라인은 정상으로 보이고 총량에서만 어긋나므로** 눈으로 발견되지 않는다.
- **검증 로직** — ① 총 소요량을 레벨 경로의 곱으로 재계산해 입력값과 대조한다. ② 보드 단위 소요량과 패널 단위 투입 계획을 분리 산출하고 두 값의 관계가 배수로 성립하는지 확인한다. ③ `Phantom_Flag` 항목이 재고·발주 대상에 포함되지 않았는지 검사한다.
- **왜 중요한가** — 수량 오류는 결품(라인 정지) 또는 과다 발주(불용 재고) 중 하나로 반드시 귀결된다. 계층 전개의 결과물은 **재계산으로 검증 가능한 형태**여야 하며, 이 재계산은 모델이 아니라 결정론적 산술로 수행한다.

## 5. 예외 룰북 (Living Rulebook)

4장이 '자주 일어나는 해석 문제'를 다룬다면, 이 장은 **'드물게 일어나지만 터지면 큰 것'** 을 다룬다. 표준 플로우에서 벗어나는 경로, 자동화하면 안 되는 판단, 표기가 어긋나는 지점을 규칙 단위로 등록한다.

빈도가 낮다는 이유로 문서화되지 않으면 규칙은 담당자 머릿속에만 남는다. **이 룰북은 완성본이 아니라 사고가 날 때마다 한 줄씩 늘어나는 문서다.**

### 5.1 룰북 운영 규칙

**ID 체계** — `RB-{분류}-{번호}`

| 분류 | 의미 |
|---|---|
| `LT` | 리드타임·납기 규칙 |
| `DP` | 지정 부품 (대체 제한) |
| `SY` | 동의어·표기·단위 정규화 |
| `EX` | 프로세스 예외 경로 |
| `SF` | 물리·안전 가드레일 |
| `ST` | 구조 판정 (계층 깊이·품번 발번) |

**위험 등급** — 규칙 위반 시 Agent의 행동을 결정한다.

| 등급 | 행동 | 의미 |
|---|---|---|
| **S** (Stop) | 자동 진행 차단, 사람 판단 없이는 다음 단계로 넘어가지 않음 | 안전·품질·법적 리스크 |
| **H** (Human) | 처리안을 제시하고 승인 요청 | 판단이 갈리는 사안, 비용 영향 |
| **L** (Log) | 자동 처리하고 근거를 기록 | 되돌릴 수 있는 사안 |

**등록·개정 절차** — ① 사고·이슈 발생 시 원인을 규칙 문장으로 환원해 초안 등록 → ② 해당 부서와 품질팀이 위험 등급 합의 → ③ 규칙에 대응하는 검증 로직이 구현 가능한지 확인(구현 불가하면 체크리스트 규칙으로 분류) → ④ 개정 이력에 사유와 일자 기록. **규칙을 지웠다면 왜 지웠는지도 남긴다.**

| `RB-ST-08` | Agent가 반제품 품번을 발번하거나 계층 구조를 확정하려 함 | **자동 확정 금지.** 후보 분류와 근거 제시까지만 수행하고 생산기술 승인으로 확정 | **S** |
| `RB-ST-09` | 사내 도면번호로 관리되는 제작품(판금·패널·하네스)이 구조에 포함됨 | MPN 추론 경로에서 분리하고 도면 리비전 검증 경로로 분기(`RB-DP-06`) | **S** |

> **RB-ST의 성격** · 다른 분류가 '틀린 데이터'를 막는 규칙이라면, RB-ST는 **'구조를 임의로 바꾸는 것'을 막는 규칙**이다. 계층은 조달·회계·품질 정책이 반영된 결과물이므로, 정보 처리 계층이 단독으로 결정할 사안이 아니다([1.3.4](#134-ax의-역할-경계--무엇을-없애고-무엇을-없앨-수-없는가)).

> **룰북과 모델의 관계** · RB-SF·RB-DP·RB-ST는 모델이 아니라 **Agent 애플리케이션 계층의 결정론적 로직**으로 구현한다([7.2](#72-상세-역할-및-인터페이스-사양)). 모델의 추론 결과를 규칙이 사후 검증하는 구조여야 하며, 규칙을 프롬프트에만 넣는 방식은 이 등급의 리스크를 막지 못한다.

## 6. 업계 표준 기반 BOM Agent 핵심 성과 지표 (KPI)

BOM Agent가 도입되었을 때 기존의 수작업 및 회의 중심 프로세스를 얼마나 효과적으로 대체하고 개선했는지 정량적으로 검증하기 위한 지표 체계다.

| 관점 | KPI 명칭 | 산출 공식 및 측정 기준 | 목표 벤치마크 |
|---|---|---|---|
| **설계·엔지니어링** | ECO 리드타임 (Cycle Time) | 설계 변경 요청(ECR) 발생 시점부터 생산 현장 M-BOM 및 ERP 동기화 완료까지의 총 소요 시간 | 기존 7~17일 → **24시간 이내** |
| | 대기 시간 비율 (Wait Time Ratio) | 전체 ECO 사이클 타임 중 실제 검토·작업 없이 승인 대기 상태로 머문 시간의 비율 | 기존 80% 이상 → **15% 이하** |
| | ECO 재작업 루프 횟수 (Rework Loops) | 영향도 분석 누락으로 인해 ECO가 이전 검토 단계로 반려·회귀된 횟수 | **건당 0.05회 미만** (Near Zero) |
| | 부품 표준화율 *(시나리오 E)* | 신규 프로젝트 BOM 라인 중 사내 표준 품목(`Preferred`)으로 충족된 비율 | **85% 이상** · 신규 등록 건수의 절대적 감소 |
| | BOM 구조 유지 공수 *(1.3.4)* | 리비전 발생 시 계층 구조를 사람이 갱신하는 데 드는 인시(man-hour) | **수작업 갱신 0** — 관계 필드에서 전개해 산출 |
| **구매·공급망** | 발주 처리 주기 (PO Cycle Time) | BOM 업로드 완료 시점부터 공급처별 정식 구매발주서(PO) 발행 확정까지의 시간 | 기존 3~5일 → **4시간 이내** |
| | BOM 정제 속도 (Scrubbing Time) | 원시 E-BOM 1,000 라인 기준 사내 IPN 매핑 및 오류 검증 완료 소요 시간 | 기존 40시간 → **10분 이내** |
| | 비관리 지출 비율 (Maverick Spend) | 표준 단가 대조 없이 긴급 스팟 바잉으로 구매된 금액의 비율 | 15% 이상 → **3% 미만** |
| | 구매 원가 절감률 (Cost Variance) | Agent의 다채널 최적 단가 조합 추천을 통한 BOM 총 자재비 절감률 | 기존 대비 **8~12% 절감** |
| | 단종 통보 대응 선행일수 *(시나리오 H)* | PCN·EOL 통보 수신일부터 대응안(LTB 발주 또는 대체 ECO) 확정까지의 소요일 | **통보 후 10영업일 이내** · 최종 발주 기한 대비 여유 확보 |
| | 원가 산정 정확도 *(시나리오 G)* | 승인 시점의 산정 원가와 실제 매입 확정 원가의 절대 편차율 | **±3% 이내** |
| **제조·자재관리** | 라인 스톱 위험 부품 선행 감지율 | 납기 지연·EOL·재고 부족으로 실장 라인이 정지될 위험 품목의 사전 탐지율 | **99.5% 이상** (사전 차단) |
| | 유령 재고 오차율 (Ghost Inventory) | ERP 전산 재고와 창고 실물 재고의 수량 불일치율 | 5% 이상 → **0.5% 미만** |
| | Clear-to-Build 판정 적중률 *(시나리오 I)* | 착수 가능으로 판정한 작업지시 중 자재 결품으로 중단되지 않은 비율 | **99% 이상** |
| | MSL 플로어 라이프 초과 건수 *(시나리오 J)* | 개봉 후 실장 가능 시간을 초과한 상태로 라인에 투입된 건수 | **0건** · 베이킹 누락 0건 |
| | 구조 오류 사전 검출률 *(검증 규칙 V3)* | 레벨 곱셈 누락·패널 배수 누락·팬텀 재고 계상이 발주·투입 **전에** 검출된 비율 | **100%** — 사후 발견 0건 |
| **에이전트 정확도** | 무인 자율 변환율 (Zero-Touch Rate) | 사람의 수기 개입 없이 원시 텍스트가 정확한 MPN/IPN으로 자동 변환된 비율 | 수동소자 **95% 이상**<br />능동소자·IC **90% 이상** |
| | 오발주 유발 환각 건수 (Hallucination) | Agent가 자율 확정한 건 중, 실장이 불가능한 자재가 실제 발주까지 도달한 **건수**(월 단위 집계) | **0건** (Zero Tolerance) |
| | 가드레일 차단율 *(신규)* | 모델이 추론했으나 하드 가드레일(정격·Footprint 검증)에서 거부된 건수 ÷ 전체 추론 건수 | 모니터링 지표 (하락 추세 관리) |

> **KPI 정의 보정** — 원본의 '오발주 유발 환각률 0.00%'는 분모 정의가 없어 측정이 불가능하다. 위와 같이 **발주까지 도달한 건수(월 0건)** 로 재정의하고, 모델의 오추론 자체는 별도의 '가드레일 차단율'로 관측한다. 즉 *모델은 틀릴 수 있고, 시스템은 틀린 것을 통과시키지 않는다*를 지표 구조로 표현한다.
>
> **벤치마크 출처** — 위 '기존' 수치(7~17일, 40시간, 3~5일 등)는 사내 실무 관측치와 업계 통용 범위를 근거로 한 목표 설정값이다. 착수 시점에 **사내 베이스라인 실측**을 선행해 확정할 항목이다.

## 7. BOM Agent 시스템 아키텍처 및 협력사 역할 분담

시스템 구축의 성공을 위해 본사(Agent Application 개발)와 협력사(AI/파운데이션 모델 구성) 간의 책임 한계를 엄격히 분리한다. 본사는 비즈니스 로직·상태 기계(State Machine)·안전 제약 조건(Guardrails)을 총괄하고, 협력사는 모델의 추론 성능·문서 이해도·응답 지연 시간(Latency) 최적화에 집중한다.

### 7.1 계층별 분장 사양

```text
┌─────────────────────────────────────────────────────────────┐
│       [본사 담당] Agent Application & Orchestration 계층    │
│  - EDA 파일 파서 및 엑셀 그리드 뷰포트 관리                 │
│  - E-BOM/M-BOM 단일 마스터 테이블 상태 관리 (SSOT State)    │
│  - 부서별 가상 뷰 렌더링 및 RBAC 권한 통제                  │
│  - ERP, 유통사 API(Digi-Key 등), SMTP, 메신저 웹훅 연동     │
│  - 하드코딩된 물리적 안전 제약(Safety Guardrails) 검증      │
│  - 휴먼 인 더 루프(HITL) 예외 에스컬레이션 트리거           │
└──────────────────────────────┬──────────────────────────────┘
                               │
            Tool Calling / JSON Schema Interface
                               │
┌──────────────────────────────▼──────────────────────────────┐
│        [협력사 담당] Foundation Model & Inference 계층      │
│  - 비정형 BOM 레이아웃 인식 및 다중 헤더 시맨틱 파싱        │
│  - 도메인 특화 NER (Value, Footprint, Tolerance 개체 추출)   │
│  - 부품 텍스트 임베딩 및 지식 베이스 벡터 검색              │
│  - 비정형 견적서(PDF/스캔본/이메일) VLM/OCR 비전 인식       │
│  - 대체 부품 간 전기적/물리적 사양 유사도 랭킹 산출         │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 상세 역할 및 인터페이스 사양

#### Agent System의 필수 구현 사양

- **EDA 연동 및 파싱 전처리**
  Altium, OrCAD, PADS 등에서 추출된 다채로운 포맷의 엑셀/CSV를 인메모리 데이터프레임으로 변환하여 모델이 소비할 수 있는 정형 청크(Chunk) 형태로 전달.

- **비즈니스 규칙 검증기 (Hard Guardrail)**
  모델이 추론한 MPN이 회로의 정격 사양(내압, 허용오차)을 만족하지 못하거나 Footprint 물리 규격이 다를 경우, 모델 출력을 강제로 거부하고 에스컬레이션 상태로 전환하는 **결정론적** 검증 로직 구현.

- **단일 마스터 테이블 트랜잭션 관리**
  부서 간 동시 접근 시 동시성 제어(Concurrency Control) 및 이벤트 기반 감사 로그(Audit Trail) 저장.

- **외부 I/O 인터페이스 구현**
  모델이 필요할 때 호출하는 함수 도구(Tool Calling / MCP) 제공:

  ```text
  query_internal_erp_stock(ipn, mpn)               # 내부 가용 재고 및 단가 조회
  call_distributor_api(mpn)                        # 실시간 시장 가용성 및 리드타임 조회
  send_approval_request(department, impact_report)  # 부서별 결재 라우팅
  query_part_standard(spec)                        # 사내 표준·AVL 내 충족 품목 검색 (시나리오 E)
  explode_bom_levels(item_id)                      # 다층 구조 전개 및 소요량 산출 (시나리오 F)
  get_price_breaks(mpn, qty)                       # 수량 구간별 단가·환율 기준 조회 (시나리오 G)
  query_lifecycle_status(mpn)                      # 라이프사이클·PCN·EOL 상태 조회 (시나리오 H)
  allocate_kit(work_order_id)                      # 작업지시별 자재 예약 및 CTB 판정 (시나리오 I)
  get_msl_profile(ipn, lot_no)                     # MSL 등급·플로어 라이프·데이트코드 조회 (시나리오 J)
  ```

#### AI Model Architecture의 필수 구현 사양

- **시맨틱 파서 (Semantic Layout Analyzer)**
  헤더 행이 비정형 위치에 있거나 다중 레벨로 병합된 셀이 존재하는 복잡한 엑셀 시트에서 RefDes, Part Name, Description, Package 필드를 **정확도 99% 이상**으로 구조화.

- **도메인 엔티티 추출 모델 (Hardware NER)**
  `0.1uF 50V 0603 X7R 10%`와 같은 단일 텍스트 문자열에서 `Capacitance=100nF`, `Voltage=50V`, `Size=0603`, `Dielectric=X7R`, `Tolerance=10%`를 독립 키-값 쌍으로 분해하는 정보 추출 성능 보장.

- **견적서 VLM(시각 언어 모델) 파이프라인**
  국내 유통상 및 해외 벤더가 보내온 각기 다른 레이아웃의 비정형 PDF 견적서 및 거래명세서 이미지에서 견적 일자, 유효 기간, 품목별 단가, 통화, MOQ를 환각 없이 추출하는 신뢰성 확보.

- **임베딩 및 유사도 랭커**
  엔지니어의 모호한 텍스트 쿼리와 사내 자재 마스터 DB 품목 간 시맨틱 거리를 계산하여 **상위 3개 부품 후보와 신뢰도 점수(Confidence Score)** 를 반환. 신뢰도 80% 미만이면 불확실성 플래그를 생성하여 본사 Agent가 사용자 확인을 유도할 수 있도록 지원.

> **정확도 기준 합의 노트** — '정확도 99% 이상' 같은 수치는 **측정 데이터셋과 판정 기준이 함께 정의되지 않으면 계약상 의미가 없다.** 협력사 선정 전에 사내 실제 BOM 샘플로 구성한 평가셋(골든셋)과 필드 단위 채점 규칙을 먼저 확정해야 한다.

| **EMS·턴키 위탁 이관** (사급 / 턴키 자재 소유권 분리) | 사내 생산 전제 | 외주 생산 도입, 또는 특정 모델의 위탁 전환 |
| **위조품 리스크 검증** (독립 유통·브로커 구매 건 진품 검증) | 개념은 국내 상가 조달 현실에 부합하나, 인용 가능한 규격([AS6081A](https://www.sae.org/pps/standards-news/q3-2023/foundational-sae-counterfeit-parts-standard-is-updated), IDEA-STD-1010)이 항공·방산 공급망 기준이어서 현 단계에 과잉 | 고신뢰 등급 제품 진입, 또는 위조품 사고 발생 |
| **로트 단위 추적성 역추적** (필드 이슈 시 영향 제품 범위 산출) | 시나리오 J의 5항으로 데이터 기반은 확보. 독립 시나리오로 분리할 만한 별도 판단 로직은 아직 없음 | 리콜·필드 클레임 프로세스 정식화 |
| **멀티레벨 BOM의 ERP 품목 마스터 양방향 동기화** | 시나리오 F는 전개·소요량 산출까지만 다룸. ERP 측 구조 마스터 갱신은 ERP 커스터마이징 범위 | ERP 연동 방식 확정 시 |

> 시나리오 개수를 채우기 위해 위 항목을 본문에 넣지 않았다. **적용 전제와 맞지 않는 시나리오는 문서의 신뢰도를 떨어뜨린다.**
