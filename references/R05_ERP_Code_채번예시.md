## 0. 요지

**세 줄 요지**

1. **사내 품번은 회사가 품목에 붙이는, 하나뿐이고 바뀌지 않는 이름이다.** 제조사 부품 번호(MPN)는 제조사가 정한 이름이라 표기가 흔들리고, 대체품이 생기면 여러 개가 되며, PCB·기구물·조립품처럼 MPN 자체가 없는 품목도 많다. ERP의 발주·입고·재고·원가·BOM 전개는 모두 사내 품번을 기준으로 돈다.
2. **사례 기업의 회로 자재 규칙은 `대분류 2자리 - 본체 9자리`, 12자 고정 길이의 의미 부여형 체계다.** 자리마다 사이즈·공차·전압·값 같은 사양이 들어가므로 코드만 보고 사양을 읽을 수 있다. 예를 들어 `12-155710400`은 1005 사이즈, ±10%, 50V, 100nF MLCC다.
3. **실데이터 349개 품번을 전수 검증한 결과 형식은 100% 지켜졌고, 저항·커패시터 값 자리는 160개 중 156개가 맞았다.** 문제는 두 곳에서 생겼다. 규정이 다루지 않는 영역에서 사람마다 다른 확장이 생겼고, 틀린 설명 문자열이 그대로 코드로 굳었다. 그래서 에이전트의 일은 번호를 새로 지어내는 것이 아니다. **규칙대로 만들고, 기존 번호를 감사하고, 규칙의 빈칸은 사람에게 올리는 것**이다.

**검증 결과 한눈에 보기** (상세는 [5장](#5-실데이터-검증--3개-파일))

| 항목 | 결과 |
|---|---|
| 검증 대상 | 고유 품번 349개 (부품 347, 제품·반제품 2) |
| 형식 (`NN-` + 영숫자 9자, 12자 고정) | 부품 347/347 준수. 다만 금지 문자(I) 사용 1건 |
| 값 자리 정합 | 저항 78/82, 커패시터 78/78 |
| 코드와 규격의 불일치 | 17건 (부품의 4.9%) — 값·공차·분류·등급·위치 |
| 규정 밖 확장 | 미정의 대분류 2개, 문서화되지 않은 하위 체계 6종 이상 |
| 파일 간 일관성 | 재고↔ERP 규격 100% 일치, BOM↔ERP 수량 100% 일치, BOM 설명 문자열 충돌 5건 |
| 판정 | **규격화된 업체(유형 A)에 가깝다.** 다만 규정의 빈칸에서 부실 관리(유형 B)로 새는 지점이 보인다 |

## 1. ERP 코드는 왜 필요한가

### 1.1 용어

| 용어 | 정의 | 예 |
|---|---|---|
| **사내 품번** (ERP 코드, Part No, Item Code, IPN) | 회사가 품목에 부여하는 고유 식별자. ERP 품목 마스터의 기본 키 | `10-151100200` |
| **MPN** (Manufacturer Part Number) | 제조사가 붙인 부품 번호. 포장·등급 접미사까지 포함하면 주문 번호가 된다 | `AC0402FR-0710KL` (YAGEO) |
| **SPN** (Supplier Part Number) | 유통사가 붙인 주문 번호 | 유통사 카탈로그 번호 |
| **AVL / AML** | 한 사내 품번에 대해 사용이 승인된 제조사·MPN 목록 | 같은 사양 SPI NOR의 ISSI·ESMT 제품 |
| **채번 (발번)** | 규칙에 따라 새 품번을 만들어 부여하는 일 | 신규 부품 등록 시 수행 |
| **품목 마스터** | 품번과 품명·규격·제조사·단위 같은 속성을 담은 ERP 테이블 | 재고 현황·물류 BOM이 참조 |

이 문서에서 **ERP 코드·사내 품번·품번은 같은 뜻**이다. 지향점 문서의 `Internal_PN`(IPN)도 같은 대상을 가리킨다.

세 번호의 관계는 다음과 같다. 사내 품번 하나에 승인된 MPN이 여러 개 붙을 수 있고, MPN 하나는 여러 유통사에서 살 수 있다([InvenTree](https://github.com/inventree/InvenTree/issues/1389), [Z2Data](https://www.z2data.com/products/part-risk-manager/features/ipn-internal-part-number-search/)).

```text
사내 품번 (회사가 정의하는 품목)
  ├─ MPN 1 (제조사 A)  ──  SPN (유통사 X), SPN (유통사 Y)
  └─ MPN 2 (제조사 B)  ──  SPN (유통사 Z)
```

### 1.2 MPN만으로는 왜 부족한가

| # | 이유 | 실데이터에서 본 모습 |
|---|---|---|
| 1 | **같은 부품도 MPN 문자열이 흔들린다** | E51K 설계 BOM은 `PJQ5443-AU`, ERP 마스터는 `PJQ5443-AU_R2_000A1`로 적었다. 둘 다 `18-010544300`이라 같은 품목으로 묶였고, 덕분에 BOM과 ERP의 소요량이 309개 행 전부에서 일치했다 |
| 2 | **한 기능에 제조사가 여럿이다** | 16Mb SPI NOR 플래시는 ISSI(`20-411001600`)와 ESMT(`20-411001601`) 두 제품이 같은 사양으로 등록돼 있다 |
| 3 | **MPN이 없는 품목이 많다** | PCB(`30-102E51M11`), 커버·브래킷·나사, 라벨, FFC 케이블, 조립품(`MS01C0P1PP` SET-ASSY), 펌웨어 |
| 4 | **자유 텍스트는 중복을 만든다** | 품번 열이 없는 KK1 E-BOM에는 같은 100nF가 `100nF/25v/C1005`, `0.1uF/50v/C1005` 등 10가지 표기로 흩어져 있다([4.4](#44-규칙만으로-결정되지-않는-경계-사례)) |
| 5 | **ERP는 흔들리지 않는 키가 필요하다** | 발주서·입고·재고·원가·BOM 전개를 잇는 연결 키가 공백·대소문자·접미사에 따라 달라지면 집계가 깨진다 |
| 6 | **변경 이력의 기준점이 필요하다** | 품번이 기준이어야 개정·대체·단종 이력이 한 품목에 쌓인다. 품번이 바뀌면 이력이 끊긴다 |

### 1.3 좋은 품번의 조건

| 원칙 | 내용 | 사례 기업 규칙의 대응 |
|---|---|---|
| **유일성** | 1품번 = 1품목, 1품목 = 1품번 | 파일 안 중복 품번 0건 (5장) |
| **불변성** | 한 번 부여한 번호는 바꾸지 않고 재사용하지 않는다 | 문서에 명시 없음 |
| **고정 길이** | 길이가 같아야 누락·잘림이 눈에 띄고 정렬이 안정된다([PDXpert](https://www.buyplm.com/plm-good-practice/part-numbering-system-software.aspx), [mbedded.ninja](https://blog.mbedded.ninja/electronics/general/a-sensible-part-numbering-scheme-for-electronic-components/)) | 12자 고정 |
| **혼동 문자 배제** | 숫자와 헷갈리는 영문자를 쓰지 않는다([Clearly Inventory](https://clearlyinventory.com/resources/inventory-basics/how-to-design-good-item-numbers-for-products-in-inventory/)) | I·O·Z 제외 |
| **FFF 호환 기준** | 형상·결합·기능(Form·Fit·Function)이 같으면 같은 품번, 호환되지 않으면 새 품번([Aligni](https://docs.aligni.com/guides/form-fit-function/), [OpenBOM](https://www.openbom.com/blog/interchangeable-parts-new-part-number-or-revision)) | 기구물·PCB의 버전 자리(XY) |
| **설명과의 일치** | 의미 부여형이면 코드와 규격 설명이 어긋나지 않아야 한다 | 5장 검증 대상 |
| **발번 권한 단일화** | 누가 어떤 절차로 번호를 내는지 정해져 있어야 한다 | 문서에 명시 없음 |
| **확장 여유** | 새 분류를 끼워 넣을 자리가 있어야 한다 | 대분류를 짝수 간격으로 배치 |

### 1.4 두 가지 설계 철학

| | 의미 부여형 (Intelligent / Significant) | 무의미 일련번호형 (Non-significant) |
|---|---|---|
| 형태 | 자리마다 사양·분류의 의미가 있다 | 순번만 있고 의미는 품목 속성에 둔다 |
| 장점 | 코드만 보고 사양을 안다. 현장에서 읽기 쉽다. 같은 사양의 중복 등록이 눈에 띈다 | 규칙 유지 비용이 없다. 분류가 바뀌어도 깨지지 않는다. 입력 오류가 적다 |
| 약점 | 분류를 추가할 때마다 규칙을 고쳐야 한다. 자리가 모자라면 깨진다. 설명이 틀리면 코드도 틀린다 | 사람이 읽을 수 없다. 품목 마스터와 검색 품질에 전적으로 의존한다 |
| 전제 조건 | 규칙 문서와 주기적 감사 | 정돈된 품목 마스터와 검색 기능 |

의미 부여형은 분류가 늘 때마다 규칙을 손봐야 하는 유지 비용이 단점으로 꼽힌다([OpenBOM](https://www.openbom.com/blog/part-numbers-intelligent-or-just-numbers)). PLM 업계에서는 순차적 무의미 번호를 더 나은 관행으로 보는 시각이 있고([PDXpert](https://www.buyplm.com/plm-good-practice/part-numbering-system-software.aspx)), AI 시대에는 번호를 단순하게 두고 분류·공급사·개정 정보를 연결된 데이터로 옮기라는 권고도 나온다([OpenBOM](https://www.openbom.com/blog/design-part-numbering-ai-era)). 반대로 의미 부여형은 오류와 중복 등록을 줄인다는 주장도 있다([Duro](https://durolabs.co/blog/part-numbering-schemes/)).

**[판단] 에이전트는 두 체계를 모두 다룰 수 있어야 한다.** 이미 의미 부여형을 쓰는 회사가 많고, 수천 개 품목이 쌓인 뒤 체계를 바꾸는 일은 비용이 크고 혼란스럽다([OpenBOM](https://www.openbom.com/blog/part-numbers-best-practices-and-future-improvements)). 의미 부여형 회사에서 에이전트는 **규칙의 집행자이자 감사자**가 되고, 무의미형 회사에서는 **품목 속성 마스터의 관리자**가 된다. 어느 쪽이든 기존 번호는 보존하고, 새 규칙은 신규 품목부터 적용한다([OpenBOM](https://www.openbom.com/blog/design-part-numbering-ai-era)).

## 2. 사례 — 회로 자재 채번 규칙

사례 기업은 2022년에 회로 자재(v1.0)와 기구물(v1.0) 채번 규칙을 각각 문서로 만들었다. 이 장은 회로 자재 규칙을 상세히 정리한다. 원본은 엑셀 규정표 1장과 시각화 슬라이드 5장이다.

### 2.1 목적과 구조

**[규정] 목적** · 회사 고유의 PART NO 체계를 만들어 프로젝트별로 쓰이는 부품·원자재·제품을 효율적으로 관리한다.

**[규정] 적용 범위**

- 신규 제품 개발 중 BOM 등록
- ERP 등 전산을 통한 자재 구매, 재고 관리, 자산 관리
- 프로젝트 단계별 샘플, 양산 현장의 반제품·완제품 관리

**전체 구조** · 모든 회로 자재 품번은 같은 틀을 쓴다. 앞 2자리가 대분류이고, 하이픈 뒤 9자리의 자리 배분은 대분류마다 다르다.

```text
 ┌────┬────┐   ┌────┬────┬────┬────┬────┬────┬────┬────┬────┐
 │ D1 │ D2 │ - │ D3 │ D4 │ D5 │ D6 │ D7 │ D8 │ D9 │ D10│ D11│
 └────┴────┘   └────┴────┴────┴────┴────┴────┴────┴────┴────┘
    CLASS                         BODY                 SUFFIX
```

- 총 12자 = 숫자·영문 11자리 + 하이픈 1개
- D1~D2 대분류, D3~D9 분류별 속성 또는 일련번호, D10~D11 접미(제조사 또는 버전)

> **자리 번호 주의** · 원본 회로 슬라이드는 끝 두 자리를 "Digit 11~12"로 적었다(하이픈을 한 자리로 셈). 기구물 슬라이드는 같은 자리를 "Digit 10~11"로 적었다. 이 문서는 하이픈을 빼고 D1~D11로 통일한다.

### 2.2 공통 표기 규칙

**[규정]**

1. 숫자 표기를 우선하고, 자리 수를 넘으면 영문자를 섞어 쓴다.
2. 2자리 필드는 `01~99`를 다 쓰면 `A1, A2 … A9`, 그다음 `B1 …`로 이어 가며 `Y9`까지 쓴다.
3. 3자리 필드는 `001~999`를 다 쓰면 `A01~A99`로 이어 가며 `Y99`까지 쓴다.
4. 숫자와 헷갈리는 **I, O, Z는 쓰지 않는다** (1, 0, 2와 혼동).

**[관측]** 실무에서는 일련번호 확장 외에도 영문자를 쓴다. 저항 값의 소수점 `R`(`01R0` = 1Ω), 인덕턴스 값의 소수점 `N`(`04N7` = 4.7nH), FAKRA 커넥터 코딩 문자(`A0`), MPN에서 따온 문자(`6155P`, `1G08`)가 그 예다.

### 2.3 대분류 코드표

```yaml
                "±10%": "5", "±20%": "6", "±25~30%": "7"}
    observed_layouts:
      chip:  "14-SS T VVVV NN   (nH, N=소수점)"
      bead:  "14-6 SS T VVV NN  (Ω, 유효숫자2 + 승수)"
      power: "14-7 SS T VVV NN  (nH 기준 유효숫자2 + 승수, 대형은 SS=9X)"
```

### 2.8 규정 문서에 남아 있는 모호점과 오류

규정을 기계 판독용으로 옮기는 과정에서 확인한 문제다. 에이전트가 규정을 그대로 믿고 집행하면 아래 지점에서 사람과 다른 답을 낸다. **규정 개정 시 먼저 정리해야 할 목록**이다.

| # | 위치 | 내용 | 실무에 생긴 일 |
|---|---|---|---|
| 1 | 회로 슬라이드 전체 | 끝 두 자리를 "Digit 11~12"로 표기 (기구물은 10~11) | 자리 번호가 문서마다 다르다 |
| 2 | 슬라이드 "그 이외" | "Digit 5~9: 공차"와 "Digit 6~9: 고유번호"가 겹친다 | 색 상자와 엑셀 규정표로 보면 D5~D9가 일련번호다. 앞 문장은 복사 잔재로 보인다 |
| 3 | 엑셀 `17` Clock | `X·X·X·XXXXX·XX` = 본체 10자리로 한 자리 초과 | 실무는 주파수를 4자리로 쓴다 |
| 4 | 엑셀 `30` PCB vs 슬라이드 | 자리 배분이 서로 다르다 (2.5 참조) | 실무는 엑셀 쪽을 따른다 |
| 5 | 인덕터 `6X·7X·8X`, 커패시터 `8X` | X의 의미가 없다 | 비드·파워는 사이즈 2자리, 전해는 지름, 대형 파워는 `9X`를 사람이 정해 썼다 |
| 6 | 공차 표 | 인덕터 ±2%(G), 커패시터 ±1%·±2%, 저항 ±0.1%·±0.25%·±2%가 없다 | ±2% 인덕터 4개가 ±3% 코드 `3`으로 등록됐다 |
| 7 | 커패시터 전압 | "50V~"와 "100V~"가 범위로만 적혀 경계가 모호하다 | 63V는 `7`, 100V는 `8`, 250V는 `9`(Others)로 처리됐다 |
| 8 | `18` 헤더 | "TR, Diode, Crystal, Module"이라 적었지만 Crystal은 `17`, 모듈은 `26`에 있다 | 분류 판단이 사람마다 갈릴 여지 |
| 9 | `22` IC 세부 코드 | `10, 11, 22, 33, 99`로 비연속. LED 드라이버·전압 감시·인증 칩·영상 디코더 칸이 없다 | 비슷한 품목이 서로 다른 칸에 들어갔다 (5.4) |
| 10 | `20` Memory 용량 | 단위가 없다 | LPDDR4X `0004`는 GB, SPI NOR `0016`은 Mb다 |
| 11 | `24` CPU `04`, `38` Harness `02` | 코드만 있고 명칭이 없다 | 미사용 |
| 12 | 대분류 전체 | 펌웨어·소프트웨어, 라벨·인쇄물, 포장재, 공정 부자재의 자리가 없다 | 라벨에 `84`, 소음 방지 패드에 `86`이 규정 없이 쓰였다 |
| 13 | 끝 2자리 | "Vendor"라고만 적었고 제조사별 코드표가 없다 | 같은 자리가 제조사·충돌 구분·버전·커넥터 키·펌웨어 변형 다섯 가지로 쓰인다 (5.6) |

> 오탈자(Alumnium, Capasitor, INVETOR 등)도 있으나 해석에는 영향이 없다.

## 3. 기구물 — 회로 밖 부품에도 같은 체계가 필요하다

이번 Phase는 회로 자재를 깊이 다룬다. 다만 **품번 부여 체계는 회로 부품에만 필요한 것이 아니다.** BOM에는 기구물, 부자재, 조립품이 회로 부품과 같은 표에 섞여 있고 ERP는 이들을 같은 품목 마스터로 관리한다. 어느 한 갈래에 규칙이 없으면, 그 갈래는 사람이 그때그때 번호를 지어 붙인다.

### 3.1 BOM 안의 회로 밖 품목

E51K 완제품(`MS01C0P1PP`, SET-ASSY) 바로 아래 19개 품목 중 회로 PCBA(`MS01C0P1SM`)를 뺀 대부분이 기구·부자재다.

| 품번 | 품목 | 대분류 |
|---|---|---|
| `62-020100110`, `62-020200200` | 앞·뒤 커버 (PC-ABS 사출) | 62 Cover |
| `72-030500100` 외 2 | 브래킷 좌·우·하 (Al 압출) | 72 Bracket |
| `74-050500100` | 메인 플레이트 (ALDC12 다이캐스트) | 74 Plate |
| `66-050501200` 외 3 | 나사 (SEMS·머신·태핑) | 66 Screw·Bolt |
| `78-050100100`, `78-050100200` | 캡톤 테이프 | 78 Protective Tape |
| `82-020300100`, `82-020300200` | 써멀 패드 | 82 Absorber |
| `84-010E51K00` | 제품 라벨 | **84 — 규정에 없음** |
| `86-040100100` | 소음 방지 패드 | **86 — 규정에 없음** |
| `38-010501020`, `40-010128000` | FFC 케이블, LCD | 38 Harness, 40 LCD |

E51K BOM 310행 중 기구·부자재가 18행이다. 행 수는 적지만 이 품목들이 빠지면 완제품을 조립할 수 없다. 그리고 규칙이 없는 라벨과 소음 방지 패드에는 규정에 없는 대분류 `84`, `86`이 붙었다.

### 3.2 기구물 채번 규칙 요약

```text
 🟥🟥 - 🟩🟩 🟦🟦 🟨🟨🟨 🟪🟪
 C C  -  M M  S S  U U U  X Y
 대분류  중분류 소분류 고유번호 버전
```

| 자리 | 의미 [규정] |
|---|---|
| D1~D2 | 제품군 (Cover, Bolt, Nut, Bracket 등) |
| D3~D4 | 외관 특성에 따른 중분류 (재질, 색상, 외형) |
| D5~D6 | 규격·목적에 따른 소분류 (규격, 장착 위치, 적용 목적) |
| D7~D9 | 제품군 안의 고유번호 `001~999` |
| D10~D11 | 버전 `01~99`. Minor 개정은 Y, Major 개정은 X를 올리고 Y를 0으로 되돌린다 |

| 대분류 | 중분류 예 (D3~D4) | 소분류 예 (D5~D6) |
|---|---|---|
| `62` Cover, `64` Housing | ABS `01` · PC-ABS `02` · PMMA `03` · PP `04` · Al `05` | Front `01` · Rear `02` · Left `03` · Right `04` · Inner `05` |
| `66` Screw·Bolt | 둥근머리 `01` · 접시머리 `02` · 평나사 `03` · 무두볼트 `04` | M1 `01` ~ M5 `05` |
| `68` Nut | 육각 `01` · 캡 `02` · 플랜지 `03` · 웰드 `04` | M1 `01` ~ M5 `05` |
| `70` Frame, `72` Bracket, `74` Plate | Steel `01` · SUS `02` · Al `03` · ABS `04` · SECC `05` | Front `01` · Rear `02` · Left `03` · Right `04` · Inner `05` |
| `76` Adhesive | 흑색 `01` · 백색 `02` · 황색 `03` · 투명 `04` · 반투명 `05` | 제품 고정 `01` · 방수방진 `02` |
| `78` Protective Tape | 투명 `01` · 불투명 `02` · 폼 `03` · 직물 `04` | 단면 `01` · 양면 `02` |
| `80` Gasket | 실리콘 `01` · 고무 `02` · 직물 `03` · Steel `04` · Al `05` | 방수방진 `01` · EMI `02` |
| `82` Absorber | 스폰지 `01` · 실리콘 `02` · 고무 `03` | 진동 방지 `01` · 방수방진 `02` · 방열 `03` |

**회로 규칙과 다른 점**

- **끝 2자리가 제조사가 아니라 버전이다.** 기구물은 대부분 사내 도면으로 만드는 주문 제작품이라 제조사보다 도면 개정이 더 중요하다.
- **사양 대신 재질·위치·목적을 담는다.** 저항처럼 값 하나로 정의되지 않기 때문이다.
- **[관측] 고유번호 자리에 치수를 넣기도 한다.** `66-050501200`(SEMS M5×12)의 `012`는 길이 12mm다.

> **[판단] 버전을 품번 안에 둘 때의 주의** · 품번 안에 개정 정보를 넣지 말라는 권고가 있다([OpenBOM](https://www.openbom.com/blog/interchangeable-parts-new-part-number-or-revision)). 이 규칙처럼 버전이 품번에 들어 있으면 **개정할 때마다 새 품번이 생긴다.** 그래서 FFF 호환 개정(구·신 부품을 섞어 써도 되는 개정)까지 새 품번으로 만들면 재고가 불필요하게 갈린다. 개정할 때 FFF 호환 여부를 먼저 판정하고, 호환이면 ERP의 리비전 속성으로 처리할지 회사 정책으로 정해 둬야 한다.

### 3.3 제품·반제품 품번 — 채번 규칙의 적용 범위 밖

| 품번 | 품목 | 형식 |
|---|---|---|
| `MS01C0P1PP` | SET-ASSY, E51K IVI-E (완제품) | 10자, 하이픈 없음 |
| `MS01C0P1SM` | PCB-ASSY, MAIN, SMT, E51K IVI-E (반제품) | 10자, 하이픈 없음 |

**제품·반제품 품번에는 별도의 채번 규칙이 없다**(사례 기업 확인). 이들은 구매해서 관리하는 부품이 아니라 회사가 직접 만드는 자체 양산품이다. 따라서 제품·반제품 품번은 이 문서가 다루는 ERP 코드 채번 규칙(회로 자재·기구물)의 **적용 범위 밖**이다. 형식이 부품 품번과 다른 것도 이 때문이다. 5장 검증에서도 제품·반제품 2개는 형식·자리 검사 대상에서 제외했다.

**[판단] 에이전트는 제품·반제품 품번을 부품 채번 규칙으로 해독하거나 형식 위반으로 판정하지 않는다.** 대분류 코드표에 없다는 이유로 오류를 올리거나, 부품 규칙에 맞춰 새 번호를 제안하는 것도 하지 않는다.

### 3.4 아직 규칙이 없는 품목군

| 품목군 | 왜 품번이 필요한가 | 현재 상태 |
|---|---|---|
| 펌웨어·소프트웨어 | 하드웨어가 같아도 펌웨어 개정이 다르면 다른 완성품이 된다(M-BOM 시나리오 A10) | 대분류 없음. LTE 모듈은 펌웨어 변형을 끝 2자리(`10`·`20`)로 구분했다 |
| 라벨·인쇄물 | 인증 마크·정격 표시가 지역마다 다르다 | `84` 무규정 사용 |
| 포장재 | 포장 단위·지역 변형 관리 | 사례 없음 |
| 공정 부자재 | 솔더 페이스트·언더필·접착제 | `76` Adhesive만 있음 |
| 소음·완충 부자재 | 기구 조립 품질 | `86` 무규정 사용 |

### 4.1 채번 절차

```text
[1] 품목 정체성 확정   MPN, 제조사, 데이터시트 사양을 먼저 확정한다
[2] 대분류 판정        무엇인가: 저항, 비드, 커넥터, LDO ...
[3] 속성 추출          사이즈, 공차, 전압, 값, 종류, 방향
[4] 자리 코드 변환     규정 코드표로 본체 D3~D9를 만든다
[5] 충돌 검사          같은 본체(D1~D9)가 이미 있는가
```

### 4.4 규칙만으로 결정되지 않는 경계 사례

**① 코드에 담기지 않는 속성이 다를 때** · 저항 코드는 사이즈·공차·값만 담는다. 저항 구조(후막·금속판), 온도계수(TCR), 정격 전력은 코드에 없다. 그래서 0.1Ω 3216 ±1% 저항 두 개가 같은 본체를 갖는다.

### 5.6 끝 2자리의 다중 용도

규정은 끝 2자리를 "Vendor"(회로)·"Version"(PCB·기구)으로 정했다. 실데이터에서는 부품 347개 중 **321개(92.5%)가 `00`**이고, 나머지 26개가 다섯 가지 이상의 용도로 쓰였다.

| 용도 | 사례 | 건수 |
|---|---|---|
| 같은 사양의 다른 제조사 (규정 의도대로) | `20-411001601` ESMT (ISSI는 `00`) | 1 |
| 제조사로 보이지만 코드표가 없음 | 시계: TXC `01`(4건)·`05`(1건), KDS `03`, TI `04` / 저항: Panasonic `02` / 메모리: SK hynix `01` | 9 |
| 같은 본체의 충돌 구분 | `10-31100R101`(전류 감지 금속막), `14-797633210`(다른 제조사 3.3µH) | 2 |
| 커넥터 결합 키 | FAKRA·HSD `A0`(2), `B0`, `C0`, `D0`, `K0` | 6 |
| 커넥터 기타 | `16-512800510` (USB-C, `10`) | 1 |
| 펌웨어·사양 변형 | LTE 모듈 `10`·`20`, FFC 케이블 `10`·`20` | 4 |
| 버전 | PCB `30-102E51M11`(V1.1), 커버 `62-020100110`(V1.0) | 2 |
| 금지 문자 | `18-0500132I0` | 1 |

**드러난 문제**

- **제조사 코드표가 없다.** TXC가 크리스털에서는 `01`, 발진기에서는 `05`다. 같은 자리를 다른 사람이 다른 뜻으로 썼다.
- **반대로 이 자리가 결측 데이터를 복원하는 단서가 되기도 한다.** `17-122024001`은 재고 현황의 제조사가 `#N/A`지만, 접미 `01`과 MPN 접두 `AY`가 같은 계열의 TXC 품목과 일치한다. 다만 이것은 추정이므로 확정은 MPN 조회로 한다.

**[판단] 끝 2자리 정책을 하나로 정해야 한다.**

| 선택지 | 내용 | 장단점 |
|---|---|---|
| ① 규정대로 제조사 코드 | 제조사 코드표를 만들고 끝 2자리에 넣는다 | 규정과 일치. 대신 2nd source가 생길 때마다 새 품번이 생기고, BOM은 여러 품번 중 하나를 골라 적어야 한다 |
| ② 본체 안 순번으로 재정의 | 끝 2자리는 "같은 본체 안에서 구분이 필요할 때 쓰는 순번"으로 정의하고, 제조사는 AVL 속성으로 뺀다 | 지금의 실무(92.5%가 `00`)와 맞는다. FFF가 같은 제조사 제품은 한 품번 아래 AVL로 묶는다 |

업계에서는 사내 품번 하나에 여러 승인 제조사 품번을 매다는 AVL 구조가 일반적이다([Z2Data](https://www.z2data.com/products/part-risk-manager/features/ipn-internal-part-number-search/), [Oracle AML](https://docs.oracle.com/en/cloud/saas/supply-chain-management/20a/faupd/approved-manufacturers-list.html)). 다음 5.7의 1번 문제는 사례 기업에 이 구조가 없어서 생긴 증상이다. 이 문서는 **②를 권고**한다. 결정은 회사가 한다.

### 5.8 판정 — 이 업체는 어느 유형인가

**유형 A(규격화된 업체)의 특징을 갖추고 있다.** 규칙이 문서로 있고, 형식 준수 100%, 값 자리 정합 97.5%, 품목 마스터가 단일 원본이며, 설계 BOM과 ERP가 동기화돼 있다.

**동시에 유형 B(부실 관리)로 새는 지점이 네 곳 있다.**

1. 규정의 빈칸(초크, 대형 인덕터, 라벨, 공차 G)이 문서 대신 구두 관행으로 메워졌다.
2. 끝 2자리의 의미가 사람마다 다르다.
3. 틀린 설명이 코드로 굳었다.
4. 대체 품목 구조(AVL)가 없어 품명 칸에 대체품을 적는다.

| 1 | 다른 사양의 자리를 차지한 4건(5.4의 1·2·4·5번) 재채번 검토 | 신규 등록 때 충돌이 확실히 생긴다 |

## 6. 업체 유형별 에이전트 접근 시나리오

같은 에이전트라도 회사의 품번 관리 수준에 따라 할 일이 다르다. 규칙이 정돈된 회사에 새 체계를 제안하면 혼란만 생긴다. 규칙이 없는 회사에서 규칙 집행부터 하려 하면 집행할 대상이 없다. 그래서 **먼저 유형을 판정하고, 유형에 맞는 역할을 맡는다.**

| | 유형 A · 규격화된 업체 | 유형 B · 규정은 있으나 부실한 업체 | 유형 C · 자체 품번 관리가 없는 업체 |
|---|---|---|---|
| 모습 | 규정 문서가 있고 실데이터가 대체로 따른다 | 규정 문서는 있지만 오래됐거나 실무와 어긋난다. 담당자마다 확장 방식이 다르다 | 품번 열이 없거나, MPN·거래처 품번을 품번처럼 쓴다 |
| 에이전트 역할 | **집행자·감사자** | **진단자·정리자** | **설계 조력자·초기 구축자** |
| 첫 산출물 | 기계 판독용 규칙 스키마 | 규정–실무 격차 리포트 | 정규화된 품목 속성 목록 |
| 가장 큰 위험 | 규칙의 빈칸을 에이전트가 임의로 메운다 | 대량 재채번으로 발주·재고·도면의 연결이 끊긴다 | 체계를 에이전트가 정해 버린다 |
| 이 문서의 사례 | 사례 기업 회로 자재 (5장) | 사례 기업의 규정 공백 영역 (5.5·5.6) | KK1~KK6 E-BOM (품번 열 없음) |

**판정은 회사 단위가 아니라 품목군 단위로 한다.** 사례 기업도 회로 자재는 유형 A에 가깝지만, 라벨·소음 방지 패드는 문서화된 규칙이 없어 유형 C에 가깝다(3.4). 제품·반제품 품번은 부품이 아니라 자체 양산품의 코드라 이 판정의 대상이 아니다(3.3).

### 6.1 유형 판정 신호

| 신호 | 측정 방법 | 유형 A | 유형 B | 유형 C | 사례 기업 회로 자재 |
|---|---|---|---|---|---|
| 규정 문서 | 존재 여부, 개정 이력, 적용 범위 | 있음, 개정 관리 | 있음, 개정 없음 또는 범위 부족 | 없음 | 있음 (2022, v1.0) |
| 형식 준수율 | 품번 길이·패턴 분포 (정규식) | 99% 이상 | 패턴 여러 개 혼재 | 측정 대상 없음 | 100% |
| 해독 정합률 | 품번 해독 결과와 규격 문자열 대조 (의미 부여형만) | 95% 이상 | 90% 미만 | 해당 없음 | 95.1% (불일치 17/347) |
| 1품목 1품번 | 같은 MPN에 품번 여럿, 품명에 MPN 병기 | 드묾 | 반복됨 | 같은 부품이 표기마다 갈림 | 품명 병기 2건 |
| 자유 텍스트 의존 | 품명·규격 칸의 상태 문구·대체품·메모 | 드묾 | 흔함 | 품목 식별 자체가 자유 텍스트 | 상태 문구 1건 |
| 발번 창구 | 누가 품번을 내는가 | 단일 창구 | 여러 명 또는 불명 | 없음 | 문서에 명시 없음 |

> 기준값(99%, 95%, 90%)은 이 문서의 제안이며 업계 표준이 아니다. 회사마다 기준선을 먼저 재고 조정한다.

### 6.2 유형 A — 규격화된 업체: 규칙의 집행자이자 감사자

**목표** · 규칙이 쓰인 그대로 지켜지게 한다. 규칙 자체는 바꾸지 않는다.

**절차**

1. **규정을 기계 판독용 스키마로 옮긴다.** 2.7의 YAML이 그 예다. 옮기면서 나온 모호점은 목록으로 만들어 사람에게 확인받는다(2.8). 확정한 스키마에는 버전을 붙여 고정한다. 스키마가 바뀌면 같은 입력에서 다른 품번이 나올 수 있기 때문이다.
2. **기준선을 잰다.** 스키마로 기존 마스터 전체를 해독해 정합률을 측정한다. 이 단계는 스키마가 실무를 제대로 설명하는지 확인하는 과정이기도 하다. 불일치가 흩어져 있으면 데이터가 틀린 것이고, 같은 방식으로 몰려 있으면 스키마가 틀린 것이다. 5.5의 비드·파워 인덕터 37건은 모두 같은 방식으로 규정과 달랐다. 고칠 대상은 데이터가 아니라 스키마였다.
3. **신규 품번은 결정적으로 만든다.** 4.1의 8단계를 따른다. 같은 입력에는 언제나 같은 품번이 나와야 한다. 모델은 [1]~[3](MPN 해석, 분류 판정, 속성 추출)에 쓰고, [4]~[7](자리 코드 변환, 충돌·형식 검사)은 규칙 엔진이 처리한다. 자리 코드 변환을 모델이 생성하면 33Ω을 `3300`으로 쓰는 류의 자릿수 착오(5.4의 1·2번)를 그대로 재현할 수 있다.
4. **충돌은 우회하지 않고 올린다.** 규칙대로 만든 번호가 이미 쓰이고 있으면, 기존 품목이 정말 같은 사양인지부터 확인한다. 아래 워크스루가 그 예다.
5. **정기 감사를 돌린다.** 신규 등록분은 매 건, 전체 마스터는 주기적으로 형식·해독 정합·중복·금지 문자·미정의 코드를 검사한다(7.3 룰북).
6. **규정의 빈칸은 개정 제안으로만 다룬다.** 코드표에 칸이 없는 품목을 가장 가까운 칸에 끼워 넣지 않는다. 5.4의 판단 사례(영상 디코더를 `11` LVDS/DP에, LED 드라이버를 `02` DC-DC에 넣은 것)가 그렇게 생겼다. 후보 코드(`99` Others 또는 신규 세부 코드)와 근거를 올리고, 결정되면 규정 개정 이력에 남긴다.

규칙만 보면 `12-155347500`이 이미 있으니 "등록된 품목"으로 처리하거나 접미를 `01`로 올리면 끝난다. 둘 다 틀린 처리다. 앞의 것은 ±20% 부품과 ±10% 부품을 한 품목으로 섞고, 뒤의 것은 ±10%로 해독되는 번호 두 개 중 하나가 실제로는 ±20%인 상태를 굳힌다. 에이전트는 아래처럼 선택지를 만들어 올린다.

```yaml
request:
  mpn: CL05A475KP5NRNC
  decoded_spec: {class: "12", size: "1005", tolerance: "±10%", voltage: "10V", value: "4.7µF"}
  expected_ipn: "12-155347500"
conflict:
  existing_ipn: "12-155347500"
  existing_mpn: GRT155R61A475ME13
  existing_spec: "1005 ±20% 10V 4.7µF"
  existing_decoded: "1005 ±10% 10V 4.7µF"
  finding: "기존 품목 공차 자리 오류"
rule: RB-PN-03        # 등급 H
options:
  - id: 1
    action: "흡수 — 회로가 ±20%를 허용하면 기존 품목을 그대로 쓰고 신규 등록하지 않는다"
    check: "회로 설계 공차 요구, 차량용 등급 등 코드에 없는 속성"
  - id: 2
    action: "기존 품목 정정 — GRT155R61A475ME13에 12-156347500 신규 발번, 12-155347500은 Superseded 처리 후 재고·BOM·미결 발주 이관. 신규 부품은 12-155347501"
    cost: "재고 이관, BOM 개정, 협력사 통보"
  - id: 3
    action: "기존 품목 유지 — 12-155347500을 예외표에 등록(실제 ±20%), 신규 부품은 12-155347501"
    cost: "해독 시 예외표를 항상 먼저 조회해야 한다"
confidence: 0.95
provenance: ["ERP 품목 마스터 규격", "제조사 데이터시트", "채번 규칙 v1.0"]
approver: "구매·R&D"
```

**선택지 1이 가장 먼저다.** 지향점 시나리오 E는 신규 등록 전에 기존 표준 품목으로 흡수할 수 있는지부터 본다. 흡수할 수 없을 때만 2와 3 중에서 고른다. 어느 경우든 **`12-155347500`을 ±10% 신규 부품에 다시 쓰는 선택지는 없다.** 이미 발주·입고 이력이 ±20% 부품에 쌓인 번호이기 때문이다.

**유형 A에서 에이전트가 하지 않는 일**

- 규정에 없는 대분류·세부 코드를 만들어 쓰지 않는다.
- 사람 승인 없이 접미를 올려 충돌을 피하지 않는다.
- 체계 전환(예: 무의미 순번형으로 바꾸기)을 먼저 제안하지 않는다. 잘 돌아가는 체계를 바꾸는 비용이 더 크다.

### 6.3 유형 B — 규정은 있으나 부실한 업체: 진단자이자 정리자

**목표** · 실제로 쓰이는 규칙을 찾아 문서로 되돌리고, 위험한 오류만 골라 고친다. 전부 고치려 하지 않는다.

**흔한 모습** (가상 예)

- 시기마다 형식이 다르다. `R1005-10K`, `RES-0001`, `10-151100200`이 한 마스터에 섞여 있다.
- 같은 부품에 품번이 둘이거나, 품번 하나의 품명에 부품 둘이 적혀 있다.
- 품명 칸에 "미사용", "대체품 있음", "단종 예정" 같은 메모가 들어 있다.
- 규정 문서의 개정일이 수년 전이고, 그 뒤에 생긴 품목군은 담당자가 알아서 번호를 붙였다.

**절차**

1. **전수 프로파일링.** 품번 길이·패턴 분포, 대분류 분포, 해독 정합률, 중복 후보를 잰다. 5.2가 그 결과표의 예다.
2. **실무 규칙을 역추론한다.** 반복되는 패턴을 규칙 후보로 뽑고 **지지 건수와 반례 건수**를 붙인다. 지지가 적은 후보는 규칙으로 올리지 않고 "해석 불확실"로 남긴다.
3. **규정–실무 격차 리포트를 만든다.** 세 칸으로 나눈다. 규정에만 있는 것(안 쓰이는 규칙), 실무에만 있는 것(문서 밖 확장), 둘 다 있지만 다른 것.
4. **불일치를 처리 경로별로 나눈다.** 아래 표의 네 경로 중 하나로 분류한다.
5. **중복·대체 관계를 연결한다.** 병합하지 않고 연결한다.
6. **우선순위를 정한다.** 위험도와 사용 범위(재고, 미결 발주, 사용하는 BOM 수)를 곱해 순서를 정한다.
7. **레거시는 보존한다.** 고쳐야 하는 건만 신규 발번 후 상호 참조로 잇는다.

**2단계 예 — 사례 기업 데이터에서 역추론한 규칙 후보**

| 규칙 후보 | 지지 | 반례 | 판정 |
|---|---|---|---|
| 비드 `14-6 SS T VVV NN` | 13 | 0 | 문서화 후보 |
| 파워 인덕터 `14-7 SS T VVV NN` (대형 `9X` 12건 포함) | 24 | 0 | 문서화 후보. `9X` 구간 경계 치수는 정의 필요 |
| 전해 커패시터 사이즈 = 지름 (`86`·`88`·`89`) | 7 | 0 | 문서화 후보 |
| 공통모드 초크 D6 = 용도 (신호 `1`, CAN `2`) | 3 | — | **지지 부족.** 담당자 확인 전에는 규칙으로 쓰지 않는다 |
| 0Ω 값 표기 | — | `0R00`과 `0000` 공존 | 표기를 하나로 정해야 한다 |
| 끝 2자리 = 제조사 | 10 | 14 (충돌 구분·커넥터 키·펌웨어 변형 등) | **규칙으로 성립하지 않는다.** 정책 결정이 먼저다 (5.6) |

끝 2자리 행의 건수는 PCB·기구 버전 2건을 뺀 부품 24건 기준이다. 역추론 결과는 아래처럼 근거와 함께 남긴다.

```yaml
inferred_rule:
  id: OBS-14-BEAD
  scope: "14 Inductor / bead"
  pattern: "14-6 SS T VVV NN"
  fields: {SS: "일반 사이즈 코드", T: "공차", VVV: "Ω, 유효숫자 2 + 승수", NN: "접미"}
  support: 13
  counter_examples: 0
  example: "14-615712100 = bead 1005 ±25% 120Ω"
  status: proposed        # 사람이 승인하면 규정 v1.1에 편입
```

**3단계 예 — 사례 기업의 격차 리포트**

| 칸 | 내용 |
|---|---|
| 규정에만 있음 | 메모리 등급 자리(4건 중 3건이 실제 등급과 다름), 끝 2자리 제조사 코드(코드표 없음) |
| 실무에만 있음 | 5.5의 확장 10종 (대분류 `84`·`86` 포함) |
| 둘 다 있지만 다름 | PCB 자리 배분(엑셀 vs 슬라이드), Clock 값 자리 수(규정 5자리, 실무 4자리), 자리 번호 표기(11~12 vs 10~11) |

**4단계 — 불일치 처리 경로**

| 경로 | 언제 | 조치 | 사례 기업 적용 |
|---|---|---|---|
| 설명 정정 | 코드가 맞고 설명이 틀렸다 | 품명·규격만 고친다. 품번은 그대로 | 설계 BOM 설명 충돌 5건 (5.7의 2번) |
| 재채번 검토 | 코드가 **다른 사양의 자리를 차지**한다 | 정식 품번 신규 발번 → 구 품번 `Superseded` → 재고·BOM·미결 발주 이관 → 상호 참조 유지 | 5.4의 1·2·4·5번 (4건) |
| 정책 결정 후 처리 | 규정의 자리 자체가 쓰이지 않는다 | 그 자리를 살릴지 없앨지 먼저 정한다. 살리면 재채번 검토로, 없애면 규정에서 지운다 | 메모리 등급 3건 (5.4의 10~12번) |
| 레거시 유지·예외표 | 코드가 틀렸지만 다른 품목과 부딪힐 가능성이 낮다 | 품번은 유지하고 예외표에 "해독 결과 ≠ 실제 사양"을 기록. 해독할 때 예외표를 먼저 조회 | 5.4의 3·6~9·13~17번 (10건) |

4건 + 3건 + 10건 = 17건으로 5.4의 불일치 전부가 어느 한 경로에 들어간다. 6·7번은 코드가 아니라 설계 BOM 설명이 틀린 경우라 설명 정정도 함께 한다.

**5단계 — 병합하지 말고 연결한다**

같은 사양의 품번이 둘 있다고 하나를 지우면, 지운 품번에 쌓인 발주·입고·재고 이력이 갈 곳을 잃는다. 대신 대체 관계로 잇는다.

| 사례 | 지금 | 연결 후 |
|---|---|---|
| SPI NOR 16Mb 1.8V | BOM에는 ESMT `20-411001601`만 있다. ISSI `20-411001600`(재고 4,699)은 BOM 소요와 무관 | 한 품번 아래 AVL로 묶거나(5.6의 정책 ②), 두 품번을 대체 관계로 연결해 소요 계산이 두 재고를 함께 본다 |
| FAKRA `59S16K-40MT5-A / 102080-012200 A` | 품명 칸에 MPN 둘, 품번은 `16-2125640A0` 하나 | 두 번째 부품 `16-2120122A0`(재고 1,453)을 대체 관계로 등록하고 품명에서 뺀다 |
| LTE `RC7630_1105120 / RC7630_1104912` | 품명 칸에 펌웨어 변형 둘 | FFF가 다르므로(4.4의 ④) 대체가 아니다. 두 품번(`26-090763020`, `26-090763010`)을 따로 두고 BOM이 어느 쪽을 쓰는지 명시한다 |

마지막 행처럼 **품명에 같이 적혔다고 대체품인 것은 아니다.** 연결하기 전에 FFF 호환 여부를 판정한다.

**7단계 — 대량 재채번은 하지 않는다**

품번은 ERP 안에만 있지 않다. 발주서, 입고·재고 이력, 원가, BOM, 도면, 라벨·바코드, 고객 제출 문서, 협력사 시스템에 퍼져 있다. 일괄 변경은 이 연결을 한꺼번에 끊는다. 새 규칙은 신규 품목부터 적용하고 기존 번호는 그대로 두는 것이 업계의 일반 권고다([OpenBOM](https://www.openbom.com/blog/design-part-numbering-ai-era)). 사례 기업의 경우 347개 중 재채번 검토 대상은 4건이다.

**유형 B에서 에이전트가 하지 않는 일**

- 규정 문서와 다르다는 이유만으로 실무 관행을 오류로 판정하지 않는다. 지지 건수가 많으면 규정이 낡은 것일 수 있다.
- 지지 건수가 적은 패턴을 규칙으로 확정하지 않는다.
- 같은 사양 품번을 병합하거나 삭제하지 않는다.

### 6.4 유형 C — 자체 품번 관리가 없는 업체: 설계 조력자이자 초기 구축자

**목표** · 품번을 붙이기 전에 품목부터 정리하고, 체계는 회사가 고르게 한다.

**흔한 모습** · KK1~KK6 E-BOM에는 품번 열이 없다. 부품은 `100nF/25v/C1005` 같은 자유 텍스트나 MPN으로만 식별된다. 이런 회사는 MPN을 품번 대신 쓰거나, 거래처 품번을 그대로 쓰거나, ERP가 자동으로 주는 순번을 쓴다. 1.2의 여섯 가지 문제가 모두 그대로 나타난다.

**절차**

1. **품목 정체성부터 정리한다.** MPN 정규화(지향점 룰북 `RB-SY-*`), 동일 부품 판정, 사양 속성 추출을 먼저 한다. 품번이 없어도 할 수 있는 일이고, 어떤 체계를 고르든 필요한 일이다. KK1의 100nF 표기 10종은 이 단계에서 사양 7종으로 모이고, 공차·MPN이 확정되면 최종 품목 수가 정해진다(4.4의 ⑤).
2. **품목군 트리 초안을 만든다.** 회로 부품, PCB, 기구물, 케이블·하네스, 공정 부자재, 라벨·포장, 소프트웨어·펌웨어. 사례 기업 규정에서 빠진 갈래(3.4)를 처음부터 넣는다. 자체 양산품(반제품·완제품)의 코드는 부품 채번 규칙과 분리해 둔다(3.3).
3. **체계 선택지를 근거와 함께 제시한다.** 결정은 회사가 한다(아래 표).
4. **초기 마스터를 한 번에 구축한다.** 보존할 레거시가 없으므로 유형 C에서는 일괄 발번이 허용된다. 다만 기존 엑셀·발주 이력에 남은 거래처 품번·MPN과 새 품번의 **상호 참조표**를 함께 만든다. 그래야 과거 발주서로 새 품번을 찾을 수 있다.
5. **운영 규칙을 함께 정한다.** 발번 창구 단일화, 신규 등록 절차(지향점 시나리오 E), 불변·재사용 금지, FFF 정책(비호환 변경은 신규 품번, 호환 변경은 리비전), 단종 품목은 삭제 대신 상태 변경.
6. **회로 밖 품목도 같은 날 시작한다.** PCB·케이블·기구물·소프트웨어를 나중으로 미루면 그 갈래는 사람이 그때그때 번호를 짓는다. 바로 아래 사례가 그렇다.

**3단계 — 체계 선택지**

| 기준 | 의미 부여형 (사례 기업 방식) | 분류 접두 + 무의미 순번 | 완전 무의미 순번 |
|---|---|---|---|
| 형태 예 | `12-155710400` | `12-000431` (가상) | `100431` (가상) |
| 사람이 읽을 수 있는 것 | 분류와 사양 | 분류 | 없음 |
| 규칙 유지 비용 | 높다. 분류마다 코드표가 필요하다 | 낮다. 분류 코드표만 있으면 된다 | 거의 없다 |
| 대표 오류 | 자리 착오가 다른 사양과의 충돌로 번진다 (5.4) | 분류 착오 | 품번 오류는 거의 없고, 속성 오류가 대신 생긴다 |
| 전제 조건 | 규칙 문서와 주기적 감사 | 속성 마스터와 검색 | 속성 마스터와 검색 |
| 어울리는 회사 | 현장이 품번을 눈으로 읽고, 규칙 관리 담당이 있다 | 담당 인력이 적은 중소 제조사 | PLM·ERP 속성 검색이 잘 갖춰진 회사 |

**[판단]** 담당 인력이 적은 유형 C 업체에는 **분류 접두 + 무의미 순번**이 현실적이다. 분류 두 자리로 정렬과 담당 부서 구분은 유지하고, 사양은 속성 필드에 둔다. 의미 부여형의 장점인 "같은 사양의 중복이 눈에 띈다"는 에이전트의 속성 기반 중복 검사가 대신한다. 번호는 단순하게 두고 의미는 연결된 데이터로 옮기라는 권고와도 맞는다([OpenBOM](https://www.openbom.com/blog/design-part-numbering-ai-era), [PDXpert](https://www.buyplm.com/plm-good-practice/part-numbering-system-software.aspx)). 반대로 창고·수삽 현장에서 품번을 눈으로 읽어야 하는 회사라면 의미 부여형이 맞을 수 있다.

**반면교사 — 체계 없이 붙인 임시 번호**

앞선 M-BOM 생성 작업(`M-BOM_생성\`)에서 정식 품번이 없는 품목에 아래 식별자를 임시로 붙였다. 문서 안에서 품목을 구별하는 데는 충분했지만 ERP 품번으로는 쓸 수 없다. 사람이 그때그때 짓는 번호가 어떻게 흩어지는지 보여 주는 예로 남긴다.

| 임시 식별자 | 품목 | 문제 | 사례 기업 규칙에 넣는다면 |
|---|---|---|---|
| `PCB-KK1-FACT-V01A` | KK1 PCB (8층) | 길이가 가변이고, 버전을 E-BOM 파일명에서 그대로 따왔다 | `30-08…` (8층 `08` + 구조 + 일련번호 + 버전 `XY`) |
| `PCB-KK4-IFBD-V2.0` | KK4 PCB (8층) | 같은 품목군인데 버전 표기가 `V01A`와 `V2.0`으로 다르다 | `30-08…` |
| `CBL-KK1-LCD-080`, `CBL-KK1-LCD-200` | LCD 케이블 40P, 80mm·200mm | 길이는 넣었지만 핀 수는 없다 | `38` Harness, 핀 수 `040`. 길이 자리 `LL`은 단위가 정의되지 않아 규칙만으로는 만들 수 없다 |
| `MEC-SHD8550-F01`, `MEC-SHD8550-C01` | KK2 쉴드 프레임·커버 | 쉴드 캔 분류가 규칙에도 없다 | 사례 기업은 `64` Housing에 넣었다(5.4 판단 사례). 대분류 신설 검토 대상 |
| `SW-KK1-OSIMG-R1.0` 외 4건 | eMMC OS 이미지, USB 브리지 설정 파일 | 무형 품목 | **대분류가 없어 사례 기업 규칙으로도 만들 수 없다** (2.8의 12번) |

같은 작업에서 추가한 BGA 언더필 레진도 공정 부자재라 `76` Adhesive 외에는 갈 자리가 없다. **유형 A 회사의 규칙도 회로 밖 갈래에서는 유형 C와 같은 상태**라는 것이 3장의 요지다.

**유형 C에서 에이전트가 하지 않는 일**

- 체계를 혼자 정해 일괄 발번하지 않는다. 선택지와 근거까지만 낸다.
- MPN을 그대로 사내 품번으로 쓰자고 제안하지 않는다. MPN이 없는 품목, 제조사가 여럿인 품목, 표기가 흔들리는 품목을 감당하지 못한다(1.2).
- 임시 식별자를 정식 품번처럼 ERP에 등록하지 않는다. 임시 식별자는 `Legacy_Code`로 남기고 정식 발번 대상으로 표시한다.

### 6.5 세 유형 공통 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | **품번은 지어내지 않고 도출한다.** 규칙과 확정 사양이 같으면 결과도 같아야 한다. 규칙이 답을 주지 않으면 사람에게 올린다 | 같은 부품에 다른 번호가 나오는 순간 1품목 1품번이 깨진다 |
| 2 | **사양 확정이 채번보다 먼저다.** MPN과 데이터시트로 확정한 사양으로 채번한다. 설명 문자열만으로 채번하지 않는다 | 틀린 설명이 코드로 굳는다 (5.4의 6·7번) |
| 3 | **기존 품번은 바꾸지 않고, 다시 쓰지 않는다.** 정정은 신규 발번과 `Superseded_By`로 한다 | 품번에 쌓인 발주·재고·원가 이력이 끊기거나 섞인다 |
| 4 | **유일성 검사는 전체 마스터를 대상으로 한다.** 비활성·단종·`Superseded` 품번도 포함한다 | 단종 품번과 같은 번호를 새로 내면 과거 이력과 새 품목이 섞인다 |
| 5 | **새 분류·새 코드 값은 제안만 한다** | 분류 체계는 조달·품질·회계 정책이 반영된 결과다 |
| 6 | **모든 제안에 근거를 붙인다.** 해독 결과, 대조한 원본, `Confidence_Score`, `Source_Provenance` | 사람이 빠르게 승인하거나 반려할 수 있어야 한다 |
| 7 | **확정은 사람이 한다.** 발번 확정, 재채번, 규정 개정은 승인 후에만 반영한다 | 되돌리기 어려운 결정이다 |
| 8 | **판정은 품목군 단위로 한다** | 한 회사 안에도 A·B·C가 섞여 있다 |

## 7. BOM Agent 설계 연결

이 장은 앞의 내용을 지향점 문서(`BOM_Agent_지향점(내부용)2026.09.17.md`)의 필드·룰북·시나리오에 연결한다. **기존 문서는 수정하지 않았다.** 반영 제안은 7.6에 모았다.

### 7.1 지향점 문서의 기존 필드와 연결

| 지향점 필드 | 이 문서에서의 역할 |
|---|---|
| `Internal_PN` (IPN) | 채번 결과. 4.1 절차의 산출물 |
| `Approved_MPN_List` | 끝 2자리 정책 ②에서 제조사를 담는 곳 (5.6). 대체 품목 재고를 소요 계산에 잇는 연결 고리 (6.3의 5단계) |
| `Part_Standard_Class` / `NPR_Status` | 신규 등록 심사 결과. **발번은 `NPR_Status = Approved` 뒤에 한다** |
| `Confidence_Score` / `Source_Provenance` | 채번 제안과 해독 감사의 근거 (6.5의 6번) |
| `Lifecycle_Status` | 단종 품번도 유일성 검사 대상에 넣는다 (6.5의 4번) |

### 7.2 신규 필드 제안

| 필드 | 값 | 용도 |
|---|---|---|
| `IPN_Scheme_ID` | 예: `DRIMAES-CIRCUIT-v1.0`, `DRIMAES-MECH-v1.0`, `LEGACY` | 품번을 만든 규칙과 버전. 규정 개정 전후의 품번을 구분한다 |
| `IPN_Decoded` | 구조화된 해독 결과 (예: `{class: 12, size: 1005, tolerance: ±10%, voltage: 10V, value: 4.7µF}`) | 속성 검색, 감사 |
| `IPN_Spec_Consistency` | `Match` / `Mismatch` / `Exception_Listed` / `Not_Decodable` | 해독 결과와 마스터 규격의 대조 결과 |
| `IPN_Exception_Note` | 문자열 | 예외표 내용. 예: "공차 자리 `5`이나 실제 ±20%" |
| `IPN_Status` | `Active` / `Frozen` / `Superseded` / `Inactive` | 정정·단종 시 품번의 상태 |
| `Superseded_By` / `Supersedes` | 품번 | 재채번 전후의 상호 참조 |
| `Legacy_Code` | 문자열 | 유형 C 초기 구축 시의 거래처 품번·옛 관리번호·임시 식별자 |
| `IPN_Assigned_By` / `IPN_Assigned_At` | 사람, 시각 | 발번 권한과 시점의 감사 추적 |

### 7.3 룰북 초안 — `RB-PN` 품번 규칙

지향점 룰북의 ID 체계(`RB-{분류}-{번호}`)와 등급(S 차단 · H 승인 요청 · L 자동 처리 후 기록)을 따른다.

| ID | 조건 (When) | 판정·조치 (Then) | 등급 |
|---|---|---|---|
| `RB-PN-01` | 신규 품번이 형식(길이, 정규식, 금지 문자 I·O·Z)을 어긴다 | 등록 차단 | **S** |
| `RB-PN-02` | 대분류·세부 코드가 규칙 코드표에 없다 | 등록 차단. 가장 가까운 코드에 끼워 넣지 않는다. 후보 코드와 근거를 규정 개정 요청으로 올린다 | **S** |
| `RB-PN-03` | 규칙대로 만든 품번이 이미 다른 품목에 쓰이고 있다 (비활성·단종 포함) | 기존 품목의 해독 결과와 규격을 대조한다. 기존이 오등록이면 정정 경로(6.3의 4단계) 선택을 요구하고, 정상이면 흡수(시나리오 E)를 검토한다. 접미를 올려 자동으로 피하지 않는다 | **H** |
| `RB-PN-04` | 기존 품번의 해독 결과가 마스터 규격과 다르다 | `IPN_Spec_Consistency = Mismatch`로 표시하고 처리 경로 분류를 제안한다 | **H** |
| `RB-PN-05` | 정규화한 같은 MPN이 둘 이상의 품번에 등록돼 있다 | 중복 후보로 올린다. 병합·삭제하지 않는다 | **H** |
| `RB-PN-06` | 같은 본체(D1~D9)에 접미만 다른 품번이 있다 | 차이(제조사, FFF, 결합 키, 펌웨어)를 기록하고 AVL 연결 여부를 확인한다 | **L** |
| `RB-PN-07` | 품명·규격 칸에 MPN이 둘 이상 있거나 상태 문구(미사용, 단종 등)가 있다 | 대체 관계·상태 필드로 분리를 제안한다. 분리 전까지 해당 품목의 소요 계산에 경고를 붙인다 | **H** |
| `RB-PN-08` | 같은 품번에서 설계 BOM 설명과 ERP 설명이 충돌한다 | 데이터시트로 먼저 판정한다. 판정 전에는 어느 설명으로도 채번·정정하지 않는다 | **H** |
| `RB-PN-09` | 에이전트가 기존 품번을 바꾸거나 다른 품목에 다시 쓰려 한다 | 차단. 신규 발번과 `Superseded_By` 경로만 허용한다 | **S** |
| `RB-PN-10` | 제조사가 결측(`#N/A`, 공란)이거나 비정규 표기다 | MPN으로 복원·정규화하고(`RB-SY-02`) 복원 근거를 남긴다 | **L** |
| `RB-PN-11` | 개정 요청이 들어왔다 | FFF가 바뀌면 신규 품번. FFF 호환이면 회사 정책에 따라 리비전 처리 여부를 판정하고 근거를 남긴다 | **H** |
| `RB-PN-12` | 에이전트가 품번 체계 자체를 정하거나 초기 마스터를 일괄 발번하려 한다 | 차단. 선택지와 근거 제시까지만 한다 (6.4) | **S** |

### 7.4 지향점 시나리오와의 연결

| 시나리오 | 연결 지점 |
|---|---|
| **A** 인제스천·암묵지 해석 | 품번이 있는 BOM이면 품번 해독 결과를 MPN 해석의 교차 검증 신호로 쓴다. 해독 결과와 텍스트 사양이 다르면 `Confidence_Score`를 낮춘다. 품번이 없는 BOM(유형 C)은 4.4의 ⑤처럼 빈 자리 `?`가 있는 후보 품번으로 결측 사양을 드러낸다 |
| **E** 신규 부품 등록 심사 | 2단계 "기존 표준 품목으로의 흡수 시도"가 `RB-PN-03`의 흡수 검토와 같은 흐름이다. 4단계 "등록 승인 및 IPN 발급"에 4.1의 [4]~[7]과 `RB-PN-01`~`03`을 넣는다 |
| M-BOM `CR-19` 기록 정정 | 6.3의 "설명 정정" 경로와 같은 사유다. 정정이 MPN·값·정격을 바꾸면 `RB-CF-09`에 따라 설계 변경으로 재분류한다. 재채번 검토도 같은 판단을 거친다 |
| M-BOM `A10` 펌웨어 개정 | 소프트웨어 대분류가 생기기 전에는 펌웨어 개정을 품번으로 추적할 수 없다 (3.4) |

### 7.5 KPI 제안

| 지표 | 정의 | 사례 기업 기준선 | 목표 [판단] |
|---|---|---|---|
| 신규 품번 규격 정합률 | 신규 발번 중 해독 결과가 확정 사양과 같은 비율 | — | 100% |

| 중복 품번률 | 같은 정규화 MPN에 품번이 둘 이상인 품목 비율 | 이번 범위에서 0 | 0 유지 |
| BOM 밖 대체·변형 재고 | 대체·변형 관계가 연결되지 않아 BOM 소요 계산에서 안 보이는 재고 품목 수 | 3품목 (1,453 · 2,041 · 4,699개) | 0 |

| 신규 발번 리드타임 | 등록 요청부터 품번 확정까지 | — | 회사 기준 설정 |
