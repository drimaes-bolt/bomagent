> **문서 성격** · 9/29 설계안 회의를 앞두고, **데이터를 공급하고 에이전트 기능을 제안하는 드림에이스**와 **언어모델에 CPT를 수행하는 NC AI**가 각각 무엇을 더 연구하고 채워야 하는지를 정리한 제안서다. 9/16 회의록의 Action Item(D1~D10 / N1~N8)을 대체하지 않고, **그 목록에서 빠져 있거나 아직 근거가 약한 항목을 보강**한다.

>
> **관점** · 이 문서는 "무엇을 더 하면 좋은가"를 나열하지 않는다. **지금 비어 있어서 9/29 설계안이 막히는 것**부터 순서대로 다룬다.

## 0. 핵심 진단과 제안 요지

**진단 세 줄**

1. 데이터는 생각보다 많이 준비되어 있다. 다만 **학습 가능한 형태로 라벨링된 것은 거의 없다.** 특히 회의록 D4로 요청된 E-BOM→M-BOM 페어는 이미 폴더에 존재한다(`Refine_1k2chgr.xlsm`, `Refine_BMS.xlsm` · 합계 214행). 이 두 파일이 현재 가장 값비싼 자산이다.
2. 태스크는 정의되어 있다(T-01~T-20). 그런데 **모든 태스크에 "판정 기준"만 있고 "측정 방법"이 없다.** 평가셋과 채점 규칙이 없으면 9/29 설계안은 검증 불가한 약속이 된다.
3. 모델과 에이전트의 경계는 합의되었으나, **"가중치에 넣을 것 / 검색에 둘 것 / 규칙으로 박을 것"의 3분할이 문서로 고정되지 않았다.** 이 분할이 곧 CPT 코퍼스 설계이자 데이터 제공 범위다.

**제안 요지**

| 층 | 무엇을 | 누가 |
|---|---|---|
| **가중치 (CPT/FT)** | 제조업체가 달라도 변하지 않는 것 — 부품이 무엇인지, 어떤 정격을 갖는지, 표기 체계가 어떻게 읽히는지 | NC AI |
| **검색 (RAG/Tool)** | 회사·시점에 따라 변하는 것 — 리드타임, MOQ, 선호 제조사, 재고, 단가, 사내 코드 | 드림에이스 데이터 + NC AI 검색 계층 |
| **규칙 (결정론)** | 틀리면 안 되는 것 — 채번, 소요량 계산, FIFO 배분, 정격 위반 차단, 안전 부품 대체 금지 | 드림에이스 애플리케이션 |

이 3분할은 규격문서 `00_읽기전`의 "통합 대상과 비통합 대상" 서술과 정확히 같은 논리다. 문서에 이미 원칙이 있으니 **항목 단위로 배치표를 만들어 양사가 서명하는 것**이 첫 과제다.

## 1. 현 자료 실측 진단 — 무엇이 준비되고 무엇이 비어 있는가

### 1.1 자료 준비도

| 자료 | 상태 | 학습 활용 가능성 |
|---|---|---|
| 통합관리 BOM (E51K, 58행) | ✅ 정제 완료, 부서별 뷰 2종 분리 | 스키마·뷰 구조 학습. **양은 부족** |
| 분류 사전 (대분류 22 / 중분류 165) | ✅ 완성도 높음, 출처 명기 | T-02 분류 판정의 정답 체계 |
| 패키지 동의어 사전 (54행) | ✅ JEDEC 정식지정 + 벤더 별칭 | T-05 동일 부품 판정 직접 입력 |
| 칩 사이즈 코드표 (inch↔metric) | ✅ 함정 3건까지 명시 | 정규화 룩업 테이블 |
| 코드 매핑 사례집 (149행 × 5체계) | ✅ 합성 라벨 동봉 | T-06 학습 입력 |
| 태스크 정의서 (T-01~T-20) | ✅ 담당 경계 구분 완료 | 파인튜닝 태스크 명세의 골격 |
| **E-BOM↔M-BOM 페어** | ⚠️ **존재하나 미인지·미정제** | **핵심 자산. 즉시 정규화 필요** |
| 원본 설계 BOM (6종) | ⚠️ 원형 그대로, 라벨 없음 | 입력 분포 학습·평가셋 후보 |
| 평가셋(골든셋)·채점 규칙 | ❌ 없음 | — |
| 사내 암묵지 표기 사전 | ❌ 없음 | — |
| 사람의 교정 로그 | ❌ 수집 체계 없음 | — |

### 1.2 원본 설계 BOM 실측 — 입력이 얼마나 거친가

KK 계열 5종(`.xlsx`) **877행**을 파싱했다. 6번째 파일 `KK4-...산업용.xls`는 **구형 이진 포맷으로 openpyxl이 읽지 못했다.** 파이프라인 첫 관문이 파일 포맷이라는 점부터 실측된다.

| 항목 | 실측 |
|---|---|
| 컬럼 레이아웃 | **2종 분기** — 5열(`Item·Qty·Reference·Part·Note`) 4개 파일, 8열(`+Description·Part Name·Vendor`) 1개 파일 |
| **MPN 열 보유** | **5개 중 1개뿐.** 나머지 4개 파일에는 제조사 품번이 아예 없다 |
| 전압 단위 대소문자 | `v` 91회 : `V` 75회 — **거의 반반** |
| 용량 단위 | `uF` 83 : `UF` 4 / `pF` 24 : `PF` 11 |
| 패키지 표기 | `R1005` 179, `C1005` 104, `R0603` 40, `C0603` 16 — **전량 metric 단독 표기** |
| 미실장(`NC`) 표기 | **103건 / 877행 (11.7%)** |
| 비구매 항목 | 테스트포인트·패드·실드클립·쇼트 17건 (발주 대상 아님) |
| 수량↔레퍼런스 불일치 | 3건 — 전부 **케이블·하네스 품목**에서 발생 |

읽어야 할 결론은 셋이다.

**① 설계 BOM에는 MPN이 없다.** 회의에서 지적된 "구매팀이 해독한다"는 병목이 데이터로 확인된다. 모델이 풀어야 하는 것은 MPN **정규화**가 아니라 값·패키지 문자열로부터의 **MPN 결정**이다.

**② 미실장 표기가 8행에 1행꼴이다.** `NC`를 부품으로 오인하면 발주량이 12% 부풀고, 반대로 일괄 제거하면 `NC`가 값의 일부인 행까지 날아간다. 이 비중이면 별도 태스크로 세울 값이 있다.

**③ 정합성 결함은 회로 부품이 아니라 케이블·기구에서 나온다.** 회로 부품은 EDA가 참조 부호를 생성하므로 수량이 맞는다. 사람이 손으로 적는 하네스·커넥터에서 어긋난다. 검증 규칙의 적용 우선순위가 여기서 나온다.

### 1.3 E-BOM↔M-BOM 페어 실측 — 가장 값비싼 자산

`Refine_1k2chgr.xlsm`과 `Refine_BMS.xlsm`은 **한 파일 안에 `(E-BOM)` 시트와 `(M-BOM)` 시트가 짝으로** 들어 있다. 회의록 D4가 요청한 바로 그 데이터다.

| 항목 | 1k2chgr | BMS | 합계 |
|---|---|---|---|
| E-BOM 행 / M-BOM 행 | 91 / 92 | 123 / 123 | **214행 페어** |
| M-BOM에 MPN 확보 | 86 (94.5%) | 112 (91.1%) | **198 (92.5%)** |
| 참조 부호 **범위 표기** 사용 | 31 | 48 | 79 (36.9%) |
| 공백 구분 참조 (→ 콤마 변환) | 45 | 77 | 122 |
| 패키지 표기 변환 발생 | 26 | 24 | 50 |
| E-BOM 패키지 공란 → M-BOM 보충 | 5 | 15 | 20 |
| 수량 ↔ 범위전개 개수 불일치 | 2 | 6 | **8** |
| 리드타임 범위 | 1~24주 (평균 5.2) | 1~12주 (평균 3.6) | — |

이 페어가 담고 있는 변환은 **단일 태스크가 아니라 최소 6종의 복합 변환**이다.

```text
[E-BOM 1행]                                  [M-BOM 1행]
Reference : "Q1-16"                    ①→   "Q1,Q2,Q3,...,Q16"      범위 전개 + 구분자 통일
PART-TYPE : "2N2222A,2n2222"           ②→   Part Name 승계
Package   : (공란)                      ③→   "SOT23-3"              패키지 추론·보충
—                                      ④→   MPN "MMBT2222ALTG"     제조사 품번 결정
—                                      ⑤→   Manufacturer "On-semiconductor"
Qty       : 16                         ⑥→   16                     범위 전개 개수와 교차 검증
```

**변환 규칙의 실제 예시** (실측에서 추출)

| 변환 | E-BOM 표기 | M-BOM 표기 | 성격 |
|---|---|---|---|
| 참조 부호 | `C4 C168 C218-220 C235-237` | `C4,C168,C218,C219,C220,C235,C236,C237` | 결정론적 (규칙) |
| 패키지 | `C1608` → `SMD1608`, `C3216` → `SMD3216` | 접두 규칙 | 결정론적 (규칙) |
| 패키지 | `B_S_1W` → `4-SIP`, `DO214 (SMC)` → `DO-214AB` | 사전 매핑 | 검색 (동의어 사전) |
| 패키지 보충 | `XTAL,24M` (공란) → `SMD 3225` | 데이터시트 조회 | 모델 + 검색 |
| MPN 결정 | `18pf C1608` → Walsin `0603N180J500` | 제조사 선택 = 구매 권한 | 모델 후보 + 사람 확정 |

**동시에 이 페어는 세 가지 오염을 안고 있다.** 정제 없이 그대로 학습에 넣으면 잘못된 것을 배운다.

- **라벨 노이즈** — `18pF`·`22pF` 행의 Description이 `Capacitor, 1608 SMD Ceramic, 50V, X5R, 10%`로 기재되어 있다. 이 용량대는 통상 C0G(Class I)이며 X5R은 템플릿 복사 흔적으로 보인다. **모델에 유전체를 잘못 가르치는 라벨이다.**
- **열 오염** — M-BOM `Package` 열에 `재고없음`, `NC` 같은 **재고 상태 값**이 들어가 있다(2건). 패키지 필드로 학습하면 안 되는 값이다.
- **제조사 표기 비표준** — `On-semiconductor` 9건(정규형 onsemi), `Any` 2건(제조사 미지정 의미). 정규화 사전이 먼저 필요하다.

### 1.4 구조적 공백 3가지

| # | 공백 | 왜 지금 문제인가 |
|---|---|---|
| **G1** | **평가셋과 채점 규칙이 없다** | T-01~T-07의 "판정 기준"은 서술뿐이다. 9/29에 학습 설계안이 나오더라도 성공 여부를 판정할 기준이 없다. 규격문서 7.2에 해당하는 계약 기준도 여기 의존한다 |
| **G2** | **사내 암묵지 표기가 해독되지 않았다** | 원본 BOM에 `1uF/6.3V_1`, `22uF/4V_0503`, `Short_L7`, `TP_0.8` 같은 접미사가 다수 존재한다. 접미사의 의미(두께·길이·등급?)를 아는 사람이 사내에 있고 문서에는 없다. **모델이 추론으로 만들 수 없는 정보** |
| **G3** | **사람의 교정 로그를 수집하지 않는다** | 현재 앱에 `audit_log` 1,542행이 있으나, "모델 제안 → 사람이 무엇을 어떻게 고쳤는가"의 쌍으로 구조화되어 있지 않다. 운영 시작 후 가장 값비싼 학습 신호가 그냥 흘러간다 |

## 2. 선행 합의 과제 — 여기부터 정하지 않으면 뒤가 전부 흔들린다

양사 중 어느 한쪽이 단독으로 정할 수 없고, 정하지 않으면 각자의 작업이 서로 어긋나는 항목이다. **9/29 이전에 합의 초안이 나와야 하는 것들이다.**

### 2.1 지식 배치표 (가중치 / 검색 / 규칙)

회의에서 원칙은 합의되었다. 남은 것은 **항목 단위 배치**다. 아래 표를 양사가 함께 채우고 확정하는 것을 제안한다.

| 지식 항목 | 제안 배치 | 근거 |
|---|---|---|
| 부품 종류·정격의 물리적 의미 (X7R의 온도특성, 탄탈의 극성) | **가중치** | 제조사·시점과 무관하게 불변 |
| 패키지 동의어·JEDEC 대응 (SOT-23 ↔ TO-236AB ↔ SC-59) | **가중치 + 검색** | 체계는 불변이나 벤더 별칭은 증가 |
| 칩 사이즈 inch↔metric 대조 | **규칙 (룩업)** | 008004·009005 구간은 계산으로 유도 불가 |
| MPN 명명 규칙 (삼성전기 CL 시리즈, Yageo RC 시리즈) | **가중치** | 카탈로그 규칙은 안정적 |
| 특정 파생 품번의 실재 여부 | **검색** | 생성하면 환각. 카탈로그 역검증 필수 |
| 사내 분류·채번 체계 | **검색 + 규칙** | 회사별로 다름. 채번은 결정론 |
| 선호 제조사·승인 벤더 | **검색** | 회의록: "변동 가능하므로 RAG" |
| 리드타임·MOQ·단가·재고 | **검색** | 태스크 정의서 T-16·T-17: 모델 대상 아님 |
| 대체 승인 이력 | **검색 (지식그래프)** | 사내 자산. 누적될수록 가치 상승 |
| 안전 부품 대체 금지·정격 위반 차단 | **규칙** | 모델 신뢰도와 무관하게 차단 |
| 소요량·원가·FIFO 계산 | **규칙** | T-12·T-13: 같은 입력에 같은 출력 |

> **경계 사례를 미리 정해 둘 것** · "RF단·전원단은 용량이 같아도 제조사 변경 불가"(T-07)는 **물리 지식인가 회사 규칙인가.** 물리적 근거(기생 파라미터·ESR 편차)는 가중치, 어느 회로 블록을 RF단으로 볼지는 검색이다. 이렇게 한 문장을 두 층으로 쪼개는 작업이 배치표의 실제 난도다.

### 2.2 인터페이스 계약 — 모델 출력 스키마

에이전트와 모델 사이의 계약을 **필드 단위로 고정**해야 한다. 아래는 제안 초안이다.

```json
{
  "line_id": "E51K-0042",
  "task": "mpn_resolution",
  "status": "auto_confirmed | recommended | unresolved | blocked",
  "result": {
    "mpn": "CL10B104KB8NNNC",
    "manufacturer": "Samsung Electro-Mechanics",
    "class_code": "CA02",
    "value": "100nF", "voltage": "50V", "tolerance": "±10%",
    "dielectric": "X7R", "package": "0603 (1608 Metric)"
  },
  "confidence": 0.94,
  "provenance": ["internal_order_history:PO-2025-3312", "datasheet:samsung_CL10B"],
  "candidates": [ { "mpn": "...", "confidence": 0.71, "why": "..." } ],
  "unresolved_fields": ["tolerance"],
  "blocked_by": null,
  "needs_human": false,
  "question_to_engineer": null
}
```

계약에서 반드시 지켜야 할 네 가지를 제안한다.

1. **`status`는 4값 고정** — 자동확정 / 추천 / 미결 / 차단. 문서의 트리아지 분류와 동일하게 두어 KPI가 그대로 계산되게 한다.
2. **`confidence`와 `provenance`는 필수** — 근거 없는 값은 계약 위반으로 본다. 규격문서 T-01의 "미확인 시 값을 만들지 않고 '확인 불가'로 표기"를 스키마로 강제한다.
3. **빈 값과 모름을 구분** — 학습데이터 `00_읽기전`의 `TBD_확인필요` 규칙을 출력에도 적용한다. 공란과 미확인은 다른 상태다.
4. **스키마는 토큰 레벨에서 강제** — 프롬프트로 "JSON으로 답해줘"는 보증이 아니다. [문법 기반 제약 디코딩](https://arxiv.org/html/2501.10868v2)으로 샘플링 단계에서 스키마를 강제하는 방식을 NC AI 측 요구사항으로 명시한다.

### 2.3 평가셋(골든셋)과 채점 규칙 — 최우선 공동 과제

**G1을 해소하는 작업이며, 이 문서에서 가장 우선순위가 높다.** 규격문서 7.2가 지적한 "측정 데이터셋과 판정 기준이 없으면 정확도 99%는 계약상 의미가 없다"가 그대로 적용된다.

| 구성 | 제안 |
|---|---|
| **규모** | 1차 300~500행. 부품 대분류 22종이 최소 5행씩 포함되도록 층화 추출(stratified) |
| **출처** | `Refine_*` 페어 214행 + 원본 KK BOM에서 층화 추출 + 통합관리 BOM 58행 |
| **라벨 단위** | 행 단위 정답이 아니라 **필드 단위 정답** (MPN / 분류코드 / value / package / 유전체 / 허용차) |
| **채점** | 필드별 정확도·재현율을 따로 집계. MPN은 완전일치, value는 단위 정규화 후 등가 비교, package는 동의어 사전 통과 후 비교 |
| **난이도 태그** | 각 행에 `쉬움/보통/어려움`과 **오류 유형 태그**(단위혼재·범위표기·패키지공란·미실장·오타·중복) 부여 |
| **분리 원칙** | 평가셋은 **학습에서 완전 배제**. NC AI에 전달할 때 학습 금지 라벨을 파일 레벨로 명시 |
| **기권 채점** | "모른다고 답한 것"을 오답으로 세지 않는다. 오답(틀린 값 제시)과 기권(미결 표기)을 분리 집계 |

마지막 항목이 특히 중요하다. **기권을 오답으로 세면 모델은 모르는 것도 답하도록 학습된다.** 연구 문헌에서도 기권과 환각의 트레이드오프를 별도 지표로 다루며([abstention–hallucination frontier](https://arxiv.org/html/2604.03904)), 우리 KPI 구조(자동확정률 / 환각 0건 / 가드레일 차단율)와 정확히 대응한다.

### 2.4 데이터 거버넌스

| 항목 | 제안 |
|---|---|
| 단가·거래처 | **가중치 학습 금지.** 검색 계층에만 둔다. 학습데이터 `00_읽기전`의 "금액 자체를 학습 대상으로 삼지 말 것"을 계약 문구로 승격 |
| 합성 데이터 라벨 | 구코드 4스타일처럼 **합성 데이터는 파일·행 레벨 라벨 필수**. 미동봉 시 실제 타사 코드로 오인 (정제가이드 V-05) |
| 데이터시트 라이선스 | 공개 유통사 페이지는 문제없다는 회의 결론을 유지하되, **robots.txt와 이용약관을 수집 파이프라인에 기록**. 규격문서 C1_출처에 이미 "IEC CDD는 robots.txt 차단으로 미확보" 사례가 있다 |
| 삭제·보존 | 제공 데이터의 보존 기간, 학습 후 원본 삭제 여부, 모델 가중치에 남은 정보의 취급을 명문화 |
| 제3자 재사용 | 드림에이스 데이터로 학습한 모델을 타 고객에 제공할 때의 범위 (D6 판매 데이터 논의와 연결) |

### 2.5 정규형 사전의 소유권

패키지 동의어·사이즈 코드·유전체 코드·제조사 표기 — 이 네 사전은 **양사가 동시에 쓰지만 갱신 주체가 하나여야 한다.** 제안: 사전의 **정규형 정의는 드림에이스**(도메인 권한), **기계 판독 포맷과 버전 관리는 NC AI**(학습·검색 양쪽에서 소비). 버전 번호를 모델 출력의 `provenance`에 포함시켜 어느 사전 버전으로 판정했는지 추적한다.

## 3. 드림에이스 연구 과제 — 데이터 공급자와 기능 설계자로서

### 3.1 데이터를 학습 가능한 형태로 만드는 5가지

#### D-A. E-BOM↔M-BOM 페어의 정규화와 확장 ★ 최우선

이미 가진 214행을 **정답 페어 스키마로 표준화**하는 것이 가장 빠른 성과다. 새 데이터를 모으기 전에 이것부터 한다.

- **행 정렬 보장** — 현재 두 시트는 행 순서로 암묵적 대응한다(1k2chgr는 91 vs 92행으로 이미 1행 틀어져 있다). `pair_id`를 명시적으로 부여한다.
- **변환 유형 태그 부여** — 각 페어에 어떤 변환이 일어났는지 태그(`ref_expand`, `pkg_map`, `pkg_fill`, `mpn_decide`, `mfr_normalize`)를 붙인다. 태그가 있으면 태스크별 학습셋을 자동 분리할 수 있다.
- **오염 3종 제거** — ① Description 라벨 노이즈(18pF에 X7R/X5R 표기) ② Package 열의 재고 상태 값 ③ 제조사 표기 비정규형. 제거가 아니라 **원문 보존 + 정규형 병기**를 권한다. 원문이 곧 입력 분포다.
- **확장 목표** — 프로젝트 3~5건을 같은 형식으로 추가. 회의록 D3의 "양은 많을수록"에 대한 구체적 환산: **페어 1,000행이면 MPN 결정 태스크의 파인튜닝 최소선**에 들어간다.

#### D-B. 사내 암묵지 표기 사전 (G2 해소)

원본 BOM에서 관측되나 문서에 없는 표기를 사전화한다. 실측된 미해독 표기 예시는 다음과 같다.

| 표기 | 출현 | 추정 | 확인 필요 |
|---|---|---|---|
| `1uF/6.3V_1`, `10uF/6.3V_2`, `4.7uF/25V_3` | 다수 | 말미 숫자가 **패키지 등급 또는 두께 코드**? | ★ |
| `22uF/4V_0503` | 소수 | 0503 = 사이즈 코드 | ★ |
| `Short_L7`, `Short_L3`, `Short_L2` | 53건 | 점퍼 길이 또는 패턴 쇼트 종류 | ★ |
| `TP_0.8` | 215개 참조 | 테스트 포인트 패드 직경 | ★ |
| `PAD4x2/0.6x0.6x0.3` | 소수 | 패드 배열·치수 | ★ |
| `NC` (말미 부착) | 103건 | 미실장 | 확정 |

**이 사전은 드림에이스만 만들 수 있다.** 사내 엔지니어 1~2명의 반나절 인터뷰로 끝나는 작업이지만, 없으면 모델은 이 표기를 영구히 해독하지 못한다. 회의록 D2(룰북)의 하위 항목으로 편입하는 것을 제안한다.

#### D-C. 사람의 교정 로그 수집 설계 (G3 해소)

**운영이 시작되면 가장 값비싼 학습 신호가 발생한다.** "모델이 제안한 값"과 "사람이 최종 확정한 값"의 쌍이다. 지금 설계에 넣지 않으면 이 신호는 사라진다.

수집 스키마 제안:

```text
correction_log
  ├ line_id, task, model_version, dictionary_version
  ├ model_output (status, value, confidence, provenance)
  ├ human_final (value)
  ├ edit_type  (accept / modify / reject / escalate)
  ├ edit_reason (선택: 드롭다운 — 스펙불일치·재고없음·선호제조사·인증문제·기타)
  └ actor, timestamp
```

`edit_reason`을 드롭다운으로 강제하는 것이 핵심이다. 자유 텍스트는 분석되지 않는다. 이 로그는 ① 파인튜닝 데이터 ② 신뢰도 임계값 조정 근거 ③ KPI(자동확정률) 계측 계기 세 가지로 동시에 쓰인다.

#### D-D. 부결·반려 사례 (Negative examples)

현재 모든 자료가 "정답"이다. **틀린 판단이 왜 틀렸는지를 보여주는 데이터가 없다.** 모델은 "하지 말아야 할 것"을 배울 재료가 없다.

수집 대상: 대체품 검토에서 반려된 케이스와 그 사유, 오발주 사고 이력, 실장 불가로 반품된 자재, 설계 변경으로 폐기된 재고. 각 건마다 **"어떤 판단이 어떤 근거로 기각되었는가"** 한 줄이면 충분하다. 규격문서 T-07의 "자동 승인 시 감점"을 학습 데이터로 구현하는 방법이다.

#### D-E. 계층형 BOM과 기구 BOM (D5 연장)

이미 `BOM_Agent_지향점` 문서 1.4에 3계층 샘플과 회로/기구 구조 차이표가 정리되어 있다. 남은 것은 **실물 기구 BOM 1건**이다. 회로 BOM만으로 학습한 모델은 기구 품목에 MPN 추론을 시도한다(도면번호로 관리해야 하는 품목이다). 최소 1건이라도 있으면 이 구분을 가르칠 수 있다.

### 3.2 도메인 지식의 자산화

#### D-F. 룰북을 기계 판독 형태로

`BOM_Agent_지향점` 5장의 룰북(RB-LT/DP/SY/EX/SF/ST 47개)은 현재 산문 표다. 이를 **에이전트가 실행할 수 있는 형태**로 전환하는 연구가 필요하다.

| 규칙 유형 | 구현 형태 |
|---|---|
| 조건-판정형 (`RB-LT-02` 납기 미정 → 리스크 최대) | 결정 테이블 / 룰 엔진 |
| 사전 참조형 (`RB-SY-01` 사이즈 이중 체계) | 룩업 테이블 |
| 계산형 (`RB-LT-04` 셧다운 기간 가산) | 함수 + 파라미터 테이블 |
| 판단 위임형 (`RB-DP-04` 교정 재수행 필요) | 체크리스트 + HITL 라우팅 |

전환 과정에서 **구현 불가능한 규칙이 드러난다.** 그것은 규칙이 아니라 체크리스트로 재분류해야 한다. 이 선별 자체가 연구 과제다.

#### D-G. 대체 승인 이력 → 지식그래프 시드

회의에서 논의된 "대체 타이밍 알림"이 성립하려면 **과거에 무엇을 무엇으로 대체했고 그것이 승인되었는지**가 있어야 한다. 현 앱은 메일 초안 생성까지만 구현되어 있고(IO-09) 후보 탐색·판정 기능이 없다.

시드 스키마: `원부품 MPN / 대체 MPN / 적용 모델 / 승인자 / 승인일 / 승인 근거 / 제약조건(RF단 제외 등) / 결과(양산 적용 여부)`. **10건만 있어도 그래프의 형태가 잡힌다.** 100건이면 추천 근거로 쓸 수 있다.

#### D-H. 벤더 스코프의 활용 설계

`EP_Vendor_List_by_Category.md`(15 카테고리 × 20 벤더 = 300개, HQ·생산지 포함)는 회의록 D9의 답이다. 여기서 한 걸음 더 나가는 연구를 제안한다.

- **선호도 가중치 부여** — 리스트는 업계 순위다. 사내 실제 채택 빈도로 가중치를 다시 매기면 "우리 회사가 주로 쓰는 제조사"가 된다. 회의에서 "후보 3개 중 회사가 주로 쓰는 것을 추천"이라 한 기능의 데이터가 이것이다.
- **생산지 정보의 리스크 활용** — 리스트에 이미 Fabless/생산국이 있다. 지정학 리스크·관세 변동 시 영향 벤더를 즉시 뽑을 수 있다. **현재 어느 BOM 자료에도 없는 축이다.**
- **승인 등급 부여** — 각 벤더를 `승인/조건부/미승인`으로 3분류. 대체 후보 필터의 1차 관문이 된다.

#### D-I. 전장 도메인 추가 요구사항 ★ 범위 재확인 필요

회의에서 **전장(자동차 전자부품)이 1순위 도메인**으로 합의되었다. 그런데 전장은 산업용과 요구사항이 다르다. 아래는 현재 어느 문서에도 반영되지 않은 축이다.

| 요구 | 내용 | 영향 |
|---|---|---|
| **AEC-Q 등급** | [AEC-Q100](http://www.aecouncil.com/files/Documents/AEC%20Q100-Rev%20J1.pdf)(IC)·[AEC-Q200](http://aecouncil.com/Documents/AEC_Q200_Rev_E_Base_Document.pdf)(수동소자). **동작 온도로 Grade 0~4 구분** | 대체 후보 필터의 하드 조건. 등급 미달 부품은 후보에서 제외되어야 함. 규격문서 A6에 이미 `온도등급`·`AEC-Q101` 표기가 등장하므로 필드는 준비되어 있다 |
| **IMDS** | OEM 필수 물질 데이터 시스템(VDA 주도). 중국은 CAMDS 병행 | 이전 판단("물질 선언 요구 없음")은 **산업용 전제였다.** 전장 납품이 실제로 발생하면 IMDS는 선택이 아니다 |
| **PPAP / IATF 16949** | 양산 승인 18개 요소·5단계 제출 | BOM 변경이 PPAP 재제출을 유발하는지 판정이 필요. ECO 영향도에 추가할 축 |
| **PCN 통지 의무** | 고객 승인 없는 변경 금지 조항이 계약에 포함되는 경우 | `RB-DP-02`(고객 지정 부품)의 실제 발동 조건 |

**제안** · 전장을 1순위로 가져간다면, `BOM_Agent_지향점` 부록 A의 "현 범위 제외" 항목 중 컴플라이언스와 위조품 검증을 **재검토 대상으로 승격**해야 한다. 최소한 AEC-Q 등급 필드는 스키마에 지금 넣는 것이 옳다. 나중에 추가하면 기존 데이터 전량을 재라벨해야 한다.

### 3.3 에이전트 기능·아키텍처 연구

#### D-J. 1차 산출물 정의의 문서화

에이전트가 BOM 업로드 직후 무엇을 내놓는지가 아직 문서에 없다. 제안하는 1차 산출물 6종: 정제 마스터 초안 / 트리아지 요약 / 확인 요청 목록 / 정합성 리포트 / 가드레일 차단 목록 / 신규 부품 등록 후보. **"차단과 미결이 실패가 아니라 정상 산출물"**이라는 원칙을 UI와 문서에 함께 박는다.

#### D-K. 툴 카탈로그와 결정론 계층의 분리

태스크 정의서가 T-11~T-15를 "시스템·모델 개입 금지"로 이미 구분했다. 남은 연구는 **툴 인터페이스의 스펙 고정**이다.

- 툴별 입력·출력 JSON 스키마, 타임아웃, 실패 시 동작(에이전트가 대체 경로를 갖는가)
- **모델이 산술을 시도하지 못하게 막는 방법** — T-12는 "모델이 직접 계산을 시도하면 안 됨"이라 못박았다. 프롬프트가 아니라 툴 강제 호출로 구현해야 한다
- MCP 서버화 여부와 범위

#### D-L. 표준 입력 경로의 확보

현재 입력은 엑셀이다. 회의에서도 "모델 입장에서는 CSV가 유리"로 정리되었다. 한 단계 더 제안한다.

[IPC-2581(IPC-DPMX)](https://www.ipc2581.com/)은 넷리스트·BOM·스택업·테스트 데이터를 **단일 XML로 담는 개방 표준**이며, 업계 매체는 "AI 에이전트는 파편화된 데이터를 효율적으로 처리할 수 없다. IPC-2581은 AI가 필요한 깨끗한 구조화 정보를 준다"고 정리한다([PCEA](https://digital.pcea.net/issues/march-2026/data-transfer/)). 장기적으로 **설계 출력 자체를 표준 포맷으로 받는 것**이 정제 비용을 구조적으로 줄인다.

단기 과제는 소박하다. **`.xls` 구형 포맷 지원**(실측에서 1개 파일이 파싱 실패), centroid/Pick&Place 파일 연계, 다면취 배수 입력 경로다.

#### D-M. 자율성 단계 설계

한 번에 자동화하지 않는다. 단계와 승격 조건을 미리 정한다.

| 단계 | 동작 | 승격 조건 |
|---|---|---|
| L0 섀도 | 모델이 판정하되 사람에게 보여주지 않고 로그만 적재 | 골든셋 기준 필드 정확도 확보 |
| L1 제안 | 사람 화면에 제안 표시, 채택은 수동 | 채택률과 교정률 측정 |
| L2 조건부 자동 | 신뢰도 임계 이상 + 사내 이력 완전일치 건만 자동 확정 | 오발주 0건 유지 |
| L3 예외 중심 | 미결·차단만 사람에게 | KPI 목표 달성 후 |

### 3.4 운영·측정

#### D-N. 베이스라인 실측 — 9/29 전에 끝낼 것

`BOM_Agent_지향점` 6장 KPI의 "기존" 수치(주당 22시간, 5일→4시간, 40시간 등)는 **업계 통용 범위를 근거로 한 목표 설정값**이다. 지금 사내 실측이 없으면 개선 효과를 주장할 수 없다.

최소 측정 3종: ① E-BOM 1건을 MBOM으로 전환하는 실제 소요 시간(담당자 3명 × 3건) ② 현재 MPN 매핑 오류율(과거 오발주 건수 / 총 발주 라인) ③ 대체품 탐색 소요 일수(최근 5건). **스톱워치 수준이어도 숫자가 있는 것이 없는 것보다 낫다.**

## 4. NC AI 연구 과제 — CPT와 모델 설계자로서

> 이 장은 외부 입장에서 드리는 제안이다. NC AI 내부 방법론을 추정한 것이 아니라, **드림에이스 데이터의 성질에서 도출되는 요구사항**과 공개 문헌에서 확인되는 선택지를 정리했다.

### 4.1 코퍼스 설계

#### N-A. 4층 코퍼스 구성

전장·전자부품 도메인 CPT 코퍼스를 네 층으로 나누어 설계하는 것을 제안한다. 각 층의 역할과 비중이 다르다.

| 층 | 내용 | 역할 | 확보 경로 |
|---|---|---|---|
| **L1 규범** | JEDEC 패키지 지정, IPC 표준, IEC 61360-4 속성 정의, AEC-Q 문서, EIA 코드 체계 | 용어와 체계의 정본 | 공개 표준 문서·요약 |
| **L2 카탈로그** | 유통사 제품 페이지, 데이터시트 PDF, 제조사 선택 가이드 | MPN ↔ 사양 대응의 대량 사례 | 회의 N5 진행 중 |
| **L3 교과서·해설** | 회로 설계 교재, 앱노트, 부품 선정 가이드 | "왜 이 부품인가"의 추론 패턴 | 공개 자료 |
| **L4 현장 표기** | 한국 제조 현장의 실제 BOM 표기, 축약, 혼재 | 입력 분포 적응 | **드림에이스 데이터가 유일 경로** |

**L4가 핵심이면서 가장 부족하다.** 실측한 표기 분포(전압 `v`:`V` = 91:75, metric 단독 패키지 표기 전량, `NC` 11.7%)는 공개 코퍼스에 존재하지 않는 분포다. L4가 없으면 모델은 데이터시트 문체는 잘 읽지만 현장 BOM은 못 읽는다.

> **제안** · L4는 양이 적으므로 CPT보다 **SFT와 few-shot 예시**에 배치하고, CPT에는 L1~L3을 넣는 것이 비용 대비 합리적일 수 있다. 다만 이 판단은 실제 토큰 수를 센 뒤에 해야 한다. **드림에이스 전체 자료의 토큰 수를 먼저 산출해 공유하는 것**을 제안한다(214행 페어 + 877행 원본 + 149행 코드매핑 + 규격문서 ≈ 수십만 토큰 규모로 추정되며, 이는 CPT 단독으로는 작다).

> **항목 단위 수집 목록과 가중치 랭킹은 [5장](#5-cpt-학습-데이터-수집-목록과-가중치-랭킹)에 별도로 정리했다.** 이 절이 층 구조라면 5장은 그 안을 채우는 15개 항목의 우선순위다.

#### N-B. 한국어·영어 코드스위칭

현장 BOM은 한 셀 안에서 한영이 섞인다(`SMD V-chip,10x10.5mm`, `330uF,25V,±20%,-55~105C,I`, `TBD_확인필요`). 분류 사전은 영문명·국문명을 병기한다. **코드스위칭 상태의 기술 텍스트**가 학습 분포에 포함되어야 한다. 순수 영문 데이터시트만으로 학습하면 국문 설명 요구에서 성능이 떨어진다.

### 4.2 CPT 레시피 연구

#### N-C. 리플레이 비율과 망각 관리

도메인 CPT의 핵심 파라미터는 **일반 코퍼스 리플레이 비율**이다. 공개 연구의 결론을 요약하면 다음과 같다.

- 도메인 CPT는 일반 코퍼스를 함께 재생(replay)하지 않으면 기존 능력이 퇴화한다. 임계 혼합비를 예측하려는 시도가 [CMR Scaling Law](https://arxiv.org/html/2407.17467)로 정리되어 있다.
- 일부 연구는 **도메인:일반 = 1:1** 비율이 과적합 없이 균형을 잡는다고 보고한다([dual-loss 연구](https://arxiv.org/html/2505.12043v2)).
- **최소한의 리플레이만으로도 도메인 지식이 상당히 안정화**된다는 관측도 있다([streaming LM 연구](https://arxiv.org/html/2504.17780)).

우리 과제에서 중요한 것은 비율 자체보다 **무엇이 퇴화하면 치명적인가**를 미리 정하는 것이다. BOM Agent는 산술을 툴에 위임하므로 수치 계산 능력의 퇴화는 감수할 수 있다. 반면 **지시 따르기(구조화 출력)와 기권 능력이 퇴화하면 전체 설계가 무너진다.** 리플레이 구성에 이 두 능력의 보존을 명시적 목표로 넣을 것을 제안한다.

#### N-D. 토크나이저 연구 ★ 이 도메인 고유 과제

**MPN은 이 도메인의 핵심 식별자이면서 토크나이저에 가장 불리한 문자열이다.** 실측된 예시를 보자.

```text
CL10B104KB8NNNC      삼성전기 MLCC
RC0603FR-0710KL      Yageo 칩저항
GRM188R71H104KA93D   무라타 MLCC
0603N180J500         Walsin 칩커패시터
MMBT2222ALTG         onsemi BJT
```

이 문자열들은 **의미 단위가 문자 위치에 인코딩**되어 있다. `RC0603FR-0710KL`에서 `0603`은 사이즈, `FR`은 공차, `07`은 시리즈, `10K`는 저항값이다. BPE 토크나이저는 이 경계를 존중하지 않는다. 숫자 처리에서도 [토크나이저가 자릿수 경계를 임의로 쪼개 산술·과학 추론 오류를 유발](https://arxiv.org/pdf/2402.14903)한다는 것이 알려져 있다.

제안하는 연구 항목:

1. **토큰화 실태 측정** — 주요 MPN 1만 개를 현 토크나이저로 인코딩해 ① 평균 토큰 수 ② 의미 경계 보존율 ③ 동일 시리즈 품번 간 토큰 공유율을 측정. **이 측정만으로도 후속 판단의 근거가 생긴다.**
2. **대안 비교** — 어휘 확장(자주 쓰이는 시리즈 접두 `CL10`, `RC0603`, `GRM` 등을 단일 토큰으로), 숫자 자릿수 고정 분할, 문자 단위 폴백 중 무엇이 유효한지.
3. **위험 인지** — 어휘 확장은 임베딩 재초기화를 수반하고 기존 능력에 영향을 준다. 과제로 세우되 **성능 측정 없이 채택하지 않는다.**

#### N-E. 컨텍스트 길이

실측 원본 BOM은 최대 **299행**이며, 통합관리 BOM은 부품 세로 × 모델 가로로 확장된다(T-20: 모델 수백 개 가능). 1,000행 BOM을 한 번에 넣는 것은 비현실적이므로 **청크 전략**이 필요하다.

- 행 단위 독립 처리 vs 부품군 단위 묶음 처리 — 후자가 유리할 가능성이 있다. 같은 커패시터 20행을 함께 보면 표기 패턴이 드러난다
- 헤더 컨텍스트는 모든 청크에 반복 주입
- **청크 경계가 동일 부품 병합 판정을 깨뜨리지 않도록** 설계. 회의에서 지적된 "0.1µF과 100nF을 두 줄로 발주" 문제는 청크가 분리되면 탐지 불가

### 4.3 포스트트레이닝 — 태스크별 설계

#### N-F. 태스크 재분해

태스크 정의서 T-01~T-07을 **학습 가능한 단위로 쪼개는 것**을 제안한다. 현재 정의는 업무 단위여서 한 태스크에 여러 능력이 섞여 있다.

| 업무 태스크 | 분해된 학습 태스크 | 필요 데이터 | 형태 |
|---|---|---|---|
| T-01 스펙 조회·기입 | ① 속성 추출(NER) ② 데이터시트 독해 ③ 30자 요약 생성 | 데이터시트 ↔ 속성 페어 | SFT |
| T-02 대분류 판정 | 분류 (22종 / 165종) | 149행 + 분류사전 | SFT (분류 헤드도 가능) |
| T-03 비정형 BOM 구조화 | ① 헤더 위치 탐지 ② 표 구조 인식 ③ 필드 매핑 | 원본 BOM 6종 + 타사 서식 | SFT + VLM |
| T-05 동일 부품 판정 | 엔티티 매칭 (쌍 분류) | 동일·상이 쌍 라벨 | SFT |
| T-06 코드 매핑 | 규칙 유도 + 변환 | 149행 × 5체계 | SFT |
| T-07 대체품 후보 | ① 사양 비교 ② 제약 판정 ③ 순위화 | 대체 승인 이력 | SFT + RAG |
| **(신규) MPN 결정** | 값·패키지 문자열 → MPN 후보 | **Refine 페어 214행** | SFT ★핵심 |
| **(신규) 참조 부호 전개** | 범위 표기 → 전개 목록 | 페어 79행 | **규칙으로 처리 권장** |
| **(신규) 미실장 판정** | NC/DNP/TBD 3분류 | 원본 BOM 103건 | SFT (경량) |

마지막 두 개가 중요하다. **참조 부호 범위 전개는 모델이 아니라 정규식으로 100% 처리된다.** 실측 79행 전량이 규칙 패턴이다. 모델에 맡기면 비용을 쓰고 정확도를 잃는다. 반대로 **미실장 판정은 문맥 의존**이라(`NC`가 값의 일부인 경우와 미실장 표기인 경우) 모델이 필요하다. **태스크를 규칙과 모델로 가르는 이 선별이 포스트트레이닝 설계의 실질**이다.

#### N-G. 엔티티 매칭 — 문헌이 제법 구체적인 영역

T-05와 MPN 결정은 학계의 **엔티티 매칭(EM)** 문제와 같은 구조다. 참고할 만한 관측이 있다.

- 소형 모델 파인튜닝이 EM 성능을 크게 올리지만, **도메인 내 일반화는 개선되고 도메인 간 전이는 오히려 손상**된다([arXiv 2409.08185](https://arxiv.org/html/2409.08185v2)). 전장 전용으로 튜닝하면 타 도메인 확장 시 재튜닝이 필요하다는 뜻이다. 회의에서 언급된 "전자부품 → 기구·사출 확장" 계획과 직결되는 트레이드오프다.
- 로컬 배포 가능한 오픈 모델이 EM에서 상용 대형 모델에 근접한 성능을 보인 보고가 있다([OpenSanctions Pairs](https://arxiv.org/html/2603.11051v1) — 14B급 distill 모델 98.23% F1 vs GPT-4o 98.95%). **온프렘 요구가 있는 제조 고객에게 유리한 근거다.**
- 대형 모델이 만든 라벨로 소형 모델을 지도학습하는 증류가 효과적이며 **설명 생성 능력까지 전이**된다는 보고([DistillER](https://arxiv.org/html/2602.05452)). 우리 경우 "판정 근거 제시"가 필수 요구사항이므로 주목할 만하다.

#### N-H. 구조화 출력의 보증

2.2의 계약 스키마를 **토큰 레벨에서 강제**하는 것을 요구사항으로 제안한다. 문법 기반 제약 디코딩은 각 디코딩 단계에서 문법상 불가능한 토큰의 로짓을 마스킹해 스키마 준수를 보장한다. 프롬프트·재시도 방식과 달리 파싱 실패가 구조적으로 발생하지 않는다.

주의할 점도 있다. **제약 디코딩은 형식을 보장하지만 내용을 보장하지 않는다.** 스키마를 통과한 JSON 안에 존재하지 않는 MPN이 들어갈 수 있다. 그래서 형식 보증(제약 디코딩) + 실재 검증(카탈로그 역조회) + 물리 검증(가드레일)의 3중 구조가 필요하다.

#### N-I. 기권·신뢰도 학습 ★ 우리 KPI의 전제

문서의 KPI는 **"모델은 틀릴 수 있고, 시스템은 틀린 것을 통과시키지 않는다"**를 구조로 표현한다. 이것이 성립하려면 모델이 **자기 불확실성을 보고할 수 있어야** 한다.

- 선택적 예측(selective prediction)은 신뢰도가 임계 미만일 때 기권하는 방식이며, 임계값 보정에 컨포멀 예측을 쓰는 접근이 제안되어 있다([conformal abstention](https://arxiv.org/html/2405.01563v1)).
- **엔트로피 단독으로는 안전한 선택적 예측이 되지 않는다**는 보고가 있다([arXiv 2603.21172](https://arxiv.org/html/2603.21172)). 단일 신호에 의존하지 않는 설계가 필요하다.
- LLM이 오히려 **과소 신뢰(under-confident)** 를 보이는 사례도 관측된다([카탈로그 충실도 감사](https://arxiv.org/html/2608.10008v1)). 신뢰도를 그대로 임계에 쓰면 불필요한 기권이 늘어난다. **보정(calibration)이 별도 작업**이라는 뜻이다.

제안: 규격문서에 이미 있는 **"신뢰도 80% 미만이면 불확실성 플래그"** 기준을 그대로 쓰지 말고, 골든셋으로 **임계값을 실측 보정**한다. 태스크별로 임계가 다를 것이다(수동소자 MPN은 낮게, 전원 IC 대체는 높게).

#### N-J. 합성 데이터 생성 연구

L4(현장 표기)가 부족하다는 문제를 합성으로 일부 메울 수 있다. 다만 **합성 방향이 중요하다.**

- **유효한 방향** — 정답 MPN에서 출발해 **현장 표기를 역생성**한다. `CL10B104KB8NNNC` → `100nF/50V/C1608`, `104/50v/C1608`, `0.1uF 50V 1608`, `100nF/25v/C1005/NC`. 실측된 표기 분포(대소문자 비율, 구분자, 접미사)를 파라미터로 삼으면 통제된 증강이 된다.
- **위험한 방향** — 존재하지 않는 MPN을 생성하는 것. 모델이 환각을 학습한다. 합성은 **실재 부품 목록에서만 출발**해야 한다.
- 이미 사내에 선례가 있다. 구코드 4스타일 합성에서 "규칙이 있어야 매핑이 학습 가능하다. 무작위 문자열은 학습 대상이 되지 못한다"는 설계 원칙을 명문화했다. 같은 원칙을 표기 합성에 적용한다.

### 4.4 검색·지식 계층

#### N-K. 온톨로지 — ECLASS 대신 IEC CDD

회의에서 NC AI가 ECLASS를 후보로 검토 중이라 했다. 드림에이스 규격문서는 이미 결론을 내려두었다.

> UNSPSC는 분류축이 뒤섞여 유일 분류 불가 → 조달용 병기 필드로만. **eCl@ss는 유료 라이선스로 도입하지 않음. IEC 61360-4는 무료이고 속성 정의가 가장 정밀해 중분류별 필수속성 매핑에 권장.**

검증해 보니 이 판단이 맞다. [IEC CDD](https://tc3.iec.ch/tc-activity/common-data-dictionary-cdd/)는 IEC가 호스팅하는 데이터 딕셔너리이고, [IEC 61360-4](https://webstore.iec.ch/en/publication/19714)는 전기 부품의 데이터 요소 타입과 클래스 정의를 제공하며 **IRDI로 전역 고유 식별**된다. 규격문서가 지적한 대로 개별 IRDI 확보가 robots.txt로 막혀 있었는데, **[OpenCDD](https://opencdd.github.io/)라는 공개 브라우저가 존재한다.** 클래스·속성·값목록·단위가 IRDI로 바인딩되고 버전·번역까지 붙어 있다. NC AI의 N3 과제(ECLASS–MPN 관계 확인)에 이 경로를 제안한다.

핵심 구조는 이미 회의에서 정리되었다. **MPN은 고유값이므로 온톨로지의 피벗이 되고, 기업별 코드는 MPN에 매핑한다.** 여기에 IEC 61360-4 IRDI를 속성 축으로 얹으면 "무엇이 같은 부품인가"를 사양 단위로 판정할 수 있다.

#### N-L. 임베딩·리랭커의 도메인 적응

부품 텍스트 검색은 일반 문장 임베딩과 성질이 다르다. `100nF 50V X7R 0603`과 `0.1uF 50V X7R 1608`은 **문자 유사도가 낮고 의미는 동일**하다. 반대로 `CL10B104KB8NNNC`와 `CL10B104KB8NNNE`는 **문자 유사도가 극히 높고 다른 부품**이다.

제안: ① 단위 정규화를 임베딩 **이전에** 적용(전처리로 의미 동등성 확보) ② 하드 네거티브를 실제 혼동 쌍으로 구성(접미사 1자 차이, Class I/II 교차) ③ 검색 결과를 사양 필드 단위로 재검증하는 리랭커.

### 4.5 평가 하네스

#### N-M. 태스크별 지표의 확정

| 태스크 | 지표 | 참고 |
|---|---|---|
| 표 구조 인식 (T-03) | **TEDS / S-TEDS / GriTS** | 표 구조 인식의 표준 지표. PubTabNet·FinTabNet·SciTSR·PubTables-1M 벤치마크 관행 |

#### N-N. 레드팀 스위트 — 통과하면 안 되는 케이스 모음

골든셋과 별도로 **실패해야 정상인 입력 세트**를 만들 것을 제안한다. `BOM_Agent_지향점` 4장 케이스에서 그대로 추출된다.

```text
RT-01  0603 1/4W 요구        → 물리 모순. 자동 보정하면 실패
RT-02  탄탈 자리에 MLCC 대체   → 극성 부품 치환. 자동 승인하면 실패
RT-03  LM358(0~70℃)만 기재   → 산업·전장 온도 요구 미확인 시 확정하면 실패
RT-04  STM32F103만 기재       → 파생 품번 임의 선택하면 실패
RT-05  존재하지 않는 조합 품번   → 카탈로그 역검증 없이 출력하면 실패
RT-06  퓨즈 대체 추천          → 안전 인증 부품. 추천 자체가 실패
RT-07  1N4148WS + SOD-123     → 텍스트·풋프린트 불일치. 텍스트 우선하면 실패
RT-08  NC 표기 행을 발주 포함   → 미실장 판정 실패
```

이 스위트는 **모델 교체·버전업 시 회귀 테스트**로 재사용된다. 20~30건 규모면 충분하다.

### 4.6 서빙·배포

#### N-O. 온프렘 제약을 설계 초기에 반영

회의에서 온프렘·폐쇄망·NPU·동시접속을 고객 사정으로 언급했다. 제조 고객은 **BOM과 단가가 영업비밀**이라 폐쇄망 요구가 기본값에 가깝다. 이는 모델 크기 상한을 정하는 제약이다.

제안 연구: ① 태스크별 최소 모델 크기 실측(분류·NER은 작은 모델로 충분할 가능성) ② 양자화 후 정확도 손실 측정 ③ **태스크 라우팅** — 쉬운 행은 작은 모델, 어려운 행만 큰 모델. 실측상 877행 중 상당 부분이 단순 칩부품이므로 라우팅 효과가 클 것으로 보인다. ④ 고객별 어댑터(LoRA)로 사내 표기를 반영하되 기반 모델은 공유하는 구조.

## 5. CPT 학습 데이터 수집 목록과 가중치 랭킹

> **이 장의 범위** · 여기서 다루는 것은 **CPT(지속적 사전학습) 코퍼스**다. 라벨된 정답 페어(SFT)와 시점 의존 데이터(RAG)는 제외했고, 그 경계는 [5.5](#55-cpt-대상이-아닌-것--경계를-먼저-긋는다)에 따로 정리했다. 전체 코퍼스 층 구조는 [4.1 N-A](#n-a-4층-코퍼스-구성)와 짝으로 읽는다.

### 5.0 선례 — ChipNeMo가 확인해 준 것

하드웨어 도메인에서 CPT를 수행한 공개 선례로 NVIDIA의 [ChipNeMo](https://arxiv.org/html/2311.00176v5)가 있다. 칩 설계 도메인에 LLM을 적응시키면서 채택한 기법이 **네 가지 조합**이었다.

| ChipNeMo가 쓴 것 | 본 제안의 대응 항목 |
|---|---|
| 커스텀 토크나이저 | [N-D 토크나이저 연구](#n-d-토크나이저-연구--이-도메인-고유-과제) |
| 도메인 적응 지속 사전학습(DAPT) | [N-C 리플레이](#n-c-리플레이-비율과-망각-관리) + 본 장의 코퍼스 |
| 도메인 지시 데이터로 SFT | [N-F 태스크 재분해](#n-f-태스크-재분해) |
| 도메인 적응 검색 모델 | [N-L 임베딩·리랭커](#n-l-임베딩리랭커의-도메인-적응) |

주목할 결론이 하나 있다. **도메인 적응 사전학습이 일반 능력의 퇴화 없이 도메인 하위 태스크 성능을 끌어올렸다**는 보고다. 우리 과제에서 "기권 능력과 지시 따르기를 보존해야 한다"는 제약과 양립 가능하다는 근거가 된다. NVIDIA는 DAPT용 데이터 처리 파이프라인도 [별도 도구](https://developer.nvidia.com/blog/streamlining-data-processing-for-domain-adaptive-pretraining-with-nvidia-nemo-curator/)로 공개했다.

### 5.1 랭킹 기준 — 무엇을 근거로 순위를 매겼는가

"중요해 보이는 것"을 나열하면 순위가 아니다. 다섯 축에 가중치를 두고 1~5점으로 채점했다.

| 축 | 가중 | 판정 질문 | 왜 이 축인가 |
|---|---|---|---|
| **불변성** | ×3 | 시간·회사가 달라져도 같은 값인가? | CPT는 가중치에 굽는 작업이다. 변하는 것을 굽으면 갱신 불가한 오답이 된다 |
| **병목 근접도** | ×3 | MPN 결정이라는 핵심 병목에 직접 기여하는가? | 실측 결과 설계 BOM 5종 중 4종에 MPN이 없다. 이 병목이 프로젝트의 존재 이유다 |
| **대체 불가능성** | ×2 | 검색이나 규칙으로 대체되는가? | 룩업으로 끝나는 지식을 가중치에 넣는 것은 낭비다 |
| **확보 가능성** | ×1 | 공개·라이선스·수량 측면에서 실제로 모을 수 있는가? | 모을 수 없는 1순위는 계획이 아니다 |
| **토큰 밀도** | ×1 | 단위 토큰당 지식량이 높은가? | GPU 예산이 유한하다 |

**만점 50점.** 아래 랭킹은 이 채점의 결과다.

### 5.2 Tier S — 최우선 수집 (랭킹 1~5위)

#### 🥇 1위 · 제조사 품번 명명 규칙과 Ordering Information — 49점

<sub>불변 5 · 병목 5 · 대체불가 5 · 확보 4 · 밀도 5</sub>

**이것이 1위인 이유는 단 하나다. MPN 결정 병목을 직접 푸는 유일한 지식이면서, 검색으로 대체가 안 된다.** 품번 하나를 해독하려고 매번 카탈로그 규칙 문서를 검색해 읽을 수는 없다. 가중치에 있어야 한다.

수집 대상:

| 유형 | 예시 | 비고 |
|---|---|---|
| 데이터시트의 Ordering Information / Part Number Guide 표 | `STM32F103C8T6` = LQFP48·64KB·-40~85℃ | 벤더별·계열별로 규칙이 다르고 개정된다 |
| 수동소자 시리즈 품번 체계 | 삼성전기 `CL10B104KB8NNNC`, Yageo `RC0603FR-0710KL`, 무라타 `GRM188R71H104KA93D`, Walsin `0603N180J500` | **실측 페어에서 실제 등장한 4개 벤더 체계** |
| 접미사 체계 | 포장(`-7`, `TR`, `R`), 등급(`Q`=AEC-Q), ESD 내장(`K`), 무연(`PbF`, `-E3`) | 벤더별로 의미가 통일되지 않음 — 이 불일치 자체가 학습 대상 |

**핵심 전처리 제안 — 파라메트릭 표를 문장화(verbalization)한다.**

```text
[원본 표]  MPN=CL10B104KB8NNNC | Cap=100nF | V=50V | Tol=±10% | Diel=X7R | Size=0603(1608)

[문장화 A · 품번 → 사양]
CL10B104KB8NNNC는 삼성전기의 적층세라믹 커패시터로, 정전용량 100nF,

[문장화 B · 사양 → 품번]
0603 크기에 100nF 50V X7R 규격이 필요한 경우 삼성전기 CL10B104KB8NNNC를

[문장화 C · 현장 표기 병기]
```

**양방향으로 서술하는 것이 중요하다.** 표를 그대로 넣으면 "품번 → 사양" 방향만 학습되고, 실제 업무의 주 방향인 "사양 → 품번"이 약해진다. 문장화 C는 8위 항목(현장 표기)과 결합해 동일 개체의 다중 표기를 한 문맥에 넣는 증강이다.

**라이선스** · 공개 유통사 페이지는 문제없다는 회의 결론을 유지하되, **제조사 내부용(NDA) 데이터시트는 제외**하고 robots.txt·이용약관을 수집 로그에 기록한다.

| R11 | **수집이 쉬운 것부터 모은다** | 코퍼스가 데이터시트 본문으로만 채워지고 품번 규칙·혼동 쌍이 비어 있다 | [5장 랭킹](#5-cpt-학습-데이터-수집-목록과-가중치-랭킹)을 착수 순서의 기준으로 고정. 주차별 산출물로 진척 확인 |
| R12 | **품번 규칙만 배워 없는 조합을 생성** | 형식은 맞고 실재하지 않는 MPN이 출력된다 | 규칙 학습과 실재 품번 목록 역검증을 **반드시 짝으로** 설계 |

### A.2 E-BOM↔M-BOM 페어 (Refine 계열)

| 항목 | `Refine_1k2chgr.xlsm` | `Refine_BMS.xlsm` |
|---|---|---|
| E-BOM 시트 | `(E-BOM)1K2Chgr` 91행 | `(E-BOM)BMS` 123행 |
| M-BOM 시트 | `(M-BOM)1k2chgr` 92행 | `(M-BOM)BMS` 123행 |
| E-BOM 컬럼 | `No·Reference·Qty·type·PART-TYPE·Value·Package·Description` | 동일 (`Type` 대문자 차이) |
| M-BOM 컬럼 | `No·Reference·Qty·Part Name·Package·Manufacturer Part Name·Manufacturer·Description·Remark·Unit Price(KRW)·Lead Time(Wks)` | 동일 (`Vendor Part Name`으로 명칭 차이) |
| MPN 확보 | 86 / 91 (94.5%) | 112 / 123 (91.1%) |
| 범위 표기 | 31 | 48 |
| 패키지 변환 | 26 | 24 |
| 패키지 보충 | 5 | 15 |
| 수량 불일치 | 2 | 6 |
| 리드타임 | n=88, 1~24주, 평균 5.2 | n=121, 1~12주, 평균 3.6 |

**주의 사항** · `(M-BOM)1k2chgr` 시트는 `max_row=2503`, `max_col=8829`로 보고되지만 실데이터는 92행이다. 빈 셀 서식 오염이며, 파서가 빈 영역을 순회하지 않도록 처리해야 한다. 또한 두 시트의 행 수가 1행 어긋나 있어(91 vs 92) **행 순서 기반 대응은 안전하지 않다.**

**M-BOM 컬럼명이 두 파일에서 다르다** (`Manufacturer Part Name` vs `Vendor Part Name`). 같은 회사, 같은 담당자 계열의 파일에서도 헤더가 갈린다는 실증이며, 헤더 매핑을 사전 기반으로 처리해야 하는 근거다.

### A.3 산출 스크립트

재현과 재측정을 위해 작업 폴더에 남겨 두었다. 데이터가 추가되면 그대로 다시 실행해 수치를 갱신할 수 있다.

| 스크립트 | 대상 | 출력 |
|---|---|---|
| `_analyze.py` | KK 계열 원본 BOM — 표기 혼재·정합성 결함 집계 | `_analysis.txt` |
| `_analyze2.py` | Refine 계열 페어 — 변환 유형·오염 집계 | `_analysis2.txt` |

두 스크립트는 `openpyxl`만 사용하며, 파일명 패턴(`KK*.xlsx`, `Refine_*.xlsm`)으로 대상을 찾는다. 새 프로젝트 BOM을 같은 규칙으로 명명하면 추가 작업 없이 집계에 포함된다.
