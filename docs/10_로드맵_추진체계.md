# 10. 로드맵과 추진 체계

> 다섯 단계로 나눈다. 0단계에서 기준정보와 합의를 준비하고, 1단계에서 초안을 만들고, 2단계에서 확정·ERP 등록·개정 관리를 붙이고, 3단계에서 외부 통보와 원가 영향을 다루고, 4단계에서 전 모델로 넓힌다. 일정은 [가안]이며 NC AI 모델 일정에 맞춰 조정한다.

**확장 게이트** [제안 · DEC-18] · 단계가 올라가며 부서별 기능이 늘어도 시작과 뿌리는 BOM이다. 2단계 이후에 기능을 더할 때마다 [docs/04 1.1 BOM 뿌리 지도](04_기능_범위.md)에 "BOM에서 읽는 것"과 "BOM에 돌려주는 것"을 한 줄로 적을 수 있어야 한다. 적을 수 없으면 단계에 넣지 않고 미결로 올린다. 4단계 '확산'도 새 업무 영역이 아니라 줄기와 가지를 전 모델·전 부서로 넓히는 일이다.

**0단계 선행 미결 6건** · OI-01(적용 시장 기본값), OI-02(사내 변경 용어), OI-05(ERP 코드 접미 정책), OI-07(Amaranth 등록 방식), OI-09(검색 계층 소유), OI-15(9/29·10/02·10/16 회의 결정 반영). 상세는 [docs/11](11_결정_미결_목록.md).

## 2. 협력사 일정과의 연결

- NC AI 모델의 학습 설계 → 데이터 가공 → 학습 → 서빙 일정에는 아직 날짜가 없다(R01 5장, OI-11).
- 다봄은 모델을 스키마 버전으로 분리해 둔다. 그래서 모델 준비와 상관없이 1단계의 규칙 계층(구조 해독, 동일 MPN·사내 이력 매칭, 수량 계산, ERP 코드, 양식 출력)을 먼저 만든다.
- 모델이 필요한 기능(표기 해석 `IMP-05`, 후보 판정 `MAT-06`)은 NC AI 모델이나 보안 승인을 받은 임시 모델(OI-12)이 준비될 때 붙인다. 그 전에는 해당 행을 미결로 두고 사람이 처리한다. 그 처리 기록이 결정 기록과 평가 데이터가 된다.
- 양사 기술 회의에서 인터페이스 변경과 평가 결과를 공유한다.

## 7. 변화관리와 교육

- 1~2단계는 기존 엑셀 업무와 병행한다. 다봄 결과와 사람 결과를 비교해 교정 로그를 쌓는다(A0~A1).
- 키유저가 부서 교육을 맡는다. 부서별로 한 쪽짜리 사용 안내(무엇을 올리고, 무엇에 답하고, 무엇을 승인하는가)를 만든다.
- 운영위원회 승인 뒤 사내 절차에 넣는다: E-BOM 출도 시 다봄 업로드, 변경 요청은 다봄 변경 패키지로, 신규 품목 등록 요청은 다봄을 거쳐서.
- 성과는 베이스라인과 비교해 매월 공유한다.

## 8. 비용 항목 (금액 미산정)

- 모델 API 사용료 또는 사내 서빙 비용(미논의, R01 2.6, OI-11)
- 다봄 서버·저장소
- 개발 인력
- 기준정보 정비 인력(0~1단계 집중)
- ERP 연동 비용(더존 측 작업이 필요한 경우, OI-07)
- 유통사 API 이용 조건(약관·호출 한도)
- 병행 운영 기간의 현업 시간
