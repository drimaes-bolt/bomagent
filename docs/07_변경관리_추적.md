# 07. 변경관리와 추적

> M-BOM은 상태다. 모든 변경은 사유 코드와 변경 층을 가진 변경 패키지로 들어오고, 층과 적용 시장에 따라 승인 경로가 정해지며, 효력 시점과 기존 재고 처분이 함께 결정된다. 개정은 덮어쓰지 않고 쌓으며, 개정 이력은 자동으로 남는다. 이 문서의 체계는 R04(M-BOM 다단계 확정 시나리오)를 이어받았다.

---

## 1. 기본 관점

- M-BOM은 '양산 중이거나 양산 예정인 제품의 최신 상태'다(10/16 미팅). 양산 뒤에도 여러 번 개정된다.
- 개정마다 상태 필드를 둔다(R04 6.1).

| 필드 | 값 | 쓰임 |
|---|---|---|
| `BOM_Stage` | S0~S6 | 변경 통제 강도와 승인 경로 |
| `Baseline_Flag` | 양산 기준선 여부 | 기준선 뒤 변경은 고객 승인 판정 대상 |
| `Certified_Revision` | 인증 시험에 쓴 개정 | 인증 구성 부품 변경 시 재시험 경고 |
| `Target_Market` | 산업용 · 전장 · 기타 | 승인 경로, 원산지·환경 규제 선택 |

- 각 개정은 이전 개정과 변경 패키지로 연결된다. 어느 개정에서든 "무엇이, 왜, 누구 승인으로, 언제부터" 바뀌었는지 거슬러 볼 수 있어야 한다.

## 2. 변경의 층 (R04 1.4)

| 층 | 무엇이 바뀌나 | E-BOM 영향 | 승인(산업용) | 예 |
|---|---|---|---|---|
| L1 설계 변경 | FFF, 회로, 풋프린트 | 있음 | 연구소 + 변경위원회 | 부품 추가·삭제, 정격·패키지 변경 |
| L2 승인 대체 전환 | 같은 E-BOM 행 안에서 승인된 다른 MPN으로 | 없음 | 구매/자재(+ 품질 확인) | 2nd source 사용, 제조사 변경 |
| L3 조달 속성 변경 | 공급처·포장·단가·리드타임. 부품은 같다 | 없음 | 구매/자재 | 유통사 변경, 릴 크기 접미사 변경 |
| L4 공정·부자재 변경 | E-BOM에 없는 M-BOM 전용 행 | 없음 | 생산관리(생산기술) | 솔더 페이스트, 방열 패드, 펌웨어 기입 방식 |
| 정정 | 실물은 그대로, 기록만 실물·설계에 맞춘다 | 없음 | 가벼운 경로 | 수량·참조부호 불일치 수정 |

- **L3의 함정** · 포장 접미사만 바뀌어도 MPN 문자열이 달라진다. 동일 부품 판정(`MAT-02`)으로 L3로 분류해야 불필요한 승인이 생기지 않는다.
- **L1과 L2의 경계** · 승인 대체가 미리 있는 행은 공급 문제가 생겨도 L2로 끝난다. 없는 행은 L1로 올라가 설계 검증과(전장이면) 고객 승인을 거친다. AVL 확보가 변경 비용을 줄이는 이유다.
- **정정의 재분류** · 정정이 MPN·값·정격·패키지를 바꾸면 설계 변경으로 다시 분류한다(RB-CF-09).

| CR-10 | 인증·신뢰성 시험 | 품질 | L1 |

| CR-17 | 시제 → 양산 품번 전환 | 공급망 | L2 |

- 한시 편차·특채(R04 A12)는 코드를 따로 두지 않는다. 원래 사유 코드에 효력 유형 '한시'를 붙인다.
- 이 코드는 교정 로그의 사유 드롭다운이자 모델 학습 라벨로도 쓴다(R04 6.2).
- **초기 변환 기록 코드**는 사유 코드와 별개다. E-BOM을 처음 M-BOM으로 옮길 때의 처리를 남긴다. KK 샘플 범례에서 쓴 이름은 `S0-정규화`·`S0-미결`·`S0-추정`·`S0-검토`·`S0-표준품`·`S0-중복`·`S0-비구매`·`S0-NC`·`S0-Set`·`S0-추가(L4)`, `S1-확정`·`S1-미결해소`·`S1-표준품`, `확인`(변경 없이 확인 결과만), `반려`(검토 뒤 미적용)다.

## 4. 변경 패키지 (R04 6.3)

여러 행에 걸친 변경을 행 단위가 아니라 묶음 단위로 다룬다.

| 필드 | 내용 |
|---|---|
| `package_id` | 패키지 번호 |
| `reason_code` | CR-01~19 |
| `trigger_ref` | 발단 문서(변경 요청 번호, 통보 번호, 고객 요청서) |
| `affected_lines[]` | 영향 행(제품 × 모델 × 행) |
| `change_layer` | L1~L4 · 정정 |
| `effectivity` | 즉시 · 일자 · 시리얼 · 로트 · 재고 소진 후 · 한시(기한·수량) |
| `disposition` | 그대로 사용 · 재작업·재프로그래밍 · 폐기 · 소진 후 전환 |
| `approval_route` | 층 × 시장으로 자동 결정 |
| `customer_approval` | 불필요 · 필요 · 진행 중 · 승인 |
| `conflicts[]` | 같은 행에 걸린 다른 패키지, 충돌 규칙 결과 |
| `cost_impact` | 대당·연간 원가 변화, 처분 비용(`CST-03`) |
| `schedule_impact` | 리드타임에 따른 투입 일정 변화 |

**처리 흐름**

```text
접수 (변경 요청 · 고객 요청 · 외부 통보 · E-BOM 개정)
  → 영향 행 찾기 (where-used: 제품 × 모델 × 개정)
  → 층·사유 판정 (모델 제안 + 사람 확인)
  → 충돌 검사 (RB-CF)
  → 영향 분석 (재고 · 미결 발주 · 원가 · 일정)
  → 승인 라우팅 (층 × 시장, 병렬 승인)
  → 효력·처분 결정
  → M-BOM 새 개정 + ERP 변경 등록 파일
  → 개정 이력 기록
```

- 구매/자재·생산관리·품질은 변경 요청(ECR) 단계에서 알림을 받는다. ECN이 나온 뒤에 처음 알면 이미 발주가 진행 중이거나 재고가 쌓여 있을 수 있다(R04 2.1).
- 가격 인상처럼 한 제조사·시리즈 전체에 걸린 변경은 한 패키지로 묶는다. 묶음이 클수록 한 행이 막혀 전체가 늦어지므로, 막힌 행은 따로 떼어 낼 수 있게 한다(R04 2.5).

## 5. 승인 경로 — 층 × 적용 시장 (R04 5.4)

| 층 | 산업용 | 전장(PPAP 이후) |
|---|---|---|
| L1 | 연구소 + 변경위원회 | + 고객 승인 |
| L2 | 구매/자재(+ 품질 확인) | + 고객 승인(승인 구성 변경) |
| L3 | 구매/자재 | 구매/자재. 공급처 변경은 고객 통지 대상일 수 있다 |
| L4 | 생산관리(생산기술) | + 고객 통지 |
| 정정 | 기록 담당 + 관련 부서 확인 [제안] | 같음 |

다봄이 더하는 승인 [제안]

- 원가 영향이 기준을 넘으면 회계가 확인한다. 기준은 OI-13에서 정한다.
- 기준선(S5) 뒤의 변경은 전 부서에 통지한다.
- 인증 구성(`Certified_Revision`) 부품을 바꾸면 품질이 재시험 여부를 판단한다(RB-CF-05).
- '변경위원회'가 사내에 있는지, 누구로 구성되는지는 확인이 필요하다(OI-02).

## 8. 개정 이력 기록 형식

KK 샘플의 '개정이력' 시트를 기본 형식으로 쓴다.

| 열 | 내용 |
|---|---|
| 순서 · 시트 · 구분 | 개정 순번, 개정 시트 이름, M-BOM 또는 E-BOM |
| 단계 · 일자 · 기준 문서 | S0~S6, 개정 일자, 근거 문서(E-BOM 개정, 회신, 통보) |
| 변경 · 신규 · 삭제 · 확인 | 행 수 |
| 미결 MPN · 제조사 확인 필요 | 남은 미결 |
| 자재비 합계 | 개정별 자재비(단가 기준 표시) |
| 주요 내용 | 한 줄 요약 |

행 단위 표기

- 비고는 `[사유 코드 · 층] 사유` 형식으로 적고, 여러 건이면 ` / `로 잇는다. 예: `[CR-19 · 정정] 연구소 회신: …`
- KK 샘플은 변경 = 파랑, 신규 = 초록, 삭제 = 회색 취소선으로 표시했다. 다봄 화면은 같은 뜻을 색과 함께 글자·아이콘으로도 보여 준다. 색만으로 구분하지 않는다.
- 삭제 행은 지우지 않고 그 개정에서 취소선으로 남긴다.

## 9. E-BOM 변경과 M-BOM 변경의 연결

- E-BOM 개정(ECN)은 별도 개정으로 저장하고, 그것을 반영한 M-BOM 개정과 연결한다. KK13·KK16 샘플의 'E-BOM(2차)' 시트가 이 구조다(원 작업 폴더의 KK7·KK8·KK10·KK11도 같다).
- 구매·생산 사유의 변경이 회로·풋프린트를 건드리면(L1), M-BOM만 고치고 끝내지 않고 연구소에 E-BOM 변경 요청을 낸다.
- E-BOM이 그대로여도 M-BOM이 바뀌는 경우가 있다. 시제 → 양산 품번(A9), 펌웨어 개정(A10), 기록 정정(A11), 한시 편차(A12)다(R04 3장). 그래서 E-BOM 비교만으로 변경을 잡지 않는다.

## 10. 외부 통보 감시 (`ALR`)

| 통보 | 원천 | 다봄 처리 | 사람 |
|---|---|---|---|
| PCN·EOL | 제조사·유통사 공지 | 대상 MPN 매칭 → where-used → FFF 영향 분류 → 변경 패키지 초안, LTB 산정 근거 | 구매/자재·연구소 확인, LTB 수량 확정 |
| 가격 인상 | 제조사·유통사 통보, 업계 보도 | 제조사·시리즈 단위 영향 행·모델·연간 금액 | 구매/자재 대응 결정, 회계 확인 |
| 공급 중단 | 보도, 거래처 통보 | 제조사 노출도, 대체 가능 행 비율 | 구매/자재 |
| 규제 | 법령, 고객 통보 | 대상 시장 제품 표시 | 품질·법무 판단 |

- 반도체 업계는 J-STD-046에 따라 변경 시행 전 통상 90일 이상 사전 통지한다(R02 시나리오 H).
- 통보 자동 수집 범위(구독, 메일 해석)는 3단계에서 정한다. 그 전에는 사람이 통보를 등록하고 다봄이 영향을 찾는다.

|---|---|---|
| E51K 설계 BOM과 ERP 추출본의 거래처가 45행 다르다 [관측] | 언제, 왜 바뀌었는지 | L3 변경 패키지로 남기고 주거래처 변경 이력을 둔다 |
