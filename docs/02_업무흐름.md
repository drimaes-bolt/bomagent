# 02. 업무 흐름 — E-BOM 가져오기부터 유지 관리까지

> 연구소가 E-BOM을 올리면 다봄은 사내에 이미 있는 것(지정 부품·기존 품목·보유재고·사내 거래처)을 먼저 맞추고, 그다음 후보 부품 풀, 마지막으로 외부 후보를 찾는다. M-BOM은 한 번 만들고 끝나지 않는다. 기준선(양산 확정) 뒤에도 변경 패키지 단위로 계속 개정된다.

---

## 1. 전체 흐름

```text
 연구소                         다봄 (규칙·도구 + NC AI 모델)                              각 부서
 ──────                         ─────────────────────────────                              ──────
 E-BOM 업로드 ──▶ ① 가져오기     파일 구조 해독, 원문 보존, 표기 분류·사양 해석
                      │
                      ▼
                   ② 맞추기      지정 부품 → 사내 기존 품목(동일·동등, 재고 보유 → 사용 이력) → 후보 풀 → 거래처 카탈로그 → 외부 후보
                      │          품목별 사내 거래처·구매 조건, 승인 대체(AVL)
                      ▼
                   ③ 만들기      제품 → 반제품 → 부품 구조, 수량·LOSS, M-BOM 전용 행
                      │          (베어 PCB·펌웨어·Set 조립), Amaranth 양식 초안
                      ▼
                   ④ 품번        기존 ERP 코드 재사용 / 규칙 발번 / 발번 보류
                      │
                      ▼
                   ⑤ 확정        확인 요청 처리  ◀────────────────────────────▶  사양·후보·구조·품번 응답
                      │          부서 승인 → 기준선 → ERP 등록                    승인 (층 × 시장)
                      ▼
                   ⑥ 추적·알림   개정 비교, 변경 패키지, 효력·재고 처분, 원가 영향  ◀──  ECR·고객 요청·외부 통보
                      │          PCN·EOL·가격·공급 중단 감시 → 영향 BOM 역추적
                      └─────────▶ ②~⑤를 변경 패키지 단위로 다시 (양산 종료까지)
```

| 단계 | 모듈 | 핵심 질문 | 주 결정자 |
|---|---|---|---|
| ① 가져오기 | `IMP` | 이 파일의 각 행은 무엇인가 | 연구소(사양 확인) |
| ② 맞추기 | `MAT` | 사내에 이미 있는가, 무엇을 어디서 살 것인가 | 구매/자재(제조사 선택) |
| ③ 만들기 | `BLD` | 어떤 구조로 만들고 몇 개가 드는가 | 생산관리(구조·공정) |
| ④ 품번 | `COD` | 어떤 ERP 코드를 쓰는가 | 기준정보 담당·구매/자재(발번 승인) |
| ⑤ 확정 | `CFM` | 모두 동의했는가, 언제부터 쓰는가 | 각 부서(변경 층 × 시장별) |
| ⑥ 추적·알림 | `TRK` `ALR` `CST` | 무엇이 왜 바뀌었고 무엇에 영향을 주는가 | 변경 층별 승인자 |

## 2. 단계별 상세

각 표의 '모델'은 NC AI BOM 도메인 모델이 하는 일이다. 모델 호출 방식은 [docs/06 4장](06_시스템구조_모델역할.md)에 있다.

### ① 가져오기 (`IMP`)

| 구분 | 내용 |
|---|---|
| 입력 | E-BOM 파일(xlsx·xls·csv), 모델명·개정 정보(제목·시트명·날짜), 이전 개정(있으면) |
| 다봄 | 헤더 위치 탐지와 열 의미 매핑, 한 시트 안의 여러 보드 분리, 병합 셀·줄바꿈 정리, 참조부호 전개와 수량 대조, 행 원문 보존, 구형 `.xls` 변환, 개정 표기 불일치(제목 vs 시트명) 표시 |
| 모델 | 행 분류(부품 종류, 비구매, 미실장), 사양 해석(값·정격·공차·패키지를 원문 문자열 그대로 제시, 모호하면 확인 요청 생성) |
| 사람 | 연구소: 차단성(blocking) 확인 요청에 답하고, 원문 오기를 고친다 |
| 출력 | 정제 E-BOM(원문 + 정규화 사양 + 상태), 확인 요청 목록, 정합성 리포트 |
| 멈추는 조건 | 수량과 참조부호 개수 불일치(자동 보정 금지, R02 검증 규칙 V1), 사이즈·정격 모순(RB-SF-02), 극성·온도 등급 등 RB-SF 위반 |

실제 입력은 양식이 제각각이다. KK1~KK16 16개 파일에서 8열 양식(KK3), 구형 `.xls`(KK4), 한 시트에 두 보드(KK8·KK13), 제목과 시트명의 개정 불일치(KK14·KK15), 품번 없는 케이블 행(KK10·KK11)을 확인했다. 이 파일들이 가져오기 평가셋이 된다([docs/09](09_검증_평가.md) G1).

### ② 맞추기 (`MAT`)

| 구분 | 내용 |
|---|---|
| 입력 | 정제 사양, 사내 품목 마스터, 가용 재고, 후보 부품 풀, 승인 대체(AVL), 거래처·구매 조건, 고객 지정·인증 고정 목록, 결정 기록 |
| 다봄 | 3장의 순서대로 조회, 사양 동등 판정(정격 이상·유전체와 온도 등급 동등 이상), 지정 부품 잠금, 재고 사용 가능 판정(데이트코드·MSL·보관수명), 외부 후보 조회(유통사 API, 값·사이즈 1차 선별), 후보 정렬, 거래처·조건 붙이기 |
| 모델 | 후보별 판정(적합·조건부·미정·부적합 + 근거). 동일 부품 판정(표기 변형·포장 접미사)은 추가 협의 태스크 |
| 사람 | 구매/자재: 후보 중 선택(제조사 선택은 구매 권한, R01 2.2), 조건부 후보 승인, 신규 등록 필요 판단 |
| 출력 | 매칭표(행별 후보·선택·근거·출처), 신규 품목 등록 요청 초안, 후보 풀 갱신 제안 |
| 멈추는 조건 | 적합 후보 0건, 1순위가 조건부, 지정 부품 위반(RB-DP), 사용 불가 재고 배분(RB-EX-09) |

### ③ 만들기 (`BLD`)

| 구분 | 내용 |
|---|---|
| 입력 | 매칭 결과, 제품 구조 정보(반제품 구성, Set 조립 품목), 공정 구분 기준, LOSS 기준, 제품·반제품 품번(생산관리가 부여) |
| 다봄 | 모품번–자품번 구조 생성(제품 → 반제품 → 부품), 보드별 반제품 배정, M-BOM 전용 행 추가(베어 PCB, 펌웨어 개정 기록, Set 조립 품목의 제품 레벨 이동), 실장 구분(SMT·DIP·SET·NC·비구매), 정미수량·LOSS·필요수량 계산, 같은 자품번 행 통합, 미실장 행 처리(BOM사용여부 미사용, 필요수량 0), Amaranth 양식 생성 |
| 모델 | 없음. 계산과 구조는 규칙이 맡는다 |
| 사람 | 생산관리: 구조 확정, 제품·반제품 품번 부여, 공정 구분과 LOSS 기준 확인 |
| 출력 | M-BOM 초안(Amaranth 22열), 구조 검토 요청 |
| 멈추는 조건 | 구조 확정 전(RB-ST-08), 팬텀 노드의 재고 계상(RB-ST-07), 모품번 미지정 |

### ④ 품번 (`COD`)

| 구분 | 내용 |
|---|---|
| 입력 | 확정 MPN과 사양, 채번 규칙 스키마, 품목 마스터(비활성·대체된 품번 포함) |
| 다봄 | 동일 MPN 기존 코드 재사용. 신규는 규칙 엔진이 본체 생성 → 충돌 검사 → 접미 결정 → 형식 검사. MPN 미확정은 발번 보류. 제품·반제품은 대상이 아니다 |
| 모델 | 분류 판정·속성 추출(R05 4.1의 [1]~[3]). ①·②에서 나온 결과를 쓴다 |
| 사람 | 기준정보 담당·구매/자재·연구소: 신규 발번 승인, 충돌 처리 선택(흡수·정정·예외표), 규정 공백 판단 |
| 출력 | ERP 코드 발번 내역(재사용·신규·보류와 근거), 품목 등록 요청서 |
| 멈추는 조건 | 규정에 없는 코드(RB-PN-02), 이미 쓰인 번호와 충돌(RB-PN-03), 형식 위반(RB-PN-01) |

상세 규칙은 [docs/08](08_ERP코드_발번.md).

### ⑤ 확정 (`CFM`)

| 구분 | 내용 |
|---|---|
| 입력 | M-BOM 초안, 확인 요청·발번 승인 결과, 변경 층과 적용 시장(개정일 때) |
| 다봄 | 승인 라우팅(층 × 시장), 미결 집계, 기준선 동결 조건 검사(시제 품번 잔존 금지 RB-CF-07 등), ERP 등록 파일 생성, 등록 뒤 ERP 추출본과 대조 |
| 사람 | 부서별 승인, 기준선 동결 결정(전 부서), ERP 등록 수행(1단계는 사람이 등록) |
| 출력 | 확정 M-BOM(개정 ID·단계·기준선 표시), 개정 이력, ERP 등록 파일, 등록 대조 결과 |
| 멈추는 조건 | 미결 MPN 잔존, 승인 누락, 등록 대조 불일치 |

### ⑥ 추적·알림 (`TRK` `ALR` `CST`)

| 구분 | 내용 |
|---|---|
| 입력 | 새 E-BOM 개정(ECN), 변경 요청(ECR), 고객 요청, 외부 통보(PCN·EOL·가격 인상·공급 중단), 재고·원가 정보 |
| 다봄 | 개정 비교, 변경 패키지 생성(사유 코드·층·영향 행), 충돌 검사(RB-CF), 영향 분석(where-used·재고·미결 발주·원가·일정), 효력·처분 선택지 제시, 승인 라우팅, 반영 뒤 개정 이력 기록 |
| 모델 | 변경 층·사유 제안, 통보문 해석(추가 협의 태스크) |
| 사람 | 변경 승인, 효력 시점과 기존 재고 처분 결정 |
| 출력 | 변경 패키지, 영향 리포트, 새 M-BOM 개정, ERP 변경 등록 파일 |

상세 규칙은 [docs/07](07_변경관리_추적.md).

## 3. 맞추기 순서 [제안 · DEC-13, DEC-08을 갱신]

사내에 있는 것을 먼저 쓴다. 위에서 찾으면 아래로 내려가지 않는다. 2026-11-23에 사용 이력 품목(재고 0)과 거래처 카탈로그를 넣었다([docs/14 5장](14_부서기능_확장검토.md)).

| 순위 | 대상 | 조건 | 처리 | 근거 |
|---|---|---|---|---|
| 0 | 지정 부품 | 고객 지정, 인증 고정 구성, 칩셋 벤더 지정 목록에 있음 | 그대로 쓰고 대체 추천을 막는다 | RB-DP-01·02, RB-CF-01 |
| 1 | 동일 MPN 기존 품목 | ERP 품목 마스터에 같은 MPN이 있음(포장 접미사 변형은 동일 부품 판정으로 묶는다) | 기존 ERP 코드 재사용. 재고가 0이면 사용 이력 품목으로 표시하고 재구매 견적으로 보낸다. 같은 사양의 재고 보유 품목이 있으면 흡수안을 함께 낸다 | R05 5.3, DEC-14 |
| 2 | 사양 동등 기존 품목 | 사이즈·값·공차가 같고 정격은 같거나 높으며 유전체·온도 등급이 같거나 나음. 비드는 같은 계열 품번 | 흡수 제안, 연구소·구매 확인. 정렬: 사용 가능 재고 보유 > 사용 이력 품목(재고 0, 재구매 가능) > 사내 표준 등급 > 사용 모델 수 | R02 시나리오 E, KK13~KK16 [가상] 적용, DEC-14 |
| 3 | 후보 풀 승인품 | 연구소·구매가 등록하고 승인(조건부 포함)한 후보 | 채택하면 신규 품목 등록 요청 | 신설([docs/05](05_데이터와_ERP연동.md) 2장) |
| 4 | 거래처 카탈로그 | 기존 거래처 라인카드에 있는 제조사의 카탈로그 계열 중 사양이 맞는 것 | 견적 → 구매 선택 → 신규 품목 등록 요청. 신규 거래처 등록이 필요 없다 | 신설(DEC-15, `MAT-11`) |
| 5 | 외부 유통 후보 | 유통사 검색 결과를 값·사이즈로 1차 선별한 뒤 모델이 판정. 조회 결과는 저장하지 않는다 | 구매 선택 → 신규 품목 등록 요청 | R06, 유통사 API 약관(docs/14 4장) |
| — | 미결 | 위에서 모두 찾지 못함 | 확인 요청 발행. 빈 값을 추정으로 채우지 않는다 | R03 2.2 |

- 사용 이력 품목 = 사내 제품에 쓰인 적이 있고 ERP 코드가 있지만 지금 재고가 0인 품목. 상태가 '확인 필요'(NRND·EOL, 제조업체 미기재 등)면 확인 요청을 붙이고, '사용 중지'(품질 보류·고객 금지·대체 완료)면 추천하지 않는다(`MAT-10`, `MDM-09`).

- 선택된 품목에는 승인 대체(AVL)를 함께 붙인다. 공급 문제가 생겼을 때 설계 변경(L1)이 아니라 대체 전환(L2)으로 끝낼 수 있게 하기 위해서다(R04 1.4).
- 장기재고 소진 지침(CR-07)이 있으면 순위 2에서 재고 보유 품목을 더 앞에 둔다. 데이트코드·보관수명 검사를 통과한 재고만 대상이다(RB-CF-04).

**품목마다 붙이는 거래처·구매 조건**

| 품목 유형 | 붙이는 정보 | 원천 |
|---|---|---|
| 기존 품목 | 주거래처, 최근 단가·통화·기준일, 리드타임, MOQ·SPQ | ERP 품목·구매 이력 |
| 사용 이력 품목 | 마지막 구매 거래처·단가·일자, MOQ·SPQ(오래됐으면 다시 확인) | ERP 구매 이력 |
| 후보 풀 품목 | 등록 때 받은 견적 조건과 유효기간 | 후보 풀 |
| 거래처 카탈로그 품목 | 취급 거래처(라인카드). 단가·리드타임은 견적으로 받는다 | 라인카드, 제조사 카탈로그 |
| 외부 후보 | 유통사 조회 값(조회 시각 표시), 해당 제조사를 취급하는 사내 거래처 후보 | 유통사 API, 거래처 마스터 |

- 조건이 없으면 0이 아니라 '미정'으로 둔다(RB-LT-02).
- 이 정보는 화면과 원가 계산에만 쓰고 모델에는 보내지 않는다([docs/06 4장](06_시스템구조_모델역할.md)).

## 4. M-BOM 생애 단계와 흐름

M-BOM 단계(S0~S6)는 R04 1.1을 따른다.

| 단계 | 이름 | 주로 도는 흐름 | 승인 강도 | 주 승인자 |
|---|---|---|---|---|
| S0 | 설계 출도 | ①~④ 초안 생성 | 느슨함 | 구매/자재(초안 검토) |
| S1 | 견적 | ②·④ 재실행, 미결 해소, 흡수·통합 | 느슨함 | 구매/자재·연구소 |
| S2 | EVT 빌드 | ⑥ DFM 피드백 | 보통 | 연구소·생산관리 |
| S3 | DVT 빌드 | ⑥ 인증·신뢰성 시험 대응 | 보통 | 연구소·품질 |
| S4 | PVT·양산 승인 | ⑤ 기준선 준비 | 강함 | 전 부서 |
| S5 | 양산 기준선 | 동결 | 매우 강함 | 전 부서 |
| S6 | 양산 유지 | ⑥ 변경 패키지 | 매우 강함(전장은 고객 승인) | 변경 층 × 시장 |

산업용·전장 제품은 양산 기간이 길어 개정의 대부분이 S5 이후에 일어난다(R04 1.1). `references/samples/`의 KK13~KK16은 한 제품의 M-BOM이 S0에서 S6까지 5~6번 개정되는 과정을 보여 주는 [가상] 예시다.

## 5. 사람이 개입하는 지점

| 확인 요청 유형 | 언제 | 누가 답하나 | 응답이 남는 곳 |
|---|---|---|---|
| 사양 확인 | 표기가 모호하거나 서로 모순될 때(차단성) | 연구소 | 결정 기록(회사 범위 또는 보드 범위) |
| 후보 선택 | 적합 후보가 둘 이상이거나 1순위가 조건부일 때 | 구매/자재 | 매칭표, 결정 기록 |
| 흡수 승인 | 사양 동등 기존 품목으로 바꿀 때 | 연구소·구매/자재 | 변경 기록(`S1-표준품`) |
| 구조 확정 | 반제품·Set 구성을 정할 때 | 생산관리 | M-BOM 구조 |
| 품번 승인 | 신규 발번, 번호 충돌 | 기준정보 담당·구매/자재 | 발번 내역 |
| 변경 승인 | 변경 패키지 | 변경 층 × 시장별 승인자 | 변경 패키지 |
| 효력·처분 | 변경 적용 시점과 구 재고 처리 | 생산관리·구매/자재·회계 | 변경 패키지 |

규칙성이 있는 응답("공차 표기가 없으면 1%로 본다" 같은 것)은 결정 기록으로 저장해 같은 질문을 다시 하지 않는다. NC AI 데모의 결정 기록(`D-0001` 형식, 범위 company·board)과 같은 방식이다(R07). 단, 사내 규약을 자동 확정 근거로 쓰려면 먼저 문서로 정해야 한다(R02 케이스 1).

## 7. 예시 — KK13 흐름 [가상]

`references/samples/KK13-PLT-IMX6Q-MPAD_main&LCD_M-BOM.xlsx`는 위 흐름을 사람이 손으로 재현한 예시다. 값과 회신은 모두 [가상]이다.

|---|---|---|
| M-BOM 1차 | S0 | E-BOM V01 한 시트에 MAIN(232행)과 LCD-SUB(35행) 두 표가 있어 반제품 2개로 나눴다. i.MX6Q 품번이 미완이라 발번을 보류했다 |
| M-BOM 2차 | S1 | 미결 품번을 확정하고, 유통사 주문번호를 제조사 품번으로 고쳤다. E51K 등록품과 사양이 같은 수동소자 62행을 흡수해 기존 ERP 코드 22개를 재사용했고, 그 결과 같은 자품번이 된 행 49개를 기존 행에 합쳤다 |
| E-BOM 2차 | — | 고객 요청으로 RS-232 트랜시버를 미실장으로 바꾼 V02가 나왔다 |
