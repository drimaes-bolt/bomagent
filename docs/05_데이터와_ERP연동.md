# 05. 데이터·기준정보와 ERP 연동

> 다봄이 맞추기에 쓸 데이터 중 지금 있는 것은 연말 재고 스냅숏, E51K 한 모델의 ERP BOM, 채번 규정 정도다. 후보 부품 목록, 거래처별 구매 조건, 가용 재고는 없다. 0단계에서 이것들을 먼저 준비한다. ERP(더존 Amaranth)는 품목·재고·거래처의 정본으로 두고, 다봄은 BOM 개정과 그 근거·결정의 정본이 된다(DEC-05).

**후보 부품 풀 운영 절차** [제안 · OI-06]

1. 등록: 연구소·구매/자재가 MPN·제조사·용도·대상 모델·근거 자료·예상 조건을 올린다.
2. 정규화·중복 검사: 다봄이 사양을 정규화하고, 사내 동등 품목과 기존 후보를 찾는다. 동등 품목이 있으면 그 품목을 먼저 권한다.
3. 검토: 연구소(FFF·등급), 구매/자재(조달성·거래처), 품질(등급·신뢰성).
4. 상태 결정: 승인, 조건부(조건 명시), 반려(사유 기록), 보류.
5. 사용: 맞추기 순위 3으로 쓰인다([docs/02 3장](02_업무흐름.md)).
6. 채택: 신규 품목 등록 요청 → ERP 코드 발번 → 후보 상태를 '등록됨'으로 바꾸고 ERP 코드를 연결한다.
7. 재검토: 유효기간이 끝나거나 라이프사이클이 바뀌면 다시 검토한다.

## 4. 상태 값

| 대상 | 값 |
|---|---|
| BOM 행 상태 | 자동확정 `auto_confirmed` · 추천 `recommended` · 미결 `unresolved` · 차단 `blocked` (R03 2.2) |
| 실장 구분 | SMT · DIP · SET(Set 조립) · NC(미실장) · 비구매 · 미정 |
| ERP 코드 부여(`IPN_Assignment`) | 재사용(기존 품목) · 신규 발번 · 발번 보류 |
| 품번 상태(`IPN_Status`, R05 7.2) | Active · Frozen · Superseded · Inactive |
| 후보 부품 상태 | 검토 중 · 승인 · 조건부 · 반려 · 보류 · 만료 · 등록됨 |
| 신뢰도 | 모델 인터페이스는 0~1, 화면은 백분율. R02의 0~100과 같은 뜻이다 |

빈 값과 모름은 구분한다. 확인하지 못한 값은 비워 두지 않고 '확인 필요'로 표시한다(R03 2.2).

## 5. ERP(Amaranth) 출력 양식

E51K ERP 추출본의 22열을 그대로 따른다. KK13~KK16 샘플의 M-BOM 시트가 이 양식이다.

| 열 | 내용 | 다봄 규칙 |
|---|---|---|
| No | 행 번호 | 순서대로 |
| 모품번 · 모품명 · 규격 · 재고단위 · 계정구분 | 제품 또는 반제품 | 사람이 정한 품번을 쓴다(DEC-04). 계정구분은 제품·반제품 |
| 조달구분 | 모품번의 조달 | [관측] E51K는 전 행 '생산' |
| BOM등록여부 | 등록 여부 | 등록 |
| 순번 | 자품번 순서 | [관측] 텍스트로 저장된다 |
| 자품번 | ERP 코드 | 재사용 또는 신규. 보류 행은 등록 파일에서 빼고 미결 목록으로 보낸다 |
| 자품명 | 품목명 | [관측] E51K는 자품명이 MPN이다 |
| 규격 | 사양 문자열 | [관측] ERP 규격 형식(예: `RES/THICK-FILM/R1005/47KΩ/±1%…`)으로 만든다. NC AI 출력의 Description 형식과 다르므로 다봄이 변환한다 |
| 재고단위 | 단위 | EA 등 |
| 정미수량 | 모품번 1단위당 소요 | 전개 결과 |
| LOSS(%) | 손실률 | 생산관리 기준(DT-07) |
| 필요수량 | 정미수량 × (1 + LOSS%) | 미실장 행은 0 |
| 도면번호 | 기구·PCB 도면 | [관측] E51K는 전부 공란. 기구·PCB는 채우기를 권한다 |
| 재질 | — | [관측] MSL 등급이 들어 있다. 유지 여부는 OI-19 |
| 주거래처 | 품목별 기본 거래처 | 거래처 마스터에서 채운다. 신규 품목은 구매 확정 뒤. KK13~KK16 샘플은 거래처 정보가 없어 비워 두었다 |
| 사용여부 | 품목 사용 | 사용 |
| BOM사용여부 | 행 사용 | 사용 / 미사용(미실장) |
| 비고 | 변경 기록 요약 | `[사유 코드] 사유` |

등록 파일에는 두 시트를 함께 붙인다.

- **개정 이력**: 순서·시트·구분·단계·일자·기준 문서·변경·신규·삭제·확인·미결 MPN·제조사 확인 필요·자재비 합계·주요 내용([docs/07 8장](07_변경관리_추적.md))
- **ERP 코드 발번 내역**: No·자품번(ERP 코드)·MPN·품목 설명·구분(재사용·신규)·발번 근거

## 6. 연동 방식

| 단계 | ERP → 다봄 (읽기) | 다봄 → ERP (쓰기) | 조건 |
|---|---|---|---|
| 1단계 | ERP 추출 엑셀(품목·재고·BOM·구매 이력)을 정기 적재 | Amaranth 등록용 엑셀을 만들고 사람이 등록 | 추출·등록 양식 확인(OI-07) |
| 2단계 | 읽기 전용 조회 또는 예약 추출 자동화 | 등록 뒤 ERP 추출본과 자동 대조 | ERP 운영 승인 |
| 3단계 | API 연동 | 승인된 변경의 자동 등록 | 더존 측 연동 수단 확인 |

- 더존 제품에 대해 공개 개발자 API나 자가 발급 키는 찾지 못했고 연동은 파트너 계약을 거친다는 외부 정리가 있다([FrontierStack](https://frontierstack.app/ja/services/douzone.html)). 공식 확인이 아니므로 사내 ERP 운영 담당과 더존 측에 확인한다(OI-07).
- BOM·품목을 엑셀로 등록하는 기능이 Amaranth에 있는지, 있다면 양식이 무엇인지도 아직 확인하지 못했다. 현재 근거는 E51K 'Amaranth 물류공통' 추출본뿐이다.
- 더존비즈온은 Amaranth 10과 외부 온톨로지 기반 AI 플랫폼을 결합하는 AX 협력을 발표했다([ChosunBiz, 2026-06-08](https://biz.chosun.com/en/en-industry/2026/06/08/YZFSQVA2OVHL3HNVP5OXJG2W2M/)). ERP 쪽 AI 기능과 다봄 기능이 겹치는지 2단계 전에 확인한다(OI-18).
