# 12. 용어집

> 이 폴더의 문서에서 쓰는 용어와 겹치기 쉬운 ID를 정리했다. 원 문서에서 정의한 용어는 출처를 함께 적었다.

---

## 1. 이름과 주체

| 용어 | 뜻 |
|---|---|
| 다봄(DaBOM) | 이 프로젝트가 만드는 사내 시스템. 전사 BOM 변환·추적 시스템. 기존 문서의 'BOM Agent'와 같은 대상이고 'BOM Agent'는 약칭으로도 쓴다. 이름의 '봄'은 BOM이다 |
| 뿌리 원칙 | 시작도 뿌리도 BOM이다. 부서별 기능이 아무리 넓어져도 모두 BOM에서 뻗는다는 원칙(DEC-18, docs/01 1.6) |
| 뿌리 · 줄기 · 가지 · 받침 | 뿌리 = BOM(E-BOM + SCM 정보 → M-BOM과 개정 이력), 줄기 = 처음 만든 E-BOM → M-BOM 변환·추적 기능(`IMP` `MAT` `BLD` `COD` `CFM` `TRK`), 가지 = 부서별 확장 기능(`ALR` `CST` `PRD` `QLT` 등), 받침 = 줄기가 맞춰 보는 기준정보(`MDM`) |
| BOM 뿌리 지도 | 모듈마다 BOM에서 읽는 것과 BOM에 돌려주는 것을 적은 표(docs/04 1.1). 새 기능은 여기에 한 줄을 먼저 적는다 |
| SCM 정보 | M-BOM을 만들 때 E-BOM에 합치는 공급망 정보. 재고 리스트, 거래처, 구매 이력, 입고 예정 등 |
| 다봄 구축 프로젝트 | 이 폴더가 다루는 파생 프로젝트(Project DaBOM, 코드 `DABOM`) |
| NC AI BOM 도메인 모델 | 협력사 NC AI가 만드는 BOM 특화 언어모델. 다봄이 API로 호출한다 |
| 오케스트레이터(에이전트 계층) | 다봄 안에서 경로를 정하고 컨텍스트를 만들어 모델을 호출하고 결과를 검증하는 계층 |
| BOM AX 협업 | 드림에이스와 NC AI의 상위 협업 |
| 키유저 | 부서를 대표해 요구 확인·시험 사용·교육을 맡는 사람 |
| 기준정보 담당 | 채번 규정·품목 마스터·사전·룰북을 관리하는 사람 |

## 2. BOM과 구조

| 용어 | 뜻 |
|---|---|
| E-BOM | 연구소가 설계 도구에서 내보내는 부품 목록. 보드 1장 기준 단층이다(R02 1.3) |
| M-BOM | 생산·구매·회계가 쓰는 제조 BOM. 제품 → 반제품 → 부품 구조, ERP 코드, 수량·LOSS를 담는다. 다봄에서는 산출물이 아니라 상태다 |
| 모품번 / 자품번 | ERP BOM의 상위 품번 / 구성 품번 |
| 제품 / 반제품 | 완제품(예: `MS01C0P1PP` SET-ASSY) / 중간 조립품(예: `MS01C0P1SM` PCB-ASSY SMT). 자체 양산품이라 채번 규칙이 없다 |
| 정미수량 · LOSS · 필요수량 | 모품번 1단위당 소요 · 손실률(%) · 정미수량 × (1 + LOSS%) |
| 실장 구분 | SMT, DIP, SET(Set 조립), NC(미실장), 비구매, 미정 |
| 미실장(NC) | 풋프린트는 있지만 부품을 싣지 않는 행. 소요에서 빠진다 |
| 비구매 | 테스트 포인트·패드·고정 홀처럼 사지 않는 행 |
| Set 조립 품목 | PCB 밖에서 완제품 조립에 들어가는 구매 품목(라벨, 브래킷, 나사, FFC, LCD, 팬 모터 등) |
| 베어 PCB | 부품을 싣기 전의 기판. 외주 제작해 사는 품목이다 |
| 프로그래밍 품목 | 공 칩 + 펌웨어 개정 = 프로그래밍이 끝난 품목(R04 A10) |
| 팬텀 | 재고를 잡지 않고 전개만 하는 가상 조립 단위(R02 1.3.3) |
| 기준선(Baseline) | 양산 확정으로 동결한 M-BOM 개정(S5) |
| BOM 단계 S0~S6 | 설계 출도 · 견적 · EVT · DVT · PVT·양산 승인 · 양산 기준선 · 양산 유지(R04 1.1) |
| where-used | 한 품목이 어느 제품·모델·개정에 쓰이는지의 역추적 |

## 3. 품번·품목·거래

| 용어 | 뜻 |
|---|---|
| ERP 코드 | 사내 품번. IPN, `Internal_PN`과 같다. 회로 자재는 12자 `CC-BBBBBBBBB`(R05) |
| MPN | 제조사 부품 번호 |
| SPN | 유통사 주문 번호 |
| 승인 대체(AVL·AML) | 한 ERP 코드에 대해 사용이 승인된 제조사·MPN 목록 |
| 후보 부품 풀 | 연구소·구매/자재가 새 Set에 쓰려고 골라 두고 검토하는 부품 목록. 아직 ERP 품목이 아닐 수 있다(docs/05 2장) |
| 사양 동등 흡수 | 새 부품 대신 사양이 같거나 나은 기존 품목을 쓰는 것(R02 시나리오 E) |
| 채번(발번) | 규칙에 따라 새 품번을 만들어 부여하는 일 |
| 발번 보류 | 사양이 확정되지 않아 품번을 만들지 않은 상태 |
| 품목 마스터 | ERP의 품목 기준정보(품번·품명·규격·제조사·단위 등) |
| 사내 거래처 · 주거래처 | 회사가 거래하는 공급업체 · 품목별 기본 공급업체(ERP 열 이름) |
| 보유재고 · 가용 재고 | 장부상 재고 · 현재고 − 할당 + 기한 내 입고 예정 |
| 계정구분 | 원재료 · 반제품 · 제품 등 회계상 품목 구분 |
| 사용 이력 품목 | 사내 제품에 쓰인 적이 있고 ERP 코드가 있지만 지금 재고가 0인 품목. 상태는 재구매 가능·확인 필요·사용 중지(DEC-14) |
| 거래처 카탈로그 | 거래처 라인카드 × 제조사 선택 가이드로 만든 "기존 거래처에서 살 수 있는 부품" 사양 DB(DEC-15) |
| 라인카드 | 거래처(대리점·유통사)가 정식으로 취급하는 제조사 목록 |
| 선택 가이드(Selection Guide) | 제조사가 제품 계열별 사양 범위를 정리한 자료. 카탈로그·파라메트릭 내보내기와 함께 카탈로그 DB의 원천 |
| MOQ · SPQ | 최소 주문 수량 · 표준 포장 수량(릴·트레이 단위). MPN·포장 코드마다 다르다 |
| 분류 필터 | ERP 대분류(품번 앞 2자리) 체크 상자로 먼저 거르고 크기·값·허용오차로 좁히는 품목 탐색(MAT-12) |
| 좌표 파일 | CAD가 내보내는 부품 위치 목록(Pick & Place·Centroid). 참조부호·좌표·각도·면 |
| 피더 목록 | SMT 장비에 부품 릴을 거는 피더 배치의 초안. 다봄은 초안과 공용 부품까지만 |
| 불출 목록(키팅) | 작업지시 수량만큼 창고에서 라인으로 내보낼 부품 목록. 출고 처리는 ERP |
| 수입검사(IQC) · 초도품 확인(FAI) | 입고 부품 검사 · 새 개정 첫 생산품 확인. 다봄은 대상 목록만 만든다(`QLT`) |
| 과잉·불용 재고(E&O) | 앞으로의 소요보다 많거나 쓸 곳이 없어진 재고(CST-04) |

## 4. 변경 관리

| 용어 | 뜻 |
|---|---|
| 변경 층 L1~L4 · 정정 | 설계 변경 · 승인 대체 전환 · 조달 속성 변경 · 공정·부자재 변경, 그리고 기록 정정(R04 1.4) |
| 사유 코드 CR-01~19 | 변경 사유 분류(R04 6.2, docs/07 3장) |
| 초기 변환 기록 코드 | E-BOM을 처음 옮길 때의 처리 기록. `S0-정규화`, `S0-미결`, `S1-확정` 등 |
| 변경 패키지 | 여러 행에 걸친 변경을 묶은 단위. 사유·층·영향 행·효력·처분·승인을 담는다(R04 6.3) |
| 효력(Effectivity) | 변경을 언제부터 적용하는가. 즉시 · 일자 · 시리얼·로트 · 재고 소진 후 · 한시 |
| 처분(Disposition) | 구 부품 재고를 어떻게 하는가. 그대로 사용 · 재작업 · 폐기 · 소진 후 전환 |
| ECR · ECO · ECN | 변경 요청 · 변경 승인·지시 · 변경 통지(R04 2.1). 사내 용어 범위는 OI-02 |
| 편차 · 특채 | 만들기 전에 받는 한시 사양 이탈 허가 · 이미 만들어진 부적합품 사용 허가(R04 A12) |
| PCN · EOL · NRND · LTB | 제품 변경 통보 · 단종 · 신규 설계 비권장 · 최종 구매 |
| FFF | 형상·결합·기능(Form·Fit·Function). 같으면 같은 품번, 다르면 새 품번 |
| 인증 개정(`Certified_Revision`) | 인증 시험에 쓴 M-BOM 개정 |
| 적용 시장(`Target_Market`) | 산업용 · 전장 등. 승인 경로를 정한다 |
| 지정 부품 | 고객이 사용을 지정한 부품(Directed buy). 대체가 금지된다 |
| 시제 품번 | 양산 전 엔지니어링 샘플 품번. 양산 품번과 다른 품목이다(R04 A9) |

## 5. 모델과 평가

| 용어 | 뜻 |
|---|---|
| CPT · FT(SFT) · RAG | 도메인 지속 사전학습 · 태스크별 미세조정 · 검색 결합 생성(R01 2.5) |
| 무상태 호출 | 매번 완성된 입력 한 벌을 보내고 앞선 대화에 기대지 않는 호출 방식(R07) |
| 확인 요청 | 다봄이 사람에게 묻는 질문. 차단성(blocking)이면 답이 올 때까지 그 행이 멈춘다 |
| 결정 기록 | 확인 요청에 대한 답 가운데 다시 쓸 수 있는 것. 회사 범위와 보드 범위가 있다(R07 `D-0001` 형식) |
| 교정 로그 | 모델·다봄 제안을 사람이 수락·수정·거절한 기록(R03 D-C) |
| 기권 | 모르면 값을 내지 않고 미결로 두는 것. 오답과 따로 센다 |
| 골든셋 | 필드 단위 정답이 붙은 평가셋. 학습에 쓰지 않는다(R03 2.3) |
| 레드팀 | 통과하면 안 되는 입력 모음(docs/09 5장) |
| 자율성 단계 A0~A3 | 섀도 · 제안 · 조건부 자동 · 예외 중심(docs/06 9장) |
| 룰북 등급 S · H · L | 차단 · 승인 요청 · 자동 처리 후 기록(R02 5.1) |
| 결정론 검증기 | 같은 입력에 같은 결과를 내는 규칙 검사(docs/09 4장) |
