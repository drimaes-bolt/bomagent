# 14. 부서 기능 확장 검토

> 2026-11-23 요청 9건을 검토하고 반영한 기록이다. 결론은 다섯 가지다. ① 재고 목록은 E-BOM과 상관없이 열람하고 ERP 대분류로 거른다. ② 재고가 0이지만 쓴 적이 있는 품목은 '사용 이력 품목'으로 따로 관리하고 재고 보유 품목 다음으로 추천한다(조건부 적절). ③ 주요 거래처 카탈로그 DB는 제조사가 낸 사양 자료만 쌓는 조건으로 적절하다. ④ 부서별 기능 후보 18건 중 10건은 적합, 7건은 조건부, 1건은 범위 밖이다. ⑤ 생산기술·품질에 화면 기획을 미리보기로 넣고 모듈 `PRD`·`QLT`를 새로 둔다. 모두 [제안]이다.

근거: 사내 문서는 docs/01~13과 R01~R12, 외부 사실은 9장 출처(2026-11-23 웹 조사). 외부 출처의 상당수는 장비·소프트웨어 회사의 글이라 수치는 참고값이다. 국내 스마트공장·MES 지침 중 BOM 협업을 직접 다룬 공식 자료는 찾지 못했다.

## 2. 재고 데이터 갱신

### 2.1 Inventory.xlsx 수량 조정 [가상]

| 항목 | 내용 |
|---|---|
| 대상 | 원재료 시트 1,048품목(2025 기말 실제 품목 315 + 가상 Drim_IO 733). 제품-반제품 시트(2품목)는 부품이 아니라 대상에서 뺐다 |
| 규칙 | 재고수량 2,000 미만 → max(2,000, MOQ). 예: 1,911개인 R1608 칩저항(MOQ 5,000) → 5,000 |
| 결과 | 114품목을 올렸고, 이어서 저항 5·커패시터 5품목을 0으로 두었다(3.4). 수량 합계 11,234,364개, 금액 합계는 작성기준 C절 |
| 금액 | 조정한 행만 반올림(재고 단가 × 조정 후 수량)으로 다시 계산했다 |
| 기록 | `수량조정_20261123` 시트(124행: 품번·조정 전·MOQ·조정 후·처리), 작성기준 C절, 속성(매칭용) 시트의 `MOQ(표준 포장 추정)`·`MOQ 근거(추정)` 열 |

### 2.2 MOQ 추정 [가상]

파일에 MOQ가 없어서 7인치 릴 표준 포장 수량(SPQ)으로 추정했다. 제조사 공개 자료와 맞췄다 [관측: 2026-11-23 웹 조사].

| 분류 | 크기·두께 | MOQ(추정) | 근거 |
|---|---|---|---|
| 칩저항 | R0603·R1005 | 10,000 | Yageo RC_L 데이터시트 Table 4 |
| 칩저항 | R1608·R2012·R3216·R3225 | 5,000 | 같음 |
| 칩저항 | R5025·R6432 | 4,000 | 같음(엠보스 테이프) |
| MLCC | C0603 | 15,000 | Walsin·Murata 15,000, 삼성전기 10,000 |
| MLCC | C1005 | 10,000 | 3사 같음 |
| MLCC | C1608 | 4,000 | 3사 같음 |
| MLCC | C2012 두께 0.85 이하 / 초과 | 4,000 / 3,000 | 삼성전기 T1.25 2,000, Walsin 3,000 |
| MLCC | C3216 두께 0.85 이하 / 초과 | 4,000 / 2,000 | 같음 |
| MLCC | C3225 두께 1.6 이하 / 초과 | 2,000 / 1,000 | 같음 |
| 그 밖 | IC 2,500, 소신호 TR·다이오드 3,000, 크리스털 3,000, 나사 5,000, 커넥터·파워 인덕터·모듈·기구 500~1,000 | → 결과는 2,000 이상 | [판단] |

같은 크기·두께라도 제조사마다 포장 수량이 다르다. 운영에서는 SPQ·MOQ를 MPN(포장 코드 포함)별 구매 조건으로 받는다(DT-02, OI-24). 위 표는 값이 없을 때 쓰는 기본값이다.

### 2.3 목업에 넣는 방식

- 품목·수량·제조업체·규격은 Inventory.xlsx 그대로다. 사용자 요청(재고 자체 내장)을 따랐다.
- **단가는 예외다.** 작성기준 시트가 "실제 재고는 원본 단가·금액 그대로"라고 적은 2025 기말 실제 품목 315개는 기존 목업의 [가상] 단가로 바꿔 넣었다. 문서·예시에 실제 단가를 쓰지 않는 규칙(CLAUDE.md 7장) 때문이다. 그래서 목업의 재고 금액 합계는 Inventory.xlsx와 다르다. 가상 품목 733개는 파일의 가상 단가를 그대로 썼다.
- 할당·입고 예정·주거래처는 기존 목업 값을 품번으로 이었고, 없으면 거래처 라인카드(취급 제조사)에서 [가상]으로 붙였다.

## 3. 사용 이력 품목 DB — 조건부 적절

### 3.1 정의

사내 제품에 한 번이라도 쓰였고 ERP 코드가 있지만 지금 재고가 0인 품목이다. 재고 목록에서는 수량 0으로 보이거나 아예 빠지지만, "써 본 부품"이라는 사실과 품번·거래처·단가 이력이 남아 있다.

### 3.2 판단 [판단]

추천 때 신규 후보·외부 후보보다 먼저 보는 것이 맞다. 이점은 재고가 아니라 **새 품번과 새 부품 승인을 피하는 데** 있다.

| 이점 | 근거 |
|---|---|
| 신규 발번·품목 등록이 없다 | 기존 ERP 코드를 재사용한다(COD-02, docs/08 4장) |
| 검증 이력이 있다 | 이미 사내 제품에 실장·양산된 부품이다 |
| 거래처·단가 이력이 있어 견적이 빠르다 | 구매 이력(DT-02) |
| 신규 부품 하나의 등록 비용이 크다 | IBM은 신규 부품 등록 행정 비용을 건당 $10,000~15,000으로 보고 재사용률을 높였다. 미 국방물류청 보고서는 약 $20,000으로 본다 [관측: 9장 출처] |
| 품목 마스터가 불어나는 것을 막는다 | 신규 품번 생성 단계를 통제해야 중복 부품이 줄어든다 [관측: 9장 출처] |

### 3.3 조건

| # | 조건 | 처리 |
|---|---|---|
| 1 | 라이프사이클 | NRND·EOL 표기면 '확인 필요'로 내린다. 새 설계에 NRND 부품을 피하라는 권고가 있다 |
| 2 | 재고가 0이 된 이유 | 단순 소진은 추천한다. 단계적 퇴출(ECN), 품질 보류, 고객 금지, 대체 완료는 '사용 중지'로 빼거나 경고한다. 이유는 ERP 처분 이력·ECN 이력으로 확인한다 |
| 3 | 최근성 | 마지막 구매·사용이 오래된 품목은 거래처·리드타임·MOQ를 다시 확인한다. 기간은 [가안], 기준은 OI-23 |
| 4 | 등급 범위 | 차량용(AEC-Q200) 승인인지 산업용 승인인지 구분한다(적용 시장 OI-01) |
| 5 | 재고 보유 동등품과의 순서 | 같은 사양의 재고 보유 품목이 있으면 그쪽이 먼저다. 동일 MPN인데 재고가 0이면, 재고 보유 동등품으로 흡수하는 안을 함께 제안한다 |

상태 값은 세 가지다: **재구매 가능**(추천) · **확인 필요**(추천하되 확인 요청을 붙임) · **사용 중지**(추천 안 함).

### 3.4 이번에 만든 것

| 항목 | 내용 |
|---|---|
| 예시 10품목 | Inventory.xlsx에서 수량을 0으로 둔 저항 5(`AC0402FR-0712KL`·`AC0402FR-0775KL`·`AC0402FR-071K4L`·`AC0402FR-071K82L`·`AC0201FR-07220KL`)과 커패시터 5(`CL05A106MP5NUNC`·`CL05A474KA5NNNC`·`CL05C271JB5NNNC`·`GRT1885C1H222JA02`·`GRT1555C1H360JA02`). 고른 기준: E51K ERP BOM이나 KK13~KK16 M-BOM에서 쓰였고, KK16 흡수 제안 대상이 아니며, 같은 사양의 재고 보유 품목이 따로 있는 것. KK16 변환에서 재사용으로 맞춰지는 3품목을 넣어 시연에서 보이게 했다 |
| 재고 목록 밖 346품목 | 기존 목업의 재고 701품목 중 346품목은 E51K ERP BOM·KK13~KK15 M-BOM [가상]에서 온 품목이고 Inventory.xlsx에 없다. 정의상 사용 이력 품목이라 수량 0으로 옮겼다. 라이프사이클 표기나 제조업체 미기재가 있는 124품목은 '확인 필요'다 |
| 파일 | 루트 `PartHistory.xlsx`(시트 `사용이력품목` 356행, `작성기준`) |
| 목업 | 재고 현황의 '사용 이력 품목' 목록과 같은 사양 재고, 연구소 찾기의 '사용 이력' 탭, 맞추기 막대의 '재사용 · 재고 0' 칸, 견적 필요 품목의 '재구매' 행 |

KK16 시연 결과가 바뀐다. 기존 코드를 재사용하는 61행 중 49행이 재고 0인 사용 이력 품목이 된다. KK13~KK15 품목이 Inventory.xlsx에 없기 때문이다 [관측: 2026-11-23 목업 실행]. 신규 발번은 늘지 않고, 재구매 견적이 늘어난다.

## 4. 거래처 카탈로그 DB — 조건부 적절

### 4.1 무엇을 만드나

"이미 거래 중인 거래처에서 공급 가능한 부품 목록"은 두 자료의 곱이다.

| 자료 | 내용 | 원천 |
|---|---|---|
| 라인카드 | 거래처가 정식으로 취급하는 제조사 목록 | 거래처 마스터, 거래처 제공 자료. 목업의 거래처 41곳 중 39곳에 취급 제조사 기록이 있다 [가상] |
| 제조사 선택 가이드·카탈로그 | 제조사의 제품 계열별 크기·값 범위·정격·등급·라이프사이클 | 제조사가 낸 선택 가이드, 카탈로그, 파라메트릭 내보내기 |

맞추기에서는 재고·사용 이력·후보 풀에 없을 때, 외부 유통 후보로 가기 전에 본다(5장 순위 4). 신규 거래처 등록 없이 살 수 있는 부품을 먼저 찾는 것이 목적이다.

### 4.2 판단 [판단]

적절하다. 단, **사양 정보 DB로만** 쓰고 가용성·단가의 근거로 쓰지 않는다.

| # | 조건 | 이유 |
|---|---|---|
| 1 | 제조사가 낸 자료만 쌓는다 | 유통사 API 결과는 약관상 자체 DB로 쌓을 수 없다. Digi-Key는 API 데이터로 DB를 만들거나 갱신하는 것을 금지하고, Nexar(옛 Octopart)는 24시간을 넘는 저장을 금지한다 [관측: 9장 출처]. 유통사 조회는 외부 후보 검색(MAT-06)에서 실시간으로만 쓴다 |
| 2 | 행마다 문서·판·수집일을 단다 | 카탈로그는 판이 바뀐다. 갱신 주기는 OI-22 |
| 3 | 라이프사이클은 추천할 때마다 다시 확인한다 | 단종 통보 없이 나온 EOL이 많다는 보고가 있다. 유통사 표기보다 제조사 제품 페이지를 기준으로 삼는다 [관측: 9장 출처] |
| 4 | 라인카드는 정규 유통 여부 확인용이다 | 정규 대리점 여부는 제조사 사이트나 제조사에 확인한다 |
| 5 | 단가·재고·납기는 견적으로 받는다 | 카탈로그에 있다고 살 수 있는 것은 아니다 |
| 6 | 모델에는 사양만 넣는다 | DEC-03(단가·재고·거래처 조건 제외)과 충돌하지 않는다. 카탈로그 사양은 검색 계층(DEC-02)의 자료가 된다 |
| 7 | 제조사 사이트 이용 조건을 회사별로 확인한다 | 사내 이용 범위, 재배포 금지 |
| 8 | 규모가 커지면 상용 부품 DB 라이선스를 비교한다 | 직접 수집 비용이 더 클 수 있다 |

### 4.3 데이터 구조 [제안]

| 엔티티 | 핵심 필드 |
|---|---|
| 라인카드 | 거래처 코드, 제조사(정규명), 취급 분류, 정규 유통 여부, 확인 일자 |
| 카탈로그 문서 | 문서 ID, 제조사, 문서 이름, 형식(PDF·CSV·웹), 판·발행일, 수집일, 상태(확보 전·적재·만료) |
| 카탈로그 항목 | 문서 ID, 제조사, 계열, 분류, 크기, 값 범위, 정격, 유전체·공법, 등급(상용·차량용), 라이프사이클, 신규 설계 권장 여부 |

### 4.4 다음 작업

1. 대상 정하기: 구매 금액·품목 수 상위 거래처와 그 제조사, 분류(저항·MLCC·인덕터·다이오드·커넥터부터).
2. 라인카드 받기: 거래처별 정식 취급 제조사.
3. 제조사 자료 받기: 선택 가이드·파라메트릭 내보내기. PDF는 표로 바꾸고 원본을 남긴다.
4. 다봄 적재(MDM-08) 뒤 맞추기 순위 4로 연결(MAT-11).

## 5. 맞추기 순서 개정 [제안 · DEC-13]

| 순위 | 대상 | 바뀐 점 |
|---|---|---|
| 0 | 지정 부품 | 같음 |
| 1 | 동일 MPN 기존 품목 | 재고 보유를 먼저 보이고, 재고 0이면 사용 이력 품목으로 표시한다. 같은 사양의 재고 보유 품목이 있으면 흡수안을 함께 낸다 |
| 2 | 사양 동등 기존 품목 | 정렬: 사용 가능 재고 보유 > 사용 이력 품목(재구매 가능) > 사내 표준 등급 > 사용 모델 수 |
| 3 | 후보 풀 승인품 | 같음 |
| 4 | 거래처 카탈로그 | **신설.** 기존 거래처 라인카드 제조사의 계열 → 견적 → 신규 품목 등록 |
| 5 | 외부 유통 후보 | 순위 4에서 5로. 유통사 조회 결과는 저장하지 않는다 |

상세는 [docs/02 3장](02_업무흐름.md).

**뿌리 점검(2026-11-24, DEC-18)** [판단] · 위 18건을 "BOM에서 읽는 것이 있는가"로 다시 보았다. 17건은 E-BOM·M-BOM 행, 변경 패키지, BOM 이력 중 하나를 입력으로 쓴다([docs/04 1.1](04_기능_범위.md)). 이 중 '재고 열람과 분류 필터'(`MAT-12`)는 BOM 행이 아니라 BOM이 맞춰 볼 사내 품목을 E-BOM 작성 전에 보는 입구다. 나머지 1건(MSL 개봉 시간 추적)은 BOM에서 읽을 입력이 없고 현장 실행의 일이라 범위 밖이었다. 이 판정은 뿌리 원칙과 같은 방향이다.
