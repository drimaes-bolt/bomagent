# 08. ERP 코드 발번

> 다봄은 ERP 코드를 지어내지 않는다. 같은 부품이면 기존 코드를 쓰고, 새 부품이면 규칙대로 만들어 사람 승인을 받고, 사양이 확정되지 않았으면 보류한다. 규칙에 빈칸이 있으면 가장 가까운 코드로 메우지 않고 개정 요청으로 올린다. 제품·반제품 품번에는 규칙이 없으므로 사람이 정한다. 상세 규칙과 근거는 R05에 있다.

---

## 1. 다봄에서 ERP 코드가 하는 일

- ERP 코드(사내 품번, M-BOM의 자품번)는 품목 마스터의 키다. 발주·입고·재고·원가·BOM 전개가 모두 이 코드로 돈다(R05 1장).
- MPN만으로는 부족하다. 같은 부품도 표기가 흔들리고, 대체품이 생기면 MPN이 여럿이 되며, PCB·기구·조립품처럼 MPN이 없는 품목도 많다(R05 1.2).
- 다봄에서 ERP 코드는 M-BOM의 자품번, 재고·거래처를 잇는 키, 개정·대체 이력의 기준점이다.

## 2. 규칙 요약 [규정]

| 항목 | 내용 |
|---|---|
| 형식 | `CC-BBBBBBBBB`. 대분류 2자리 + 하이픈 + 본체 9자리 = 12자. 정규식 `^[0-9]{2}-[0-9A-HJ-NP-Y]{9}$`(I·O·Z 제외) |
| 자리 | 하이픈을 빼고 D1~D11. D1~D2 대분류, D3~D9 본체, D10~D11 접미(회로는 제조사, PCB·기구는 버전) |
| 회로 대분류 | 10 저항 · 12 커패시터 · 14 인덕터 · 16 커넥터 · 17 클록 · 18 TR·다이오드·LED · 20 메모리 · 22 IC · 24 CPU · 26 RF · 28 스위치·릴레이 · 30 PCB · 32 USIM · 34 안테나 · 36 마이크·스피커 등 · 38 하네스 · 40 LCD |
| 기구 대분류 | 62~82 (커버, 하우징, 나사, 너트, 프레임, 브래킷, 플레이트, 접착, 보호 테이프, 개스킷, 흡수재) |
| 구성 I (10·12·14) | 사이즈·공차·(전압)·값을 자리에 넣는다. 예: `12-155710400` = MLCC 1005 · ±10% · 50V · 100nF |
| 구성 II (30 PCB) | 층수·구조·일련번호·버전. 예: `30-102E51M11` |
| 구성 III (그 외) | 세부 분류 + MPN 숫자부에서 딴 일련번호 |
| 기구 | 중분류(재질 등)·소분류(위치·목적)·고유번호·버전 |

기계 판독용 규칙(R05 2.7의 YAML)이 규칙 엔진(`COD-01`)의 출발점이다.

## 3. 발번 절차와 담당 (R05 4.1)

| 단계 | 내용 | 담당 |
|---|---|---|
| [1] 정체성 확정 | MPN·제조사·데이터시트 사양 | 모델 + 사람(구매/자재·연구소) |
| [2] 대분류 판정 | 무엇인가(저항, 비드, 커넥터, LDO…) | 모델 |
| [3] 속성 추출 | 사이즈·공차·전압·값·종류·방향 | 모델 |
| [4] 자리 코드 변환 | 코드표로 본체를 만든다 | 규칙 엔진 |
| [5] 충돌 검사 | 같은 본체가 이미 있는가(비활성·단종·대체된 품번 포함) | 규칙 엔진 |
| [6] 접미 결정 | 처음이면 `00`. 같은 본체가 있으면 FFF·제조사 비교 | 규칙 엔진 + 사람 |
| [7] 형식 검사 | 12자, 허용 문자 | 규칙 엔진 |
| [8] 승인과 등록 | 사람이 승인하고 ERP에 등록 | 사람 |

[1]을 건너뛰고 설명 문자열만으로 채번하면 틀린 설명이 코드로 굳는다(R05 5.4의 6·7번).

## 4. 재사용 우선

| 경우 | 처리 | 근거 |
|---|---|---|
| 동일 MPN 기존 품목 | 기존 코드 재사용. 포장 접미사 변형은 동일 부품 판정 뒤 | R05 6.5 |
| 사양 동등 기존 품목 | 흡수를 제안하고, 승인되면 기존 품목(MPN 포함)으로 바꿔 기존 코드를 쓴다 | R02 시나리오 E |
| 흡수 조건 | 같은 사이즈·값·공차, 정격은 같거나 높게, 유전체는 같거나 낫게(X5R → X7R 허용), 비드는 같은 계열(MPN 앞 11자 일치) | KK13~KK16 [가상] 적용 기준 |
| 흡수의 영향 | 단가·등급이 바뀔 수 있다(예: 차량용 등급 품목으로 흡수하면 단가가 오른다) | 구매/자재·연구소 확인 |

- 한 MPN이 두 코드에, 한 코드에 두 MPN이 붙으면 안 된다. 자동 검증기로 막는다([docs/09 4장](09_검증_평가.md)).
- 같은 반제품 안에서 같은 자품번이 된 행은 한 행으로 합친다. 실장과 미사용은 따로 둔다(DEC-11).

## 5. 신규 발번, 충돌, 접미

- **충돌** · 규칙으로 만든 번호가 이미 다른 품목에 쓰이고 있으면 접미를 올려 자동으로 피하지 않는다. 기존 품목의 해독 결과와 규격을 대조한 뒤 ① 흡수 ② 기존 오등록 정정(신규 발번 + `Superseded_By`) ③ 예외표 등록 중에서 사람이 고른다(RB-PN-03, R05 6.2 사례).
- **불변** · 기존 품번은 바꾸지 않고 다른 품목에 다시 쓰지 않는다(RB-PN-09).
- **접미 정책(OI-05)** · ① 제조사 코드표를 만들어 끝 2자리에 넣거나, ② 끝 2자리를 본체 안 순번으로 다시 정의하고 제조사는 AVL로 관리한다. R05는 실무와 맞는 ②를 권고했다(부품 347개 중 92.5%가 `00`). 결정 전까지 다봄은 관측된 관행(처음 `00`, 같은 본체면 다음 번호)을 따르고 근거를 남긴다.

---

## 6. 발번 보류

- MPN·사양이 확정되지 않은 행은 번호를 만들지 않는다. 사양 확정이 채번보다 먼저다(R05 4.4·6.5).
- 값이 적히지 않은 미실장 행은 보류 상태로 두고 소요에서 뺀다.
- MPN이 바뀌면 그 개정에서 코드도 바뀐다. 시제 품번과 양산 품번은 다른 품목이다(R04 A9). KK14 샘플에서는 AP가 시제 EVT1 → EVT2 → 양산 품번으로 바뀌면서 자품번이 두 번 바뀐다 [가상].

## 7. 규칙 밖 품목

| 품목 | 지금 | 다봄 처리 | 과제 |
|---|---|---|---|
| 제품·반제품(`MS…` 10자) | 채번 규칙 없음(사례 기업 확인, R05 3.3) | 생산관리가 정한 번호를 기록만 한다. 해독·형식 판정·번호 제안을 하지 않는다 | — |
| 펌웨어·소프트웨어 | 대분류 없음 | 프로그래밍 품목 행의 `Firmware_Revision`과 비고로 개정을 관리한다 | 대분류 신설 검토(OI-17) |
| 라벨, 소음 방지 패드 | `84`·`86`을 규정 없이 쓰는 중 | 관측된 코드를 그대로 쓰고, 신규는 개정 요청 | 대분류 정의 |
| 기구물 | 규칙이 슬라이드에만 있다 | 3단계에 스키마로 옮긴다(`COD-07`) | 버전 자리 정책(FFF 호환 개정의 처리) |
| 포장재, 공정 부자재 | 자리가 없다 | 신규는 개정 요청 | 대분류 정의 |
| 학습용 코드 체계(예: `CA000013`) | 학습 시트의 가상 체계 | 다봄에서 쓰지 않는다. 실제 ERP 12자 체계가 정본이다(DEC-10) | OI-14 |

## 8. 규정 공백과 v1.1 개정 과제 (DT-09)

**R05 2.8에서 정리한 13개**

자리 번호 표기 불일치, '그 이외' 설명의 자리 중복, 클록 본체 길이 초과, PCB 자리 배분의 문서 간 차이, `6X`·`7X`·`8X`의 X 의미 없음, 공차 코드 누락(인덕터 ±2% 등), 커패시터 전압 경계 모호, 18 머리말과 실제 품목 불일치, 22 IC 세부 코드 칸 부족, 메모리 용량 단위 없음, 명칭 없는 코드, 펌웨어·라벨·포장·부자재 자리 없음, 접미 제조사 코드표 없음.

**KK13~KK16 전개에서 더 확인한 공백** [관측]

| 품목 | 규정 상태 | 샘플의 임시 처리 [가상] |
|---|---|---|
| 크리스털 크기 2520·1610 | 크기 코드 없음 | `9` |
| DDR3 1.5V | 전압 코드 없음 | `9` |
| 탄탈 커패시터 케이스 | 크기 코드 없음 | `99` |
| 공통모드 필터 2010 | 크기 코드 없음 | `21` |
| 칩 인덕터 ±0.3nH | 공차 코드 없음 | `9` |
| 배터리 | 대분류 불명확 | `36` Others(`09`) |
| 쉴드 클립 | 대분류 없음 | `64` 하우징 중분류 `00` |
| FPGA | 세부 코드 없음 | `22` Others(`99`) |

샘플에서는 Others 관례로 임시 처리했다. 실제 운영에서는 RB-PN-02에 따라 등록을 막고 개정 요청으로 올린다.

**정책 결정이 필요한 것**

- 접미 정책(OI-05)
- FFF 호환 개정을 새 품번으로 할지 리비전 속성으로 할지(R05 3.2)
- 메모리 등급 자리를 살릴지(R05 5.4의 10~12번)
- 발번 권한 창구와 불변성의 명문화(R05 1.3에서 '문서에 명시 없음')

## 9. 기존 마스터 정리

- 불일치 17건(R05 5.4)의 처리 경로: 재채번 검토 4건(다른 사양의 자리를 차지한 1·2·4·5번, OI-20), 정책 결정 뒤 처리 3건(메모리 등급), 레거시 유지·예외표 10건. 6·7번은 설명 정정을 함께 한다(R05 6.3).
- 대량 재채번은 하지 않는다. 품번은 발주서·재고 이력·원가·도면·라벨에 퍼져 있다(R05 6.3).
- 같은 사양 품번은 병합하지 않고 연결한다. 품명 칸에 MPN이 둘 적힌 품목은 대체 관계로 나눈다(RB-PN-05·07).
- 정기 감사(`COD-06`): 형식, 해독 정합, 중복, 금지 문자, 미정의 코드.
