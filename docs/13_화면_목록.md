# 13. 화면 목록

> 시연 목업에는 세 부서(연구소·생산관리·자재/구매)의 동작 화면 12개와 다음 단계 미리보기 화면 12개가 있다. 회계·품질·영업·기준정보 담당은 부서 이름만 있고 화면이 없다. 새 화면 기획은 이 문서에 행을 더하는 것에서 시작한다.

기준 판: [`briefing/DaBOM_taste_skill_20261021.html`](../briefing/DaBOM_taste_skill_20261021.html). 이 문서의 화면·구성·기능 ID는 목업 코드의 `DEPT`·`FUT`·`TIPS` 정의와 화면 함수에서 옮겼다. [관측: 2026-11-19 목업 코드 확인]

---

## 0. 읽는 법

| 열 | 뜻 |
|---|---|
| 주소 | 화면 ID. 목업 주소 `#부서/화면`과 같다. 부서 코드는 `rnd` 연구소 · `pm` 생산관리 · `mp` 자재/구매. 미리보기 화면은 `f-`로 시작한다 |
| 답하는 질문 | 그 화면에서 사용자가 답을 얻는 질문 하나 |
| 기능·질의 | [docs/04](04_기능_범위.md)의 기능 ID, [docs/03](03_부서별_활용.md)의 질의 ID, [docs/05](05_데이터와_ERP연동.md)의 데이터 준비 과제 ID |
| 단계 | 그 기능이 처음 들어가는 단계([docs/10](10_로드맵_추진체계.md)) |
| 상태 | 시연 = 목업에서 동작 · 미리보기 = 설명과 옅은 표만, 버튼 동작 없음 · 기획 = 목업에 없음 |

## 1. 공통

| 요소 | 내용 |
|---|---|
| 진입 화면 | 부서를 고른다. 시연이라 인증이 없다. 운영에서는 사내 계정 권한에 따라 부서 화면이 바로 열린다(`MDM-05`) |
| 상단 막대 | 다봄 표지(처음으로), 전역 검색(연구소·자재/구매는 사내 품목, 생산관리는 제품), "시연 목업 · 값은 [가상]" 표시, 설명 풍선 켜기·끄기, 알림, 부서 전환, 시연 초기화 |
| 사이드바 | 부서 메뉴(동작 화면), "다음 단계에 들어갈 화면"(미리보기), 부서 안내, 현재 범위 표시(데이터: samples 사본·가공·가상 값 / 모델: NC AI 튜닝 전, 사전 계산 결과 재생 / 자율성: A1 제안 [제안]) |
| 설명 풍선 | 화면 요소마다 제목·존재 이유·실무 쓰임·근거·단계·기능 ID를 보여 준다. 기획 의도를 설명하는 장치다 |
| 알림 | 부서 간 전달(전송·구조 확정·회신)이 받는 부서의 알림으로 들어간다 |
| 내보내기 | 화면마다 "Excel 내보내기", "ERP 등록 파일" 같은 단추가 있지만 시연용 더미다. 실제 파일은 만들지 않는다 |

## 2. 연구소 (`rnd`)

승인 권한: 사양 확정, FFF 판정, L1 설계 변경. 단가·거래처 정보는 연구소 화면에 보이지 않는다(공개 범위 [제안], [docs/03 7장](03_부서별_활용.md)).

| 주소 | 화면 | 답하는 질문 | 주요 구성 | 기능·질의 | 단계 | 상태 |
|---|---|---|---|---|---|---|
| `rnd/import` | E-BOM 가져오기·변환 | 이 E-BOM으로 M-BOM 초안이 나오나 | 5단계 진행: ① 파일 가져오기(원본 보관) ② E-BOM 확인(표 해독·원문 보존) ③ M-BOM 변환(맞추기·만들기·품번, 맞추기 순위별 행 수) ④ 검토·수정(행별 근거, 셀 수정, 교정 로그) ⑤ 생산관리로 전송. 개정 이력·ERP 코드 발번 내역 보기 | `IMP` `MAT` `BLD` `COD` `CFM-05` | 1 | 시연 |
| `rnd/requests` | 확인 요청함 | 다봄이 내게 묻는 사양 질문은 무엇인가 | 요청 목록과 응답, 다시 쓸 답은 결정 기록으로 저장, 상위 보고 | `CFM-01` `CFM-05` | 1 | 시연 |
| `rnd/search` | 사내 품목 검색 | 이 사양의 사내 품목이 이미 있나 | 낱말 검색(품번·품명·규격·제조업체), 가용 재고·입고 예정·사용 모델·라이프사이클. 재고 단가는 비공개 | `MAT-03` `MAT-04` · D-1 | 1 | 시연 |
| `rnd/sent` | 전송 이력 | 내가 보낸 초안·변경이 어디까지 반영됐나 | 일시·모델·문서·내용·받는 부서·상태 | `TRK` · KPI-04 | 1 | 시연 |
| `rnd/f-ecompare` | E-BOM 개정 비교 | V02를 올렸다. 무엇이 바뀌나 | 행 단위 비교(추가·삭제·수량·사양), M-BOM 반영 초안, 변경 층 판정 | `IMP-08` `TRK-02` · D-7 | 2 | 미리보기 |
| `rnd/f-impact` | 설계 변경 영향 확인 | 이 부품을 바꾸면 무엇이 영향받나 | 발주 상태, 잔여 재고와 불용 금액, 신규 부품 리드타임, 같은 부품을 쓰는 다른 모델 | `TRK-04` · D-4 | 2 | 미리보기 |

|---|---|---|---|---|---|---|
| `pm/products` | 제품 BOM 현황 | 이 제품의 최신 M-BOM은 무엇이고 어떻게 바뀌어 왔나 | 제품 카드(KK13·KK14·KK15, 전송되면 KK16), 단계 타임라인(S0~S6, 기준선 표시), 탭: M-BOM·개정 이력·E-BOM·ERP 코드, where-used, ERP 등록 파일 대화상자(22열 + 개정 이력 + 발번 내역, 파일은 만들지 않음) | `BLD-06` `TRK-01` `TRK-02` `CFM-04` | 1~2 | 시연 |
| `pm/inbox` | 수신함 · 구조 확정 | 받은 초안의 구조를 확정할 수 있나 | 연구소 전송분 수신, 제품·반제품 품번 입력, 구조 점검(자동 구조 검증 `BLD-07`은 2단계 표시) | `BLD-01` · M-4 | 1 | 시연 |

| `pm/f-effect` | 효력 시점·재고 처분 | 새 개정을 언제부터 투입하나 | 재고 소진 예상·미결 발주·투입 계획 비교, 효력 유형(즉시·일자·시리얼·로트·소진 후·한시) | `TRK-04` · M-5 | 2 | 미리보기 |

## 6. 기능 대비 화면 공백

[docs/04](04_기능_범위.md)의 기능 중 동작 화면이나 미리보기 화면에 연결되지 않은 것이다. 새 화면 기획의 후보 목록으로 쓴다. [판단]

| 단계 | 기능 | 지금 상태 | 화면 후보 |
|---|---|---|---|
| 1 | `MDM-02` 후보 풀 관리, `MDM-03` 사전 관리, `MDM-05` 권한과 뷰, `MDM-06` 감사 로그, `MDM-07` 지정 부품·인증 구성 목록, `COD-01` 채번 규칙 스키마 | 기준정보 담당 부서에 화면이 없다. 후보 풀은 연구소 미리보기만 있다 | 기준정보 담당 부서 화면 |
| 2 | `CFM-03` 기준선 동결 | 단계 타임라인의 기준선 표시와 "차단성 요청이 남으면 동결할 수 없다"는 안내만 있고, 동결 조건 검사 화면이 없다 | `pm/products` 또는 확정 화면 |
| 2 | `MAT-09` 같은 값 변형 탐지·통합 후보 | 화면이 없다 | `mp/purchase` 흡수 제안 옆 |
| 2 | `COD-05` 충돌 처리안, `COD-06` 품목 마스터 감사 | 화면이 없다 | 기준정보 담당 부서 화면 |
| 2 | `CST-01` `CST-02` 자재비 롤업·개정별 추이 | 회계 부서에 화면이 없다 | 회계 부서 화면 |

| 3 | `TRK-05` 충돌 규칙 검사, `TRK-07` 편차·특채 만료 | 품질 부서에 화면이 없다 | 품질 부서 화면 |

| 3 | `CST-03` `CST-04` 변경 원가 영향·불용 위험 재고 | 재고 현황에 불용 위험 후보 표시만 있다 | 회계 부서 화면 |

## 7. 화면을 더할 때

1. 이 문서의 해당 부서 표에 행을 더한다. 주소는 기존 주소와 겹치지 않게 정한다.
2. 화면이 쓰는 기능이 [docs/04](04_기능_범위.md)에 없으면 기능 ID부터 만든다.
3. 목업에 넣을 때는 `.claude/skills/dabom-mockup/SKILL.md`의 절차를 따른다.
4. 6장 공백 표에서 해결된 행을 지운다.
