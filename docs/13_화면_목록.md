# 13. 화면 목록

> 시연 목업에는 동작 화면 15개와 미리보기 화면 33개가 있다. 동작 부서는 연구소·생산관리·자재/구매이고, 생산기술·회계·품질·기준정보는 화면 기획을 미리보기로 넣은 부서다(회계와 기준정보는 동작 화면 1개씩). 영업·고객 대응만 화면이 없다. 새 화면 기획은 이 문서에 행을 더하는 것에서 시작한다.

기준 판: [`briefing/DaBOM_avl_20261127.html`](../briefing/DaBOM_avl_20261127.html)(AVL 판. 뿌리 판에 AVL·공급 제품 화면을 더했다). 이 문서의 화면·구성·기능 ID는 목업 코드의 `DEPT`·`FUT`·`TIPS` 정의와 화면 함수에서 옮겼다. [관측: 2026-11-23 목업 코드 확인] 이전 기준 판은 뿌리 판 [`DaBOM_root_20261124.html`](../briefing/DaBOM_root_20261124.html), 확장 판 [`DaBOM_expand_20261123.html`](../briefing/DaBOM_expand_20261123.html)이고, 그 앞은 [`DaBOM_taste_skill_20261021.html`](../briefing/DaBOM_taste_skill_20261021.html)이다.

## 0. 읽는 법

| 열 | 뜻 |
|---|---|
| 주소 | 화면 ID. 목업 주소 `#부서/화면`과 같다. 부서 코드는 `rnd` 연구소 · `pm` 생산관리 · `mp` 자재/구매 · `pe` 생산기술 · `acc` 회계 · `qa` 품질 · `mdm` 기준정보. 미리보기 화면은 `f-`로 시작한다 |
| 답하는 질문 | 그 화면에서 사용자가 답을 얻는 질문 하나 |
| 기능·질의 | [docs/04](04_기능_범위.md)의 기능 ID, [docs/03](03_부서별_활용.md)의 질의 ID, [docs/05](05_데이터와_ERP연동.md)의 데이터 준비 과제 ID |
| 단계 | 그 기능이 처음 들어가는 단계([docs/10](10_로드맵_추진체계.md)) |
| 상태 | 시연 = 목업에서 동작 · 미리보기 = 설명과 옅은 표만, 버튼 동작 없음 · 기획 = 목업에 없음 |

## 1. 공통

| 요소 | 내용 |
|---|---|
| 진입 화면 | 첫머리에 "시작도 뿌리도 BOM이다"(뿌리 원칙, DEC-18)와 한 줄 정의, 이름의 뜻(다 + 봄)을 둔다. 그 아래 **뿌리(BOM = E-BOM + SCM 정보 → M-BOM) → 줄기(처음 만든 여섯 기능) → 가지(부서)** 지도 안에서 부서를 고른다. 가지 목록은 동작 부서(연구소·생산관리·자재/구매) → 미리보기 부서 → 참여 부서 순서이고, 부서마다 BOM의 어디를 보는지 한 줄이 붙는다([docs/03 0.1](03_부서별_활용.md)). 그 아래 "가지를 더하는 규칙" 3개, "한 행이 M-BOM이 되기까지", 시연 순서, "재고 목록 바로 보기"(E-BOM 없이 연구소·자재/구매 화면으로 열기)가 있다. 시연이라 인증이 없고, 운영에서는 사내 계정 권한에 따라 부서 화면이 바로 열린다(`MDM-05`) |
| 상단 막대 | 다봄 표지(처음으로), 전역 검색(생산관리는 제품, 나머지는 사내 품목. 사용 이력 품목은 "재고 0 · 사용 이력"으로 표시), "시연 목업 · 값은 [가상]" 표시, 설명 풍선 켜기·끄기, 알림, 부서 전환(동작 부서 / 화면 기획 부서 / 참여 부서), 시연 초기화 |
| 사이드바 | 부서 메뉴(동작 화면), "다음 단계에 들어갈 화면" 또는 "화면 기획(미리보기)", 부서 안내, 현재 범위 표시(데이터: 재고 Inventory.xlsx · 사용 이력 PartHistory.xlsx · 그 밖 samples 사본·가상 값 / 모델: NC AI 튜닝 전, 사전 계산 결과 재생 / 자율성: A1 제안 [제안]) |
| 분류 필터 | 재고 현황·사내 재고·부품 찾기·거래처 카탈로그에 공통. ERP 대분류 체크 상자 → (저항·커패시터·인덕터) 크기·값·허용오차·유전체·정격전압 → 제조업체·재고·이력 상태·사용 모델·자료 출처. 숫자는 그 값을 고르면 남는 품목 수. 1100px 이하에서는 "분류 필터" 단추로 접힌다(`MAT-12`) |
| 설명 풍선 | 화면 요소마다 제목·존재 이유·실무 쓰임·근거·단계·기능 ID를 보여 준다. 기획 의도를 설명하는 장치다 |
| 알림 | 부서 간 전달(전송·구조 확정·회신)이 받는 부서의 알림으로 들어간다 |
| 내보내기 | 화면마다 "Excel 내보내기", "ERP 등록 파일" 같은 단추가 있지만 시연용 더미다. 실제 파일은 만들지 않는다 |

## 11. 화면을 더할 때

1. 이 문서의 해당 부서 표에 행을 더한다. 주소는 기존 주소와 겹치지 않게 정한다.
2. 화면이 쓰는 기능이 [docs/04](04_기능_범위.md)에 없으면 기능 ID부터 만든다.
3. 목업에 넣을 때는 `.claude/skills/dabom-mockup/SKILL.md`의 절차를 따른다.
4. 10장 공백 표에서 해결된 행을 지운다.
5. 기획 현황판을 다시 만든다: `python tools/build_plan_board.py`
6. 새 화면은 BOM의 무엇을 읽고 무엇을 돌려주는지 12장 표와 목업 `FUT_BOM`에 한 줄 적는다. 적을 수 없으면 화면을 만들지 않고 [docs/11](11_결정_미결_목록.md)에 미결로 올린다(DEC-18).

- 33개 화면 가운데 32개는 BOM에서 읽는 것을 적을 수 있다. `mp/f-po`(발주 발행)는 목록까지가 다봄이고 발행은 ERP와 구매 업무의 일이라 'BOM 밖의 실행'으로 둔다(docs/01 4장).
- `rnd/f-pool`처럼 받침 층의 화면은 BOM 행을 입력으로 받지 않고, 맞추기가 조회하는 기준정보를 채운다. 그래서 읽는 것을 "맞추기가 조회하는 …"으로 적었다.
- 동작 화면 15개 가운데 14개는 줄기(가져오기·맞추기·만들기·추적)와 회계 롤업(`CST-01`)이라 BOM과의 연결이 화면 이름에 드러난다. 따로 띠를 두지 않았다. 나머지 `mdm/avl`은 받침 층(`MDM-10`)으로, BOM 행이 맞춰 보는 AVL·공급 제품을 보여 주고 `MAT-14`가 이것을 읽는다.
