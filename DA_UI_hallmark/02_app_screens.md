# 02 업무 화면 (`app` 프로필)

DA UI hallmark v1.0. `01_foundation.md`를 먼저 읽는다. 시작 틀은 `10_template_app.html`이다.

업무 화면은 읽고 끝나는 페이지가 아니라 매일 일하는 화면이다. 목록·상세·설정, 승인 대기열, 관리 화면, 현황판, 시연용 목업이 여기에 든다. 기준은 taste-skill의 앱 화면 규칙(23개 실제 제품 화면 조사)과 다봄 시연 목업 taste 판이다.

---

## 1. 만들기 전에 쓸 것

노트에 8~12줄로 쓴다. 이것이 화면의 질을 정한다.

| 항목 | 예 |
|---|---|
| 다루는 대상과 필드, 단위 | 변경 요청(ID, 제목, 요청 부서, 영향 품목 수, 요청일, 상태) |
| 실제 규모 | 열린 요청 12건, 한 요청의 영향 품목 1~40개, 하루 2~5건 접수 |
| 쓰는 사람과 빈도 | 구매 담당이 매일 아침 10분, 연구소는 가끔 |
| 다음 할 일 | 승인, 보류, 영향 품목 확인 |
| 이 제품만의 것 | 제품 이름과 표시, 업무 범위(부서·제품), 사람들이 알아보는 대상(품번, 엑셀 시트) |

그다음 화면마다 두 줄을 쓴다.

- **이 화면이 답할 질문 하나.** "오늘 먼저 처리할 요청은 무엇인가." 가장 큰 블록이 이 질문에 답한다.
- **오늘 데이터의 발견 하나.** "보류 3건이 모두 같은 품목을 기다린다." 제목 아래 한 줄에 쓴다.

질문에 답하지 않는 블록은 만들지 않는다. "지표 줄 → 큰 차트 → 작은 차트 두 개 → 표" 같은 상투적 순서를 따르지 않는다.

**데이터는 맞아야 한다.** 합계는 행에서 계산한다. 같은 사실을 두 곳에 보이면 같은 변수에서 만든다. 변화량은 화면에 보이는 두 값의 차이다. 상대 표현에는 기준을 쓴다("지난주보다").

## 2. 셸: 회색 틀 + 흰 시트

```
┌───────────────────────────────────────────────┐  ← 상단 막대 48px (--frame)
│ [표시] 제품명 · 범위        [검색 /]     [도움말][역할] │
├──────────┬────────────────────────────────────┤
│ 사이드바   │ ┌──────────────────────────────┐ │
│ 228px    │ │ 흰 시트 (r16, 1px --edge)       │ │  ← 오른쪽·아래 8px 띄움
│ (--frame)│ │  제목 줄                        │ │
│          │ │  블록 …                         │ │
│          │ └──────────────────────────────┘ │
└──────────┴────────────────────────────────────┘
```

- 사이드바와 상단 막대는 같은 `--frame` 색이고 사이에 선이 없다.
- 시트는 흰색, 모서리 16px, 1px `--edge` 테두리, 그림자 없음. 창의 오른쪽과 아래에서 8px 띄운다.
- 사이드바를 진하거나 채도 높은 색으로 칠하지 않는다.
- 대상이 다섯 곳 이하이고 화면이 단순하면 사이드바 없이 상단 막대 + 가운데 열(최대 1200px)로 만든다.

### 2.1 사이드바

- 맨 위에 제품 표시와 이름, 그 아래 범위(부서, 제품, 프로젝트)를 보인다. 어느 제품 화면인지 캡처만 보고 알 수 있어야 한다.
- 메뉴 행은 높이 32px, 글자 14px, 아이콘 16px 회색 선. 메뉴는 다른 화면으로 가는 것이지 같은 페이지의 앵커가 아니다.
- 선택된 메뉴는 `--active` 채움 + `--ink` + 600. 막대·점·글로우를 쓰지 않는다. `aria-current="page"`를 단다.
- 묶음 이름은 12px 회색 문장형. 대문자·자간 넓힘 없음.
- 숫자 배지는 처리할 일이 쌓인 대기열에만 단다("변경 요청 5"). 네이비 바탕 흰 숫자.
- 아래쪽에는 범위 요약(`dl`)이나 도움말 한 줄을 둘 수 있다.

### 2.2 상단 막대

실제로 담을 것이 있을 때만 둔다: 제품 표시, 검색, 범위 전환, 사용자 역할. 검색은 가운데 최대 548×32px, 단축키 `/` 표시. 비어 있는 넓은 막대를 남기지 않는다.

### 2.3 제목 줄 (`.pg-head`)

- `h1` 하나, 22px/600, 명사형("변경 요청", "품목", "설정"). 대상 하나를 보는 상세 화면은 그 대상의 이름.
- 아래 한 줄(14px `--ink-2`)에 발견이나 범위를 쓴다. 화면 사용법("이 화면은 …을 보여 줍니다")을 쓰지 않는다.
- 오른쪽에는 실제 동작만 둔다. 주 버튼(네이비)은 화면에 하나다. 갱신 시각("10:24 기준")을 둘 수 있다.

## 3. 블록 배치

- 시트 안 여백 24px, 블록 사이 16px 하나로 통일한다.
- 열 수는 항목 수로 정한다. 지표 4개면 4열. 3열 격자에 4개를 넣어 하나가 혼자 남게 하지 않는다.
- 같은 줄의 블록은 아래 끝을 맞춘다. 내용이 짧은 블록을 옆 블록 높이로 늘려 빈 띠를 만들지 않는다(`align-items: start`).
- 열 다섯 개 이하의 표나 여섯 행 이하의 목록은 1440px에서 화면 전체로 늘리지 않는다. 760px 안팎으로 두고 옆에 다음 블록을 둔다.
- 1440×900 첫 화면에서 요청받은 모든 블록의 머리와 첫 행이 보이게 한다. 긴 목록은 4~6행으로 자르고 "전체 보기"를 둔다.
- 화면의 주 업무 동작은 한 번에 닿게 한다: 제목 줄의 주 버튼, 그 행의 동작 버튼.

## 4. 지표 (`.kpis`)

- 지표마다 상자를 따로 만들지 않는다. 한 상자를 1px 선으로 나눈다.
- 라벨(13px `--ink-2`) 위, 값(22~24px/600 `--ink`) 아래. 단위는 작은 회색 글자("12 건", "2.4 일").
- 아이콘, 색 원, 미니 차트(sparkline)를 넣지 않는다.
- 화면의 답이 되는 숫자 하나만 28~30px로 키운다. 48px 이상은 쓰지 않는다.
- 지표가 필터 역할을 하면(누르면 표가 걸러짐) 선택된 칸 아래 2px 네이비 선을 긋는다.
- 변화량은 선택이다. 쓸 때는 기준을 문장으로 쓴다("지난주보다 +2"). 0이나 비교 불가는 회색 "–".

## 5. 표와 목록 (`.tbl`)

| 항목 | 규칙 |
|---|---|
| 머리글 | 12~13px, 400, `--ink-3`, 문장형. 바탕 띠·대문자·자간 없음. 아래 1px `--edge` 선 하나 |
| 행 | 높이 40~48px, 행 사이 1px `--rule`. 줄무늬(zebra) 없음 |
| 숫자 | 오른쪽 정렬, `tabular-nums`, 지표마다 소수 자릿수 고정. 머리글도 오른쪽 정렬 |
| 식별 열 | 가장 넓게(표의 1/3~1/2). 잘리는 열이 되지 않게 한다 |
| 글자 색 | 식별 값과 핵심 숫자만 `--ink`, 나머지는 `--ink-2` |
| 상태 | 행마다 꼬리표 하나. 같은 뜻의 꼬리표와 배지를 겹쳐 달지 않는다 |
| 빈 값 | 회색 "–". 실제 0은 "0" |
| 날짜 | 비교하는 표는 `2026-10-21`, 최근성은 "오늘", "어제", "3일 전" |
| 넘치는 글 | 한 줄 말줄임(…), 단어 중간에서 끊지 않는다. `title`로 전체 값 |
| 선택·마우스 | 마우스는 `--raised` 바탕, 선택은 `--b50` 바탕. 행이 움직이지 않는다 |
| 행 동작 | 대부분 행에 필요하면 맨 오른쪽 고정 열에 글자 버튼, 아니면 없음 |
| 개수 | 표 위에 "12건 중 5건" 같은 개수. 개요 화면에 쪽 번호를 달지 않는다. 전체 목록 화면은 "1–50 / 1,284" |

휴대폰(640px 이하)에서는 표를 두 줄 목록으로 바꾼다. 1줄: 식별 값 + 상태, 2줄: 나머지 필드(13px `--ink-3`, 가운뎃점으로 구분). 필드를 빼지 않는다. 표를 꼭 유지해야 하면 표만 자기 틀 안에서 가로로 스크롤하고 첫 열을 고정한다. 페이지 전체가 옆으로 밀리면 안 된다.

### 5.1 엑셀형 표 (`data-sheet`)

작업 대상이 엑셀 시트(E-BOM, M-BOM, 재고표)일 때만 쓴다. 표 바깥 상자에 `data-sheet` 속성을 단다.

- 글꼴 `--sheet-font`(맑은 고딕) 13px, 행 높이 24px, 격자선 1px `--grid`.
- 열 머리(A, B, C…)와 행 번호는 `--frame` 띠. 일반 표의 "머리글 띠 금지"에서 이 표만 예외다.
- 선택 칸은 2px 네이비 외곽선, 선택 행·열 머리는 `--active` 바탕 + 네이비 글자.
- 고친 칸은 `--b50` 바탕 + 네이비 굵은 글자 + 오른쪽 위 작은 삼각 표시.
- 위에 이름 칸 + 수식 줄(선택 칸 주소와 값), 아래에 시트 탭을 둘 수 있다.
- 머리 행과 첫 열은 스크롤해도 고정한다.

## 6. 상태 꼬리표 (`.tag`)

높이 20px, 12px/500, 모서리 4px, `flex:none; white-space:nowrap`(찌그러지지 않게). 색은 `01_foundation.md` 2.5를 따른다. 제목 위에 꼬리표를 달지 않는다.

---

## 7. 필터·탭·검색

- **칩 필터** (`.chips`): 28px, 선택된 칩만 네이비 바탕 흰 글자, 개수는 칩 안 작은 숫자. 휴대폰에서는 선택 상자 하나로 바꾼다.
- **구간 선택** (`.seg`): `--hover` 바탕 안에 선택된 흰 칸. 선택지만큼만 넓게.
- **밑줄 탭** (`.tabs`): 1px `--edge` 선 위, 선택 탭 아래 2px 네이비. `role="tablist"`, `role="tab"`, `aria-selected`.
- **검색**: 한 화면에 하나, 높이 32px, 앞에 14px 돋보기.
- 순서: 범위(기간·부서)는 왼쪽, 보조 동작은 오른쪽. 필터 줄은 한 줄로 끝낸다. 휴대폰에서 첫 목록 행이 화면 위 60% 안에 오게 한다.
- 개수는 지금 보이는 범위로 계산하고, 필터를 바꿀 때마다 다시 계산한다.

## 8. 입력과 설정

- 라벨은 칸 위에(13~14px/500, 6~8px 간격). 자리채움 글을 라벨 대신 쓰지 않는다.
- 입력칸 높이: 도구 막대 32px, 양식 36~40px. 한 줄의 컨트롤은 높이를 맞춘다.
- 입력칸은 흰 바탕 + 1px `--control-strong`. 초점은 2px 네이비 외곽선.
- 켜기·끄기 스위치(`.sw`): 28×16px, 켜짐은 `--ink` 채움, 꺼짐은 `--control-strong` 채움. 브랜드 색을 쓰지 않는다.
- 사용할 수 없는 컨트롤도 읽히게 두고 이유를 쓴다("승인 권한이 없어 바꿀 수 없다").
- 설정 화면: 왼쪽 라벨 열(제목 16px/600 + 설명 14px), 가운데 `--raised` 패널, 오른쪽에 그 설정이 만드는 결과 미리 보기(받게 될 알림, 거칠 단계). 설정 영역마다 별도 화면(주소 #)으로 나눈다.
- 저장 방식은 화면마다 하나: 바꾸면 바로 저장되고 "저장됨" 표시, 또는 패널 오른쪽 아래 저장 버튼 하나.
- 지우기·되돌리기 같은 위험한 동작은 맨 아래 별도 영역에, 무엇이 사라지는지 문장으로 쓰고, 대상 이름을 밝힌 확인 대화상자를 거친다. 빨간색을 쓰지 않는다.

| 종류 | 모양 | 쓰임 |
|---|---|---|
| 주 버튼 `.btn-1` | 네이비 바탕 흰 글자 | 화면의 주 동작 하나 |
| 보조 버튼 `.btn-2` | 흰 바탕 + 1px `--control` | 그 밖의 동작 |

## 10. 떠 있는 요소

툴팁, 메뉴, 팝오버, 대화상자, 토스트, 셀 편집기만 그림자(`--float`)를 쓴다.

- 흰 바탕, 1px `--edge`, 모서리 8px(대화상자 12px).
- 대화상자: 폭 600px(넓게 900px), 뒤 가림막 `rgba(17,17,17,.32)`. 제목, 본문, 오른쪽 아래 버튼(취소 → 주 동작). Esc로 닫힌다. 초점이 대화상자 안에 머문다.
- 토스트: 화면 아래 가운데, 3~4초 뒤 사라짐, `aria-live="polite"`.
- 떠 있는 버튼은 화면의 주 동작이고 아무것도 가리지 않을 때만 쓴다.

## 11. 상태

모든 블록에 빈 상태·0·불러오는 중·오류를 만든다. 모든 행과 컨트롤에 마우스·선택·초점·사용 불가 상태를 만든다.

| 상태 | 모양 |
|---|---|
| 0 | 보통 모양 그대로 "0건" |
| 빈 상태 | 블록의 틀과 머리는 그대로, 한 문장 + 다음 동작. 1px 점선 상자(모서리 8px)를 쓸 수 있다. 그림·이모지 없음 |
| 처음 사용 | 틀과 제목은 그대로, 데이터가 올 자리에 첫 동작 |
| 불러오는 중 | 최종 배치 그대로, 값 자리에 같은 크기의 회색 막대(`--hover`). 반짝이는 그라데이션 없음, 데이터가 와도 배치가 움직이지 않음 |
| 오류 | 실패한 블록 안에 한 문장(무엇이, 언제 마지막 정상값인지) + "다시 시도" 글자 버튼. 화면 전체 경고 띠를 쓰지 않는다 |
| 오래된 값 | "10:24 기준" 표시와 새로 고침 버튼 |
| 향후 기능 | 메뉴나 버튼을 `--ink-3`로 옅게, 꼬리표 "향후". 누르면 무엇이 언제 생기는지 한 문장 |

## 12. 차트

- 차트 하나에 색 하나: 핵심 계열은 네이비, 나머지는 회색(`--control` 또는 `--grid`). 두 번째 색이 필요하면 파랑, 그다음 시안. 한 화면에 네 색을 넘기지 않는다.
- 선 2px 직선, 점 표시 없음. 면 채움은 쓰지 않거나 14% 이하 단색.
- 가로 격자선 3~5개, 옅게(`--rule`). 세로 축 선 없음. 계열이 하나면 범례 없음.
- 도넛은 얇게, 조각에 글자를 달지 않고 범례를 표로.
- 그라데이션, 무지개 색, 3D, 지표 옆 미니 차트를 쓰지 않는다.
- 비어 있는 기간도 그린다(0선, 빈 막대). "데이터 없음" 그림을 쓰지 않는다.
- 그림 라이브러리 없이 SVG로 직접 그려도 된다. 템플릿에 막대 차트 예가 있다.

## 13. 폭에 따라

| 폭 | 바뀌는 것 |
|---|---|
| 1280px 이하 | 열이 많은 격자를 줄인다(5열 → 3열) |
| 1100px 이하 (태블릿) | 사이드바가 상단 막대의 메뉴 버튼으로 접힌다. 오른쪽 보조 열은 본문 아래로. 표는 4~5열 유지, 나머지는 2줄 정보로 |
| 640px 이하 (휴대폰) | 회색 틀이 사라지고 시트가 화면 전체가 된다(여백 16px). 지표 2열. 칩은 선택 상자로. 표는 두 줄 목록으로. 누르는 곳 40px 이상. 제목 20px |

휴대폰에서 사이드바가 화면 폭의 30% 이상을 차지하면 안 된다. 여러 영역(목록과 상세)은 한 번에 하나만 보인다.

## 14. 업무 화면에서 금지

| 금지 | 대신 |
|---|---|
| 진한 네이비 사이드바, 색 채운 활성 메뉴 + 왼쪽 막대 | 바탕색 사이드바, 회색 채움 |
| "환영합니다, ○○님" 인사 제목 | 명사 제목 22px |
| 아이콘 원이 달린 지표 카드 4개 | 1px로 나눈 지표 줄 |
| 모든 지표의 초록 "+12.5%" 알약 | 기준을 쓴 변화량, 0은 회색 |
| 줄무늬 표 + 대문자 머리글 + 행마다 체크 상자·아바타·꼬리표·더보기 | 선과 정렬, 꼬리표 하나, 필요한 곳에만 동작 |
| 왼쪽 정렬 숫자 | 오른쪽 정렬 `tabular-nums` |
| 모든 버튼·탭·링크에 네이비 | 주 버튼 하나와 선택 표시만 |
| 다섯 행 목록 아래 쪽 번호 | 행 자르기 + "전체 보기" + 개수 |
| 자리채움 사람·회사, 반올림한 과장 숫자 | 역할 이름, 행에서 계산한 합계, `[가상]` 표시 |
| 36px 이상 화면 제목, 48px 이상 숫자 | 제목 22~24px, 숫자 22~30px |
| 행마다 상자에 든 아이콘 | 16px 회색 선 아이콘 하나 또는 없음 |

장치를 다 빼고 아무것도 넣지 않으면 깔끔한 빈 틀이 된다. 그 자리를 채우는 것은 제품 자신이다: 실제 규모의 데이터, 가장 큰 블록이 답하는 화면의 질문, 이 제품에만 있는 요소 하나(예: 다봄의 맞추기 결과 막대, BOM 단계 트랙).
