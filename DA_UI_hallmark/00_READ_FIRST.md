# DA UI hallmark v1.0 · 먼저 읽기

이 폴더는 드림에이스의 웹 화면·웹 문서 디자인 규칙이다. HTML로 만드는 업무 화면, 웹 발표 자료, 브리핑·보고 문서에 쓴다. 디자인 작업을 시작하기 전에 이 문서를 끝까지 읽는다.

## 1. 우선순위

1. 사용자가 이번 대화에서 직접 지시한 것
2. 이 폴더의 규칙 (hallmark)
3. 그 밖의 디자인 지침: `DA_WEBUI_KIT.md`, `DA_WEB_darkUI_KIT.md`, 프로젝트에 있는 다른 스타일 규칙

hallmark와 다른 지침이 충돌하면 hallmark를 따른다. 사용자 지시가 hallmark와 어긋나면 지시를 따르고, 어긋난 점을 보고서에 적는다.

## 2. 이 폴더의 파일

| 파일 | 누가 읽나 | 내용 |
|---|---|---|
| `00_READ_FIRST.md` | AI | 이 문서. 우선순위, 읽는 순서, 작업 절차, 결과물 형식 |
| `01_foundation.md` | AI | 색·글꼴·면·간격 기준값, 빼야 할 장치, 예외 표시, 문구 규칙. 모든 결과물에 적용 |
| `02_app_screens.md` | AI | 업무 화면 규칙 |
| `03_slides_docs.md` | AI | 웹 발표·브리핑 문서 규칙 |
| `04_checklist.md` | AI | 넘기기 전 점검 항목, 금지 패턴 검색, 보고 양식 |
| `10_template_app.html` | AI | 업무 화면 시작 틀 |
| `11_template_slides.html` | AI | 발표 자료 시작 틀 |
| `12_template_doc.html` | AI | 스크롤형 브리핑·보고서 시작 틀 |
| `checker.html` | 사람 | 결과 HTML을 Edge에서 검사하는 도구 |
| `GUIDE.html` | 사람 | 처음 쓰는 사람을 위한 안내 |

## 3. 읽는 순서

1. 이 문서, `01_foundation.md`, `04_checklist.md`는 항상 끝까지 읽는다.
2. 만들 것에 맞는 프로필 문서를 읽는다. 둘이 섞이면 둘 다 읽는다.
3. 맞는 템플릿을 열어 구조와 CSS를 확인한다.

| 만들 것 | 프로필 | 규칙 | 템플릿 |
|---|---|---|---|
| 업무 화면, 관리 화면, 목록·상세·설정, 현황판, 시연용 목업 | `app` | `02` | `10` |
| 회의 발표 자료, 한 장씩 넘기는 설명 자료 | `slides` | `03` | `11` |
| 브리핑 문서, 보고서, 요약 페이지, 안내 페이지 | `doc` | `03` | `12` |

## 4. 작업 절차

1. **정리**: 프로필을 정하고 화면(또는 장) 목록을 쓴다. 화면마다 답할 질문 하나, 장마다 주장 하나를 한 줄로 쓴다.
2. **틀에서 시작**: 템플릿을 새 이름으로 복사해 그 위에서 고친다. 템플릿의 `:root` 기준값과 공통 CSS는 바꾸지 않는다. 쓰지 않는 화면·장·구성 요소는 지운다.
3. **내용**: 실제 자료로 채운다. 없는 값은 지어내지 않는다. 시연용으로 만든 값에는 화면에 `[가상]` 또는 "예시 값" 표시를 남긴다.
4. **상태와 폭**: 빈 상태, 불러오는 중, 오류, 사용 불가 상태를 만든다. 1440·768·390 폭에서 깨지지 않게 한다.
5. **점검**: `04_checklist.md` 1~3장을 하나씩 확인한다. 코드 실행을 쓸 수 있으면 4장의 금지 패턴 검색을 돌린다.
6. **보고**: `04_checklist.md` 5장 양식으로 보고한다. 하지 않은 검사는 했다고 쓰지 않는다. 브라우저 검사는 사람이 `checker.html`로 한다고 안내한다.
7. **검사기 보고서 반영**: 사용자가 `checker.html` 보고서를 붙여 넣으면 FAIL부터 고친다. 최대 3회 반복한다(`04_checklist.md` 6장).

## 5. 결과물 형식

- HTML 한 파일로 만든다. CSS와 JS는 파일 안에 넣는다. 그림은 SVG를 직접 넣거나 data URI로 넣는다. 다른 파일을 상대 경로로 불러오지 않는다.
- `<html lang="ko" data-hm-profile="app">`(또는 `slides`, `doc`), `<meta name="viewport" content="width=device-width, initial-scale=1">`, `<title>`을 넣는다.
- 화면 또는 장이 여러 개면 각각에 `data-hm-view="이름"`을 붙이고, `window.hmShow("이름")`으로 그 화면을 열 수 있게 한다. 주소 `#이름`으로도 열린다. 검사기가 이것으로 모든 화면을 돈다. 템플릿에 들어 있다.
- 글꼴은 Pretendard를 CDN으로 불러오고, 인터넷이 없으면 시스템 글꼴로 보이게 한다. 템플릿에 들어 있다.
- 외부 라이브러리는 꼭 필요할 때만 CDN으로 쓰고 보고서에 적는다.
- 파일 이름에 공백·괄호·`&`를 쓰지 않는다. 예: `변경요청_현황_20261021.html`.

## 6. 하지 말 것

- 규칙을 피하려고 요소를 숨기거나 `hallmark-ignore` 주석을 남발하지 않는다. 예외 주석은 `01_foundation.md` 8장의 경우에만 쓴다.
- 브라우저 검사를 하지 않았으면서 "검사 통과"라고 쓰지 않는다.
- 이 폴더 안에 결과물을 저장하지 않는다. 결과물은 프로젝트 폴더(이 폴더의 바깥)에 둔다.
- 다크 화면, PPT·Word·PDF 파일은 v1.0 범위 밖이다. 요청받으면 그 점을 먼저 알린다.
