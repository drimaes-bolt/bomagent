DA UI hallmark v1.0. 모든 결과물(업무 화면, 발표, 문서)에 적용한다. 프로필별 규칙은 `02_app_screens.md`와 `03_slides_docs.md`에 있다.

## 1. 기준값 (`:root`)

템플릿 세 개가 모두 이 값을 쓴다. 결과물에서 값을 바꾸지 않는다. 필요한 값이 없으면 가장 가까운 값을 쓰고 보고서에 적는다.

```css
:root{
  color-scheme: light;
  /* 회사 8색 */
  --co-black:#000000; --co-dark:#555555; --co-mid:#A0A0A0; --co-light:#DEDEDE;
  --co-mint:#7DEAD5;  --co-cyan:#1BBBCC; --co-blue:#4383AF; --co-navy:#06438C;
  --navy:#06438C;
  /* 네이비·민트 단계 (키트 brand·emerald 중 쓰는 것) */
  --b50:#E5F0F5; --b100:#C7DCE7; --b700:#052E62; --b800:#031F44;
  --e100:#E5F8F2; --e800:#16735F;
  /* 면 */
  --frame:#F4F5F7;   /* 바탕(틀) */
  --surface:#FFFFFF; /* 내용 면(시트·패널) */
  --raised:#FAFAFA;  /* 면 안의 보조 면 */
  --hover:#EEF0F3;   /* 마우스를 올렸을 때 */
  --active:#E6E8EC;  /* 선택된 메뉴 */
  /* 선 */
  --edge:#E3E5E9;    /* 시트·패널 테두리 */
  --rule:#EEF0F3;    /* 표·목록 행 구분 */
  --control:#CBD0D6; /* 버튼 테두리 */
  --control-strong:#868C93; /* 입력칸·선택 상자·체크 상자 테두리 (3:1) */
  --grid:#DEDEDE;    /* 엑셀형 표 격자 */
  /* 글자 */
  --ink:#111111;     /* 제목, 본문, 핵심 값 */
  --ink-2:#555555;   /* 설명, 표 칸, 메뉴 */
  --ink-3:#6B6F76;   /* 보조 정보, 단위, 출처 */
  /* 그림자: 떠 있는 것에만 */
  --float:0 10px 28px rgba(0,0,0,.08);
  /* 글꼴 */
  --font:"Pretendard Variable",Pretendard,-apple-system,BlinkMacSystemFont,system-ui,"Segoe UI","Apple SD Gothic Neo","Noto Sans KR","Malgun Gothic",sans-serif;
  --sheet-font:"HM Sheet","Malgun Gothic","맑은 고딕","Apple SD Gothic Neo","Noto Sans KR",sans-serif;
  /* 모서리 */
  --r-tag:4px; --r-ctl:6px; --r-panel:8px; --r-sheet:16px;
}
/* 엑셀형 표를 쓸 때만: 설치된 맑은 고딕을 이름 하나로 묶는다 */
@font-face{font-family:"HM Sheet";src:local("Malgun Gothic"),local("MalgunGothic"),local("맑은 고딕");font-weight:400}
@font-face{font-family:"HM Sheet";src:local("Malgun Gothic Bold"),local("MalgunGothicBold"),local("맑은 고딕 Bold");font-weight:700}
```

글꼴은 `<head>`에서 이렇게 불러온다. 인터넷이 없으면 시스템 글꼴로 보인다.

```html
<link rel="stylesheet" crossorigin href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
```

## 2. 색

### 2.1 회사 8색의 쓰임

| 이름 | 값 | 쓰는 곳 | 글자로 |
|---|---|---|---|
| 검정 | `#000000` | 거의 쓰지 않는다. 제목은 `--ink`(`#111111`) | 가능 |
| 진회색 | `#555555` | 설명, 표 칸, 메뉴 글자 (`--ink-2`) | 가능 |
| 중회색 | `#A0A0A0` | 꺼진 아이콘의 선, 장식 | **불가** (흰 바탕 2.61:1) |
| 연회색 | `#DEDEDE` | 엑셀형 표 격자 | 불가 |
| 민트 | `#7DEAD5` | 차트 채움, 장식 | 불가 |
| 시안 | `#1BBBCC` | 차트 둘째 계열, 장식 | 불가 |
| 파랑 | `#4383AF` | 차트 계열, 24px 이상 큰 글자 | 큰 글자만 (4.11:1) |
| 네이비 | `#06438C` | 2.2의 다섯 곳 | 가능 (9.59:1) |

### 2.2 네이비는 다섯 곳에만

1. 로고 표시
2. 화면의 주 버튼 하나
3. 선택 표시: 탭 밑줄, 선택된 칩, 현재 단계, 선택된 셀 테두리
4. 화면의 주 데이터 한 계열: 차트의 핵심 막대, 표의 핵심 값
5. 강조 면: So-What 바, 강조 알림 상자(네이비 바탕 + 흰 글자)

메뉴, 머리글, 테두리, 아이콘 같은 틀(크롬)은 회색으로 둔다. 화면 첫 화면에서 진한 색이 차지하는 면적은 12%를 넘기지 않는다.

### 2.3 쓰지 않는 색

빨강, 주황, 노랑, 보라, 분홍, 민트 계열이 아닌 초록은 쓰지 않는다. 브라우저 기본 파랑 링크 색도 쓰지 않는다.

경고·위험·실패는 색으로 표시하지 않는다. 네이비 + 굵은 글씨 + 문장으로 쓴다. 예: 네이비 테두리 꼬리표 "확인 필요", 네이비 바탕 꼬리표 "차단", 문장 "재고 조회에 실패했다. 10:24 값이다."

### 2.4 대비 [관측]

글자는 바탕과 4.5:1 이상이어야 한다. 24px 이상, 또는 19px 이상 굵은 글자는 3:1 이상이면 된다. 아래 값은 v1.0 제작 때 계산했다.

| 글자 \ 바탕 | 흰색 | `--raised` | `--frame` | `--hover` | `--active` | `--b50` | `--e100` |
|---|---|---|---|---|---|---|---|
| `--ink` `#111111` | 18.88 | 18.09 | 17.31 | 16.54 | 15.39 | 16.29 | 17.12 |
| `--ink-2` `#555555` | 7.46 | 7.14 | 6.83 | 6.53 | 6.08 | 6.43 | 6.76 |
| `--ink-3` `#6B6F76` | 5.05 | 4.84 | 4.63 | **4.42** | **4.11** | **4.35** | 4.58 |
| 네이비 `#06438C` | 9.59 | 9.19 | 8.79 | 8.40 | 7.82 | 8.27 | 8.70 |
| `--b700` `#052E62` | 13.35 | 12.79 | 12.23 | 11.69 | 10.88 | 11.51 | 12.10 |
| `--e800` `#16735F` | 5.75 | 5.51 | 5.27 | 5.04 | 4.69 | 4.96 | 5.21 |
| 파랑 `#4383AF` | 4.11 | 3.94 | 3.77 | 3.60 | 3.35 | 3.55 | 3.73 |
| 중회색 `#A0A0A0` | 2.61 | 2.51 | 2.40 | 2.29 | 2.13 | 2.26 | 2.37 |

- `--ink-3`은 `--hover`, `--active`, `--b50` 위에 쓰지 않는다. 그 위에서는 `--ink-2`를 쓴다.
- 흰 글자는 네이비(9.59:1), `--b700`(13.35:1), `--e800`(5.75:1) 위에만 쓴다.
- 입력칸 테두리는 `--control-strong`(흰 바탕 3.39:1)을 쓴다. 버튼은 글자가 있으므로 `--control`을 쓴다.

### 2.5 상태 꼬리표 색

| 상태 | 바탕 | 글자 | 테두리 |
|---|---|---|---|
| 중립 (대기, 초안) | `--hover` | `--ink-2` | 없음 |
| 정보 (검토 중, 추천) | `--b50` | `--b700` | 없음 |
| 완료 (승인, 자동) | `--e100` | `--e800` | 없음 |
| 확인 필요 | 흰색 | 네이비 | 1px 네이비 |
| 차단 (드물게) | 네이비 | 흰색 | 없음 |
| 향후 기능 | 없음 | `--ink-3` | 없음 |

"차단"처럼 바탕을 채운 꼬리표는 보이는 행의 1/5을 넘으면 쓰지 않는다. 넘으면 "확인 필요" 모양으로 바꾼다.

## 3. 글꼴

- 글꼴은 Pretendard 하나다. 엑셀처럼 칸을 다루는 표(엑셀형 표)만 맑은 고딕을 쓴다.
- 고정폭 글꼴은 실제 코드(`<pre>`, `<code>`)에만 쓴다. ID와 숫자는 본문 글꼴에 `font-variant-numeric: tabular-nums`를 쓴다.
- 굵기는 400·500·600·700 중 세 개까지 쓴다. 700은 한 화면에 한 가지 용도(제목 또는 핵심 숫자)에만 쓴다.
- 대문자 변환(`text-transform: uppercase`)과 자간 넓힘을 쓰지 않는다. 큰 제목만 `letter-spacing: -0.01em ~ -0.02em`을 허용한다.
- 한글 줄바꿈은 `word-break: keep-all; overflow-wrap: break-word;`로 한다.
- 제목에는 `text-wrap: balance`를 쓴다.

### 3.1 크기 단계

| 쓰임 | 업무 화면 | 발표 (1440×900 기준) | 문서 |
|---|---|---|---|
| 큰 제목 | 화면 제목 22px/600 (휴대폰 20px) | 표지 52~56px/700, 장 제목 34~38px/700 (휴대폰 26px) | 문서 제목 34px/700 (휴대폰 28px) |
| 절 제목 | 16px/600 | 20px/600 | 24px/700, 소제목 18px/600 |
| 본문 | 14px | 17~18px | 16~17px, 줄간격 1.7 |
| 표·데이터 | 13~14px | 15~16px | 15px |
| 핵심 숫자 | 22~30px/600 | 36~44px/700 | 30~36px/700 |
| 보조·출처 | 12~13px | 14px | 13~14px |
| 최소 | 12px (11px 이하 금지) | 13px | 13px |

한 화면에서 쓰는 글자 크기는 6가지 안팎으로 둔다. 9가지를 넘기지 않는다.

## 4. 면·선·그림자·모서리

- 바탕은 `--frame`, 내용 면은 흰색이다. 화면은 "회색 틀 안의 흰 시트 한 장"으로 만든다.
- 면은 한 단계 톤 차이로 나눈다. 업무 화면은 1px `--edge` 선도 쓸 수 있다. 선과 그림자를 함께 쓰지 않는다.
- 그림자는 떠 있는 것(툴팁, 팝오버, 메뉴, 대화상자, 토스트, 셀 편집기)에만 쓴다. 값은 `--float` 하나다. 검정 0.08을 넘기지 않고, 색 있는 그림자(글로우)는 쓰지 않는다.
- 반투명 + 흐림(`backdrop-filter`)을 쓰지 않는다.
- 그라데이션은 어디에도 쓰지 않는다. 표지, 로고 표시, 버튼, 글자, 점무늬 바탕 모두 포함이다.
- 모서리는 쓰임마다 하나로 정한다: 꼬리표 4px, 버튼·입력칸 6px, 패널 8px, 시트 16px, 사람·원형 표시만 원.

## 5. 간격

4px 단위로 쓴다.

| 쓰임 | 값 |
|---|---|
| 시트 안쪽 여백 | 24px (휴대폰 16px) |
| 패널 안쪽 여백 | 14~20px |
| 패널 사이 | 16px (한 화면에서 하나로 통일) |
| 제목 줄 → 첫 블록 | 20~24px |
| 절 사이 | 업무 화면 24~32px, 문서 56~72px |
| 버튼·입력칸 높이 | 32px (작게 28px, 크게 36px, 휴대폰 40px 이상) |
| 표 행 높이 | 40~48px (촘촘한 목록 36px, 엑셀형 표 24px) |

## 6. 움직임

- 움직임은 상태 변화에만 쓴다: 마우스를 올림, 선택, 펼침, 저장됨. 0.12~0.2초, `ease-out`.
- 화면이나 장이 나타날 때의 등장 효과(페이드·떠오름)를 쓰지 않는다.
- 계속 반복하는 장식(흐르는 점선, 깜박이는 점, 맥박)을 쓰지 않는다. 불러오는 중 표시(작은 회전 표시)만 예외다.
- 마우스를 올렸을 때 카드가 떠오르는(`translateY`, `scale`) 효과를 쓰지 않는다. 바탕색이나 테두리 색만 바꾼다.
- `@media (prefers-reduced-motion: reduce)`에서 모든 전환을 끈다.

## 7. 빼야 할 장치

"AI가 만든 티"가 나는 장치다. 검사기가 대부분 잡는다.

| 장치 | 대신 |
|---|---|
| 제목 위 작은 대문자 라벨(eyebrow), 제목 위 알약 배지("NEW", "v1.0") | 그 정보를 제목이나 첫 문장에 넣거나 지운다 |
| 장식용 번호 01 / 02 / 03, "STEP 01", 번호 배지 | 위치·크기·문장으로 순서를 보인다. 순서가 내용이면 `<ol>` |
| 고정폭 글꼴 라벨 | 본문 글꼴 + `tabular-nums` |
| 그라데이션 바탕·버튼·글자·로고 | 단색 |
| 쉬고 있는 카드의 그림자, 마우스를 올리면 떠오르는 카드 | 톤 차이 또는 1px 선 |
| 색 그림자(글로우), 활성 메뉴의 빛나는 막대·점 | 회색 채움 + 굵은 글씨 |
| 반투명 흐림 패널(유리), 떠 있는 둥근 알약 메뉴 | 불투명한 면, 평범한 막대 |
| 아이콘을 색 원·네모에 넣은 카드, 행마다 아이콘 상자 | 라벨과 숫자. 아이콘은 16px 회색 선 하나 |
| 같은 모양 카드를 줄줄이 늘어놓은 격자 | 한 상자를 1px로 나눈 줄, 표, 목록 |
| 이모지, 장식 도형, 회색 막대로 만든 가짜 대시보드 | 문장, 실제 데이터, 실제 화면 조각 |
| 제목 한 단어만 다른 색·기울임·밑줄 | 한 글꼴, 한 색 |
| 3줄 이상 넘어가는 제목 | 제목은 2줄 이내. 넘으면 말을 줄인다 |
| 작은 글씨로 흩뿌린 메타 정보(시각, 버전 도장, 가운뎃점 나열) | 필요한 정보만 제자리에 |

장치를 빼서 생긴 빈자리를 다른 장식으로 채우지 않는다. 핵심 내용을 키우거나, 내용을 더 온전히 보여 주거나, 빈자리를 줄인다.

## 8. 예외 표시

아래 경우에만 규칙에 걸리는 코드를 남길 수 있다. 같은 줄에 `hallmark-ignore: 이유` 주석을 단다. 검사기의 코드 검사는 이 줄을 건너뛴다. 화면 검사(브라우저)는 예외 주석을 보지 않으므로, 아래 경우는 검사기가 원래 잡지 않게 되어 있다.

| 경우 | 예 |
|---|---|
| 떠 있는 요소의 그림자 | `box-shadow:var(--float); /* hallmark-ignore: 떠 있는 요소 */` |
| 엑셀형 표의 선택 머리글 밑줄(안쪽 그림자) | `box-shadow:inset 0 -2px 0 var(--navy); /* hallmark-ignore: 엑셀식 선택 표시 */` |
| 키보드 초점 표시 | `box-shadow:inset 0 0 0 2px rgba(6,67,140,.3); /* hallmark-ignore: 초점 표시 */` |
| 불러오는 중 회전 표시 | `animation:spin .7s linear infinite; /* hallmark-ignore: 불러오는 중 */` |
| 실제 코드 블록의 고정폭 글꼴 | `<pre>`, `<code>` 안 |

이 밖의 경우에 예외 주석을 쓰면 보고서에 이유를 적는다.

## 9. 문구

- **결론 먼저.** 화면 제목 아래 한 줄, 장 제목, 문서 첫 단락에 결론을 쓴다. 근거는 뒤에 둔다.
- **제목은 2줄 이내.** 1440·768·390 폭 모두에서 지킨다. 넘으면 글자 크기가 아니라 말을 줄인다. 발표 장 제목은 24자 안팎을 목표로 한다 [가안].
- **제목은 이름 또는 주장.** 업무 화면은 명사("변경 요청", "품목"), 발표 장은 주장("처리 기간은 승인 대기에서 늘어난다")으로 쓴다. 인사말("환영합니다")로 시작하지 않는다.
- **버튼은 동작 이름.** "E-BOM 가져오기", "승인", "변경 내용 저장". "시작하기", "자세히 보기", "여기를 클릭"만 단독으로 쓰지 않는다. 한 화면의 같은 동작은 같은 이름이다.
- **흔한 광고 문구를 쓰지 않는다.** 혁신적인, 획기적인, 차세대, 원활한, 손쉽게, 강력한, 최첨단, 한 단계 더, 새로운 차원, 올인원, 극대화, 시너지, 게임 체인저, "~의 미래". 구체적으로 무엇이 얼마나 달라지는지 쓴다.
- **문장부호.** 줄표(—)를 습관처럼 쓰지 않는다. 마침표나 쉼표로 끊는다. 느낌표와 이모지를 쓰지 않는다.
- **숫자.** 단위를 붙인다. 천 단위 쉼표를 쓴다. 지표마다 소수 자릿수를 고정한다(금액 0 또는 2, 비율 1). 변화에는 부호를 붙이고 기준을 쓴다("지난주보다 +3건"). 없는 값은 회색 "–", 실제 0은 "0"으로 쓴다.
- **지어낸 근거를 쓰지 않는다.** 고객사 로고, 인용, 사용자 수, 성과 수치를 지어내지 않는다. 시연용으로 만든 값은 `[가상]` 또는 "예시 값"이라고 화면에 남긴다.
- **사람 이름 대신 역할.** 예시 데이터에 실존 인물이나 "홍길동" 같은 자리채움 이름을 쓰지 않는다. "연구소 담당", "구매 담당"처럼 역할로 쓴다.
- **자리채움 글을 남기지 않는다.** Lorem ipsum, "텍스트를 입력하세요", "샘플 텍스트", "OOO".

## 10. 접근성 기본

검사기가 대비·크기 일부를 확인하지만, 접근성 전체를 보장하지 않는다. 완전한 확인은 보조기기로 직접 써 보는 수동 점검이 필요하다.

- `<html lang="ko">`, 화면마다 `h1` 하나, 제목 순서(h1 → h2 → h3)를 건너뛰지 않는다.
- 모든 버튼·링크·입력칸에 읽을 수 있는 이름을 단다. 아이콘만 있는 버튼은 `aria-label`을 단다.
- 입력칸은 `<label>`과 연결한다. 자리채움 글(placeholder)을 라벨 대신 쓰지 않는다.
- 키보드로 모든 조작이 된다. 초점 표시는 2px 네이비 외곽선으로 보이게 한다(`:focus-visible`).
- 선택된 메뉴는 `aria-current="page"`, 탭은 `role="tab"`과 `aria-selected`를 쓴다.
- 그림·차트에는 대체 글(`alt`, `aria-label`, 또는 바로 옆 설명 문장)을 둔다.
- 휴대폰에서 누르는 곳은 높이 40px 이상으로 한다. 24px보다 작게 만들지 않는다.
- 색만으로 상태를 구분하지 않는다. 꼬리표 글자나 기호를 함께 쓴다.

## 11. 개발 프로젝트에서 쓸 때

React·Next.js·Tailwind 같은 개발 프로젝트에서도 1장의 CSS 변수를 그대로 쓴다. Tailwind는 아래처럼 변수에 연결한다.

```js
// tailwind.config.js 의 theme.extend
colors: {
  navy: 'var(--navy)', frame: 'var(--frame)', surface: 'var(--surface)',
  raised: 'var(--raised)', hover: 'var(--hover)', active: 'var(--active)',
  edge: 'var(--edge)', rule: 'var(--rule)', control: 'var(--control)',
  ink: { DEFAULT: 'var(--ink)', 2: 'var(--ink-2)', 3: 'var(--ink-3)' },
  b50: 'var(--b50)', b100: 'var(--b100)', b700: 'var(--b700)', e100: 'var(--e100)', e800: 'var(--e800)',
},
fontFamily: { sans: ['var(--font)'] },
borderRadius: { tag: '4px', ctl: '6px', panel: '8px', sheet: '16px' },
boxShadow: { float: 'var(--float)' },
```

이때도 템플릿의 화면 구조와 2~9장의 규칙을 따른다. 검사기는 빌드한 결과 HTML을 검사한다.
