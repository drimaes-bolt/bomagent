# 03 웹 발표·브리핑 문서 (`slides`·`doc` 프로필)

DA UI hallmark v1.0. `01_foundation.md`를 먼저 읽는다. 시작 틀은 발표 `11_template_slides.html`, 문서 `12_template_doc.html`이다.

| 형식 | 프로필 | 언제 | 넘기는 방법 |
|---|---|---|---|
| 발표 자료 | `slides` | 회의에서 화면에 띄우고 한 장씩 설명할 때 | 한 장씩 (←/→, 목차) |
| 브리핑·보고 문서 | `doc` | 혼자 읽거나 공유해 두고 볼 때. 요약 페이지, 안내 페이지 포함 | 위아래 스크롤 |

PPT·Word·PDF 파일은 이 규칙의 대상이 아니다. 웹 페이지(HTML)로 만드는 자료만 다룬다.

---

## 1. 쓰기 전에: 주장 목록

디자인 전에 장(또는 절)마다 한 줄씩, 주장과 그 근거를 쓴다.

```
1. 변경 요청 처리 기간이 4.8일이다 [가상]          → 지표 3개
2. 늘어난 시간의 대부분은 승인 대기다              → 원인 표
3. 승인 단계를 둘로 줄이면 2.5일이 된다 [가안]      → 지금·바뀐 뒤 비교
4. 결정할 것은 두 가지다                          → 결정 목록
```

- 주장이 없는 장은 지운다. 이 목록의 순서가 자료의 순서다.
- 한 장(한 절)에 주장은 하나다. 주장이 둘이면 장을 나눈다.
- 결론을 먼저 둔다. 둘째 장(문서는 첫 절)이 요약이다.
- 숫자에는 근거를 단다(문서 ID와 절, 외부 자료는 링크). 측정 전 목표는 `[가안]`, 시연용 값은 `[가상]`, 합의 전 안은 `[제안]`으로 표시한다.
- 결정되지 않은 것은 "결정 필요"로 따로 모은다.

## 2. 발표 자료 (`slides`)

### 2.1 셸

```
┌──────────┬─────────────────────────────────────┐
│ 목차 240px │ ┌─────────────────────────────────┐ │
│ (--frame) │ │ 흰 시트 (r16, 테두리 없음)          │ │
│ 자료 이름   │ │  장 제목 (주장, h1)                │ │
│ 날짜·버전   │ │  한 줄 설명                         │ │
│ 장 목록     │ │  본문 한 덩어리                      │ │
│          │ │  출처                              │ │
│ 발표 모드   │ ├─────────────────────────────────┤ │
│ 인쇄       │ │ ← 이전   3 / 9   다음 →            │ │
│          │ └─────────────────────────────────┘ │
└──────────┴─────────────────────────────────────┘
```

- 목차는 장 제목을 그대로 쓴다. 번호를 붙이지 않는다. 지금 장은 `--active` 채움 + 굵은 글씨.
- 시트는 흰색, 테두리 없이 바탕과의 톤 차이로만 구분한다.
- 쪽 넘김은 시트 아래 평범한 막대다(이전·쪽수·다음). 떠 있는 알약 모양으로 만들지 않는다. 쪽수는 "3 / 9"처럼 0을 채우지 않는다.
- 장마다 `<section class="slide" data-hm-view="이름" id="이름">`. 지금 장만 보인다. 장 제목은 그 장의 `h1`이다(한 번에 하나만 보이므로 화면마다 `h1`은 하나다).
- 조작: ←/→, PageUp/PageDown, Home/End, 주소 `#이름`으로 바로 열기, `F` 발표 모드(목차 숨김), 인쇄(한 장 = 한 쪽). 템플릿에 들어 있다.

### 2.2 한 장의 구성

| 부분 | 규칙 |
|---|---|
| 제목 (`h1`) | 주장 한 문장. 34~38px/700, 2줄 이내(휴대폰 26px에서도). 24자 안팎 [가안] |
| 한 줄 설명 | 선택. 17~18px `--ink-2`, 한두 줄. 제목을 다른 말로 반복하지 않는다 |
| 본문 | 한 덩어리: 표 하나, 지표 줄 하나, 흐름 하나, 비교 하나 중 하나. 섞으면 장을 나눈다 |
| So-What 바 | 선택. 표·차트 아래 네이비 바탕 한 줄. 제목과 같은 말이면 쓰지 않는다 |
| 출처 | 14px `--ink-3`. "근거: R04 6.3, 2026-10 회의록" |

- 제목과 본문은 한 덩어리로 세로 가운데에 두고, 출처는 시트 맨 아래에 둔다. 휴대폰에서는 위에서부터 흐른다.
- 1440×900에서 한 장이 한 화면 안에 들어가야 한다. 넘치면 글자를 줄이지 말고 장을 나눈다.
- 장마다 구성(표, 흐름, 비교, 지표, 목록)을 바꾼다. 같은 구성이 세 장 연속이면 다시 짠다.
- 카드 격자를 기본 구성으로 쓰지 않는다.

### 2.3 표지

- 제목 52~56px/700, 2줄 이내. 자료의 핵심 주장을 쓴다("변경 요청 처리 기간을 절반으로").
- 한 문장 설명(20px `--ink-2`), 그 아래 날짜·부서·버전 한 줄(15px `--ink-3`).
- 그라데이션, 배지, 장식 도형을 쓰지 않는다. 빈 화면이 넓으면 핵심 숫자 하나를 크게 두거나 요약 세 줄을 둔다.

### 2.4 장 종류별 모양

| 장 | 모양 |
|---|---|
| 요약 | 주장 3~4줄 목록(각 줄 굵은 핵심어 + 설명). 맨 아래 So-What 바 |
| 지표 | 톤 칸으로 나눈 지표 줄 3~4칸. 핵심 숫자 하나만 네이비. 칸마다 기준 문장 |
| 원인·근거 표 | 표 하나(머리글 14px 회색, 행 선 1px). 핵심 열 강조는 굵은 네이비 글자 |
| 흐름 | 단계 블록을 가로로(휴대폰에서는 세로로), 사이에 정지한 화살표. 순서가 번호보다 중요하면 번호 없이 위치로 |
| 비교 | 지금·바뀐 뒤 2열 표. 바뀐 뒤 열의 머리글과 값을 네이비 굵게 |
| 일정 | 단계 3~5개를 한 줄 트랙으로. 지금 단계만 네이비 채움, 지난 단계 `--b100`, 앞으로 `--hover` |
| 결정 필요 | 결정 항목, 선택지, 결정할 역할, 기한을 표로 |
| 부록·근거 | 문서 목록 표. 본문보다 작게(15px) |

### 2.5 휴대폰

목차는 상단 막대의 "목차" 버튼으로 접힌다. 장은 위아래로 흐르고 쪽 넘김 막대는 화면 아래에 붙는다. 흐름은 세로로, 비교 표는 두 줄 목록으로 바꾼다.

## 3. 브리핑·보고 문서 (`doc`)

### 3.1 셸

- 상단 막대(48px, `--frame`): 문서 표시와 이름, 버전, 오른쪽에 인쇄 버튼.
- 흰 시트(테두리 없음, 모서리 16px) 안에 본문 열. 본문 글 폭은 최대 720px(한 줄 45~75자). 표와 그림은 1000px까지 넓힐 수 있다.
- 1200px 이상에서는 왼쪽에 목차를 붙여 둔다(스크롤해도 고정). 지금 읽는 절은 `--active` 채움.

### 3.2 구조

1. 제목(`h1`, 34px/700, 2줄 이내) + 날짜·작성 부서·버전 한 줄
2. 요약: 결론 3~5줄. 정보 알림 상자 하나에 담는다
3. 본문 절(`h2` 24px/700): 절마다 주장 하나. 첫 문장이 그 절의 결론이다
4. 결정 필요
5. 근거 자료와 변경 이력(표)

- 본문 16~17px, 줄간격 1.7, `--ink`. 설명·캡션은 `--ink-2`, 출처는 `--ink-3` 13~14px.
- 절 사이는 선이 아니라 여백(56~72px)으로 나눈다.
- 문단은 짧게(3~5문장). 나열은 표나 목록으로.
- 그림·차트 아래에 한 줄 설명(캡션)을 단다.

## 4. 공통 구성 요소

| 요소 | 모양 |
|---|---|
| 알림 상자 `.call` | 테두리 없는 틴트. 정보 `--b50`, 완료 `--e100`, 보통 `--raised`, 강조 네이비 바탕 흰 글자. 제목 한 줄 + 본문 |
| So-What 바 `.sowhat` | 네이비 바탕, 흰 글자 600, 모서리 6px, 표·차트 바로 아래 |
| 지표 줄 `.kpis` | 값 위, 라벨 아래, 기준 문장 맨 아래(업무 화면과 순서가 반대다. 큰 숫자 바로 위의 작은 라벨은 eyebrow로 걸린다). 발표는 칸마다 `--raised` 바탕에 칸 사이 2px, 문서는 상자 없이 간격만 둔다. 휴대폰 문서는 라벨 왼쪽·값 오른쪽 목록 |
| 표 `.tbl` | 머리글 회색 문장형, 행 사이 1px `--rule`, 숫자 오른쪽 정렬. 표는 선을 써도 된다 |
| 흐름 `.flow` | 흰 바탕이면 `--raised` 블록, 사이에 `--ink-3` 정지 화살표(SVG). 흐르는 점선 애니메이션 없음 |
| 일정 트랙 `.road` | 6px 두께 막대를 단계 수만큼 나눔. 지금 단계 네이비 |
| 인용 `.quote` | 왼쪽 4px `--b100` 막대 + 18px 본문 + 출처 한 줄 |
| 출처 `.src` | 장·절 끝 13~14px `--ink-3` |

## 5. 발표·문서에서 금지

| 금지 | 대신 |
|---|---|
| 절·장 사이의 가는 구분선, 1px 테두리 상자를 셋 이상 | 여백, 톤 차이 |
| 장 머리의 번호 배지, eyebrow, "CHAPTER 01" | 제목(주장)만 |
| 아이콘을 얹은 같은 모양 카드 3~4개 | 표, 목록, 흐름, 비교 중 내용에 맞는 하나 |
| 장이 나타날 때 떠오르는 효과, 흐르는 점선 | 정지한 화면 |
| 사진 자리에 회색 상자, "이미지" 글자 | 실제 그림이나 SVG 도해, 아니면 없음 |
| 3줄 넘는 제목, 한 장에 주장 두 개 | 말을 줄이거나 장을 나눔 |
| 한 화면을 넘어 아래로 스크롤해야 하는 장 | 장 나누기 |
