네 단계면 된다
  • 받은 zip을 프로젝트 폴더에 푼다. 폴더 이름은 DA_UI_hallmark이다.
  • Claude 프로젝트에 지침 4줄을 한 번 붙여 넣는다.
  • 평소처럼 화면이나 자료를 요청한다. AI가 이 폴더의 규칙을 읽고 만든다.

이 폴더로 하는 일

회사 웹 화면과 웹 문서를 같은 모양으로 만들게 하는 규칙 묶음이다. 사내 웹 키트의 색과 글꼴을 이어받고, "AI가 만든 티"가 나는 장식을 뺐다. 번호가 붙은 파일은 AI가 읽고, 번호가 없는 파일은 사람이 쓴다.

파일누가무엇
00 ~ 04 (.md)AI우선순위, 색·글꼴, 업무 화면 규칙, 발표·문서 규칙, 점검표
10 ~ 12 (.html)AI업무 화면, 발표, 문서의 시작 틀. 열어 보면 완성된 예시가 보인다
checker.html사람결과 HTML을 세 가지 폭으로 띄워 규칙을 검사하는 도구
GUIDE.html사람지금 보는 안내
NOTICE.md, CHANGELOG.md사람출처·라이선스, 버전 기록

처음 한 번: 폴더 풀기

  1. 받은 DA_UI_hallmark_v1.0.zip을 작업할 프로젝트 폴더로 옮긴다. 예: 문서\변경요청_개선
  2. zip을 마우스 오른쪽 단추로 누르고 모두 압축 풀기를 고른다.
  3. 풀 위치 칸 끝의 \DA_UI_hallmark_v1.0을 지워 프로젝트 폴더만 남기고 압축 풀기를 누른다.
  4. 프로젝트 폴더 안에 DA_UI_hallmark 폴더가 생기고, 그 안에 00_READ_FIRST.md가 보이면 끝이다.

3번을 건너뛰어 DA_UI_hallmark_v1.0\DA_UI_hallmark처럼 두 겹이 되어도 동작한다. 안쪽 폴더를 프로젝트 폴더로 옮기면 깔끔하다.

처음 한 번: Claude에 알리기

Claude는 폴더 안의 규칙 파일을 스스로 찾아 읽지 않는다. 그래서 프로젝트 지침에 "먼저 읽으라"고 한 번 적어 둔다. 쓰는 화면에 맞는 쪽 하나만 하면 된다.

Cowork를 쓸 때 (유료 플랜)

  1. Claude 데스크톱 앱 왼쪽의 프로젝트(Projects)에서 +를 누른다.
  2. 기존 폴더 사용(Use an existing folder)을 고르고 프로젝트 폴더를 고른다.
  3. 지침(Instructions) 칸에 아래 지침을 붙여 넣고 만든다.
  4. 이 프로젝트에서 작업을 시작하면 AI가 폴더의 규칙을 읽고, 결과 파일을 프로젝트 폴더에 저장한다.

Chat 프로젝트를 쓸 때 (무료 포함)

  1. Claude에서 프로젝트(Projects) → 새 프로젝트를 만든다.
  2. 프로젝트 지식(Project knowledge)에 DA_UI_hallmark 폴더의 번호 붙은 파일 8개(00~04, 10~12)를 끌어다 놓는다. checker.html과 GUIDE.html은 올리지 않는다.
  3. 지침 칸에 아래 지침을 붙여 넣는다.
  4. 결과 HTML은 대화에서 내려받아 프로젝트 폴더에 저장한다.
붙여 넣을 지침

이 프로젝트의 화면·문서 디자인은 DA UI hallmark 규칙을 따른다. 1. 디자인 작업 전에 DA_UI_hallmark 폴더(또는 프로젝트 지식)의 00_READ_FIRST.md를 먼저 읽고, 거기 적힌 순서대로 번호 붙은 파일을 모두 읽는다. 2. hallmark와 다른 디자인 규칙(DA_WEBUI_KIT 포함)이 충돌하면 hallmark를 따른다. 3. 결과물을 넘기기 전에 04_checklist.md로 점검하고 5장 양식으로 보고한다. 하지 않은 검사는 했다고 쓰지 않는다. 4. 내가 checker.html 보고서를 붙여 넣으면 FAIL부터 고친다.

메뉴 이름은 앱 언어 설정과 버전에 따라 조금 다를 수 있다. Cowork 프로젝트 안내: Claude 도움말

요청하기

무엇을 만들지, 누가 쓰는지, 화면마다 답할 질문(또는 장마다 주장)을 함께 적으면 결과가 좋아진다. 자료가 있으면 같이 올린다.

업무 화면

hallmark 규칙으로 [무엇을 하는] 업무 화면을 만들어 줘. 쓰는 사람: [부서, 얼마나 자주] 화면: [목록 / 상세 / 설정 등] 화면마다 답할 질문: [예: 오늘 먼저 처리할 요청은 무엇인가] 데이터: [첨부 파일] (없으면 [가상] 예시 값으로)

발표 자료

hallmark 발표 템플릿으로 [주제] 발표 자료를 만들어 줘. 듣는 사람: [누구] 장마다 주장 하나, 둘째 장은 요약, 결정할 것은 따로 한 장. 근거 자료: [첨부 파일]

브리핑·보고 문서

hallmark 문서 템플릿으로 [주제] 보고서를 만들어 줘. 결론을 맨 앞 요약에 쓰고, 절마다 주장 하나, 결정 필요 사항은 따로 모아 줘. 근거 자료: [첨부 파일]

검사하기

  1. DA_UI_hallmark 폴더의 checker.html을 두 번 눌러 연다. Edge가 아니라 다른 프로그램으로 열리면 오른쪽 단추 → 연결 프로그램 → Microsoft Edge.
  2. 결과 HTML 파일을 검사기 화면 위로 끌어다 놓는다. 30초~2분이면 끝난다.
  3. 보고서 복사를 누르고 Claude 대화창에 붙여 넣는다. AI가 FAIL부터 고친다.
  4. 고친 파일로 다시 검사한다. 세 번까지 반복한다.
  5. 모양이 어색해 보이면 검사기의 "검사 화면"을 캡처(Win + Shift + S)해 붙여 넣고 "캡처 검토해 줘"라고 쓴다.
FAIL과 WARN

FAIL은 고쳐야 하는 것, WARN은 대개 고치는 것이다. WARN을 남길 때는 AI가 이유를 한 줄로 적는다. 검사기는 파일을 이 PC 밖으로 보내지 않는다.

새 버전으로 바꾸기

  1. CHANGELOG.md를 열어 무엇이 바뀌었는지 본다.
  2. 프로젝트 폴더의 DA_UI_hallmark 폴더를 지우고 새 zip을 같은 방법으로 푼다.
  3. Chat 프로젝트를 쓰면 프로젝트 지식의 옛 파일 8개를 지우고 새 파일 8개를 올린다.
  4. 지침은 그대로 둔다. AI는 보고할 때 몇 버전을 적용했는지 밝힌다.

막힐 때

이럴 때이렇게
끌어다 놓아도 반응이 없다검사기의 파일 고르기 단추로 고른다.
글꼴이 예시와 다르다인터넷이 없으면 Pretendard 대신 시스템 글꼴로 보인다. 검사기에 "지정한 글꼴이 안 불러와졌다" 경고가 나올 수 있다.
AI가 규칙을 안 읽은 것 같다"00_READ_FIRST.md를 읽었는지 확인하고 04_checklist.md 5장 양식으로 보고해 줘"라고 요청한다.
검사가 끝나지 않는다결과 파일이 다른 파일(그림·CSS)을 불러오면 오래 걸릴 수 있다. 그림을 파일 안에 넣어 달라고 AI에게 요청한다.
화면이 여러 개인데 하나만 검사됐다AI에게 화면마다 data-hm-view를 달라고 하거나, 검사기의 "화면 주소를 더 넣어 검사"에 #화면이름을 적는다.

알아 둘 것

검사기는 결과 HTML 안의 스크립트를 검사 화면 안에서 실행한다. 어디서 왔는지 모르는 HTML은 검사하지 않는다.

Chat 프로젝트에 올린 파일은 Claude 계정에 저장된다. 회사 자료를 올릴 때는 사내 보안 규정을 따른다. 이 폴더의 규칙 파일에는 회사 기밀이 없다.

검사기는 대비와 누르는 곳 크기 일부를 확인하지만 접근성 전체를 보장하지 않는다. 완전한 확인은 화면 읽기 프로그램 같은 보조기기로 직접 써 보는 수동 점검이 필요하다.
