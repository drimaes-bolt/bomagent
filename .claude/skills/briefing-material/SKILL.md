# 설명자료 작성 가이드

Kiro 시절의 설명자료 자동 적용 규칙을 옮겼다(2026-11-19). 내용은 같고, Kiro의 파일 자동 포함 기능은 아래 "먼저 읽기"로 바꿨다.

## 먼저 읽기

작업 전에 다음 세 파일을 끝까지 읽는다.

1. `DA_UI_hallmark/00_READ_FIRST.md` — 우선순위, 작업 절차, 결과물 형식
2. `DA_UI_hallmark/01_foundation.md` — 색·글꼴·면·간격, 빼야 할 장치, 문구 규칙
3. `DA_UI_hallmark/04_checklist.md` — 점검 항목, 금지 패턴 검색, 보고 양식

그다음 만들 것에 맞는 프로필 문서와 시작 틀을 읽는다(아래 "디자인" 표). `checker.html`, `GUIDE.html`은 사람용이라 읽지 않는다.

## 대상과 목적

| 대상 | 알고 싶은 것 | 주로 쓸 문서 |
|---|---|---|
| 기획팀 | 왜 하는가, 무엇이 달라지는가, 누가 무엇을 하는가, 일정·비용·위험, 결정할 것 | README, docs/01·02·03·10·11 |
| 개발팀 | 무엇을 만드는가, 데이터와 연동, 모델 인터페이스, 규칙, 검증 기준 | docs/04~09, docs/11, docs/13 |

두 대상을 한 자료에 담으면 앞부분은 공통 설명, 뒷부분은 대상별 상세로 나눈다.

## 기본 스토리라인 (기획팀용 10~12장)

1. 문제: 같은 BOM을 부서마다 다르게 읽는다. 해독 병목, 이원화, 변경 이력 공백 (docs/01 2장)
2. 다봄 한 줄 정의와 이름의 뜻 (docs/01 1장)
3. 큰 흐름: 가져오기 → 맞추기 → 만들기 → 품번 → 확정 → 추적·알림 (docs/02 1장)
4. 사내 것을 먼저 쓰는 맞추기 순서 (docs/02 3장)
5. 부서별로 달라지는 일 (docs/03)
6. 누가 무엇을 하나: NC AI 모델 / 다봄 / 사람 (docs/06 3·4장)
7. M-BOM은 상태다: 변경 층·사유 코드·변경 패키지 (docs/07)
8. 먼저 준비할 기준정보 (docs/05 2장, docs/08 8장)
9. 단계별 로드맵과 종료 조건 (docs/10)
10. 위험과 결정이 필요한 사항 (docs/10 6장, docs/11)
11. 다음 할 일

개발팀용은 구조(docs/06), 데이터 구조(docs/05 3장), 모델 인터페이스(docs/06 4장), 변경 패키지(docs/07 4장), 발번 규칙(docs/08), 평가(docs/09), 화면 목록(docs/13)을 각 1~2장으로 더한다.

## 반드시 지킬 것

- [가상]·[제안]·[가안] 값은 자료에도 그대로 표시한다. KK 계열 샘플 수치를 실적처럼 쓰지 않는다.
- 실제 단가·재고 금액·거래처 계약 조건·개인 이름을 넣지 않는다.
- 결정되지 않은 사항(docs/11의 OI)은 '결정 필요'로 따로 모은다.
- 숫자에는 근거(R-ID와 절)를 각주로 단다.
- 산출물은 `briefing/` 폴더에 파일로 저장하고 파일명에 날짜(YYYYMMDD)를 붙인다. 공백·괄호·`&`는 쓰지 않는다.
- 새 산출물을 만들면 README 문서 지도와 변경 이력에 한 줄 더한다.

## 디자인

HTML 자료는 루트의 `DA_UI_hallmark/` 규칙(DA UI hallmark v1.0)을 따른다. hallmark는 사내 키트(`references/R08_DA_WEBUI_KIT.md`)보다 우선한다. R10·R11·R12는 키트로 만든 옛 선례라 모양을 따라 하지 않는다.

| 만들 것 | 시작 틀 | 규칙 |
|---|---|---|
| 발표 자료(한 장씩 넘김) | `DA_UI_hallmark/11_template_slides.html` | `03_slides_docs.md` |
| 요약 페이지, 보고서 | `DA_UI_hallmark/12_template_doc.html` | `03_slides_docs.md` |
| 시연용 화면 목업 | `DA_UI_hallmark/10_template_app.html` | `02_app_screens.md` |

- 회사 팔레트와 무채색만 쓴다. 경고·위험 의미의 색을 따로 쓰지 않는다. 강조는 네이비 면과 굵은 글씨로 한다.
- 만든 뒤 `DA_UI_hallmark/04_checklist.md`로 점검하고 5장 양식으로 보고한다. 브라우저 검사는 사람이 `DA_UI_hallmark/checker.html`로 한다. 하지 않은 검사는 했다고 쓰지 않는다.
- 세부 규칙이 이 문서와 다르면 hallmark를 따른다. `DA_UI_hallmark/` 안의 파일은 고치지 않고, 결과물도 그 폴더에 저장하지 않는다.
